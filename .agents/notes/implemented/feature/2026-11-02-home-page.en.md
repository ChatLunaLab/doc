# Agent Note: Home Page

Status: implemented

## Problem

The home page used the default VitePress hero, a feature grid and a session-log demo. It showed nothing of the product and looked like any other documentation site. Two redesigns were rejected along the way: a desktop scene with a dock, and an illustrated night scene with flat hills. Both read as decoration rather than as the product, and the second felt cheap.

## Decision

- `docs/index.md` uses `layout: home` with `markdownStyles: false`. The page is built from components in `docs/.vitepress/theme/components/home/` and HTML sections styled by `docs/.vitepress/theme/styles/home.css`.
- `HomeHero.vue` is the opening screen. It shows the original `/logo.png` as an app icon, then the headline "可组合的 Agent Harness，接入任何聊天平台。", the English tagline "A composable agent harness for any chat platform.", a 快速开始 link, and a button that copies `npm i -g chatluna`.
- Behind the hero, a canvas draws a dot-matrix moon rising like a horizon below the buttons. It is the halftone crescent from the logo at the scale of the sky: each dot's size is the brightness of a lit sphere, shaded by drifting maria and a bright limb. Dots swell around the pointer.
- The canvas repaints at about 30 fps only while the hero is visible. With reduced motion it is painted once, and again on resize or theme change.
- Below the moon, the console's trace page sits in an `AppWindow`. It starts tilted back and straightens as the page scrolls, through one `--rise` variable written from a throttled scroll listener. With reduced motion the window stays flat.
- `AppWindow.vue` frames screenshots and code: window controls, then a URL pill or a monospace title. `--app-bar-height` and `--app-radius` scale it. `HomeShot.vue` puts the light and dark screenshots of one console page in an `AppWindow` and switches them with the `.dark` class.
- Four feature rows alternate sides: 快捷设置, 场景规则, 聊天平台 with models, and the dashboard with traces. Each row pairs short copy and a link into the manual with a gradient panel (`.home-panel`, `.is-dusk` variant). The panel crops a console window and carries a faint halftone in its corner.
- The rest of the page:
  - capabilities as two grouped lists linking to the usage manual;
  - a plugin sample in an editor window;
  - the npm / Docker / source install commands as a segmented code group;
  - the community links under the logo.
- Screenshots in `docs/public/home/` are 2x WebP images, 1280×760 CSS px, of the Chinese UI with mock data, in light and dark. Configuration appears only through 快捷设置 and 场景规则, never the plugin settings page.
- Headings use the theme's sans stack; no web font is loaded. When scrolled past the hero at 960px and wider, the nav becomes a translucent blurred bar.

## Alternatives considered

- **Keep the VitePress hero and features frontmatter:** it cannot host screenshots or scroll effects, and it looks like every other VitePress site.
- **A desktop scene with a dock:** rejected. It imitates an operating system instead of showing the product.
- **An illustrated night scene with hills and floating chat bubbles:** rejected as cheap. The bubbles covered the screenshot.
- **CSS scroll-driven animations:** they are not available in every target browser. One listener writing a CSS variable works everywhere, and the page falls back to a still layout.
- **A logo strip of supported platforms:** the icon sets in the repository lack QQ and Feishu marks, and a mixed set looked uneven. The platforms are named in the row copy instead.

## Consequences

- Screenshots must be re-shot when the console UI changes. The mock-data tooling lives outside this repository.
- The hero's motion depends on JavaScript. Without it, the page renders the sky gradient and the tilted window.
- `home.css` is imported globally, so its classes are prefixed `home-`, and its only nav rule is scoped to `.VPNavBar.home`.
- The `SessionLogDemo` component was removed together with the old home page.
