# 日常使用

日常管理通常从 WebUI 的快捷设置、场景规则和预设编辑开始。建议先让一个默认对话稳定工作，再逐项增加群聊触发条件、扩展工具与自动化任务，无需在初次部署时配置完整清单。

---

## 运行时配置判定流程

当一条消息进入系统时，ChatLuna 会结合平台、机器人、群组和用户等多维度身份匹配规则，最终解析出当前上下文所需的 `engine`、模型、预设、会话归属、激活机制以及渲染参数。

这些字段分属不同的命名空间，不存在一个将所有选项全局绑定的“总配置项”。

```
Incoming Message (平台 / 机器人 / 群组 / 用户)
       │
       ▼
场景规则匹配 (按特异度、priority、创建时间、id 排序)
       │
       ▼
字段锁定过滤 (锁定后阻止后续规则覆盖)
       │
       ▼
最终运行时配置 (engine / 模型 / 预设 / 激活 / 渲染)
```

- **配置类型与适用场景**：
  - **快捷设置**：用于快速调整系统级常用默认值。
  - **场景规则**：用于为特定群组、用户或平台定义覆盖策略。
- **匹配与生效机制**：
  - 规则匹配并不单纯遵循“越具体越优先”。候选规则会综合**特异度**、**`priority`**、**创建时间**和 **`id`** 依次排序，最终生效的值还会受到**字段锁定**机制的约束。
  - 请使用 WebUI 中的**预览**功能检查各字段的实际判定来源，避免仅凭规则列表的视觉排列顺序推测生效项。完整规则合并逻辑与空值处理策略参见[场景规则](/guide/rules)。
- **生命周期边界**：
  - 标记为 **`session`** 作用域的设置通常仅对新打开的会话生效，不会强制中断或修改已提交的模型请求。
  - 标记为 **`live`** 作用域的设置依据对应内部服务规定的生命周期边界实时生效。
  - 出现保存冲突时，应重新加载并合并差异，避免直接覆盖其他窗口或会话的修改。

## 管理伪装与预设

在“伪装/预设”页面中，用户可以新建、导入或直接编辑 Markdown 源文件及其关联的元数据（元信息）。

WebUI 编辑器内置源码补全、语法诊断与实时预览功能。请将 Markdown 中的 frontmatter 视为源文档内嵌的结构化数据，而非独立于文档之外的表单配置。

### 变量分区约束

预设模板严格区分静态定义与动态运行时内容：

| 分区 | 允许变量类型 | 放置内容 | 违规处理 |
| --- | --- | --- | --- |
| **`system` 区** | 仅限不可变变量（immutable） | 核心人设、固定约束、不变规则 | 若放入 mutable 变量，系统将抛出 `MutableVariableError`，**不会**将未解析的原字符串静默下发给模型。 |
| **`context` 区** | 可变变量（mutable）与不可变变量 | 轮次变化的时间戳、动态人物状态、检索召回内容 | 正常解析并按轮次注入。 |

### 生效与版本控制

- **解析回退机制**：若预设解析或校验失败，系统可能会继续沿用上一个有效版本（revision）。因此，保存后应重点检查诊断面板（diagnostics）的报错提示，不可仅凭磁盘文件写入成功判断预设已生效。
- **修改作用范围**：有效的预设变更仅在后续轮次和新的请求边界中生效，不会追溯修改已持久化的历史日志或正在执行的请求。
- **外部引入语法**：包含子模板时，需使用单独成行的 `@include ./partial.md` 语法。详细的解析语法、导入限制和格式示例参见[预设与伪装](/guide/presets)。
- **外部并发编辑**：使用外部文件监控器（file watcher）或多窗口协同修改预设时，保存后务必确认系统的版本号（revision）及当前的绑定状态。

## 群聊唤醒与消息过滤机制

一条群聊消息是否触发回复，取决于多个独立的判定条件与过滤逻辑。

### 触发与激活条件

通用激活配置支持多种独立判定项：

- `@机器人`（默认启用）
- 昵称触发（默认启用）
- 引用回复触发（`allowQuoteReply`，**默认 `false`**）
- 随机回复
- 私聊直接回复
- 冷却时间（Cooldown）控制与机器人自身消息过滤

> **注意**：`character` 等特殊引擎包含专属的行为装配链路，通用激活配置的默认值与行为模式并不会直接套用到所有引擎上。

### 消息感知与请求边界

```
群消息流入 ──┬──> 命中激活条件 ──────> 触发回复 (调用模型)
            │
            └──> 未命中 / Observer ──> 仅写入上下文 (不产生模型调用)
```

- **上下文录入 vs 模型唤醒**：在启用 Observer 等插件的情况下，非触发消息仍可能被静默捕获并写入上下文历史。记录消息并不等同于发起了模型推理请求；群内有消息刷新也不代表机器人已被唤醒。
- **故障排查顺序**：若群内未按预期回复，请依次排查最终生效的 `engine` 类型、激活规则命中源、冷却时间限制，以及 `renderer` / `transport` 层的消息投递错误日志。
- **多模态与附件解析**：图片或富媒体附件能否递交至模型，取决于系统的格式转换设置、目标模型的模态支持能力以及 Provider 的接入协议。消息元数据中包含附件引用，**并不代表**附件正文已被下载并完整装配进模型请求载荷。如需确认多模态数据的实际组装情况，请以调用轨迹（Trace）中的实际请求为准。

## 会话控制命令

可用命令的具体形式受注册列表、调用者权限及平台命令前缀配置约束。在 WebUI 中输入命令时，可利用命令补全获取可用项。

### 核心命令一览

| 命令（按平台配置添加前缀） | 作用域与边界说明 |
| --- | --- |
| `chatluna.status` | 查看当前会话的运行时状态。 |
| `chatluna.model [ref]` | 查看当前生效的模型，或为当前会话切换至指定的 `[ref]` 模型。 |
| `chatluna.stop` / `stop` | 请求立即中断当前的生成任务，保留尚未处理的输入缓冲区；**不会**回滚已触发的外部工具副作用。 |
| `chatluna.new` / `new` / `clear` | 开启全新对话上下文，原有历史会话得以保留；该操作**不会**清除已持久化的长期记忆。 |
| `chatluna.session.fork` | 基于当前历史进度分叉出新的分支；在交互层，聊天命令需通过 `conversations` 服务来协调和切换业务主线。 |
| `chatluna.compact` / `compact` | 在已加载 compaction 组件的场景下，对后续可见的上下文视图执行压缩；该操作**不会**物理删除底层的旧日志数据。 |

### 操作边界辨析

- **分叉边界**：底层 `Session` 提供的分支 API 仅完成历史链表的分叉复制，与聊天交互层将业务“主线会话”切换到新分支属于两个不同的系统步骤。不能仅凭 HTTP fork 请求调用成功，推断前端界面已自动切换至新会话。
- **压缩边界**：上下文压缩本质上是生成摘要与设定截断（cut）标记，既不是彻底清空对话历史，也不能等同于触发了模型供应商服务端的上下文缓存命中（Cache Hit）。完整命令列表与参数定义参见[命令参考](/reference/cli)。

## 扩展能力装配

在为代理增加额外执行能力时，应遵循最小权限原则：每次仅开放一组必要的工具，并验证审批流能否正确送达。

```
扩展能力
  ├── 工具 (Tools) ────── 注册源 / 参数 Schema / 执行模式 (auto / ask / off)
  ├── 技能 (Skills) ───── 描述文件解析 + 数据读取源授权 (独立两步)
  ├── MCP 服务 ────────── 进程/端点健康度 + 服务凭据 + 连接状态 (本地按服务用户权限执行)
  ├── 机器 (Machines) ─── local / ssh / 隔离容器 (区分宿主隔离边界)
  ├── 子代理 (Subagents) ─ 上下文策略 (summary / none 非文件隔离)
  └── 自动化 (Automation) 真实 Job 注册 / 终态与执行结果校验
```

- **工具（Tools）**：
  - 检查工具的注册来源、输入参数约束以及执行策略（`auto` / `ask` / `off`）。
  - 设置为 `auto` 的工具在调用时仍受能力的访问权限策略严格约束。
- **技能（Skills）**：
  - 关注技能描述文件、加载源及其配套数据文件。
  - “导入技能定义文件”与“允许技能读取特定数据源”是两个独立的操作步骤；启用技能不会自动获取运行环境的操作权限。
- **MCP（Model Context Protocol）**：
  - 持续监控 MCP 进程/端点、调用凭据以及实时连接状态。
  - 本地 MCP 命令以运行 ChatLuna 服务的主机系统用户身份执行，继承其系统权限。
- **机器（Machines）**：
  - 用于定义命令执行和文件读写操作的物理/虚拟位置。
  - `local`（本地）、`ssh`（远程主机）与隔离容器之间具有完全不同的系统安全隔离边界，不可混淆。
- **子代理（Subagents）**：
  - 用于将复杂子任务指派给独立的执行上下文处理。
  - 策略配置项（如 `summary`、`none`）属于上下文继承策略，决定子代理得到什么输入，不代表子代理运行环境的文件系统或执行权限隔离。
- **定时与后台任务（Automation）**：
  - 排查定时调度问题时，需确认底层是否生成了实际运行的调度 Job。
  - 对于异步执行的后台任务，应检查其实际终态和返回数据；任务变为 `settled` 状态仅表示执行流程结束，**不代表**业务逻辑执行成功。

各项能力的详细配置参见[工具、技能与 MCP](/guide/capabilities)、[机器](/guide/machines)、[子代理](/guide/subagents)以及[自动任务](/guide/automation)。

## 系统观测与运维安全

### 链路观测与计量统计

- **轨迹追踪（Trace）**：
  - Trace 记录用于精确回溯单轮对话中的原始输入提示词、工具调用参数和完整的模型交互请求。
  - 重建（Reconstruct）Trace 仅对既有记录进行解析重放，不发起外部模型调用。
  - 实验回放（Replay）属于发起新的模型推理实验，会消耗实际 Token 并可能产生服务计费，且默认**不会**自动重复触发原步骤中带有副作用的外部工具。
- **用量与成本核算**：
  - WebUI 用量统计页面中的 Token 消耗计数、预估成本模型、服务商原始账单以及活跃调用监控列表，各自具备不同的统计口径与时间切片边界，核算时不可混用。

### 插件管理与维护

- 安装或升级插件实质是在主机环境内执行第三方代码。在执行操作前，必须进行底层数据备份并核验插件包的代码来源。
- 插件更新后，应按照提示要求执行服务重载或完整重启服务进程。不能假定所有热更新逻辑对正在交互中的长连接会话均是透明无感的。
- 在服务配置清单中保存配置成功，仅代表持久化完成，并不代表与远端服务的通信测试已经通过。

### 安全加固与排错规范

- **管理权限收敛**：管理控制面板与核心接口仅允许开放给完全受信的管理员。
- **远程暴露检查清单**：开放远程访问前，需统一审查**网络拓扑发布规则**、**HTTPS 证书配置**、服务内 **`allowRemote`** 开关以及**管理访问口令**。在容器化部署场景下，请严格区分 Docker 内部容器网络与宿主机端口映射的安全策略差异。更多安全基线参见[安全与权限](/guide/security)。
- **故障响应流程**：当遇到未预期错误时，首先查阅[排错指南](/guide/troubleshooting)并收集包括 Trace、错误日志与运行时配置在内的最小复现证据，严禁在未排查原因前盲目执行数据清理操作。
