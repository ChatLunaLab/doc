# 首次配置

首次进入尚未完成初始化的 ChatLuna v2 实例时，WebUI 会自动引导进入向导页面 `/setup`。

当前向导包含三个核心步骤：**模型**、**聊天平台**与**用途**。推荐的初始化流程是：先在 Web 聊天中验证模型连通性，再接入实际聊天平台。请注意，“向导界面完成”、“模型就绪”、“平台连接在线”与“主人身份确认”是四个相互独立的状态边界，不能互相替代。

---

## 步骤一：连接并测试模型

在模型步骤中选择受支持的 Provider，并填写对应的凭据、Endpoint 和模型名称。

### 配置与测试边界

1. **遵循当前 Provider 的 Schema**：请直接使用目标 Provider 要求的字段结构，不要跨平台套用配置。对于私有网关或自建代理，必须核对完整的 Base URL 及其协议（如 `http://` 或 `https://`），不能仅修改显示名称。
2. **区分“保存成功”与“测试成功”**：
   - 系统中包含四个不同的技术边界：**Provider 注册**、**目录探测（List Models）**、**模型选择**与**真实推理（Inference）**。
   - 配置保存成功不代表具备可用推理能力。必须在界面中执行实际模型测试并检查返回内容。
   - 向导中模型步骤的“继续”按钮要求**测试通过**。Mock Provider 仅供本地开发验证，其测试通过不能证明真实网络、API Key 或账单配置可用。
3. **凭据安全与保留规则**：
   - 凭据管理页会隐蔽显示已保存的敏感信息。
   - 部分表单中的留空表示**保留原有值**；若需彻底删除 Key 或凭据，必须使用显式的“清除”操作，不可将空输入直接误判为删除操作。
   - 详细的角色绑定机制与回退规则，请参考[模型与提供商](/guide/models)。

### 实例命令行诊断

若需对正在运行的实例进行模型与 Provider 状态诊断，可在实例工作目录中执行：

```sh
chatluna doctor providers --dir .
```

*注：在源码工作区开发时，可使用 `yarn chatluna` 作为前缀运行。*

- **执行说明**：该命令默认连接本机的 `5028` 端口；若实例运行在非默认地址或端口，需提前配置相应的环境变量。
- **排错建议**：诊断命令仅用于读取与检查当前注册状态，不能替代实际的消息推理闭环测试。严禁在提交工单或公开日志中输出包含未脱敏认证值的输出信息。

## 步骤二：连接聊天平台

平台步骤用于展示非 Web 渠道的机器人列表及其在线状态。

### 平台接入要求

1. **适配器安装与配置**：
   - 优先安装受信任的 Satori Adapter，并根据其对应版本的 Schema 准确配置平台账号与连接参数，配置完成后检查 Adapter 进程日志。
   - 不同平台依赖的传输方式差异较大（如独立反向网关、开放平台 Webhook 或特定 Bot 服务），不得套用通用的 WebSocket 配置。
2. **“继续”的准入条件**：
   - 点击“继续”前，系统要求**至少存在一个非 Web 的 Bot 处于在线状态**。
   - 如果当前仅需在浏览器体验 Web 聊天，可在向导中点击**明确跳过**，后续再前往平台管理页接入外部账号。
3. **连接验证与隔离**：
   - **连接成功 ≠ 业务可用**：平台显示“在线”仅表示网络会话已建立，仍需进一步验证上行消息投递、命令解析以及下行回复推送。
   - **避免双重连接**：严禁让旧版 v1 与新版 v2 实例同时连接同一个 Bot 账号，以防事件冲突或状态污染。
   - **安全测试**：配置初期应在测试账号或受控单人私聊中验证，切勿直接在生产群聊中发送调试测试指令。

## 用绑定码确认主人

为了建立实例所有权，向导会生成一个 6 位数字的绑定码。

### 绑定执行流程

管理员必须使用自己的**真实聊天平台账号向机器人发送私聊命令**（例如当前命令前缀为 `/`）：

```text
/bind 123456
```

*（注：上述 `123456` 仅为格式占位示例，实际执行时必须填入 WebUI 界面当前生成的动态码。）*

### 验证与权限机制

- **基于底层传输身份**：系统直接以接收消息的底层 `platform/user` 身份进行所有权认领，不会读取或信任消息文本内手动填入的用户 ID。
- **Web Adapter 不可用**：Web Adapter 提供的浏览器聊天界面无法执行此身份绑定操作。
- **时效与重置策略**：
  - 绑定码有效期为 **10 分钟**。
  - 生成新码会自动使旧码失效，并重置错误尝试计数器。
  - 连续输入错误 **5 次**后，当前绑定码立即失效，必须重新生成。
- **权限赋权规则**：
  - 系统**不会**将首个向机器人发起私聊的用户自动视为主人。
  - 绑定成功后，若该平台身份在系统中尚无显式权限记录，初始化流程会为其赋予 **Level 5**（主人）权限。
  - 若该身份此前已有被人工降低权限的记录，系统将**保留现有记录**，不会因重新绑定而自动提升其等级。
- **访问控制分离**：
  - WebUI 使用实例共享的访问口令进行登录认证。
  - “主人”指代特定聊天平台的身份权限，绑定成功并不等同于在浏览器中新增了 Web 管理员账号。后续权限变更应在管理页面中核验。

## 步骤三：选择用途与完成向导

用途步骤用于设定实例的初始功能方向，其核心是按需开启功能，而非强制预装所有能力插件。

### 状态持久化与跳转

- **完成向导**：配置完成后，可选择直接进入 Web 聊天界面或进入平台管理面板。
- **跳过与稍后**：
  - 每一步提供的“跳过”操作允许跳过当前步骤进入下一步，但并不代表该步骤所涉及的网络连通或身份认证已验证通过。
  - 点击“稍后”会暂停引导并退回主页，此时实例**并未**标记为完成初始化。
- **重新配置**：向导的完成状态会持久化写入数据库。但实例是否能正常响应，仍取决于模型凭据与网络运行时的状态。若后续需要调整，可直接进入后台对应管理页，或重新打开 `/setup` 访问向导，无需清空数据库。

## 后续阶段：在私聊中设置伪装（人格访谈）

首次使用时的人格访谈逻辑属于底层的 **Setup 引擎**，在技术架构上并不属于 Web 向导内的第四步。

### 访谈触发与路由边界

1. **自动触发条件**：
   - 必须由已绑定的**主人账号发起私聊**。
   - 实例模型处于就绪状态。
   - 当前会话尚无活跃预设，且系统尚未建立任何全局人格状态。
   - 底层路由策略允许该流程接管上下文。
   - *注意：不能根据“Web 向导已完成”推断群聊环境会自动开启访谈。*
2. **手动命令触发**：
   - 主人可在私聊中发送配置好的 `setup` 命令（根据平台要求携带对应命令前缀）。
   - 发送命令后的**下一条消息**将正式进入人格访谈交互。
3. **访谈确认与副作用**：
   - 访谈过程中可与模型讨论设定机器人的名字、性格特点、交流风格及安全边界。
   - **生成草稿**、**写入预设文件**与**将预设绑定至当前对话**属于不同阶段的数据操作。必须严格检查落盘结果，不能仅凭模型在对话中回复“已保存”即认定配置生效。
   - 在已配置的私聊会话中显式重新执行设置操作，可能会覆盖或作用于当前私聊的既有上下文。
   - 群聊场景以及非主人身份无法触发或使用该入口。预设文件源格式与上下文变量规则，请参考[预设与伪装](/guide/presets)。

## 验证最小闭环

完成上述配置后，建议按照以下固定顺序对系统进行单点闭环测试：

1. **验证 Web 对话终态**：在 Web 聊天界面发送一条测试消息，确认模型能输出完整终态回复，而不是仅停留在临时 Stream 流式文本阶段。
2. **验证平台双向通讯**：在受控的聊天平台私聊中重复测试，逐级排查并确认是模型推理问题还是平台 Adapter 消息投递问题。
3. **核查会话归属与上下文配置**：检查该条消息实际命中的 Engine 类型、模型路由、预设文件以及对话归属，防止全局默认设置与群独立规则之间出现非预期的相互覆盖。
4. **追踪调用轨迹**：打开调试轨迹（Trace）核对原始 Prompt 输入、模型原始请求及报错日志。请注意：在消息推送过程中，上游接口返回 `HTTP 202 Accepted` 仅代表请求已被接受并进入调度，不保证最终回复投递成功。
5. **安全开放工具**：在挂载或开放外部工具调用前，先在管理页核对审批通道与权限等级；初期测试应仅使用无外部写操作、无副作用的只读工具进行验证。
