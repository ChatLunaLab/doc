# 场景规则

场景规则决定「谁在什么地方说话时，用哪套设置」。全局规则提供基线，匹配具体机器人、群、频道、私聊用户或消息条件的规则再覆盖部分字段，不必为每个群复制完整插件配置。

## 从快捷设置开始

只想改变当前范围的模型、人设、回复条件、工具或记忆时，先用 WebUI 的「快捷设置」。需要组合条件、查看字段来源或锁定配置时，再用「场景规则」。两处编辑指向同一套路由配置，不是独立的优先级系统。

先确定作用范围：全局、机器人、群/频道，还是私聊用户。同一平台的用户 ID、机器人 ID 和群 ID 不同；多个机器人接入同一群时，是否匹配 `self` 也会改变范围。实体列表来自在线机器人目录和已见过的聊天对象，暂时没有某对象不等于平台不支持它。

## 配置由哪些部分组成

| 命名空间 | 职责 |
| --- | --- |
| `chat.engine` | 选择普通 Agent、角色或其他已加载引擎及其配置 |
| `chat.model` | 回复模型与功能角色模型 |
| `chat.reasoning` | 思考等级 |
| `chat.preset` | 选择预设 |
| `chat.session` | 对话记录归属与分区 |
| `chat.activation` | 唤醒条件 |
| `chat.tools` | 工具模式与允许/禁止列表 |
| `memory` | 记忆后端、提取、回忆与整理 |

插件声明自己的 namespace。字段、默认值和可选项由能力插件提供；某页缺字段，先核对插件与引擎，不要自己造键。

引擎先解析，其他配置再依据引擎声明生效。选择 `off` 是停用该范围的聊天，不删除历史。改预设、改引擎和新建对话是不同操作；验证新人格时可新建对话，避免旧历史干扰判断。

## 匹配、排序与覆盖

`global` 全局规则最先应用，其余命中规则按以下顺序排序，再依次合并：

1. 条件特异度：按谓词结构计算，不是固定的「用户永远大于群」。
2. `priority`：特异度相同时，较大的值后应用。
3. `createdAt`：前两项相同时，较新的后应用。
4. 规则 id：最后用于确定顺序。

没有锁定时，后应用的字段覆盖前面的字段。提高 priority 不能跨过所有特异度差异；列表展示顺序也不等于生效顺序。

对象递归合并，数组整体替换，不自动拼接白名单。默认值在合并后补入，局部规则只需保存想改变的字段。

例如全局模型为 A，群规则只改模型为 B，用户规则只改思考等级：三个条件都匹配时，模型与思考等级可以来自不同规则。查看逐字段来源，而不是找一条包办所有字段的「最终规则」。

锁定路径会保留先前来源，并记录后续被压制的写入。改了却没生效时先查锁定；重复保存不会越过它。

## 留空、空列表与禁止

工具允许列表未配置，表示该层没有新增限制，仍受继承值与其他策略约束；显式 `[]` 表示不允许任何工具。工具同时在允许与禁止列表时，禁止优先。预设和权限还可进一步收窄，场景规则允许不代表必然能执行。

数组覆盖会替换整份数组。修改 activation 的启用列表时，未保留的判定器不在新列表中。编辑前先查看有效配置，避免删掉想保留的项。

## 对话记录怎么分

`chat.session.ownership` 支持：

- `shared`：同一聊天范围共用记录。
- `personal`：按人分开记录。
- `custom`：由 `customKey` 决定。

自定义键可用 `{platform}`、`{selfId}`、`{guildId}`、`{channelId}`、`{userId}`。计算出的键参与对话归属；遗漏身份维度可能造成意外共享。使用自定义分组后，要用两个不同身份验证隔离，不只用管理员测试。

`lane` 是对话分区名，默认 `default`。换名进入另一分区，改回可以继续原分区。它不是 Session 的 `branch()`，也不是权限隔离或删除操作。

## 保存、热应用与诊断

有 loader 条目和配置服务时，规则变更通过配置事务持久化并热应用。缺少这些条件的嵌入式运行可能只有内存变更并告警，不能保证重启保留。

各 namespace 用自己的 schema 校验。加载遗留或无效数据时，解析器记录诊断，并针对出错 namespace 从后往前排除覆盖层。因此较早值生效，不一定是排序问题，也可能是较新层无效。未知 namespace 会保留并产生诊断，不会自动成为已加载能力。

旧 `chatluna.*` 不是当前 `chat.*` 的别名。按提示修改旧键，不依赖静默迁移。

## 验证一次修改

1. 记录测试消息的平台、机器人、群/频道和用户。
2. 查看命中规则、字段来源、锁定压制和诊断。
3. 用该身份发新消息，核对轨迹里的模型、引擎和工具。
4. 涉及共享范围时，再用另一位用户验证。
5. 确认配置写入且热应用成功；需要时再安排重启验证。
