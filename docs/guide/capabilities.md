# 工具、技能与 MCP

工具（Tool）、技能（Skill）与模型上下文协议（Model Context Protocol，MCP）是 ChatLuna 扩展模型执行与感知能力的三种机制：

- **工具**：供模型调用的具体执行单元，具备结构化参数 Schema 与可执行逻辑。
- **技能**：面向特定任务的指引文档、提示词模板及相关配套资源。
- **MCP**：将外部进程或远程服务暴露的工具与资源接入 ChatLuna 的标准通信协议。

三者存在明确的生命周期分级。一个功能在系统内的**已安装**、**对模型上下文可见**、**获得执行授权**以及**实际执行成功**属于不同的状态判定。在开放至实际对话前，应先在管理面板核实其能力来源与真实执行范围。

---

## 工具从注册到执行

在 WebUI 的「工具」管理页面，可查看工具名称、来源插件、参数 Schema 以及当前生效的执行策略（Execution Policy）。

### 工具执行策略

| 策略 | 行为描述 |
| --- | --- |
| `auto` | 不进行工具级的额外交互式询问；调用请求仍需经过全局及会话级的能力权限检查。 |
| `ask` | 每次执行前必须向操作者请求显式审批。若审批通道不可用、超时或拒绝，则调用终止。 |
| `off` | 彻底隐藏并禁用该工具。不仅从界面可用列表中收起，模型也将无法获取其 Schema。 |

### 调用管线与执行判定

模型输出工具名称或在自然语言中声称“已完成操作”，不构成实际执行的依据。检查调用时应逐项确认以下边界，而不是把它们理解成所有插件都固定一致的线性顺序：

- 当前 Agent 的工具集合与可见性过滤。
- 实际调用参数是否通过 Schema 校验。
- 中间件与工具级 auto/ask/off 策略。
- 主体、capability 和 target 的权限判定及必要审批。
- 本地代码、外部进程或远程服务返回的真实执行结果。

在评估工具时，应先对只读工具进行验证，再评估涉及文件写入、网络发送与系统命令执行的高风险工具。只读工具亦可能读取并返回敏感配置，因此需要限制工具作用域，不得将模型工具描述（Description）视为安全信任边界。

关于工具参数定义（`args`）与执行逻辑（`run`）的接口契约，参见[工具开发](/development/tools)。

## 工具搜索与延迟加载

将大量工具的 Schema 同时注入模型上下文会占用高额的前缀 Token 并干扰决策。服务 `@chatluna/tool-search` 提供了根据策略划分常驻工具（Resident）与延迟工具（Deferred）并在需要时按需检索的能力。

默认 Agent 的工具执行链路依赖 `@chatluna/tool-search`。虽然该机制封装在独立插件包中，但将其从默认运行组合中移除会导致相关工具发现机制失效。

### 核心配置项

| 配置键 | 默认值 | 含义 |
| --- | --- | --- |
| `mode` | `auto` | 搜索策略模式。`auto` 结合 Provider 的原生能力自动选择；`on` 强制开启搜索机制；`off` 关闭搜索机制。 |
| `threshold` | `20` | 自动延迟生效阈值。系统内当前可用工具总数严格大于此数值时，自动延迟规则才会介入分类。 |
| `autoDefer` | `['mcp__*']` | 自动分类时判定为延迟加载的工具名称匹配模式（Glob）。 |
| `limit` | `5` | 单次工具搜索向模型返回的最大工具数量，合法取值区间为 `1`–`20`。 |

### 运行时规划与安全边界

- **常驻与延迟标记**：管理面板支持针对单个工具手动覆盖标记为 `resident` 或 `deferred`。
- **动态规划逻辑**：实际注入上下文的工具列表由当前 Agent 的配置模式、Provider 接口特性及前置过滤共同计算。可用工具数超过 20 并不会导致工具全部消失；将 `mode` 设为 `off` 也仅代表停用工具检索机制，而非禁用工具系统本身。
- **安全隔离原则**：延迟加载只是一种上下文压缩策略，不构成权限隔离边界。被延迟检索发现的工具依然必须通过完整的 Schema 校验、权限策略判定与审批流程。

关于原生工具引用与本地代理调用的底层细节，参见 [Agent 执行](/architecture/agents)。

## 技能的来源、导入和使用

技能由核心包 `@chatluna/skill` 负责扫描、解析与加载。单个技能包含任务指示正文、frontmatter 元数据以及同目录下的配套支持文件。

### 来源与冲突处理

管理面板会显示技能的物理来源、正文内容与随附资源。如果不同来源存在同名技能，最终的有效版本由来源类型及其内建优先级决定，不可仅根据本地文件名或目录名推测生效对象。

### 导入流程与核查项

系统支持导入 `SKILL.md` 单文件、文件夹以及 ZIP 压缩包。

> **注意**：**将文件导入落盘**与**将目标目录挂载为文件系统技能来源**是两个相互独立的步骤。文件存在于磁盘上并不意味着系统已将其注册为可供模型读取的技能。

导入不受信任的技能前，必须完成以下审计：

1. **来源可信度**：正文提示词中是否存在向外部地址发送敏感信息、下载执行脚本或诱导越权的内容。
2. **环境适配性**：配套脚本、执行命令和路径依赖是否兼容当前部署宿主机，避免携带其他环境的硬编码路径。
3. **凭据与环境需求**：技能所声明的环境变量和 Secret 是否必要，作用域是否已收敛至最小必需范围。
4. **工具权限联动**：技能指导模型调用的下游工具是否已被正确配置对应的权限策略。

技能文本属于提示词指引，不具备系统级授权属性。模型读取或激活技能不会自动提升用户的权限等级，亦无法绕过工具执行策略。

### 技能制作能力（Skill Forge）

插件 `@chatluna/skill-forge` 提供可选的技能编辑套件。该插件并非默认预装组件。

- **工作区草拟**：可在专用工作区内起草、修改自有技能，并执行规则检查（Lint）。
- **生命周期隔离**：在工作区内的修改与编辑不会直接覆盖宿主环境的生产技能目录。
- **发布与回滚**：将草稿发布至宿主目录、移除或回滚旧版本需要对应的操作权限。发布流程会执行命名冲突检测并维护变更历史。

## MCP 接入

MCP 核心模块负责服务生命周期管理，底层的传输通道（Transport）与工具投影（Tool Projection）由具体插件驱动。管理面板提供本地 stdio 命令与远程 HTTP（SSE/HTTP）服务的接入配置、连接诊断、工具列表枚举与启停控制。

若运行环境缺少对应的传输实现或系统依赖，服务记录可能显示在面板中，但实际功能处于不可用状态。

### 接入检查要素

- **本地 stdio 接入**：核对可执行文件绝对路径、启动参数、运行工作目录（CWD）及所需的环境变量。
  - *系统安全约束*：本地 stdio 子进程以宿主系统运行 ChatLuna 的操作系统用户权限启动，MCP 协议本身不提供沙箱或容器隔离。
- **远程 HTTP 接入**：核对服务端点（Endpoint）、网络传输协议、TLS 证书有效性、鉴权 Header 及远端服务器控制权归属。
  - *远程副作用约束*：远程工具同样可能执行数据库变更、外部通知发送或云资源调配，不能假定其仅具备只读属性。
- **凭据管理**：环境变量与 HTTP Headers 中配置的认证凭据在前端界面应脱敏展示；但下游进程及其网络端点能够获取请求中包含的明文 Secret。
- **验证阶段分离**：连接建立测试、服务工具枚举、实际工具执行属于三个独立阶段，连接成功不代表工具可以正确执行。对于未经验证或具有副作用的 MCP 工具，初始状态应配置为 `ask` 或 `off`。

## 运行时自管理工具

系统内置的自省（Introspection）、动态插件管理与 Daemon 维护分别由独立的底层服务提供支持。工具列表中包含定义不代表对应的后台服务已加载就绪。

自省工具在读取配置项与日志摘要时会执行脱敏处理，但排查输出的日志内容依然应视作敏感信息保管。

### 运行时工具策略（Runtime Policy）

运行时自管理工具的可用性受 `policy` 配置控制，该配置的默认值为 `inspect`：

| Policy 模式 | 行为描述 |
| --- | --- |
| `off` | 彻底拒绝并禁用所有运行时自管理工具的调用请求。 |
| `inspect` | 仅允许执行只读自省类操作，且每次调用仍需显式审批确认；所有写操作（如修改配置、加载插件）一律拒绝。 |
| `full` | 允许执行包含配置写入在内的完整管理流程，且所有管理调用仍需显式审批；触发 Daemon 重启操作需经过二次确认。 |

> **边界说明**：运行时 `policy` 是针对系统管理工具的专用开关，与常规工具的 `auto` / `ask` / `off` 策略以及全局权限系统的 `mode` 属于不同维度的控制机制。任何处于要求确认状态的操作，若在交互中未能完成审批，均一律按拒绝处理。动态安装包与插件具备任意代码执行能力，禁止仅凭模型自主决策放行。

## 与其他执行能力的边界

在系统架构中，各项执行机制相互正交：

- **工具（Tools）**：决定模型**“能执行哪些动作”**。
- **机器（Machines）**：决定命令调用、脚本运行与文件操作**“在哪个具体环境执行”**。
- **子代理（Subagents）**：决定任务执行链被**“分派给哪个 Agent 上下文”**。
- **后台任务（Background）**：决定耗时操作以**“何种非阻塞并发机制运行”**。

上下文继承、异步运行与隔离环境并非单一配置所能同时涵盖。当对话中出现“工具缺失”或无法调用的情况时，应按以下顺序逐步排查，避免直接盲目放开全局权限：

1. 确认工具所属插件是否成功挂载，系统底层依赖是否完备。
2. 确认当前 Agent 的工具过滤列表是否包含该工具。
3. 检查 `@chatluna/tool-search` 的延迟加载状态，确认工具是否需要通过检索发现。
4. 校验工具参数 Schema 是否与当前模型版本的能力相兼容。
5. 确认会话用户是否具备该工具的权限，策略是否处于 `off` 或审批被拒。
6. 检查绑定的 Machine 状态及下游服务返回的具体错误日志。
