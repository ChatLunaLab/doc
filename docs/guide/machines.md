# 机器与工作区

机器是 Agent 执行命令和访问文件的目标环境。`ctx.computer` 让同一台 Machine 同时负责命令与文件操作，避免「命令在容器里，文件却读到宿主机」。配置机器不等于给模型无条件开放 shell。

## 选择执行环境

| kind | 用途 | 默认共享方式 |
| --- | --- | --- |
| `local` | 可信宿主环境、本地开发 | 共享 |
| `ssh` | 已准备好的远端工作区 | 共享 |
| `docker` | 容器工作区 | 按根会话独立 |
| `e2b` | 远端沙箱 | 按根会话独立 |

各 kind 由插件注册。安装 computer 服务不代表所有实现均可用；环境还需具备对应 CLI、凭据和网络条件。

默认配置提供一台名为 `local` 的机器。共享意味着不同会话可能访问同一文件与进程环境；模型上下文独立不代表工作区隔离。

## 配置与授权

机器页管理名称、kind 与该 kind 的配置。保存、测试、删除和关闭要求 level 5；读取状态不返回配置明文。

场景规则中的 `machines.default` 选择默认机器，默认 `local`；`machines.allowed` 限制 delegate 可选择的机器，默认 `['local']`。保存机器不代表任意用户或子代理都能调用，还要通过能力授权、工具过滤和目标检查。

切换后验证命令、文件工具与技能是否均处于预期工作区。不要把某次命令的 cwd 当作其他机器的持久全局目录，也不要依赖模型记忆维持边界。

## Docker 机器

宿主需能调用 Docker CLI：

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `image` | 必填 | 执行环境镜像 |
| `root` | `/work` | 容器工作区 |
| `mounts` | `[]` | 额外 `docker -v` 挂载 |
| `host` | 未设置 | Docker socket 或 TCP 地址 |
| `idle` | 600000 ms | 空闲暂停阈值 |

首次使用创建容器，命令与文件操作都在容器中进行。空闲后暂停，后续命令先恢复。关闭执行 `docker rm -f`：未保存在持久挂载中的文件会随容器移除，需要的产物应提前导出。

挂载扩大模型可接触的数据。不要为普通任务挂载宿主根目录、密钥目录或 Docker socket。让 ChatLuna 主容器使用 socket 创建沙箱，本身是宿主 root 等价能力，不因子任务在容器中就消除风险。部署选择见[安装与启动](/guide/getting-started)。

## local 与 SSH

local 执行的是服务进程可访问的环境。使用专用系统账户和最小文件权限，不在保存私人密钥、工作文档及其他服务凭据的通用登录环境中开放它。

SSH 依赖远端账户权限。分配独立工作区与受限账号，先验证连接和目录，再开放工具。SSH 能登录不代表命令安全，文件工具的路径检查也不是 shell 沙箱：命令仍可能运行其他程序或访问网络。

## 技能环境与密钥

机器配置和技能环境变量共用 SecretBox，以 AES-256-GCM 保护配置值。宿主密钥文件默认为 `data/chatluna/.secret-key`，权限 `0600`。备份加密配置时也应安全保管密钥，否则恢复后可能无法解密；不要把两者一起提交公共仓库。

环境按当前 Agent 求值，每次 exec/spawn 合并最新值，不通过永久修改共享机器注入。密钥可见性仍需最小化，输出脱敏不是绝不泄露的保证。

## 关闭、取消与产物

机器、子代理和后台任务有不同生命周期。取消生成不等于撤销外部副作用；已写文件、已发请求或外部进程可能需单独检查。关闭前查看相关任务，保存输出，再确认移除。

排错时记录机器名、kind、工作区与退出码，不只复制模型总结。分享日志前移除环境变量、凭据及私有路径。

## 最小验证清单

1. 使用无敏感信息的专用测试目录。
2. 写一个小文件，再由文件工具读回。
3. 运行只读命令，核对机器与 cwd。
4. 用普通身份验证未授权写入与机器切换被拒绝。
5. 对容器检查两段根会话的工作区是否独立。
6. 确认产物保存方式，再测试暂停、恢复与关闭。
