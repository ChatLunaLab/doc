# 数据与存储

::: tip
插件需要持久化时，先想清楚数据属于哪一类：结构化记录进数据库，二进制文件走文件存储，敏感信息走凭据，向量走向量服务。
:::

不要把所有东西都塞进一个 JSON 文件。

不同数据的生命周期、访问模式与安全要求不一样，选错层会让后面很难受。

## 数据库

用 `ctx.model.extend` 声明表，用 `ctx.database` 读写：

```ts
ctx.model.extend('my_plugin_items', {
  id: 'unsigned',
  key: 'string',
  value: { type: 'json' },
  createdAt: 'integer',
}, {
  primary: 'id',
  autoInc: true,
  unique: [['key']],
  indexes: [['createdAt']],
})
```

### 约定

- 表名带前缀，避免冲突。
- 主键用自增整数或字符串，不要用复合主键暴露出业务键。
- 需要查询的字段建索引。
- 时间统一用毫秒整数。
- JSON 字段只用于「整体读写」的数据，不要在 JSON 里做条件查询。

### 迁移

声明新字段会在启动时补齐。

删除或重命名字段要谨慎：旧数据不会自动转换。跨版本调整时，写一次显式迁移，并在完成后清理。

## 文件

图片、附件、导出文件走文件存储：

```ts
const file = await ctx.chatluna_storage.createTempFile({
  name: 'report.csv',
  type: 'text/csv',
  buffer,
})
```

特点：

- 按内容哈希去重。
- 有临时文件与过期清理。
- 可以通过接口按名字读取。

不要把大文件塞进数据库行，也不要自己往数据目录里随手写文件。

## 凭据

敏感值不要存进数据库字段。

在 Schema 里用 `role('secret')` 声明，系统会保存引用而不是明文；读取时通过凭据服务解析。

导出配置时不包含明文，这是有意的。

## 向量

需要相似度检索时，注册一个向量后端：

```ts
ctx.vector.register(myStore)
```

一个进程只能注册一个后端。

没有后端时，调用方会收到明确错误，而不是静默降级——这样你能立刻发现「忘了装后端」。

## 数据归属

- 插件自己的数据由插件负责清理：卸载时删除或归档。
- 用户数据（会话、记忆）不要复制到插件自己的表里。
- 缓存可以丢，但要有重建路径。

## 性能

- 分页查询用游标，不要用 `offset`。
- 大结果集分批读取。
- 高频写入考虑批量。
- 给查询条件建索引，读慢时先看执行计划。

## 测试

- 用内存数据库跑单元测试。
- 测试「表不存在」与「字段缺失」的启动路径。
- 测试卸载后数据是否按预期保留或清理。

## 常见问题

**表没创建。**
插件没启用，或者 `inject` 缺少 `model` / `database`。

**写入报类型错误。**
数据库对 JSON 字段要求对象或数组；标量要包一层对象。

**查询很慢。**
缺索引，或者用了 `OR`、`LIKE` 这类难优化的条件。

**升级后旧数据读不出来。**
做了不兼容的字段变更。写迁移，不要依赖自动补齐。
