# 数据与存储

::: tip
插件需要持久化时，先想清楚数据属于哪一类：结构化记录进数据库，二进制文件走文件存储，敏感信息走凭据，向量走向量服务。
:::

很多插件在运行过程中都需要保存数据，但切忌把所有内容都塞进一个 JSON 文件。

不同类型的数据在生命周期、访问模式与安全要求上各不相同，选错存储层往往会给后续的维护带来麻烦。

## 数据库

通过 `ctx.model.extend` 声明数据表结构，并使用 `ctx.database` 进行读写：

```ts
ctx.model.extend('my_plugin_items', {
  id: 'unsigned',
  key: 'string',
  value: { type: 'json' },
  createdAt: 'integer',
}, {
  primary: 'id',
  autoInc: true,
  unique: [['key']],
  indexes: [['createdAt']],
})
```

### 约定

为了让多个插件友好共存并保证查询效率，定义数据表时建议遵循以下约定：

- **表名前缀**：表名请加上插件专属前缀，避免与其他插件产生命名冲突。
- **主键设计**：主键推荐使用自增整数或字符串，尽量不要使用复合主键暴露业务键。
- **建立索引**：对经常出现在查询条件中的字段主动建立索引。
- **时间规范**：时间戳统一使用毫秒级整数（`integer`）。
- **JSON 字段**：JSON 类型仅适用于整体读写的结构化对象，切勿在 JSON 内部做条件查询。

### 迁移

当你向已有表中追加声明新字段时，框架会在启动阶段自动完成补齐。

不过删除或重命名字段时需要格外谨慎：数据库中的旧数据并不会自动进行结构转换。如果跨版本调整了数据结构，请显式编写一次迁移逻辑，并在迁移完成后及时清理废弃数据。

## 文件

对于图片、附件或导出文件等二进制数据，应当统一交由文件存储服务处理：

```ts
const file = await ctx.chatluna_storage.createTempFile({
  name: 'report.csv',
  type: 'text/csv',
  buffer,
})
```

文件存储具备以下特性：

- **内容去重**：基于文件内容哈希自动去重，避免重复占用空间。
- **生命周期**：支持临时文件管理，并由系统定期进行过期清理。
- **便捷访问**：支持通过统一接口按名称直接读取文件。

请避免把大体积文件硬塞进数据库的字段行中，也尽量不要在数据目录下随意创建裸文件。

## 凭据

密钥与 Token 等敏感信息切勿以明文形式直接存进数据库。

在 Schema 中声明配置时，可以使用 `role('secret')` 修饰该字段。此时系统只会存储凭据引用而非明文内容，并在实际读取时经由凭据服务动态解析。

在导出配置文件时这些字段均不会包含明文，这正是系统出于安全考量的预期设计。

## 向量

在需要使用相似度检索或知识库问答时，可以向系统注册一个向量后端：

```ts
ctx.vector.register(myStore)
```

需要注意的是，一个运行进程中只能注册一个向量后端。

当没有任何后端就发起调用时，调用方会立即收到明确的错误提示，而不是默默发生静默降级——这样能帮助你在开发时迅速察觉「忘记配置向量后端」。

## 数据归属

明确数据的所有权能够避免脏数据积累与隐私泄漏：

- **插件数据**：插件自身产生的数据由插件全权负责，在卸载时应当完成删除或归档。
- **用户数据**：用户的会话记录与记忆等全局数据，切勿私自冗余复制到插件专属表中。
- **缓存数据**：缓存数据应当允许随时丢弃，但必须提供可靠的重新生成路径。

## 性能

为了保证数据读写的高效响应，可以参考以下调优建议：

- 分页查询时优先使用游标（Cursor），避免在大数据量下使用 `offset` 导致深度分页变慢。
- 面对大结果集时，应当采用分批读取而非一次性全部加载到内存。
- 面对高频写入场景，尽量合并为批量操作统一写入。
- 为高频查询条件建立索引；当接口查询变慢时，先查看执行计划排查慢查询。

## 测试

良好的测试习惯能有效杜绝上线后的存储隐患：

- 单元测试中优先使用内存数据库，保证测试执行迅速且环境干净。
- 重点测试「数据表尚不存在」以及「缺少部分字段」时的启动与初始化流程。
- 模拟测试插件卸载后的场景，验证数据是否按预期得到了完整保留或干净清理。

## 常见问题

**表没创建成功？**
插件没启用，或者上下文的 `inject` 缺少了 `model` 或 `database`。

**写入报类型错误？**
数据库对 JSON 字段要求传入对象或数组；如果是纯标量值，请先在外层包装一层对象。

**查询很慢？**
通常是缺少索引，或者查询条件中包含了 `OR` 或 `LIKE` 这类难以优化的条件。

**升级后旧数据读不出来？**
说明进行了破坏性的字段变更。请针对旧版本结构编写显式迁移脚本，不要依赖框架的自动补齐。
