# 配置模型与提供商

提供商保存连接方法，模型地址指定实际模型，默认模型与功能角色决定不同任务使用哪一个模型。初次接入按「保存提供商 → 验证真实请求 → 设置默认 → 检查场景覆盖」逐层确认：本地配置成功与远端调用成功是不同的事。

## 添加提供商

打开 WebUI 的「提供商」，选择内置定义或创建自定义提供商。登记名是本实例的标识。例如登记名为 `work`、模型名为 `example-chat`，运行时完整地址为 `work:example-chat`，不是 `work/example-chat`。

填写服务商给出的 API key 与 base URL。Chat Completions、Responses、Anthropic、Gemini 是不同协议，同一个服务可能只开放其中一部分。自定义提供商可以为不同格式配置独立端点，并针对模型覆盖格式。不要为了试错随意给 URL 叠加 `/v1`；以所选提供商定义和远端说明为准。

提供商 SDK 按需安装，首次保存可能需要访问 npm registry。安装失败与远端调用失败应分开处理：

- 安装失败：核对包名、版本、registry、文件权限和安装日志。
- 远端失败：核对 endpoint、协议、凭据、额度以及服务商响应。分享诊断时遮蔽凭据和私密消息。
- SDK 升级：已加载模块不保证随配置热应用而替换；修改版本后可能需要重启实例。升级前备份配置并保留回退版本。

## 列表探测不等于真实调用

「测试连接」或草稿探测用于查询模型，不保存当前草稿。不支持模型发现的服务需要手动填写模型表。显式提供模型列表时，保存流程可以接受列表而跳过远端探测。

| 观察到的结果 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 保存成功 | 本次本地校验、配置写入等流程完成 | API key 一定有效 |
| 可以列出模型 | 模型发现接口返回了列表 | 目标模型可调用、账户余额充足 |
| 目录显示窗口与价格 | 有相应元数据 | 当前 endpoint 已实测支持这些能力 |
| 一条短文本回复成功 | 这次基础对话请求可用 | 工具、图片、推理等能力全部可用 |

保存后，在测试会话发送短文本，检查轨迹中的实际 provider、model 和完成状态。基础对话正常后，再分别验证工具、图片、推理和结构化输出。不要从「兼容 OpenAI」推断全部协议特性。

## 默认模型与功能角色

默认模型用于没有更具体覆盖的聊天选择；场景规则中的显式模型仍可能覆盖它。子代理也不会默认继承当前主聊天模型。

| 配置 | 常见用途 |
| --- | --- |
| 默认聊天模型 | 常规会话 |
| `@small` | 记忆提取、整理、部分判断等较小任务 |
| `@medium` | 默认子代理等中等任务 |
| `@large` | 明确选择较大档位的任务 |
| `@decide` | 独立 decide 模态的结构化判断 |

角色指向实际模型。当前聊天插件未显式配置时，`@large` 与 `@decide` 回退到 `@medium`，`@medium` 回退到 `@small`，`@small` 使用该范围的回复模型；插件已注册的角色解析器可以另有行为。角色并不是附赠的远端模型，也不要求分别填写所有角色才能开始聊天。

`decide` 是独立模态；`judge` 会先尝试它，只在无法绑定该模态时尝试 chat 结构化判断，chat 回退不支持 box 问题。不能把「角色允许选聊天模型」理解为该模型原生支持全部 decide 能力。

设置默认模型会验证地址可以绑定，但绑定不是完整的远端推理测试。真实调用仍可能因认证、额度或网络失败。更完整的寻址、代次和调用边界见[模型与请求运行时](/architecture/models)。

## 更新凭据

管理界面读取凭据字段时不返回明文。编辑已有提供商时，留空表示保留；撤销凭据使用明确的清除操作。不要因修改 base URL 而把未显示的密钥当成丢失，也不要填入占位文本覆盖有效密钥。

`$credential` 是凭据引用，不应替换成明文后提交 Git。提供商凭据、WebUI 登录口令、机器与技能使用的 SecretBox 属于不同机制，不能笼统宣称所有配置都采用同一种加密。详见[安全与权限](/guide/security)。

## 参数与协议边界

`maxOutputTokens` 限制输出，不扩大输入窗口。降低输出上限也不保证过长输入能够通过；应同时检查历史消息、附件、工具 schema 和压缩结果。

采样参数、思考等级等受具体模型和协议支持范围限制。遇到参数降级 warning，先读实际原因，再决定是否调整。原生工具发现、提供方执行的工具、远程压缩、推理签名和媒体 URL 各有协议边界，不能在不同接口之间随意互换。

工具是否对模型可见，由工具过滤、运行模式和权限共同决定，不由提供商页面单独授权。

## 排错顺序

| 现象 | 优先检查 |
| --- | --- |
| 列表有模型，聊天报认证错误 | 实际请求的 key、远端授权、协议和 endpoint |
| 保存后聊天仍用旧模型 | 全局默认、具体场景覆盖、轨迹中的实际地址 |
| 子代理用了另一个模型 | 子代理 profile 与 `@medium` 等角色配置 |
| 工具调用不工作 | 模型能力、工具 schema、工具模式与权限 |
| 图片或音频失败 | 对应模态、附件转换、模型能力与 URL 支持 |
| 费用异常 | 实际 usage、缓存字段，以及额外判断、记忆和子代理调用 |

接下来用[场景规则](/guide/rules)为不同群聊和私聊选择模型；需要核对计费与失败请求时查看[轨迹与用量](/guide/observability)。
