# 术语表

本文档界定 ChatLuna v2 核心概念的技术定义与系统边界。相同中文词汇在 UI 和交互场景中可能指向不同对象；排查问题或调用接口时，应以本表声明的具体语义与系统实体为准。

## 配置与运行时

| 术语 | 定义与职责 | 边界与区别（不等于） |
| --- | --- | --- |
| **instance / 实例** | 拥有独立 `package`、根清单与运行时数据的完整运行环境。 | 单个机器人账号或浏览器标签页。 |
| **launcher** | 全局 `chatluna` CLI 命令工具，负责选择实例并管理进程、依赖包及异常修复。 | 应用全部业务服务本身的实现集合。 |
| **manifest / 清单** | Cordis 加载的插件配置树，支持通过 `include` 引入其他配置文件。 | 环境变量全集或运行时数据库。 |
| **entry / 配置条目** | 清单中带有稳定 `id` 的插件或配置组项。 | 对话日志中的 `SessionEntry`。 |
| **fiber** | Cordis 单次插件挂载的生命周期与所有权边界。 | 操作系统线程或物理机/容器隔离环境。 |
| **inject** | 插件所依赖服务的声明机制或依赖子树挂载流程。 | 运行时主动轮询服务可用性。 |
| **HMR** | 释放在改动范围内的插件并重新构建生命周期的开发热重载机制。 | 能保证所有正在执行的调用现场不受影响。 |
| **config transaction** | 配置的写入、静态校验与受控应用到运行时的变更流程。 | 跨数据库、跨网络或跨节点的全局分布式事务。 |
| **safe mode / 安全模式** | 由 supervisor 提供的最小化恢复启动环境。 | 针对任意恶意插件的安全沙箱机制。 |

## 对话与执行

### 核心对象与生命周期

| 术语 | 定义与边界说明 |
| --- | --- |
| **conversation** | 面向用户交互或业务路由的逻辑会话；其索引维护、主线切换及活跃执行调度统一由 `conversations` 服务负责。 |
| **head** | 业务对话当前指向的 `Session` 引用；不是对底层日志条目的快照复制。 |
| **Session** | 有序、仅追加（append-only）的会话日志及其视图对象；持久化存储由底层的 `SessionStore` 具体承担。 |
| **SessionEntry** | 组成 Session 日志的基础条目联合类型，包括 `message`、`cut`、`mark` 三类；`n` 为其递增的日志绝对序号。 |
| **message** | 已经正式提交的聊天消息记录；不等于流式传输过程中实时显示的未完成文本。 |
| **cut** | 上下文截断标记点与关联摘要；用于改变后续构建的消息上下文视图，不代表物理删除历史日志。 |
| **mark** | 带有特定名称的控制或追踪记录；通常用于内部状态标记，不直接作为对话消息提供给模型。 |
| **draft** | 尚未正式提交追加的生成中内容；系统不提供等同于已提交记录的持久化保证。 |
| **committed** | 已被 Session 接受并成功追加的条目；其持久化落盘时机与故障恢复保证由所配置的 store 实现决定。 |
| **Agent** | 具备运行状态、输入队列与驱动循环的活跃执行对象；独立于持久化存储中的静态 Session 数据。 |
| **turn** | Agent 的单次业务执行轮次；一个 turn 内可依次包含多次模型推理步骤与工具调用。 |
| **step** | 单次模型推理请求及其前后的步骤处理边界。 |
| **Run** | 针对单次 chat 模型推理请求的流式传输与完成结果封装；不代表完整的 Agent 工具调用闭环。 |

### 调度控制与上下文管理

| 术语 | 定义与边界说明 |
| --- | --- |
| **receive next** | 将输入放入 Agent 的待处理缓冲队列中，延迟至下一轮次（turn）进行处理。 |
| **receive now** | 在当前的步骤（step）边界处合入新输入，不会强制中断正在等待响应的外部网络调用。 |
| **receive quiet** | 写入输入但不唤醒处于空闲状态的 Agent；不作为已完成消费的业务回执。 |
| **abort** | 向当前执行流程发起终止请求；无法撤回或回滚外部已经完成的网络请求、写入操作或消息投递。 |
| **branch / fork** | 以指定的日志条目边界为起点，将历史记录复制衍生为子 Session；分支日志的创建本身不保证业务主线 `head` 同时切换；上层 conversation 操作可以进一步协调切换。 |
| **lane** | 路由层用于区分对话流向的逻辑分流维度；与 `Session.branch` 机制不同，亦不提供安全隔离能力。 |
| **compaction** | 通过生成上下文摘要并插入 `cut` 标记来缩减后续调用上下文长度的过程；与模型供应商提供的 prompt cache 机制无关。 |

> **标识符与序列号说明**：
> Session 日志序号 `n` 与前端渲染的消息列表数组索引不一致：插入 `mark`、`cut` 或特定展示合并策略均会导致视觉计数与底层日志序号产生偏移。在系统集成与调试中，严禁将 HTTP 查询参数 `seq`、SSE 传输中的 `id`、前端 UI 的 `revision` 与数据库内部主键混淆或直接替代。

## 模型

- **provider**：具体的接入协议或供应商适配实现。在系统中完成平台与密钥的配置，不代表远端推理端点已连通或可用。
- **model address**：模型寻址标识。运行时通常采用 `provider:model` 格式；部分预设元数据中使用 `provider/model`，系统按具体接口的输入边界分别解析。
- **role / 模型角色**：如 `@small`、`@medium`、`@large`、`@decide` 等逻辑角色用途绑定；角色仅代表能力映射策略，不绑定特定供应商品牌、计费单价或绝对能力等级。
- **modality / 模态**：支持的交互模态定义，包括 `chat`、`embed`、`rerank`、`draw`、`speak`、`listen`、`decide`。其中 `decide` 是用于结构化裁决的专用模态，其协议与行为与普通的聊天 JSON 格式化输出不同。
- **verb / 动词**：调用意图的统一 API 入口方法，包括 `ask`、`chat`、`extract`、`embed`、`rerank`、`draw`、`speak`、`listen`、`decide`、`decideOne`、`judge`。
- **resolve / bind / call**：模型调用的三个独立生命周期阶段：
  - *resolve*：根据规则解析出目标模型；
  - *bind*：将当次运行参数与适配器实现进行绑定；
  - *call*：正式发起网络通信。
  早期阶段（如模型寻址或参数校验）同样可能抛出异常并失败。
- **generation**：Provider 适配器在生命周期中重载或重新挂载的代际版本编号；禁止将其混同于提示词或缓存维度的 prompt/cache epoch。
- **usage**：规范化后的模型 Token 消耗计量数据。不同供应商提供的总输入、缓存读取、缓存写入及推理计算 Token 之间可能存在统计包含关系，业务计算用量时不得直接进行算术累加。

## 上下文与缓存

- **preset / 预设**：由系统管理的 Markdown 源文件及配套元数据、片段和配置集合。所谓“伪装”是预设携带人设、行为约束与记忆检索规则的具体应用方式，并非一种独立的新模型协议。
- **prompt zones**：提示词构建的区域划分，包含 `system`、`context`、`input` 三个区：
  - `system`：用于构建高稳定性的前缀内容以优化缓存；
  - `context`：用于承载动态注入的数据与历史；
  - 这种逻辑分区不构成区分可信与不可信内容的安全防御边界。
- **mutable variable**：其值会随调用轮次频繁变化的变量。在明确要求静态的 `system` 区中使用动态变量将直接抛出 `MutableVariableError`，系统不会静默降级或保留变量原文本。
- **epoch**：提示词模板或工具定义前缀的缓存生命周期边界；不代表业务层面的会话分叉（branch），亦不代表底层模型实现版本的迭代。
- **cache break**：向模型供应商协议发送的显式缓存分段指示；底层实际是否命中缓存以及具体的计费优惠，完全由该模型协议与供应商服务端的机制决定。
- **memory scope**：长期记忆的作用域分级，涵盖共享、预设、群、用户、对话等维度；群聊记忆可能在上下文构建中合并引入近期活跃发言者的用户维度记忆。
- **memory index**：系统在上下文中自动注入的主题摘要索引，而非全部记忆条目的原始正文。启用 `conversation isolation` 仅收窄上下文自动注入的索引范围，不代表限制 `memory_search` 工具在获得授权后检索其他范围的记忆数据。

## 能力与权限

| 术语 | 定义与边界说明 |
| --- | --- |
| **tool** | 注册给模型调用的动作单元，声明有输入参数的 `args` 结构与 `run` 执行方法；模型接收到 tool schema 仅表示感知到该动作，不代表系统已预先批准该执行。 |
| **tool search** | 工具的动态检索机制，通过按需发现和延迟挂载工具来减少初始请求的提示词体积；不作为绕过权限策略的手段。 |
| **MCP** | Model Context Protocol，用于连接外部工具与上下文资源的通信协议；对端进程的安全性、凭据有效性及网络可用性仍需独立配置和授信。 |
| **skill** | 能够被系统检索与激活的工作规范说明或复合能力资源；说明性文本的加载不会使执行环境自动获取额外的系统调用权限。 |
| **tool auto / ask / off** | 工具策略层提供的三种行为选项：自动（auto，仍受能力权限规则约束）、人工审批（ask）和完全禁用（off）；其概念不同于全局权限策略中的 `permission mode`。 |
| **permission mode** | 系统统一的权限求值策略，包括 `read-only`、`files`、`auto`、`allow` 等模式；最终权限由主体身份、规则列表与操作等级综合计算决定。 |
| **runtime policy** | 专门控制运行时自管理工具作用边界的策略，分为 `off`、`inspect`、`full` 三档；即使配置为 `full`，特定高危操作仍可能触发人工审批流程。 |
| **machine** | 由 `computer` 服务统一管理的外部执行后端（如 `local`、`ssh`、`docker`、`e2b`）。 |
| **sandbox** | 具体执行环境所提供的隔离机制；沙箱隔离能力依赖于底层 machine 后端的配置与实现，无法单纯通过勾选“启用工具”自动获得。 |
| **background** | 异步任务调度与结果追踪管理器；系统不保证宿主进程在非正常崩溃重启后能恢复未完成任务的内存现场。 |
| **subagent** | 由父级任务衍生出的子执行对象；即使配置了上下文继承隔离（`inherit none`），也不代表底层文件系统或操作系统层面的安全隔离。 |
| **settled** | 执行流程进入最终确定状态；该状态包含执行失败（failed）或主动取消（aborted），不等于业务执行成功。 |

## 诊断与协议

- **trace / 轨迹**：依据系统日志与执行上下文记录，用于追溯输入数据、工具调用链、模型输出及错误堆栈的诊断视图；trace 是对底层事实数据的排查呈现，并非独立于日志系统之外的第二套状态数据。
- **reconstruct / 请求重建**：根据历史记录的边界数据还原当时的请求载荷结构，该过程不会重新请求模型端点，亦不执行任何工具逻辑。
- **replay / 重放**：基于指定历史边界重新向模型发起新的推理调用用于结果比对；重放操作会真实消耗网络与模型配额并产生计费，但不会自动重新执行原历史中的工具调用，亦不会修改原 Session 日志。
- **durable SSE**：用于向客户端推送已正式提交的 Session 条目流，支持客户端携带 `sessionId:n` 游标实现断线追溯恢复；该命名仅表明协议支持持久化条目的断点重传，在未配置持久化 store 的内存模式下不具备抗进程崩溃或抗断电能力。
- **live SSE**：用于向客户端实时展示尚未提交的生成内容快照与增量分块；传输中的 `revision` 字段仅用于前端渲染视图同步，不能作为 durable SSE 的历史恢复游标使用。
- **state / action**：管理 WebUI 所使用的强类型状态快照与操作动作协议，与传输对话流的 SSE 通道职责独立。
- **access token / 访问口令**：用于验证访问当前实例权限的静态安全口令，不是模型供应商的 `provider key`；登录鉴权成功后签发的会话凭据（session credential）与访问口令在结构和用途上互不相同。
- **owner / 主人**：经应用确认的平台管理身份；已单独设置的权限等级仍应以权限记录为准；不同于标准 Web 系统的多租户账号体系，WebUI 目前直接使用实例所有者访问口令进行统一认证。
- **idempotency / 幂等**：针对相同业务操作请求的防重复提交约束机制。当前 HTTP 层的内存幂等记录表具备时间窗口限制，且在进程重启后丢失，系统不承诺提供跨多进程的绝对分布式 exactly-once 保证。
