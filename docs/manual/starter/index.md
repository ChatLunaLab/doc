# 选择安装方式

ChatLuna v2 是一套独立部署的应用程序，不是在已有 Koishi 实例中直接更新插件得到的新版本。在开始部署之前，你需要根据使用目标选择一种安装方式。

::: warning 版本说明
alpha 阶段引用的 npm 包名与镜像标签不保证在所有公共源同步发布。生产试运行请锁定经过验证的版本，升级前做好全量备份，不要在生产实例上直接测试未知插件。
:::

## 安装方式对比

你可以参考下表选择最符合你当前需求的安装途径：

| 方式 | 适合场景 | 环境要求 |
| --- | --- | --- |
| [Docker 安装](./docker) | 本机快速体验、服务器试运行 | Docker Engine 或 Docker Desktop |
| [命令行（CLI）安装](./cli) | 单机管理一个或多个实例 | Node.js 24+ |
| [从源码运行](./source) | 开发插件、调试框架核心 | Node.js 24+、Yarn 4 |

## 各方式的部署特征

根据部署环境与维护方式的不同，三种安装方式的技术特征如下：

- **Docker**：将运行环境、依赖与应用完整封装在容器内。运行时配置、数据卷持久化以及端口映射均通过 Compose 文件定义，版本升级仅需拉取并替换镜像标签。
- **CLI**：通过命令行工具在本机的 `~/.chatluna/instances/` 目录下创建和管理实例文件。支持多实例并行存在，各个实例独立启动、停止与配置。
- **源码运行**：直接克隆 v2 完整代码仓库，在 `packages/` 和 `plugins/` 目录中直接修改代码并配合热重载进行开发与调试。
