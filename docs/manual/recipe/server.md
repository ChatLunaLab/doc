# 公网部署

::: tip
这一页讲怎么把控制台安全地开放给外网访问。结论先说：不要直接暴露端口，放在反向代理后面，加 HTTPS，用强口令。
:::

默认情况下，控制台只允许本机访问。

这不是疏忽，而是刻意的选择。控制台能安装任意插件、修改任意配置、执行任意命令——它在权限上等价于服务器本身。

把这样一个界面直接挂到公网，和把服务器 root 密码贴在公告板上没有本质区别。

所以，对外提供服务之前，请先读完这一页。

## 三道门

对外开放控制台，需要同时处理好三件事：

1. **谁能访问**：来源限制与访问令牌。
2. **怎么访问**：反向代理与 HTTPS。
3. **访问了能做什么**：权限等级与审批。

任何一项缺位，另外两项都会失去意义。

## 访问令牌

登录控制台要用访问令牌，它有三个来源，优先级从高到低：

- **配置里写死**：在服务插件配置里填了令牌，就只认这个。
- **环境变量**：没有配置时，读取环境变量里的令牌。
- **自动生成**：两者都没有时，首次启动会生成一个随机令牌，写进数据目录，并在日志里打印一次。

自动生成的令牌只显示一次，日志里会同时给出带令牌的登录地址。第一次登录后，建议去「设置」页把它改成一个你记得住的强口令。

::: warning
弱口令会被直接忽略。

如果你在配置或环境变量里填了一个太弱的令牌，系统不会用它登录，而是退回数据目录里的那个，并在日志里报一条错误。看到这条错误，说明你以为生效的令牌其实没生效。
:::

有一个细节很容易踩坑：**令牌如果被配置或环境变量固定住，就不能在界面上改**。

界面会拒绝修改并提示令牌被谁固定了。想换令牌，得去改对应的位置，然后重启。

修改令牌会让所有已登录的会话失效。这是有意的——令牌泄漏时，改掉它就应该立刻踢掉所有人。

::: tip
令牌等于主人权限，但它不等于「永远安全」。

把它写进脚本、CI 变量或者聊天记录，泄漏只是时间问题。用的时候从安全的地方读，别硬编码。
:::

## 允许远程访问

只配令牌还不够。服务默认只接受来自本机的请求。

要让外部访问，需要显式打开「允许远程访问」。这个开关可以在服务插件配置里打开，也可以用环境变量在启动时打开。

不打开它，即使反代配置正确，请求也会被拒绝，并返回一条明确的提示。

::: danger
打开远程访问之前，请确认两件事：

第一，访问令牌是强口令，而且不是默认值。
第二，所有管理路径都在受保护前缀里。

控制台能安装 npm 包，这意味着它具备执行任意代码的能力。暴露一个未受保护的控制台，等于把服务器交出去。
:::

### 受保护前缀

服务默认保护两个路径前缀：接口路径和控制台路径。

这两个前缀下的所有请求都必须带有效令牌。除此之外的路径是公开的，比如静态资源。

如果你自己扩展了页面或接口，记得把新的前缀也加进受保护列表，否则它们会裸奔。

更麻烦的是，加载了控制台相关插件却没有把控制台路径列进受保护前缀时，诊断命令会直接报错。系统用这种方式阻止一个明显的错误配置。

## 反向代理

直接把端口暴露到公网还有一个问题：没有 HTTPS。

正确的做法是在前面放一层反向代理（Nginx、Caddy、Traefik 都行），由它持有证书、终止 TLS，再把请求转发给本机的实例。

配置代理时有几个关键点：

- **转发真实地址**：把原始访问者地址传下去，否则所有请求看起来都来自本机。
- **支持协议升级**：控制台靠长连接推送实时数据，代理必须转发协议升级相关的头，否则轨迹、日志、聊天页不会更新。
- **够长的超时**：长连接不能被代理提前掐断。
- **不要缓冲**：实时推送需要关闭缓冲，否则消息会攒成一批才到。

::: warning
只配好普通的 HTTP 转发，页面能打开但数据不更新，是这个环节最常见的问题。

表现是：登录正常，标题栏显示已连接，但聊天不出新消息、轨迹不刷新。检查协议升级和缓冲设置。
:::

### HTTPS

证书用反向代理统一管理，不要让实例自己处理。

这样做的好处是：续期、加密套件、HTTP/2 都在一层解决，实例只负责业务逻辑。

如果觉得证书管理麻烦，可以考虑用支持自动签发的代理工具，省去手动续期。

### 子路径部署

如果你想把控制台挂在某个子路径下（比如一个域名下的某个目录），需要同时改代理和实例的路径配置。

改完之后，记得验证静态资源、接口和实时连接都能在这个子路径下正常工作。

::: tip
子路径部署的风险点在于拼接。任何一个资源路径少拼接了一层，页面就会白屏或样式丢失。

部署后按 F12 看一下失败的请求，通常能一眼看出问题在哪。
:::

## 不开放的替代方案

如果只是自己临时访问，完全没必要开放公网。

### SSH 隧道

在本机建立一条端口转发，把远程实例的端口映射到本地，然后像访问本机一样访问。

这种方式不需要证书、不需要改配置、不暴露任何端口，用完就断。

对个人用户来说，这是性价比最高的方案。

### 内网访问

如果客户端和服务器在同一个内网（家里的 NAS、公司的局域网），直接在内网访问即可。

需要的话，再配合 VPN 从外部接入内网。

## 与其他安全措施的关系

控制台只是入口。进去之后能做什么，还要看权限系统。

对外部署时，建议把这几项一起检查：

- **权限模式**：默认不要把「完全放行」给到普通用户。
- **工具策略**：命令执行、文件写入保持需要审批。
- **审批人**：确认有权限足够的人能收到审批请求。
- **日志**：开启日志记录，方便事后回看谁做了什么。

这些设置在[权限与安全](../usage/permissions)和[工具](../usage/tools)里有详细说明。

## 上线检查清单

部署前逐条确认：

1. 访问令牌是强口令，且来源明确（配置、环境变量或数据目录）。
2. 已显式开启远程访问。
3. 接口与控制台路径都在受保护前缀里。
4. 反向代理已配置 HTTPS。
5. 代理转发了真实地址与协议升级头。
6. 长连接超时合理、缓冲已关闭。
7. 诊断命令没有报配置错误。
8. 已用手机或另一台机器从外部验证过一次完整登录。

## 排查

**打开域名提示 403。**

先看是不是没打开「允许远程访问」。再看代理是否把真实地址传下去了——来源判断依赖这个信息。

**登录一直失败。**

确认令牌来源。如果日志里提示「忽略弱令牌」，说明你填的令牌没被采用，实际生效的是另一个。

**页面能开，但数据不刷新。**

协议升级头没转发，或者代理缓冲没关。检查长连接那一侧。

**改完令牌后所有人都被登出。**

这是预期行为。告诉其他人用新令牌重新登录。

**子路径下白屏。**

静态资源路径拼接错了。检查构建时的基础路径与代理的重写规则是否一致。

**担心被扫到。**

即使是公网部署，也建议在代理层加访问控制（IP 白名单、Basic Auth、VPN），把攻击面缩小到最小。
