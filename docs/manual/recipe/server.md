# 公网部署

::: tip
切勿直接将实例端口暴露在公网上。稳妥的做法是将其置于反向代理之后，开启 HTTPS 加密，并配置足够强度的访问口令。
:::

在完成本地环境的部署与测试后，你可能希望将控制台开放到公网，以便随时远程管理机器人。

在默认情况下，控制台只允许来自本地回环地址的访问请求。这是出于安全考虑的设计：控制台拥有极高的权限，可以自由安装插件、修改系统配置、调用底层接口乃至执行命令。拥有控制台权限在很大程度上等同于掌控了服务器本身。

如果将控制台直接暴露给外部网络，会带来极大的安全风险。因此，在对外提供远程访问服务之前，请务必先了解并落实本节介绍的安全措施。

## 三道门

对外开放控制台不仅是做一次端口映射，而是需要同时构建三道相互依存的防线：

1. **谁能访问**：来源限制与访问令牌。
2. **怎么访问**：反向代理与 HTTPS 加密传输。
3. **访问了能做什么**：权限等级划分与敏感操作审批。

这三道防线缺一不可。例如，即使口令再复杂，缺乏 HTTPS 保护时凭据也可能在明文传输中被轻易窃听；而即使网络边界把控再严密，若访问令牌过于脆弱，攻击者也能通过暴力破解进入系统。只有将三道防线全部落实，公网上的控制台才能安全运行。

## 访问令牌

登录控制台必须使用访问令牌。系统提供了三种令牌提供方式，生效优先级从高到低依次为：

- **配置项指定**：在服务插件配置中填写的令牌优先级最高。在此处设定后，系统将仅使用该令牌。
- **环境变量指定**：当配置项中未填写时，系统会尝试读取环境变量 `CHATLUNA_TOKEN`。
- **自动随机生成**：若前两者均未提供，实例在首次启动时会自动生成一个高强度的随机令牌，写入本地数据目录，并在启动日志中输出一次带有该令牌的快速登录链接。

初次登录成功后，建议前往「设置」页面，将其修改为便于记忆且符合强度要求的自定义强口令。

::: warning
系统内置了严格的令牌强度校验规则，弱口令会被直接忽略。

如果在配置项或环境变量中填入的口令未达到强度要求，系统不仅不会采用，还会自动回退到数据目录中保存的旧令牌，并在运行日志中打印一条错误提示。修改口令后请务必以日志提示为准，避免误以为新口令已经生效。
:::

需要注意的是，**一旦令牌通过配置项或环境变量固定，就无法在控制台界面中直接修改**。此时在界面上尝试保存新口令，系统会提示该令牌已被外部固定并拒绝修改。若要更换，必须修改对应的配置文件或环境变量，并重启实例。

此外，每次修改访问令牌都会使此前所有已建立的登录会话全部失效。一旦怀疑口令泄露，修改令牌即可强制踢掉所有在线访客，确保系统安全。

::: tip
访问令牌在权限上等同于主人权限。切勿将令牌写在公开脚本、代码仓库、CI 环境变量或聊天记录中。实际使用时应当通过受保护的环境变量读取，避免硬编码带来泄露风险。
:::

## 允许远程访问

配置好访问令牌后，实例在默认状态下依然会拒绝来自非本机的访问请求。

这是因为配置项 `allowRemote` 的默认值为 `false`。即便端口已经映射到了外部网卡，只要该项未开启，所有远程连接依然会被阻断。

为了允许外部网络连接，你需要在服务插件配置中将「允许远程访问」开关打开，或者在启动时通过环境变量启用该选项。若未开启此项，即便外部反向代理配置完全正确，实例也会直接拒绝请求并返回禁止访问提示。

::: danger
在开启远程访问之前，请务必确认以下两点：

1. 当前使用的访问令牌符合强度要求，且绝非默认值。
2. 所有涉及核心管理与接口调用的路径，均已明确包含在受保护前缀中。

控制台拥有安装 npm 包与调用底层系统的能力，具备执行任意代码的可能。向公网暴露未受保护的控制台，无异于直接交出服务器的掌控权。
:::

### 受保护前缀

为了区分公开内容与受限资源，服务在默认情况下保护两个路径前缀：接口路径 `/api` 与控制台管理路径 `/console`。

所有落在这两个前缀之下的网络请求，都必须携带合法有效的访问令牌或认证状态。除此之外的路径则属于公开访问区（例如用于加载前端界面静态资源的静态文件路径）。

如果在后续使用中通过插件扩展了自定义的管理页面或专属接口，请务必将新的路径前缀也追加到受保护前缀列表中，避免接口暴露在公网中。

此外，系统的内置自检机制还会对此类配置进行校验。若实例加载了控制台相关插件，却未将控制台路径纳入受保护前缀，执行诊断命令时将直接报错。

## 反向代理

建议在前端架设一层反向代理（例如 Nginx、Caddy 或 Traefik），由反向代理统一负责证书管理与 TLS 终止，再将请求转发给本地运行的实例，切勿将实例监听的真实端口直接暴露在公网上。

在为控制台配置反向代理规则时，必须满足以下四个要素：

- **转发真实客户端地址**：务必在转发请求中带上 `X-Forwarded-For` 与 `X-Real-IP` 等请求标头。否则在实例看来所有访问都来自本地回环地址，导致日志审计与访问控制失效。
- **支持协议升级机制**：控制台的动态轨迹、运行日志以及聊天流式推送高度依赖长连接。代理服务器必须正确透传协议升级标头，将 HTTP 请求升级为 WebSocket 长连接。
- **配置充裕的超时时间**：控制台的长连接在待机时可能会长时间处于空闲状态。代理端的读取与发送超时时间必须设置得足够长，防止空闲长连接被反向代理掐断而引发频繁重连。
- **关闭代理响应缓冲**：实时消息推送要求产生的数据即刻下发。代理端必须显式关闭响应缓冲，否则流式输出会被缓冲积攒后一次性返回。

::: warning
在反向代理配置中，最常见的问题是「登录一切正常，界面也能加载，但聊天不出新消息、轨迹和日志不刷新」。

如果遇到这种现象，请优先排查协议升级标头是否被正确透传，以及代理响应缓冲是否已经彻底关闭。
:::

### HTTPS

建议将所有的 TLS 证书申请、加载与自动续签交由反向代理统一管理，而不是由实例自身处理。

这样可以使证书轮换、现代加密套件协商以及 HTTP/2 等协议优化全部集中在反向代理层处理，实例只需在本地保持标准明文监听即可。如果希望简化配置，也可以选用自带自动证书申请能力的代理工具（如 Caddy）。

### 子路径部署

如果希望将控制台部署在域名的某个子目录之下（例如挂载在特定的 URL 子路径后），则需要同时对反向代理的重写规则与实例的基础路径配置进行协同修改。

完成配置调整后，请仔细验证静态资源文件、API 接口调用以及实时长连接能否在新的子路径下正常工作。

::: tip
子路径部署最容易踩坑的地方在于路径前缀的拼接。

部署完成后如果在浏览器中遇到页面白屏或样式缺失，只需按下 F12 打开开发者工具的网络面板，观察具体是哪个资源文件请求返回了 404，即可排查路径拼接偏差的位置。
:::

## 不开放的替代方案

如果你只是个人偶尔需要远程查看机器人状态或排查问题，完全没有必要向公网开放端口。借助以下两种替代方案，同样可以安全高效地完成远程访问：

### SSH 隧道

在本机终端中建立一条本地端口转发通道，把远程服务器上实例监听的内部端口映射为本地机器上的端口。

此时在本地浏览器中直接访问该端口，使用体验与在服务器本机打开控制台完全一致。这种方式不需要域名，不需要配置证书，也不需要修改实例的远程访问开关与安全组端口策略，使用完毕后断开 SSH 会话即可。

### 内网访问

如果管理设备与机器人实例处于同一个家庭局域网或公司内网中（例如部署在家用 NAS 或本地软路由上），直接使用局域网 IP 进行访问即可，完全无需暴露在公网上。

如果需要出门在外时也能访问，更推荐的做法是在局域网内搭建私有网络节点（如 WireGuard 或 Tailscale）。在外网时先接入安全隧道，再通过内网 IP 发起访问，既能满足移动访问需求，又能将外部公网扫描彻底隔绝在外。

## 与其他安全措施的关系

控制台是整个系统的入口大门。用户通过鉴权进入系统后，具体能够执行哪些操作，则由权限系统进行控制。

在将控制台开放到外部网络时，建议与以下安全策略做好联动检查：

- **权限等级模式**：为不同角色的访问者划分严谨的权限等级，切勿默认将最高控制权限赋予普通访客账号。
- **敏感工具策略**：对于命令执行、文件写入等具备破坏力的工具调用，务必保持处于需要人工审批确认的状态。
- **审批责任人**：确认系统中至少存在一位具备足够权限的管理员账号，能够正常接收并处理审批请求。
- **审计日志追踪**：保持运行日志处于记录状态，确保关键操作均有迹可循，以便在发生非预期行为时能够快速回溯排查。

关于权限等级的具体划分方式以及工具调用的审核机制，请参阅 [权限与安全](../usage/permissions) 与 [工具](../usage/tools) 两节的专门说明。

## 上线检查清单

在正式向外部网络提供访问服务之前，请对照以下清单逐条核对，确认每一项防御措施均已妥善就位：

1. 访问令牌为高强度口令，且其配置来源清晰明确（配置项、环境变量或数据目录三选一）。
2. 已显式开启 `allowRemote` 选项，允许接收经由外部转发的访问请求。
3. 接口路由 `/api` 与控制台路由 `/console` 均已纳入 `protectedPrefixes` 受保护前缀中。
4. 反向代理服务已正确配置并启用了合规的 HTTPS 加密证书。
5. 反向代理已正确传递真实的客户端来源地址标头与 WebSocket 协议升级标头。
6. 长连接超时时间设置充裕，且代理端的响应缓冲机制已明确关闭。
7. 执行系统诊断命令确认整体运行状况良好，未出现受保护路由缺失等配置警报。
8. 已借助手机移动网络或另一台外网机器，完整模拟并成功通过了一次真实的远程鉴权与登录测试。

## 排查

在公网部署与反代对接的过程中，偶尔可能会遇到一些连接与鉴权异常。可以参考以下常见问题进行排查：

**打开域名后浏览器直接提示 403 Forbidden。**

遇到这种情况时，请首先确认是否在服务插件配置中开启了「允许远程访问」（即 `allowRemote`）。如果确认已经开启，接着检查反向代理是否正确透传了真实客户端 IP 标头。

**控制台登录一直失败，提示口令错误。**

请检查访问令牌的实际来源与运行日志。如果此前在配置项或环境变量中填入了不满足强度规则的弱口令，系统会在启动日志中提示「忽略弱令牌」并自动回退至数据目录下的随机令牌。

**页面能够顺利打开，但聊天数据与轨迹完全不刷新。**

这通常是反向代理在长连接环节配置有误。请检查反向代理配置中是否遗漏了长连接协议升级标头，或者代理响应缓冲处于开启状态，导致推送数据滞留在了代理层。

**修改访问令牌后，所有正在使用中的用户都被登出。**

这属于符合预期的正常设计。修改令牌会自动作废之前签发的所有会话凭证，通知相关成员使用新配置的高强度口令重新登录即可。

**在子路径模式下访问时遭遇白屏或样式混乱。**

这通常是静态资源路径拼接错误造成的。请打开浏览器网络面板检查加载失败的文件地址，对比实例配置的基础路径与反向代理中的路由重写规则，确保两者对前缀的约定完全一致。

**防范公网被恶意自动化脚本扫描探测。**

即便已经部署在公网上，依然建议在反向代理层额外叠加防护手段。例如在代理端设置来源 IP 白名单、前置 HTTP Basic 认证，或是配合 VPN 接入，尽可能降低公网暴露面。
