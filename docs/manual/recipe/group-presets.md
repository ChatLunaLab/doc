# 给每个群配一套

::: tip
这一页是一套完整配方：同一个机器人，在不同群里表现出不同的性格、模型和行为。跟着做一遍，你就能掌握场景规则最实用的用法。
:::

假设你有一个机器人，同时待在三个群：

- 一个技术交流群，需要严谨、准确，回答尽量短。
- 一个朋友闲聊群，需要活泼、会接梗，最好能主动搭话。
- 一个客户服务群，需要克制、专业，只回答业务问题，不能乱用工具。

如果三个群共用一个配置，无论怎么调，总有一个群不满意。

这时候就该给每个群单独配一套。

## 先想清楚要变什么

场景规则能覆盖的项目很多，但不是每个都要改。先列出「这个群和别的群有什么不同」，再决定改哪几项。

常见的差异只有四类：

| 差异 | 对应设置 |
| --- | --- |
| 说话的风格、人格 | 引擎与预设 |
| 聪不聪明、贵不贵 | 模型与推理档位 |
| 什么时候开口 | 回复条件 |
| 能干什么 | 工具、技能、MCP |

剩下的（提供商密钥、插件、数据目录）都是全局的，不需要也不应该在每个群里重复配置。

::: tip
一开始不要把所有项都改一遍。

先只改最能体现差异的那一项——通常是预设或模型——跑几天看看，再决定要不要继续加。
:::

## 第一步：建一条规则

打开「场景规则」，点击新建。

每一页顶部都有一个「作用目标」的选择器，决定这条规则管谁：

- 全局：所有会话的默认值。
- 某个机器人账号：只管这个账号。
- 某个群：只管这个群。
- 某个私聊用户：只管和这个人的私聊。
- 群里的某个成员：只管这个人在群里的行为。

按群配置时，选「群」，然后选中目标群。

如果这个群还没有出现在列表里，说明机器人还没在这个群收到过消息。先去群里发一句话，再回来选。

## 第二步：继承还是覆盖

新建规则时，系统会让你选两件事：

- **从哪条规则继承**：通常是全局规则。
- **覆盖哪些项**：只改你想改的，其余沿用上级。

这个设计的意思是：全局改了，所有没覆盖的群跟着改；某个群单独改了一项，就只影响这一项。

例如，你只想让技术群用更强的模型，那就只覆盖「模型」一项。之后你在全局调整回复延迟，技术群也会跟着变。

::: warning
不要为每个群都新建一条「从零开始」的规则。

那样全局设置就失效了，以后每加一个功能都要去每个群改一遍。
:::

## 第三步：配置这个人设

### 选引擎

引擎决定这个群用哪套对话逻辑。

- **对话**：标准的问答机器人，安静、稳定，适合技术群和客服群。
- **伪装**：带角色状态、作息、主动性，适合闲聊群和角色扮演群。

选完引擎之后，下面会出现这个引擎专属的设置项。

### 选预设

预设是人格与提示词的集合，在「预设」页管理。

在规则里选中一个预设，这个群就会用这个人格。不同群选不同预设，就实现了「一个机器人，多个性格」。

预设的修改是实时生效的，改完不用重启，下一句话就能体现出来。

### 调整主动性

技术群和客服群大多希望「叫了才回」。

闲聊群则希望「聊到点上会接话」。

同一个引擎下，通过「什么时候回复」里的选项就能区分：前者只保留直接触发，后者打开气氛判断。

::: tip
角色扮演群最常见的翻车，是主动性开得太高。

先用很低的插话频率跑几天，觉得太安静再往上调。反过来调（先高后低）体验很差。
:::

## 第四步：限定能力范围

客服群最需要这一步。

同样是接入了工具、技能和 MCP，不同群应该看到不同的能力：

- **技术群**：可以查文档、读代码、搜网页。
- **闲聊群**：可以发表情、搜图，但不要执行命令。
- **客服群**：只能查业务数据，其他一概不开放。

在「场景规则 → 能力」里，可以为这个群单独勾选允许的工具与技能；没有选中的，模型在那个群里根本看不到。

::: warning
「不勾选」比「禁用」更适合按群隔离。

禁用是全局的，会影响所有群；按群取消勾选只影响这一个群。
:::

## 第五步：测试

保存之后，不用重启。

回到这个群里发一条消息，然后打开「轨迹」页：

- 找到刚才那一轮。
- 确认使用的引擎、预设和模型是不是你配的那套。
- 如果不对，检查是不是有另一条更具体的规则覆盖了它。

::: tip
规则冲突时，越具体的目标优先。

「某个群」比「全局」优先，「某个成员」比「某个群」优先。同一层级的规则再看优先级和创建时间。
:::

## 三个完整例子

### 技术群

- **引擎**：对话。
- **预设**：一个语气平实、擅长解释的助手。
- **模型**：大模型，或者你手上最强的那一个。
- **回复**：只回应 @ 和叫名字，不主动搭话。
- **工具**：允许搜索与文件读取，命令执行需要审批。

效果：安静、准确、不会抢话。

### 闲聊群

- **引擎**：伪装。
- **预设**：一个有性格的角色。
- **模型**：中档即可，太贵反而浪费。
- **回复**：开气氛判断，插话频率从低开始。
- **工具**：表情、图片这类轻量能力。

效果：会看气氛接话，偶尔主动，但不刷屏。

### 客服群

- **引擎**：对话。
- **预设**：礼貌、简短的业务助手。
- **模型**：稳定优先，不追求最强。
- **回复**：只回应明确提问，关闭主动说话。
- **工具**：只开业务查询类，写入与命令全部关掉。
- **权限**：默认只读模式，敏感操作走审批。

效果：可控、可审计，不会越权。

## 规则怎么命名

规则多了以后，名字比配置更重要。几个习惯：

- 名字里带上群的特征，而不是群号。
- 写了例外就在名字里体现，比如「客服群 - 禁用命令」。
- 停用而不是删除，方便以后复用。

::: tip
场景规则页可以按目标和工作区分组。先把命名规范定下来，再开始批量建规则，后期维护会轻松很多。
:::

## 常见问题

**改了预设，群里没变化。**

确认这条规则确实覆盖了预设；确认预设已经保存；确认这个群的会话没有被更具体的规则接管。

**换了引擎，群里还是老样子。**

引擎只在会话建立或切换时生效。已经存在的对话可能还跑在旧引擎上，开一个新对话再看。

**模型换了，但账单还是很高。**

检查模型角色。判定、提取、摘要这些后台任务用的是角色模型，不是你在规则里选的对话模型。

**工具在某个群不见了。**

先看场景规则里的工具勾选，再看全局工具策略里是不是禁用了它。两处都会影响可见性。

**两个群配了同样的规则，行为却不一样。**

它们多半继承自不同的上级，或者有一条更具体的规则（比如按成员配的）在生效。
