# 给每个群配一套

::: tip
这是一个实操配方：让同一个机器人在不同的群聊中展现不同的性格、模型与行为模式。跟着本节操作，你即可掌握场景规则的实用配置方法。
:::

假设你的机器人同时加入了三个不同的群聊：

- 技术交流群：回答需要严谨准确，内容尽量精炼，杜绝废话。
- 朋友闲聊群：性格活泼风趣，接梗迅速，最好还能根据气氛偶尔搭话。
- 客户服务群：语气克制礼貌，专注业务解答，不能随意调用无关工具。

如果让这三个群共用同一套全局配置，往往难以兼顾所有群的需求。

解决办法很简单：给每个群单独配置一套场景规则即可。

![场景规则页 · 规则列表](/webui/routing.png)

## 先想清楚要变什么

场景规则支持覆盖很多配置项，但通常不需要逐项修改。更稳妥的做法是：先理清当前群聊与其他场景的具体差异，再针对性地调整。

实际场景中，群聊之间的差异通常只有四类：

| 差异 | 对应设置 |
| --- | --- |
| 说话的风格、人格 | 引擎与预设 |
| 聪不聪明、贵不贵 | 模型与推理档位 |
| 什么时候开口 | 回复条件 |
| 能干什么 | 工具、技能、MCP |

模型提供商密钥、全局插件和数据存储目录等基础配置并不在表中。它们属于全局基础设施，所有群聊共用即可，无需重复设置。

::: tip
建议不要一开始就修改全部选项。

通常可以先调整最核心的设置（例如预设或模型），让机器人在群里运行几天，再根据实际反馈决定是否需要进一步微调。
:::

## 第一步：建一条规则

前往「场景规则」页面，点击右上角的「新建」按钮。

进入编辑界面后，顶部的「作用目标」选择器用于指定这条规则的生效范围：

- 所有聊天：全局通用的默认规则。
- 群聊：只对指定的群聊生效。
- 私聊：只对与该用户的私聊生效。
- 群成员：限制指定成员在群内的交互行为。
- 更多条件：使用自定义条件组合出更复杂的过滤规则。

由于我们要按群定制，这里选择「群聊」，然后在目标群列表中选中你要配置的群聊。

如果目标群没有出现在下拉列表中，通常是因为机器人加入后尚未在该群接收过消息。只需在群里发送一条消息触发一次，再回到页面即可看到该群。

## 第二步：继承还是覆盖

选好目标后，只需要确定当前群需要修改哪些项：

- **要修改的项**：在表单中填入新值，即为一次覆盖。
- **不修改的项**：保持原样，会自动继承全局设定。

这种继承机制的核心是「差异化覆盖」：当全局配置更新时，未单独覆盖的群聊都会自动同步；而在当前群中单独覆盖的配置，仅对该群生效。

例如，如果你只想让技术群使用推理能力更强的模型，只需在继承列表中勾选覆盖「模型」即可。后续在全局调整打字延迟或回复速率时，技术群依然会自动继承全局的修改。

::: warning
请尽量避免为每个群都从零新建完全独立的规则。

一旦脱离继承，全局统一配置就会失效。后续每当新增公共能力或调整通用提示词时，你都需要逐个前往各个群的规则中手动修改。
:::

## 第三步：配置这个人设

在当前规则编辑页中，切换到「基本」标签页。这里集中管理机器人的言行举止：人设、引擎、模型与思考档位。

### 选引擎

引擎决定了机器人在该群采用的核心对话逻辑。

在「对话引擎」下拉菜单中，可以看到几套内置引擎：

- **对话**：标准的一问一答式助手，安静沉稳、响应可控，适合技术答疑群与客服群。
- **编码**：面向编程任务的工作流引擎，适合以代码协作为主的群聊。
- **伪装**：具备拟人化角色状态、作息规律与主动搭话机制，适合闲聊互动与角色扮演群。

选定引擎后，下方会展开该引擎对应的高级设置项。

### 选预设

预设是人格设定、人设背景与系统提示词的集合体，可以在左侧导航栏的「预设」页面中集中维护。

在当前规则页面的「预设选择」下拉框中，选中为该群准备的预设名称。为不同群指定不同预设后，机器人即可在各群中呈现出不同的人格风格。

预设的修改会即时生效。保存后无需重启机器人服务，群里的下一次对话就会使用新的人格风格。

### 调整主动性

不同群聊对机器人回复的主动程度要求大不相同。

技术群和客服群通常只希望在被明确叫到时才回复；而闲聊群则期待机器人在讨论热烈时适时插话。

切换到「回复」标签页，在「什么时候回复」区域中可以看到触发条件的各项开关：技术群与客服群建议仅保留 @ 提及和叫名字触发；闲聊群则可以适当调高「主动搭话概率」。

::: tip
在闲聊或角色扮演群中，若主动搭话概率设置过高，容易造成刷屏打扰。

建议先将插话频率设为较低数值，观察几天后再按需调高，避免一开始因频率过高而打扰群成员。
:::

## 第四步：限定能力范围

对于业务群和客服群，收紧权限尤为重要。

即使机器人在系统层面接入了丰富的工具、技能与 MCP，在不同群聊中也应做好权限隔离：

- **技术群**：允许使用文档检索、代码审查与网页搜索等工具。
- **闲聊群**：仅开放表情包、天气查询与搜图等趣味轻量工具，禁止运行系统命令。
- **客服群**：仅允许调用订单查询等业务接口，屏蔽其余无关能力。

在当前规则页面切换到「能力」标签页，列表中会列出所有已加载的工具与技能。逐项勾选允许当前群调用的项目即可；未勾选的能力，模型在推理时感知不到它们的存在。

::: warning
在场景规则中取消勾选比在全局直接禁用更安全，也更符合按群配置的需求。

在插件或全局面板中点击「禁用」会在全系统生效，导致所有群聊均无法使用该能力；而在场景规则中取消勾选，仅对当前群生效。
:::

## 第五步：测试

在规则编辑页面右上角点击「保存」按钮，页面提示保存成功后改动即刻生效，无需重启任何服务。

测试步骤如下：

1. 前往对应的聊天群发送一条测试消息。
2. 回到控制台，打开左侧导航栏的「轨迹」页面。
3. 在列表中找到刚才由测试消息触发的对话记录。
4. 点开详情面板，确认实际调用的引擎、生效的预设以及模型名称是否与刚才配置的一致。
5. 若调用的参数不符合预期，请检查继承链中是否存在更具体的规则覆盖了当前配置。

::: tip
遇到规则冲突时，系统始终遵循「具体目标优先」原则。

匹配优先级从高到低依次为：「某个成员」>「某个群」>「全局」。若处于同一层级，系统会依次比对手动指定的优先级与创建时间。
:::

## 三个完整例子

这里整理了三种典型群聊的推荐配置组合：

### 技术群

- **引擎**：选择「对话」。
- **预设**：选用语气平实、回答客观、擅长技术解释的助手。
- **模型**：选用推理能力更强的高规格模型。
- **回复**：仅响应 @ 提及与称呼唤醒，关闭主动接话。
- **工具**：开放网页检索与本地文档读取，执行类命令需强制审批。

实际效果：日常保持安静，有问必答且逻辑严密，不主动抢话。

### 闲聊群

- **引擎**：选择「伪装」。
- **预设**：选用个性鲜明、有专属口癖的角色预设。
- **模型**：选择响应速度快、性价比高的中档模型即可。
- **回复**：开启气氛判断与主动搭话，初始插话频率保持低位。
- **工具**：仅开放表情包、点歌与搜图等轻量级能力。

实际效果：能根据群内聊天氛围自然接梗，偶尔主动打招呼，不惹人烦。

### 客服群

- **引擎**：选择「对话」。
- **预设**：选用礼貌周到、解答清晰规范的业务助理预设。
- **模型**：以稳定性和遵循指令能力优先，不盲目追求过大参数。
- **回复**：严格限定为明确提问触发，关闭全部主动式搭话。
- **工具**：仅放行业务相关的数据查询，写操作与命令执行全部屏蔽。
- **权限**：默认开启只读保护，敏感行为必须提交审批。

实际效果：行为严谨合规、全流程可审计，杜绝越权风险。

## 规则怎么命名

当配置的群聊越来越多时，一套清晰的命名规范有助于后续维护。建议参考以下方式命名：

- 规则名称建议包含群的功能特征或业务名，而非单纯使用群号。
- 若规则包含特殊的覆盖逻辑，建议直接体现在名称中，例如「客服群 - 禁用命令」。
- 暂时不用的规则可以切换为「停用」状态，无需直接删除，日后需要时随时可以恢复。

::: tip
在「场景规则」页面顶部，你可以利用筛选器按目标和工作区分组浏览。提前制定命名规范，能让批量管理和后续维护更加清晰。
:::

## 常见问题

**修改了预设，群里却没有明显变化？**

1. 在规则编辑页面中，确认是否勾选了覆盖「预设」项。
2. 前往「预设」页面，确认预设内容是否已成功保存。
3. 检查该群或当前用户是否匹配了更具体的高优先级规则。

**更换了引擎，群里的回复表现为何还是老样子？**

引擎配置通常在新会话建立时生效。若当前群正处于活跃的长对话上下文中，旧会话可能仍在沿用旧引擎。可以在群里发送重置指令开启一个新对话再做观察。

**已将模型换成了便宜型号，账单扣费为何依然居高不下？**

请前往系统配置检查「模型角色」设置。意图判定、关键信息提取以及上下文摘要等后台任务使用的是专门的角色模型，不受你在当前群规则里所选对话模型的影响。

**某个工具在特定群里找不到或者无法调用？**

1. 检查当前群的「场景规则」→「能力」列表中该工具是否已被取消勾选。
2. 若此处勾选正常，请前往全局工具管理页面，检查该工具是否在全局层面被禁用。

**两个群配置了完全相同的规则，为何实际行为截然不同？**

这通常是因为两者的上级继承来源不同，或者其中某个群里存在针对特定成员配置的更具体的个别规则，导致部分逻辑被更优先的规则覆盖。
