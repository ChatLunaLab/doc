# 给每个群配一套

::: tip
这是一个开箱即用的实操配方：让同一个机器人，在不同的群聊里展现出完全不同的性格、模型与行为模式。跟着走一遍，你就能轻松掌握场景规则最实用的配置方法。
:::

假设你的机器人同时加入了三个不同的群聊：

- 技术交流群：回答需要严谨准确，内容尽量精炼，杜绝废话。
- 朋友闲聊群：性格要活泼风趣，接梗迅速，最好还能根据气氛偶尔搭话。
- 客户服务群：语气要克制礼貌，专注业务解答，严禁随意调用无关工具。

如果让这三个群共用同一套全局配置，往往顾此失彼——无论怎么微调，总有一个群觉得体验不合适。

解决办法其实很简单：我们只需给每个群单独配置一套场景规则。

## 先想清楚要变什么

场景规则支持覆盖的配置项很多，但我们通常不需要也不应该项项都改。最稳妥的做法是：先理清「这个群和别处到底有哪些差别」，再去有针对性地调整。

实际场景中的群间差异通常只有四类：

| 差异 | 对应设置 |
| --- | --- |
| 说话的风格、人格 | 引擎与预设 |
| 聪不聪明、贵不贵 | 模型与推理档位 |
| 什么时候开口 | 回复条件 |
| 能干什么 | 工具、技能、MCP |

细心的小伙伴可能会发现，像模型提供商密钥、全局插件和数据存储目录这类基础配置并不在表中。这是因为它们属于全局基础设施，所有群聊共用即可，完全无需重复设置。

::: tip
一开始千万不要把所有选项都改个遍。

最明智的做法是先只改动最核心的那一项——通常是预设或模型。让机器人在群里跑上几天，根据实际反馈再决定要不要继续微调。
:::

## 第一步：建一条规则

打开控制台，在左侧导航栏中点击「场景规则」页面，接着点击页面右上角的「新建」按钮。

进入编辑界面后，首先映入眼帘的是顶部的「作用目标」选择器，它决定了这条规则究竟对谁生效：

- 全局：所有会话的通用默认规则。
- 某个机器人账号：仅对指定的平台账号生效。
- 某个群：只对指定的群聊生效。
- 某个私聊用户：只管与该用户的私信交流。
- 群里的某个成员：精准限制指定成员在群内的交互行为。

既然我们要做按群定制，这里请在下拉列表中选择「某个群」，随后在目标群列表中点击选中你要配置的群聊。

如果发现目标群没有出现在下拉列表中，也不用着急。这通常是因为机器人加入后尚未在该群收到过任何消息。你只需去群里发一句话触发一次，然后再回到页面即可看到该群已出现在备选项中。

## 第二步：继承还是覆盖

选好目标后，接下来只需要想清楚一件事：这个群要改哪几项。

- **要改的项**：在表单里显式填值，就是一次覆盖。
- **不改的项**：保持原样，它们会自动沿用全局的设定。

这种继承机制的核心理念是「差异化覆盖」：只要全局配置更新，所有没有单独覆盖的群聊都会自动同步；而你在当前群里单独覆盖的配置，只会影响这一个群。

举个例子，如果你只想让技术群使用推理能力更强的大模型，那么只需在继承列表中勾选覆盖「模型」即可。日后在全局调整打字延迟或回复速率时，技术群依然能自动享受全局变更。

::: warning
千万不要给每个群都新建一条「从零开始」的独立规则。

一旦脱离继承，全局统一设置就会彻底失效，以后每新增一个公共能力或修改通用提示词，你都不得不逐个进到各个群里手动修改一遍。
:::

## 第三步：配置这个人设

在当前规则编辑页中，往下滚动找到「人设与引擎」设置区域，这里集中管理着机器人的言行举止。

### 选引擎

引擎决定了机器人在该群采用哪套核心对话逻辑。

找到「对话引擎」下拉菜单，点击后可以看到两类主流引擎：

- **对话**：标准的一问一答式助手，安静沉稳、响应可控，非常适合技术答疑群与客服群。
- **伪装**：具备拟人化角色状态、作息规律与主动搭话机制，专为闲聊互动与角色扮演群设计。

选定具体的引擎后，下方会动态展开该引擎专属的一系列高级设置项。

### 选预设

预设是人格设定、人设背景与系统提示词的集合体，可以在左侧导航栏的「预设」页面中集中维护。

在当前规则页面的「预设选择」下拉框中，点选你为该群专门准备的预设名称。不同群选择不同预设，一个机器人分饰多角的生动效果就做好了。

预设的调整是即时生效的。保存后无需重启机器人服务，群里的下一次对话就会立刻体现出新的人格风格。

### 调整主动性

不同群对机器人「接话」的主动程度要求大不相同。

技术群和客服群通常只希望在被显式叫到时才开口；而闲聊群则期待机器人在大家热烈讨论时顺畅插话。

在「什么时候回复」配置卡片中，你可以看到触发条件的各项开关：前者建议只保留提及（@机器人）和称呼触发；后者则可以开启「气氛判断」开关。

::: tip
玩角色扮演或闲聊群最容易翻车的地方，就是把主动搭话的概率调得太高导致刷屏。

建议大家先将插话频率设在一个较低的数值，观察几天。如果觉得机器人过于安静再逐步调高；反之先高后低往往会严重打扰群友。
:::

## 第四步：限定能力范围

对于业务群和客服群而言，收紧权限是必不可少的一步。

即使机器人在系统层面接入了丰富的工具、技能与 MCP，在不同的群聊里也应当严格做好权限隔离：

- **技术群**：允许使用文档检索、代码审查与网页搜索等工具。
- **闲聊群**：开放表情包、天气查询与搜图等趣味轻量工具，禁止运行系统命令。
- **客服群**：只准调用订单查询等业务接口，其余无关能力一律封锁。

在当前规则页面切换到「能力」标签页，你可以在列表中直观看到所有已加载的工具与技能。逐项勾选允许当前群调用的项目即可；未勾选的能力，模型在生成推理时根本感知不到它们的存在。

::: warning
在场景规则中「取消勾选」比全局「禁用」更安全也更符合需求。

在插件或全局面板中点击「禁用」是全系统生效的，会导致所有群聊都无法使用该能力；而在场景规则中取消勾选，仅针对当前这一个群生效。
:::

## 第五步：测试

在规则编辑页面右上角点击「保存」按钮，界面会提示保存成功，整个改动便已立刻生效，无需重启任何服务。

测试非常简单。你可以直接切到对应的聊天群里发一条消息，接着回到控制台打开左侧导航栏的「轨迹」页面：

- 在列表中找到刚才由你的测试消息触发的那一轮对话。
- 点开详情面板，确认实际调用的引擎、生效的预设以及模型名称是否与刚才配置的一致。
- 如果发现调用的参数不对，请顺着继承链检查是否有一条更具体的子规则覆盖了当前配置。

::: tip
遇到规则冲突时，系统始终遵循「具体目标优先」的继承原则。

判断权重上，「某个群」优先于「全局」，而「某个成员」又优先于「某个群」。同一层级的规则，系统会依次比对用户指定的优先级与创建时间。
:::

## 三个完整例子

为了方便大家参考，这里整理了三种最典型群聊的推荐配置组合：

### 技术群

- **引擎**：选择「对话」。
- **预设**：选用语气平实、回答客观、擅长技术解释的助手。
- **模型**：选用推理能力更强的高规格模型。
- **回复**：仅响应 @ 提及与称呼唤醒，关闭主动接话。
- **工具**：开放网页检索与本地文档读取，执行类命令需强制审批。

实际效果：日常保持安静，有问必答且逻辑严密，绝不抢话插话。

### 闲聊群

- **引擎**：选择「伪装」。
- **预设**：选用个性鲜明、有专属口癖的角色预设。
- **模型**：选择响应速度快、性价比高的中档模型即可。
- **回复**：开启气氛判断与主动搭话，初始插话频率保持低位。
- **工具**：仅开放表情包、点歌与搜图等轻量级能力。

实际效果：能捕捉群内聊天氛围自然接梗，偶尔主动打招呼，不惹人烦。

### 客服群

- **引擎**：选择「对话」。
- **预设**：选用礼貌周到、解答清晰规范的业务助理预设。
- **模型**：以稳定性和遵循指令能力优先，不盲目追求过大参数。
- **回复**：严格限定为明确提问触发，关闭全部主动式搭话。
- **工具**：仅放行业务相关的数据查询，写操作与命令执行全部屏蔽。
- **权限**：默认开启只读保护，敏感行为必须提交审批。

实际效果：行为严谨合规、全流程可审计，彻底杜绝越权风险。

## 规则怎么命名

当配置的群聊越来越多时，一套清晰的命名规范往往比配置本身更重要。这里分享几个实用建议：

- 规则名称建议包含群的功能特征或业务名，而不是单纯使用一串冰冷的群号。
- 如果当前规则包含特殊的覆盖逻辑，最好直接写在名字里，例如「客服群 - 禁用命令」。
- 暂时不用的规则建议切换为「停用」状态，而不是直接删除，日后需要时随时可以恢复。

::: tip
在「场景规则」页面中，你可以利用顶部的筛选器按目标和工作区分组浏览。先确立清晰的命名规范，再去批量添加规则，后续维护管理会倍感轻松。
:::

## 常见问题

**改了预设，群里却没有明显变化？**

请在规则编辑页面确认是否真正勾选了覆盖「预设」项；前往「预设」页面确认预设内容是否已成功保存；最后排查该群或当前用户是否被更具体的高优先级规则所接管。

**换了引擎，为什么群里的回复表现还是老样子？**

引擎配置通常在会话重新建立或切换时正式生效。若当前群正处于活跃的长对话上下文中，旧会话可能仍在沿用旧引擎，建议在群里发送重置指令开启一个新对话再做观察。

**模型已经换成了便宜型号，账单扣费为什么依然居高不下？**

请前往系统配置检查「模型角色」设置。意图判定、关键信息提取以及上下文摘要等后台任务使用的是专门的角色模型，并不受你在当前群规则里所选对话模型的影响。

**某个工具在特定群里找不到或者无法调用？**

请优先检查当前群的「场景规则 → 能力」列表中该工具是否已被取消勾选；如果这里勾选正常，请再检查全局工具管理页面是否在底层完全禁用了该工具。

**两个群明明配了完全相同的规则，为什么实际行为却截然不同？**

这通常是因为两者的上级继承来源不同，或者其中某个群里存在针对特定成员配置的更具体的个别规则，导致部分逻辑被更优先的规则悄悄覆盖了。
