# 多实例与多机器人

::: tip
本节介绍如何使用 ChatLuna CLI 管理多个独立运行的实例，以及如何权衡选择「多实例隔离」与「单实例内多账号/多平台」。
:::

## 方案选型：单实例还是多实例？

在部署多个机器人时，你可以根据数据隔离的需求选择合适的运行模式：

| 方案 | 适用场景 | 特点 |
| :--- | :--- | :--- |
| **单实例多机器人** | 同一账号在不同群组使用不同角色；或多个平台账号共享相同的会话、插件与配置体系。 | 仅需启动一个进程。通过接入多个平台适配器与账号，并配合[场景规则](../usage/rules)为不同群组/账号分流引擎与角色。 |
| **多实例独立运行** | 不同业务、不同所有者或完全隔离的环境；两个平台账号需要独立的配置、会话历史、记忆与凭据。 | 进程与目录完全隔离，互不干扰；需要为每个实例分配不同的服务端口。 |

## 创建与管理多实例

全局 `chatluna` CLI 会将所有实例集中存放在 `~/.chatluna/instances/` 目录下。每个实例都拥有完全独立的配置清单、数据目录与端口。

### 1. 创建新实例

使用 `chatluna create <name>` 命令创建实例：

```sh
# 创建名为 bot-a 的实例
chatluna create bot-a

# 创建名为 bot-b 的实例
chatluna create bot-b
```

### 2. 启动与查看实例

你可以单独启动指定的实例，或查看当前已有的所有实例：

```sh
# 启动指定实例
chatluna start bot-a
chatluna start bot-b

# 查看所有实例列表及其运行状态
chatluna list
```

如果运行 `chatluna start` 时未指定实例名称，CLI 会默认启动名为 `default` 的实例。若需要修改默认启动的目标，可以编辑全局配置文件 `~/.chatluna/config.yml`，修改其中的 `default` 键值：

```yaml
default: bot-a
```

## 配置实例端口避免冲突

::: warning
每个实例的 WebUI 默认都会尝试监听 `5028` 端口。如果同时启动多个实例且未修改端口，后启动的实例将因端口占用而启动失败。
:::

当需要同时运行多个实例时，你必须进入各个实例的清单文件，为 `chatluna-server` 显式指定不同的端口。例如将第二个实例的端口修改为 `5029`：

```yaml
chatluna-server:
  port: 5029
```

实例间的数据（包括记忆、会话、凭据与插件配置）在各自目录下独立存储，配置完成后即可并行运行且互不影响。
