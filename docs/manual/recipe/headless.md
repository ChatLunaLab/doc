# 无控制台运行

::: tip
这一页写给「只有终端」的场景：服务器、容器、CI，或者你就是不想开浏览器。ChatLuna 不依赖控制台也能完整跑起来。
:::

控制台很好用，但它不是必需品。

机器人真正需要的只有三样：一个能连上的聊天平台、一个能用的模型、一份配置。这三样都不需要通过浏览器设置。

以下场景适合无控制台运行：

- 部署在只开放 SSH 的服务器上。
- 跑在容器里，只映射了聊天平台的端口。
- 用脚本批量创建多个实例。
- 在 CI 里做冒烟测试。

## 第一次启动

用命令行启动实例后，注意看日志里的几行输出：

- 实例监听的端口。
- 自动生成的访问令牌。
- 带令牌的登录地址。

即使你不打算用浏览器，也建议把令牌抄下来——后面调试或者临时开控制台时用得到。

想固定令牌而不是用自动生成的，可以在启动前设置环境变量。

::: warning
控制台令牌是主人级别的权限。

在共享服务器上，注意日志文件的权限；把日志转发到外部平台时，先确认里面没有令牌。
:::

## 没有控制台怎么设主人

大多数管理能力都要求「主人」身份。控制台有绑定码，纯终端环境则可以直接在配置里指定。

配置里有一份主人列表，每一项写清楚平台、用户账号和一个方便辨认的名字。

填好之后重启实例，这个人就会以主人身份出现：可以发送管理指令、可以发起人设配置、可以审批高危操作。

::: tip
主人列表支持多个平台。

如果你同时接了 QQ 和 Discord，并且希望两边都是主人，就把两边的账号都写进去。漏掉一个，那边的指令就会一直提示权限不足。
:::

## 配置改在哪

无控制台运行时的所有配置，都在实例目录的文件里。

- **依赖清单**：这个实例装了哪些插件。
- **配置清单**：加载哪些插件、每个插件的配置。
- **数据目录**：会话、记忆、凭据等运行时数据。

修改方式就是编辑文件，然后重启（或者用命令行重启）。

几个实践建议：

- 改之前备份配置清单。
- 一次只改一处，改完重启验证，别攒一大堆改动一起上。
- 用诊断命令检查配置是否合法，比等启动失败再排查快。

::: warning
配置文件里的密钥字段是明文还是引用，取决于你的写法。

能加密保存的字段，优先用加密能力；实在要写明文，至少限制目录权限。
:::

## 环境变量

除了配置文件，有几个环境变量会影响启动行为：

- **令牌**：用来固定访问令牌，优先于自动生成。
- **允许远程访问**：在容器等场景下，需要它才允许外部访问控制台。
- **时区**：影响定时任务与日志时间。容器里默认往往是 UTC，配错时区会导致「早上八点的提醒在下午出现」。

::: tip
用容器部署时，时区是最容易被忽略的一项。

排查「定时任务时间不对」时，先确认容器的时区，再去看任务本身。
:::

## 用聊天指令管理

没有控制台，不代表没有管理手段。聊天里的管理指令照样可用：

- 查看状态、切换模型。
- 新建与停止对话、压缩上下文。
- 管理定时任务。
- 撤销文件修改。

审批也走聊天：需要确认的操作会以提问的形式发到会话里，回复编号即可。

所以，纯终端部署的日常操作其实很完整：平台侧负责交互，终端只负责启动和看日志。

## 日志与诊断

后台启动时，日志会写到实例对应的日志文件里。

诊断命令能检查安装、数据与配置的常见问题，也可以针对某个会话做一致性检查。

会话导出则可以把一整段会话日志导出成 JSONL，便于在本地分析或备份。

排查顺序建议是：先看启动日志，再跑诊断，最后再导出会话细看。

## 容器部署

容器是最常见的无控制台场景。

几个注意点：

- **数据要挂载出来**，否则容器重建就丢数据。
- **端口要映射**，至少映射 WebUI 端口；聊天平台是出站连接，通常不需要额外映射。
- **令牌通过环境变量注入**，不要烘焙进镜像。
- **时区显式设置**。
- **首启日志里找令牌**；如果用了固定令牌，就不会生成新的。

::: warning
不要给容器配置不必要的权限。

尤其是挂载 Docker 套接字这类操作——它等于把宿主机的控制权交出去。只有确实要用容器沙箱时才挂载。
:::

## 批量创建实例

用脚本创建多个实例时，可以指定模板来源、包管理器与目标目录。

创建完成后，逐个改端口、写配置、启动即可。

如果所有实例配置相同，创建好第一个之后复制它的配置文件，比每个都手写更快。

::: tip
批量部署时给实例起有规律的名字，比如带上业务和序号。

后期看日志、查进程、做备份时，命名规范能省掉很多对号入座的时间。
:::

## CI 里的冒烟测试

在 CI 中验证时，可以接一个本地假模型提供商。

它不产生真实调用、不需要密钥，但能完整走通消息链路：接收消息、匹配规则、生成回复、投递。

适合验证「这次改动有没有把启动搞坏」，不适合验证回答质量。

## 推荐配置

### 个人服务器

只开放 SSH，控制台只监听本机；需要时用 SSH 隧道访问。

令牌用环境变量固定，日志轮转打开。

### 容器化交付

每个客户一个容器、一个挂载目录、一个端口。

令牌随部署注入，时区随客户地区设置，配置清单随镜像版本管理。

### 纯聊天管理

不开控制台端口，只保留平台连接。

主人列表配好，日常全靠聊天指令，审批也在聊天里完成。

## 排查

**启动后连不上平台。**

先看日志里的适配器报错。常见原因是令牌错误、服务地址写错、容器网络无法出站。

**所有指令都提示权限不足。**

主人列表没配，或者平台账号写错了。确认平台标识与用户账号都与实际一致，然后重启。

**定时任务时间不对。**

时区问题。检查容器的时区设置与任务自身的时间设置。

**改了配置没生效。**

多数配置需要重启。少数设置可以在线生效，但纯终端环境下很难判断，统一用重启最稳。

**找不到访问令牌。**

自动生成的令牌只打印一次。找不回来就删除数据目录里的令牌文件再重启，会重新生成一个。

**诊断报配置错误。**

按报错里指出的插件与字段去改。改完再跑一次，直到通过为止。
