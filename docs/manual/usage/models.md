# 模型与提供商

::: tip
本节介绍如何在「提供商」页面接入模型服务，以及模型的目录、能力标记与计费统计如何组织。
:::

ChatLuna 把「怎么连上一个模型后端」和「这次对话用哪个模型」拆分为两个独立层级：

- **提供商 (Provider)**：负责网络连接、端点地址与凭据鉴权。
- **模型 (Model)**：归属于特定提供商目录，是具体任务中可被调度的实际条目。

## 安装提供商插件

部分提供商以独立插件的形式分发。

当你首次在系统中使用某种提供商类型时，插件市场会提示你安装对应的 provider 插件。完成安装后，刷新或返回「提供商」页面即可开始添加对应的实例。

## 添加提供商

前往「提供商」页面，点击「添加」按钮，选择你要接入的提供商类型：

- **OpenAI 兼容 (compatible)**：适用于绝大多数中转服务与本地自托管服务（如 vLLM、Ollama 等）。需要填写 `apiKey` 与 `baseURL`。
- **复合路由 (composite)**：允许在同一个提供商下挂载多条独立路由。每条路由可以配置独立的密钥与服务地址（例如将 chat、responses、anthropic、gemini 分别指向不同的服务后端）。
- **Azure / Vertex / Bedrock**：云厂商专用配置。除鉴权密钥外，还需要填写对应的资源名、区域或项目等字段。

配置完成后点击保存，该提供商即加入你的提供商目录。

## 配置 API 密钥与安全引用

在提供商的 `apiKey` 字段中，你可以采用以下两种方式配置凭据：

1. **多密钥轮换**：支持在 `apiKey` 中填入多个密钥，各密钥之间使用英文逗号分隔。当发起请求遇到上游限流或密钥失效时，系统会自动切换到下一个可用密钥重试。
2. **凭据库引用**：如果你不希望在表单配置中明文存放密钥，可以使用 `$credential` 形式引用凭据库中已保存的条目，避免明文落盘至配置文件。

::: warning
若将密钥明文直接保存在表单中，配置文件导出或备份时可能存在泄漏风险。生产环境下建议优先使用 `$credential` 形式引用凭据库。
:::

## 管理模型目录与能力标记

保存提供商后，模型列表可以通过以下两种方式生成：

- **远端发现**：由提供商接口自动拉取上游支持的模型列表。
- **手动声明**：在提供商条目中手动添加模型，并指定模型的元数据参数：
  - `contextWindow`：模型上下文窗口总大小。
  - `maxOutputTokens`：单次响应允许生成的最大 Token 数量。
  - `pricing`：模型的计费费率设置。

### 能力标记与用途分类

模型目录中的每个条目都具备能力标记与用途分类。除了常规的聊天补全 (Chat Completion) 之外，模型还可以承担以下专有角色：

- **图像生成**
- **嵌入 (Embedding)**
- **重排序 (Reranker)**
- **决策判定**：例如系统定时任务中的 `@decide` 判定逻辑，执行时明确要求指定一个具备决策能力标记的模型。

在为特定场景或自动化任务分配模型前，请确认所选模型在目录中已开启对应的能力标记。

## 配置用量与计费

如果为模型条目配置了 `pricing` 属性，系统将按调用记录计算费用：

- **费率结构**：支持为 `input`、`output` 以及 `cacheRead` 分别设置单价，并支持按调用量分档计费。
- **费用统计**：已配置价格的模型，「用量」页面会按次累计计算实际消耗成本；未填写价格的模型，「用量」页面仅统计消耗的 Token 数量。
- **数据一致性**：「用量」页面的统计口径与「轨迹」页面的单次运行调用记录保持完全一致。
