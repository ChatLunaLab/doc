# 模型与提供商

::: tip
提供商负责「怎么连上模型服务」，模型负责「这次用哪一个」。把这两件事分开，换模型时不用重配密钥，换服务时也不用改对话设置。
:::

ChatLuna 不内置任何模型，也不要求你只能用一个服务商。你可以同时接入多个提供商，给它们起不同的名字，再按场景、按角色、按任务选用不同的模型。

## 提供商

提供商 (Provider) 是一次具体的服务连接：一个端点、一组凭据、一份模型清单。同一个服务商可以接入多次，只要实例 ID 不同。

常见类型包括：

- **OpenAI**、**Anthropic**、**Google**、**DeepSeek**、**阿里云**等官方服务。
- **OpenRouter**、**Vercel AI Gateway** 这类聚合网关。
- **Azure OpenAI**、**Google Vertex AI**、**Amazon Bedrock** 等云厂商托管服务。
- **OpenAI 兼容**、**Gemini 兼容**、**Claude 兼容** 等自定义端点，适合中转服务、自托管服务和本地推理。
- **复合路由**：在一个提供商实例下挂多条路由，把不同的请求类型指向不同的后端。
- **Mock**：本地假模型，用于测试和演示，不产生真实调用。

### 添加提供商

在「提供商」页点击添加，选择类型，填写配置：

- **名称 / ID**：实例的唯一标识。多个同类型实例靠它区分。
- **端点地址**：服务的基础 URL。兼容类型通常需要手动填写。
- **API 密钥**：可以直接填，也可以用凭据引用。
- **模型清单**：部分类型会自动发现模型；部分类型需要手动填写模型 ID。
- **额外参数**：云厂商可能需要资源名、区域、项目 ID 等。

保存前可以测试连接。测试会验证密钥、端点和模型列表；通过后再保存，避免把一个连不上的实例写进配置。

### 凭据与多密钥

密钥有两种放法：

- **直接填写**：方便，但会出现在配置里。适合本地测试。
- **凭据引用**：配置里只保存一个引用，真实密钥存在凭据库。适合生产环境。

一个密钥字段可以放多个密钥，用逗号分隔。请求遇到限流或密钥失效时，系统会按顺序尝试下一个。轮换不等于无限重试；所有密钥都失败时，请求仍然会失败。

::: warning
不要把密钥写进截图、日志或公开的配置文件。使用凭据引用，并限制数据目录的访问权限。导出配置给他人排查时，先确认里面没有明文密钥。
:::

## 模型

模型属于某个提供商实例。一个模型至少有：

- **模型 ID**：服务端识别的名称，例如具体的版本号。
- **显示名称**：在界面上展示的名字。
- **能力**：支持哪些输入输出，例如文本、图片、音频、视频、文件；是否支持工具调用、结构化输出、推理。
- **上下文窗口**：一次请求最多能放多少 token。
- **价格**：输入、输出、缓存读写的单价，用于用量估算。
- **推理档位**：如果支持，模型会声明可选的低 / 中 / 高 / 关闭档位。

模型目录可以由插件自动拉取，也可以手动维护。自动目录不一定完整；遇到模型能力识别错误时，可以在模型详情里手动修正。

### 模型地址

在对话和规则里，模型用「提供商实例 ID : 模型 ID」表示。例如 `openai:gpt-4o-mini`。

这个地址出现在：

- 场景规则的「模型」。
- 会话的模型选择器。
- 模型角色。
- 子代理、判定、记忆提取等后台任务的配置。

地址里的提供商 ID 是实例 ID，不是你填的显示名称。改了实例 ID，引用它的地方也要一起改。

### 模型角色

除了给会话选一个主模型，系统还有几个「角色」：

- **小模型**：便宜的快速模型，用于判定、提取、摘要、标题等后台任务。
- **中模型**：比小模型强，用于子代理默认、复杂判定。
- **大模型**：最强，用于需要高质量输出的任务。
- **决策模型**：专门用于「要不要回复」「要不要批准」这类判断。

角色可以绑定到具体模型。没有绑定时会按「大 → 中 → 小 → 会话主模型」的顺序回退；决策模型通常回退到中模型。这样你只配一个主模型，后台任务也能跑起来。

角色在「提供商」页的「模型角色」标签里统一配置，不需要在每个场景规则里重复填。

### 视觉与多模态

模型的能力决定它能收到什么：

- 不支持图片的模型，图片会被替换成占位和文字描述。
- 不支持音频、视频或文件的模型，对应内容不会进入请求，只留引用和元信息。
- 支持工具调用的模型，才能使用工具体系；不支持时，工具会被隐藏或降级。

模型目录不认识的模型，系统通常会放宽限制，把内容都发过去；这可能失败，也可能被服务端忽略。遇到「模型说看不到图」时，先检查目录里的能力标记。

## 选模型的几种方式

模型可以按不同层级指定，优先级从高到低大致是：

1. **单次调用显式指定**：某次请求临时换模型。
2. **会话选择**：在聊天页或会话设置里选的模型。
3. **场景规则**：按群、按用户、按条件覆盖。
4. **引擎默认**：引擎自己的默认模型。
5. **全局默认**：所有地方都没指定时使用。

后一层会被前一层覆盖。排查「为什么用了这个模型」时，从高到低逐层看。

### 推理档位

支持推理的模型可以选思考深度：

- **低**：快，便宜，适合简单问题。
- **中**：平衡。
- **高**：慢，贵，适合复杂推理。
- **关闭**：不推理，直接回答。

可选档位由模型能力决定。路由层可以指定档位，但模型不支持时会降级或丢弃，并在日志里记录。

## 运行时增强

提供商之上还有一层可插拔的运行时能力，按需启用：

- **重试**：网络错误、限流、超时时自动重试，带退避。
- **回退**：主模型失败时切到备用模型。
- **缓存**：相同请求复用结果，减少重复调用。
- **预算**：按时间或会话限制花费，超过后拒绝或降级。
- **账本**：记录每次调用的用量和成本，供报表使用。
- **降级**：模型不支持某能力时，自动换一种表达方式。
- **分组**：把多个提供商/模型组合成一个逻辑入口，按策略选择。

这些能力默认不一定全部启用。它们会影响延迟、费用和失败行为；生产环境建议至少开启重试和用量记录。

## 首次配置

首次登录会进入设置向导，模型步骤会：

1. 让你选择提供商类型。
2. 填写密钥、端点，测试连接。
3. 选择默认模型。
4. 保存为提供商实例。

密钥保存在凭据库，不会进入聊天平台，也不会保存在浏览器的欢迎页草稿里。只有连接测试通过的实例才算「模型就绪」。

也可以跳过向导，稍后到「提供商」页手动添加；或者在没有 WebUI 的情况下，用本地覆盖配置预置提供商和默认模型。

## 推荐配置

### 个人使用

接一个主提供商，选一个通用对话模型作为主模型。小模型和决策模型绑定到同一家的便宜模型，减少跨服务商差异。开启重试和用量记录。

### 多服务商

按用途拆分：对话用一个服务商，判定和提取用另一个更便宜的，图片描述用支持视觉的。用模型角色把后台任务固定到便宜模型，避免它们偷偷用主模型。

### 本地 / 自托管

用兼容类型接本地推理服务，手动填模型 ID。关闭不必要的重试和回退，避免本地服务过载。注意上下文窗口通常比云模型小，压缩阈值要相应调低。

### 多群不同模型

在场景规则里按群覆盖模型。主模型仍然是全局默认，只有特定群用特殊模型。不要在每个群重复填完整提供商配置。

## 排查

**添加提供商时连接失败。**
检查端点地址、密钥、网络代理和模型清单。兼容类型的端点通常需要带 `/v1`；云厂商可能需要额外的区域或项目字段。

**模型列表是空的。**
有些服务不提供模型发现，需要手动填模型 ID。确认 ID 与服务端一致，大小写和版本号都不能错。

**回复报「模型不存在」。**
检查模型地址里的实例 ID 和模型 ID。实例 ID 是提供商页里的 ID，不是显示名称。

**图片发不出去。**
模型目录可能标记为不支持图片，或者场景规则里限制了图片数量。检查模型能力和群聊记录的图片设置。

**后台任务用了很贵的模型。**
检查模型角色绑定。没有绑定时，角色会回退到主模型；把判定、提取、标题绑定到小模型。

**切换模型后缓存不命中。**
模型是缓存前缀的一部分。频繁切换模型会让前缀失效；固定主模型，或用会话选择而不是全局切换。
