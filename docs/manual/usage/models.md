# 模型与提供商

::: tip
提供商负责「怎么连上模型服务」，模型负责「这次用哪一个」。把这两件事分开，换模型时不用重配密钥，换服务时也不用改对话设置。
:::

ChatLuna 本身不内置任何模型，也不限制你使用特定的 AI 服务商。你可以同时接入任意多个提供商，在控制台中为它们设置不同的名称以便区分，再根据聊天场景、角色或后台任务灵活选用不同的模型。

如果将模型与连接配置混在一起，每次更换模型都需要重新填写服务地址和 API 密钥；一旦服务商的接口地址变动，所有相关配置也都需要逐一修改。将两者解耦后，提供商只负责服务通信，模型则是提供商下的具体选项。日常切换模型时，无需重复配置连接参数。

## 提供商

提供商 (Provider) 代表一次具体的服务连接。配置好服务端点、访问凭据以及可用模型清单后，即构成一个提供商实例。

同一个服务商可以接入多次。例如你有两个不同的 OpenAI 账号，只需在添加时为它们指定不同的实例 ID，即可在系统中同时使用。

常见的提供商类型包括：

- **官方服务**：OpenAI、Anthropic、Google、DeepSeek、阿里云等厂商的官方原生接口。
- **聚合网关**：OpenRouter、Vercel AI Gateway 等聚合路由服务，使用单一账号即可调用多家模型。
- **云厂商托管服务**：Azure OpenAI、Google Vertex AI、Amazon Bedrock 等云厂商提供的托管服务。
- **兼容自定义端点**：OpenAI 兼容、Gemini 兼容、Claude 兼容等开放协议端点，适用于中转服务、自建代理和本地私有化部署。
- **复合路由**：在同一个提供商实例下挂载多条路由，将不同类型的请求分流至不同的后端。
- **Mock**：本地模拟模型，用于界面测试和流程演示，不会发起真实网络请求，也不产生调用费用。

### 添加提供商

前往「配置 → 提供商」页面，点击右上角的「添加提供商」按钮。在弹出的面板中选择你要接入的类型，并根据表单填写连接参数：

- **名称 / ID**：实例的唯一标识。如果接入了多个同类型服务，系统将通过此 ID 区分。
- **端点地址**：服务的基础接口 URL。对于兼容协议端点，通常需要补齐完整路径（例如以 `/v1` 结尾）。
- **API 密钥**：访问服务所需的凭据。可以直接填写，也可以使用凭据引用。
- **模型清单**：部分提供商支持自动获取模型列表；若服务不支持自动发现，需手动填入模型 ID。
- **额外参数**：云厂商托管服务通常还需填写部署区域、项目 ID 或资源名称等字段。

填写完成后，建议先点击表单底部的「测试连接」按钮。系统会向远端接口发送请求，验证端点地址是否可达、密钥是否有效以及模型列表能否正常获取。测试通过后，再点击「保存」按钮完成添加。这样可以避免将无效或错误的配置写入系统。

### 凭据与多密钥

填写 API 密钥时，系统支持两种方式：

- **直接填写**：密钥直接保存在实例配置中，适合本地调试或个人测试环境。
- **凭据引用**：配置项中仅记录凭据名称，敏感密钥存放在凭据库中。在多人协作或生产环境中推荐使用这种方式。

此外，为应对服务商的并发与频次限制，系统支持在同一密钥字段中填入多个密钥。多个密钥之间用英文半角逗号隔开即可。请求遇到限流或密钥失效时，系统会自动按顺序轮换并尝试下一个密钥。需要注意，当列表中的所有密钥均尝试失败后，请求仍会报错。

::: warning
不要把包含明文密钥的界面截图发到公开交流群，也不要把含有密钥的日志和配置文件随意分享。在导出配置请求他人协助排查时，请务必提前确认里面没有留下明文密钥。
:::

## 模型

模型隶属于具体的提供商实例。接入系统的每个模型都包含以下属性：

- **模型 ID**：服务端用来识别该模型的标识，例如官方版本号。
- **显示名称**：在控制台和聊天界面中展示的友好名称。
- **能力**：模型支持的内容格式与交互特性。包括输入与输出格式（文本、图片、音频、视频、文件），以及是否支持工具调用、结构化输出和深度推理。
- **上下文窗口**：单次请求允许的最大 Token 总量，决定了模型一次能读入的对话历史长度。
- **价格**：包含输入、输出以及上下文缓存读写的单价，用于实时估算调用成本。
- **推理档位**：若模型支持思考过程，会在此声明可选的推理深度，通常包括低、中、高以及关闭等档位。

模型目录可以通过插件自动获取，也可以在界面中手动维护。自动获取的信息若存在遗漏或偏差（例如支持识图的模型被错误标记为不支持图片），可以在模型列表中点击进入详情页，手动修改对应能力项并保存。

### 模型地址

在配置场景规则、分配任务或运行交互时，系统统一使用 `提供商实例 ID:模型 ID` 的格式定位模型。

例如 `openai:gpt-4o-mini`，表示使用实例 ID 为 `openai` 的提供商下的 `gpt-4o-mini` 模型。

该格式的模型地址会出现在以下位置：

- 「场景规则」页面中的「基本 → 模型」选项
- 聊天窗口顶部的模型下拉选择器
- 提供商管理页中的「模型角色」配置项
- 子代理调度、意图判定、记忆提取等后台任务的配置中

需要注意的是，冒号前面是提供商的「实例 ID」，而非显示名称。如果修改了某个实例的 ID，引用该旧 ID 的场景规则和角色配置不会自动更新，需要手动前往相应页面重新选择或更新模型地址。

### 模型角色

除日常对话使用的主模型外，系统还提供了「模型角色」机制。

在机器人的运行过程中，后台包含许多辅助任务（如提取用户画像、提取长期记忆、总结对话标题、判定当前是否在向机器人提问等）。如果所有后台任务都交由高规格的主模型处理，既会增加响应延迟，也会带来不必要的成本。

为此，系统预设了四个模型角色：

- **小模型**：轻量快捷，用于处理判定、信息提取、对话摘要、生成标题等轻量后台任务。
- **中模型**：性能与理解力介于小模型与大模型之间，适合作为通用子代理的默认模型，或处理较复杂的条件规划。
- **大模型**：综合能力最强，用于需要高质量文本生成和复杂逻辑论证的重度任务。
- **决策模型**：用于核心行为裁决，例如在群聊中实时判定是否需要回复，或高危操作是否允许执行。

你可以将每个角色分别绑定到具体的模型地址。

若未单独配置这些角色，系统会自动按以下规则回退：常规角色未绑定时，按「大模型 → 中模型 → 小模型 → 会话主模型」的顺序向下寻找可用模型；决策模型未绑定时，默认回退到中模型。因此，即使只配置了一个主模型，后台任务也能照常运行。

如需调整角色绑定，前往「配置 → 提供商」页面，切换到顶部的「模型角色」标签页。为各角色选定模型并保存后，设置将在全局生效，无需在每个群的场景规则中重复配置。

### 视觉与多模态

当用户在聊天中发送富媒体内容时，系统会根据目标模型的能力标记进行处理：

- **图片**：若当前模型不支持视觉识别，系统会自动移除图片，并替换为对应的占位提示与文字描述，避免远端接口报错。
- **音视频与文件**：若模型不支持音频、视频或文件解析，系统仅保留引用链接与元信息，不会将媒体文件本体传入请求。
- **工具调用**：仅在能力清单中明确支持工具调用的模型才能调用插件工具；不支持时，相关工具会自动隐藏或降级。

对于模型目录中未登记的新模型，系统默认会将富媒体内容按标准格式发送给服务端。这取决于服务端自身的兼容程度，请求可能会失败或被服务端忽略。若遇到机器人无法识别图片的情况，请先前往模型详情页确认该模型的视觉能力是否已被正确勾选。

## 选模型的几种方式

ChatLuna 允许你在不同层级上指定模型。当多处配置发生冲突时，系统按照以下优先级从高到低决定使用的模型：

1. **单次调用显式指定**：在特定指令触发或自动化脚本中临时指定的模型。
2. **会话选择**：聊天窗口顶部的模型切换器，或具体会话设置中手动指定的模型。
3. **场景规则**：「场景规则」页面中针对特定群聊、账号或用户配置的模型。
4. **引擎默认**：当前对话引擎自身设定的默认模型。
5. **全局默认**：未进行上述任何配置时的全局保底模型。

高优先级的配置会覆盖低优先级的配置。若发现机器人调用的模型不符合预期，可以按照上述顺序逐层排查配置覆盖情况。

### 推理档位

对于支持深度思考的推理模型，可以在调用时调节其思考深度。可选的推理档位如下：

- **低**：思考步骤精炼，响应更快，消耗 Token 较少，适合事实明确的简单咨询。
- **中**：兼顾推导深度与等待耗时，适合绝大多数日常综合任务。
- **高**：进行详细的多步逻辑推导，耗时较长且消耗更多 Token，适合复杂分析与代码难题。
- **关闭**：跳过思维链推理，直接输出最终答案。

可选档位取决于模型自身的能力声明。若模型不支持推理，设置的档位参数会被自动忽略或降级为默认行为，并在日志中记录，不会影响正常回复。

## 运行时增强

在基础的提供商连接之上，ChatLuna 还提供了可按需启用的「运行时增强」功能：

- **重试**：遇到网络波动、限流或请求超时时，按退避延迟自动重试。
- **回退**：主模型异常或连续报错时，自动切换至备用模型继续生成回复，保障服务不中断。
- **缓存**：复用完全相同的请求生成结果，减少重复调用与开销。
- **预算**：按天、按月或按会话设置开销上限，超额时拒绝请求或降级至低成本模型。
- **账本**：记录每次调用的输入输出 Token 数量与折算成本，便于在用量报表中查阅。
- **降级**：模型缺少某项关键能力时，自动使用兼容方案处理。
- **分组**：将多个提供商或模型组合为一个逻辑入口，按轮询或负载策略分流。

这些功能默认不会全部开启。过多的中间件可能会影响响应速度与成本控制。在生产或长期运行的环境中，建议至少开启「重试」与「账本」两项基础功能，兼顾稳定性与成本透明度。

## 首次配置

初次登录控制台时，系统会自动弹出「设置向导」。模型配置包含以下步骤：

1. 在列表中选择要接入的提供商类型。
2. 填写 API 密钥与端点地址，点击「测试连接」确认通信正常。
3. 从获取到的模型列表中，选择一个作为全局默认主模型。
4. 确认配置无误后点击提交，完成首个提供商实例的添加。

向导中填写的 API 密钥会安全保存至凭据库中。只有连接测试通过的实例，系统才会判定为「就绪」状态，机器人也才能正式对外提供对话服务。

如果跳过了向导，可以随时前往「配置 → 提供商」页面手动添加。在无法使用 Web 界面的命令行或容器环境中，也可以通过配置文件预设提供商和默认模型。

## 推荐配置

这里列举了几种常见场景下的配置建议：

### 个人使用

接入一家主流大厂提供商，选择综合性价比高的通用对话模型作为全局主模型。

将后台的「小模型」与「决策模型」绑定至同一提供商旗下的经济型模型，既能减少跨服务商调用带来的延迟，又能保证输出风格连贯。同时建议在运行时增强中开启「重试」与「账本」功能。

### 多服务商

根据不同服务商的特长进行分工：

- **日常对话**：选用响应速度快、理解能力好的主力模型。
- **后台任务**：在「模型角色」中将信息提取、意图判定等绑定至单价极低的轻量模型，避免消耗昂贵的主力模型额度。
- **富媒体场景**：通过规则将包含图片的会话定向路由至擅长多模态识别的提供商。

### 本地 / 自托管

通过「OpenAI 兼容」等通用类型连接本地运行的私有化推理引擎（如 Ollama、LocalAI 或 vLLM），并在模型列表中手动补全模型 ID。

受本地显卡算力限制，建议关闭频繁重试与自动回退，防止高并发流量导致本地服务过载。此外，本地模型的上下文窗口通常比云端模型小得多，可以在高级设置中适当调低对话压缩阈值。

### 多群不同模型

管理多个不同属性的群聊时，推荐通过「场景规则」分别配置：

全局默认模型保持为通用的经济型模型，仅在重点群聊的场景规则中将模型覆盖为高性能模型。无需在每个群聊中重复配置提供商，只需在规则中按需选择模型地址即可。

## 排查

遇到问题时，可以对照以下情况排查：

**添加提供商时连接失败**
检查端点地址、API 密钥是否准确，以及网络代理配置是否妥当。若使用兼容协议端点，确认端点地址末尾是否包含版本路径（如 `/v1`）；若连接云厂商托管服务，检查区域或项目 ID 等必填参数是否已填写。

**模型列表为空**
部分中转服务商或本地端点不支持自动获取模型列表。在提供商配置面板的「模型清单」中手动输入服务端实际的模型 ID 即可，注意大小写与版本后缀需完全一致。

**回复报错「模型不存在」**
通常由模型地址格式错误或引用了无效 ID 导致。检查模型地址中冒号左侧是否为提供商的「实例 ID」（而非显示名称）。若修改过该实例的 ID，需前往对应页面重新选择模型。

**无法识别图片**
若机器人无法接收或识别图片，可能是该模型在模型目录中未勾选视觉能力，或是当前会话的场景规则中限制了接收图片。请前往模型详情页确认视觉能力是否开启，并检查场景规则中的图片相关设置。

**后台任务使用了高成本模型**
前往「配置 → 提供商」的「模型角色」检查绑定情况。若小模型或决策模型未单独指定，系统会自动回退至当前会话的主模型；若主模型规格较高，会产生意外开销。建议将这些角色明确绑定至轻量模型。

**切换模型后缓存未命中**
系统构建上下文缓存时，会将模型标识作为缓存键前缀的一部分。频繁切换模型会导致旧缓存失效并重新计算。建议尽量固定使用一个主模型，或仅在特定独立会话中选用新模型。
