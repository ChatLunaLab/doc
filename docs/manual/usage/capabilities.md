# 工具、技能与 MCP

::: tip
这一页只是概念总览：说清工具、技能与 MCP 各自的职责、它们如何汇成同一份工具清单，以及具体的操作细节在哪里。实际配置请前往各自的专题页面。
:::

## 三者的分工

三个概念在控制台里挨在一起，在对话里也常常同时出现，但职责完全不同：

- **工具**是动作，回答「能做什么」；
- **技能**是方法，回答「按什么步骤做」；
- **MCP** 是通道，回答「外部能力怎么接进来」。

<!-- 截图占位：能力分组 · 工具/技能/MCP 三个页面入口 -->

### 工具

工具是模型可以直接调用的动作，每个工具都有明确的名字、参数与返回值。读写文件、执行命令、联网搜索、发送消息，在 ChatLuna 内部都是工具。

每一轮对话开始时，系统会整理一份工具清单交给模型；模型判断需要某项能力时就发起调用，系统执行后把结果反馈回去。工具是能力体系里的**执行层**。

### 技能

技能是写给模型阅读的操作说明。多步任务往往不是一次调用能完成的，例如修一个 Bug 需要先看环境、再按顺序改文件、最后跑测试；这时光有工具还不够，模型还需要知道在什么时机按什么顺序使用它们。

技能的正文不会常驻上下文：模型平时只看到一行简介，命中之后才加载全文。技能是能力体系里的**知识层**。

### MCP

MCP（Model Context Protocol）是连接外部系统的通用协议。已有系统只要支持 MCP，就不必为 ChatLuna 重写插件，接进来之后它的能力会像内置工具一样出现在工具清单里。

MCP 是能力体系里的**接入层**。

## 三者如何汇合

不管来自哪里，三者的最终形态都是模型可调用的工具：

- 工具插件直接注册工具；
- 技能可以自带随附的脚本工具，也可以指导模型组合调用现有工具；
- MCP 服务把远端能力投射进来，名称通常带有服务前缀以避免冲突。

模型拿到的是一张扁平清单，不需要区分某个工具来自本地插件还是远端服务。

## 怎么选

- **只是要调用一个外部 HTTP 接口或云端服务**：先找现成的 MCP 服务，能接入就不必写插件。
- **要让模型掌握一套固定的操作流程**：编写技能，比在系统提示词里长篇描述更省上下文。
- **要让模型在本机或远程机器上执行命令、读写文件**：使用内置工具，并配合机器管理把执行环境限定在受控范围内。
