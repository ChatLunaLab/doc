# 工具、技能与 MCP

::: tip
本节是概念总览，主要介绍工具、技能与 MCP 各自的职责，它们如何汇总为同一份工具清单，以及对应的配置指引。具体操作请前往各自的专题页面。
:::

## 三者的分工

这三个概念在控制台和对话交互中经常同时出现，但职责完全不同：

- **工具**是具体的动作，回答「能做什么」；
- **技能**是操作的指南，回答「按什么步骤做」；
- **MCP** 是连接的通道，回答「外部能力怎么接进来」。

![能力分组 · 工具/技能/MCP 入口](/webui/tools.png)

### 工具

工具是模型可以直接调用的动作。每个工具都有明确的名称、参数与返回值。在 ChatLuna 中，读写文件、执行命令、联网搜索或发送消息等操作都是工具。

每轮对话开始时，系统会整理一份可用工具清单提供给模型。当模型判断需要某项能力时便会发起调用，系统执行完成后再把结果反馈给模型。工具构成了能力体系里的**执行层**。

### 技能

技能是提供给模型阅读的操作说明。复杂的多步任务往往无法通过一次工具调用完成。例如修复一个 Bug 时，通常需要先检查环境，再依次修改文件，最后运行测试；此时仅有工具还不够，模型还需要知道在什么时机、按什么顺序来调用它们。

技能的正文不会常驻上下文：平时模型只会读取一行简要说明，只有在命中相关场景后才会加载全文。技能构成了能力体系里的**知识层**。

### MCP

MCP（Model Context Protocol）是连接外部系统的通用协议。现有系统只要支持 MCP，就无需专门为 ChatLuna 重新编写插件。接入完成后，其提供的能力会像内置工具一样直接出现在工具清单中。

MCP 构成了能力体系里的**接入层**。

## 三者如何汇合

无论能力来自哪里，最终都会汇总为模型可调用的工具：

- 工具插件可以直接注册工具；
- 技能可以自带随附的脚本工具，也可以指导模型组合调用现有工具；
- MCP 服务将远端能力映射到本地，工具名称通常会带有服务前缀，避免产生命名冲突。

最终呈现给模型的是一张扁平清单，模型调用时无需关心某个工具来自本地插件还是远端服务。

## 怎么选

- **调用外部 HTTP 接口或云端服务**：优先寻找现成的 MCP 服务，直接接入即可，无需自行编写插件。
- **让模型掌握一套固定的操作流程**：编写技能。相比在系统提示词中长篇描述，编写技能更节省上下文空间。
- **让模型在本地或远程机器上执行命令、读写文件**：使用内置工具，并配合机器管理将执行环境限制在受控范围内。
