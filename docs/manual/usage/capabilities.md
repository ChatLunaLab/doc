# 工具、技能与 MCP

::: tip
这一页是个总览：工具、技能、MCP 分别解决什么问题，三者怎么配合，以及它们共用哪一套安全规则。具体操作在各自的分页里。
:::

刚开始接触 ChatLuna 时，很容易把这三个词混在一起。它们经常同时出现，界面上也挨得很近，但职责完全不同。

可以先记住一句话：

- **工具**是动作，解决「能做什么」。
- **技能**是方法，解决「具体怎么做」。
- **MCP** 是通道，解决「外面的能力怎么接进来」。

## 三者各自是什么

### 工具

工具是模型可以直接调用的动作，每一个都有明确的名字、参数和返回值。

读文件、写文件、执行命令、搜网页、查数据库、发消息——这些都是工具。

模型在每一轮对话里会拿到一份工具清单，清单里写着每个工具做什么、需要什么参数。它判断需要某个能力时，就发起调用，系统执行完把结果还给它。

所以工具是「执行层」。

### 技能

技能是写给模型看的说明书。

有些任务不是一步能做完的：先查环境，再按顺序改几个文件，最后跑一次验证。这种事光有工具不够，模型还需要知道「按什么顺序用哪个工具」。

技能就是把这套方法写下来，需要的时候加载。

它的好处是不会一直占着上下文：平时模型只看到技能目录里的一句话简介，真正需要时才读取正文。

所以技能是「知识层」。

### MCP

MCP 是一个开放协议，用来连接外部服务。

如果你手头已经有一个现成的服务，比如 GitHub 客户端、数据库查询工具、公司内部系统，没必要为它单独写插件。只要它支持 MCP，就能以统一的方式接进来。

接入之后，外部工具会出现在 ChatLuna 的工具清单里，模型用起来和本地工具没有区别。

所以 MCP 是「接入层」。

## 它们怎么汇到一起

三者的最终形态是同一个东西：**模型可调用的工具**。

- 工具插件直接注册工具。
- 技能可以带自己的脚本工具，也可以指导模型使用别的工具。
- MCP 服务把自己的工具投影进来，名字前面加统一前缀，避免冲突。

到了模型那里，不会区分「这个工具是内置的还是外部的」。它只看到一份清单，清单里的每一项都能调用。

这也是权限体系能统一生效的原因：不管工具从哪来，执行前都要过同一道检查。

## 模型能看到什么

工具越多，上下文压力越大。所以系统对「模型能看到什么」做了分层。

一层是**能不能用**：插件自己的限制、场景规则的允许与禁用、工具页的禁用状态，会先把一批工具排除掉。

另一层是**什么时候看到**：即使在可用范围里，工具也不一定全部塞进提示词。

- **常驻工具**：完整说明一直在提示词里，随时可调。
- **按需工具**：提示词里只有名字和一句话说明，模型先搜索，再拿到完整参数。

工具特别多的时候，第二层能省下大量上下文。这也是 MCP 工具默认走按需加载的原因。

::: tip
如果你发现模型「不知道有某个工具」，先确认它是不是被按需加载了，而模型这一轮还没有搜索。
:::

## 安全规则是共用的

无论工具来自哪里，都会经过同一套治理：

- **工具策略**：每个工具可以单独设为自动执行、需要审批或禁用。
- **场景规则**：不同的群、不同的人，可以开放不同的工具范围。
- **权限模式**：全局的只读、文件、自动、放行四档，决定高危动作的处理方式。
- **等级**：用户自身的权限等级，决定他能不能触发敏感操作。

所以 MCP 服务不需要自己实现权限——它只负责提供能力，要不要放行由 ChatLuna 决定。

反过来说，接入一个能力很强的 MCP 服务，风险也不会凭空变大，前提是你在工具页和场景规则里做了限制。

## 怎么选

不是每个需求都要三样一起上。可以按这个顺序判断：

**只是调用一个外部 HTTP 接口？**
先看看有没有现成的 MCP 服务，有就直接接，省得写代码。

**需要一套固定的操作流程？**
写技能。把步骤写清楚，比在提示词里堆说明更省上下文。

**需要在本机或远程执行命令、读写文件？**
用内置的工具，配合机器（执行环境）来限定范围。

**需要模型自己组合多个动作完成任务？**
这时候才需要同时用到工具和技能，甚至开启工具搜索或代码调用模式。

## 常见误解

**「装了技能就自动有工具了。」**
不一定。技能主要提供方法和脚本，真正执行还是要落到工具上。少数技能会带自己的工具入口，但不是所有技能都这样。

**「MCP 装得越多越好。」**
不是。每个服务都会带来一批工具和一份上下文成本。不用的服务及时停用，比留着吃灰划算。

**「工具禁用等于卸载。」**
不是。禁用只是对模型隐藏，插件本身还在运行，随时可以恢复。

**「需要审批的工具很麻烦，干脆全放开。」**
审批挡住的是模型误判，不是正常使用。如果某个工具天天需要审批又天天允许，把它改成自动更合理；如果它总是被拒绝，说明这个场景本就不该开放它。

## 推荐起点

如果你刚开始配置：

1. 先把工具页过一遍，把命令执行、文件写入这类工具设成需要审批。
2. 装一两个常用的 MCP 服务，把它们的工具保持按需加载。
3. 暂时不写技能，等真的出现「模型总是搞错步骤」的问题时再考虑。

加得太快，反而分不清是哪里出的问题。
