# 工具、技能与 MCP

::: tip
本节是概念总览：工具、技能和 MCP 各自负责什么，以及它们怎样汇成同一份工具清单。具体操作请看各自的专题页。
:::

## 三者的分工

- **工具**是动作，回答「能做什么」。
- **技能**是指南，回答「按什么步骤做」。
- **MCP** 是通道，回答「外部能力怎么接进来」。

![能力分组 · 工具/技能/MCP 入口](/webui/tools.png)

**工具**是模型可以直接调用的动作，有明确的名称、参数和返回值，例如读写文件、执行命令、联网搜索、发送消息。每轮对话开始时，系统把可用工具清单提供给模型，模型需要时发起调用，系统执行后把结果返回。

**技能**是给模型阅读的操作说明。修复一个 Bug 往往要先检查环境、再改文件、最后跑测试，光有工具不够，模型还要知道什么时候、按什么顺序调用它们。技能正文不会常驻上下文，平时模型只看到一行简介，命中相关场景时才加载全文。

**MCP**（Model Context Protocol）是连接外部系统的通用协议。只要现有系统支持 MCP，就不必为 ChatLuna 重新写插件，接入后它的能力会直接出现在工具清单中。

## 三者如何汇合

无论来自哪里，最终都会变成模型可以调用的工具：

- 工具插件直接注册工具。
- 技能可以自带脚本工具，也可以指导模型组合现有工具。
- MCP 服务把远端能力映射为本地工具，名称带有服务前缀以避免冲突。

模型看到的是一张扁平的清单，不需要关心某个工具来自本地插件还是远端服务。

## 怎么选

- **调用外部接口或云服务**：先找现成的 MCP 服务直接接入。
- **让模型掌握一套固定流程**：写成技能，比在系统提示词中长篇描述更省上下文。
- **在本地或远程机器上执行命令、读写文件**：使用内置工具，并通过机器管理把执行环境限制在受控范围内。
