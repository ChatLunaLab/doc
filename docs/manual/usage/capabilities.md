# 工具、技能与 MCP

::: tip
本节介绍 Harness 的三类能力扩展机制：工具 (Tool)、技能 (Skill) 与模型上下文协议 (Model Context Protocol, MCP) 服务器，以及它们如何汇入模型上下文并由统一权限体系管控。
:::

工具是模型可以直接调用的可执行动作；技能是按需加载的专长说明；MCP 则用于将外部服务提供的工具投影进同一个工具体系。三者最终统一注册到 Agent 的工具集中，接受权限系统的统一策略检查与用户批准管线。

## 查看与管理工具

前往「工具」页面，你可以查看当前实例中已注册的所有工具。

### 内置工具家族

系统内置了以下工具家族模块：

- **文件 (`tool-fs`)**：读取、修改与管理工作区文件。
- **命令 (`tool-bash`)**：在环境中执行 Shell 命令。
- **代码 (`tool-code`)**：执行与分析代码相关操作。
- **检索 (`tool-search`)**：执行联网搜索或本地检索。
- **配置、插件与运行时 (`tool-config` / `tool-plugins` / `tool-runtime`)**：查看与管理实例自身的运行状态、插件生命周期与配置项。

### 控制策略与批准机制

你可以对工具进行整体停用或按名称过滤：

- **禁用工具**：通过 `tool-policy` 的 `disabled` 配置列表，填入需要禁用的工具名称，即可禁止模型调用对应工具。
- **需要批准**：对于高风险工具，可以将其标记为「需要批准」。当模型尝试调用这些工具（例如 `bash` 或 `session_reference_list`）时，系统会暂停执行并等待用户显式确认。

::: warning
将敏感工具从批准列表中移除或移出 `disabled` 策略时需格外谨慎。例如未加限制的 `bash` 执行可能导致宿主或工作区环境中的数据被非预期修改。
:::

### 开启工具检索模式

当注册的工具数量庞大时，将所有工具的完整 JSON Schema 注入提示词会消耗大量上下文窗口。

启用 `tool-search` 模式后，系统仅向模型提供工具列表的摘要。当模型需要调用特定功能时，会先通过 `search` 工具检索并拉取目标工具的完整定义，从而在不损失能力的前提下显著降低上下文占用。

## 管理与加载技能

技能 (Skill) 是用于教会模型执行特定复杂任务的指导文档，每个技能以专用的 `SKILL.md` 文件存在。

### 技能目录来源

前往「技能」页面，你可以管理技能目录。系统支持从以下三类位置加载技能：

1. **宿主机目录**：本地宿主机文件系统上指定的技能路径。
2. **工作区目录**：当前工作区项目内置的技能定义。
3. **内置目录**：系统预设的基础技能集合。

### 动态加载机制

为了避免无谓占用模型的上下文长度，技能采用延迟加载策略：

1. 初始化时，模型仅在系统提示中接收技能目录列表（仅包含各技能的名称与简要介绍）。
2. 当任务触发特定专长时，模型按需调用对应技能，将其 `SKILL.md` 正文读入上下文。
3. 未被触发的技能正文不会进入提示词。

## 接入 MCP 服务器

前往「MCP」页面，你可以配置并接入外部的 MCP 服务器。

系统支持两种接入传输协议：

- **stdio**：通过本地子进程的标准输入输出进行通信。
- **HTTP**：通过远程 HTTP 服务进行连接。

### 命名空间与权限投影

外部 MCP 服务器连接成功后，其暴露的工具会自动投影至全局工具体系中，命名遵循统一格式：

```
mcp__<服务器>__<工具>
```

投影生成的 MCP 工具会自动接入现有工具管线，与普通内置工具一样受 `tool-policy` 策略限制，并支持配置用户批准确认，无需针对外部服务编写额外的适配代码。

::: tip
所有接入的 MCP 工具均在「工具」页面中统一列出，你可以像配置内置工具一样对其应用禁用或审批策略。
:::
