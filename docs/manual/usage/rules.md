# 场景规则

::: tip
场景规则决定了机器人「在什么场合、对谁、用什么方式说话」。同一个机器人，可以在 A 群扮演活泼的角色、在 B 群只严肃回答问题、在某个私聊里保持安静——这些都不需要部署多份实例，只需要几条简单的规则就能搞定。
:::

当机器人加入不同的群聊，或需要同时在群聊与私聊中提供服务时，不同场景下的需求往往截然不同。有的群希望它扮演活泼的角色，有的群只希望它严肃回答技术问题，而在私聊中，你可能只希望它安安静静充当笔记助手。

如果为每个群都单独运行一套程序或复制一份配置，不仅维护成本高，而且容易改错。ChatLuna 提供了「场景规则」机制，核心思路是**将默认行为与特殊情况分开处理**：先为机器人配置一套通用的全局设置，再在需要特殊对待的群聊或私聊中单独覆盖个别配置项。

每当机器人收到消息时，系统会自动匹配适用的规则，并按照从通用到特殊的顺序逐层叠加，计算出当前会话所需的完整配置。把机器人加入新群时，你无需重新配置整套流程，只需设置该群的差异项即可。

## 先认识页面

进入控制台，在侧边栏点击「配置」→「场景规则」，即可进入规则管理页面。

页面的界面主要分为三个区域：
- **顶部目标选择器**：选择当前正在配置的目标，默认为「全局」。
- **右上角保存按钮**：保存并提交当前修改的所有配置。
- **中间的配置标签页**：按功能分类归纳的各项设置，每一项均可单独决定是否覆盖。

### 目标选择器

目标选择器用于指定规则的生效范围。点击顶部的下拉菜单，可以选择不同的范围：

- **全局**：所有消息的默认配置底座。未单独配置特殊规则的群聊或用户均会默认采用此处的设定。
- **机器人**：针对某个平台上的具体机器人账号生效。当实例同时登录了多个账号（例如同时登录 QQ 与 Telegram）时，可在此区分账号维度的差异。
- **群聊**：仅对指定的某一个群聊生效，也是日常使用中最常用的范围。
- **私聊用户**：仅对某个特定用户的私聊生效，不影响该用户在群聊中的交互，也不影响其他人的私聊。
- **群成员**：仅对某个群内的指定成员生效。该范围最具体，适合用来给群主或管理员单独开放权限。

选择目标后，页面右侧会即时显示「设好的规则」摘要卡片。

卡片会以易懂的语言说明当前规则的生效条件。例如选中某个群聊时，卡片会提示类似「在群 123456 中，同时满足：平台是 onebot」。若配置了互相冲突的条件（例如一条规则同时限定为群聊与私聊），卡片会标红提示冲突项并给出修改建议，方便在保存前排查问题。

### 标签页

选定目标后，中间区域会展示该目标下的各项设置。配置项按功能划分为以下标签页：

- **基本**：基础对话设置，包括用途（决定由哪个引擎处理消息）、模型、思考深度以及预设人设。
- **回复**：管理机器人的回复时机，包括触发条件、连续多条消息的合并策略、群聊记录留存与主动搭话等。
- **能力**：管理机器人可以调用的扩展功能，包括工具、技能、子代理、长期记忆与控制台指令。
- **安全**：管理权限与安全合规策略，包括权限等级、执行环境与消息审核规则。
- **高级**：底层参数微调，例如聊天记录切分方式、机器人自身发送的消息是否计入历史、回复显示格式与对话压缩机制。
- **引擎专属标签页**：在「基本」标签页中将「用途」切换为「伪装」等特定引擎时，页面会自动出现对应的专属标签页，供你调整作息、心情、动作或思考方式等专属细节。

界面的标签页是动态变化的。当安装了新的扩展插件，或将「用途」切换为其他引擎时，相关设置项会自动出现或隐藏，无需手动刷新页面。

## 继承与覆盖

在场景规则中配置各项参数时，核心机制是「继承」与「覆盖」。

在顶部选好目标后，找到想要修改的项目直接填入新值，即可完成一次覆盖；未修改的项保持原样，继续沿用外层的设定。若配置有误，点击字段右上角菜单中的「恢复默认」，即可让该字段重新继承上层设定；点击「放弃修改」则可将整块表单恢复到打开时的状态。

之所以采用这种机制，是为了降低后续的维护成本。如果为每个群都保存一份包含几十个字段的完整副本，一旦更换模型或微调全局人设，就必须逐个进入所有群聊手动修改。而在「继承与覆盖」机制下，每个字段只有两种状态：

- **继承**：当前字段不设置独立的值，直接沿用更外层（通常是全局）的设定。
- **覆盖**：为当前目标显式指定一个独立的新值。

只有被显式修改过的字段，才会真正保存在当前规则中。其余保持继承的字段，在全局配置更新时会自动同步。

::: tip
覆盖是「按字段」生效的，而不是「按页面」生效。例如在技术交流群中，你只需修改「模型」和「人设」两项，其余的工具、权限、记忆等设置依然会继承全局设定。点击保存时，页面还会提示哪些改动「只影响新会话」，哪些改动能够「即时生效」。
:::

例如：你在全局设置中将模型设为基础对话模型，人设为「智能助理」，并开启了网页搜索工具。现在你想在「内部测试群」中试用最新的推理模型，但希望人设和搜索工具依然与全局保持一致。此时只需在目标选择器中选中「内部测试群」，在「基本」标签页中将「模型」改为专属的推理模型并保存即可。后续全局更新人设台词时，测试群会自动同步更新，而模型依然会锁定为测试群专属的推理模型。

### 保存与冲突

修改完配置并点击右上角「保存」时，系统会在后台校验当前规则的版本，确认在你编辑期间是否有其他管理员修改了同一目标的规则。

若打开页面后停留较久，期间他人已保存了新的修改，当前页面会弹出保存冲突提示并阻止直接覆盖。此时需要先刷新页面获取最新配置，再重新修改保存。这可以避免在多人协作或打开多个标签页时不小心覆盖他人的修改。

规则保存成功后会立即生效，留在当前页面的用户无需手动刷新。若此时其他管理员正在编辑同一条规则，对方在提交时同样会受到版本冲突机制的保护。

## 多条规则怎么叠

当一条消息同时符合多条规则时，系统会按照「越具体越优先」的原则将规则逐层叠加，后叠加的配置会覆盖先前的同名字段。

在实际使用中，通常只需按层级配置规则：通用设定写在「全局」，群专属设定写在「群聊」，个人特殊权限写在「群成员」。系统会自动将它们层层叠加，计算出最终的生效值。

规则的合并与叠加遵循以下顺序：

1. **全局规则在最底层**：作为所有会话的通用基础。
2. **条件越具体的规则越靠后**：叠加链条中越靠后的规则覆盖力越强。
3. **具体程度相同时，优先级数值大的靠后**：数值更高的规则后叠加。
4. **优先级相同时，创建较早的靠前**：若依然相同，则按照规则内部标识确定先后。

这里的「具体」是指条件的范围类型：
- 限定了具体群号的「群聊」规则，比仅限定平台的「机器人」规则更具体；
- 同时限定了群号与特定用户的「群成员」规则，比单纯限定群号的「群聊」规则更具体。

::: warning
不要试图使用「优先级」去表达本该由条件范围表达的关系。优先级主要用于微调同一层级内多条规则的先后顺序，不适合用来替代「群聊 → 群成员」这种天然存在的范围层级。
:::

若规则中的条件产生冲突（例如在同一条规则中同时勾选「私聊」与「群聊」，或将群号限定为两个不同的群），右侧规则摘要会将冲突项标红。存在冲突的规则将无法匹配任何消息，保存前请根据提示修正条件。

**示例**：
- 全局规则中，人设统一设为「默认助手」。
- 在「日常交流群」中添加一条规则，将人设覆盖为「群管家」。
- 为该群群主单独配置一条群成员规则，将人设覆盖为「私人秘书」。

当普通群员在群内呼叫机器人时，系统命中全局与群聊两条规则，叠加后生效的人设为「群管家」；当群主在群内呼叫机器人时，三条规则全部被命中，群成员规则排在最后生效，机器人将以「私人秘书」的人设回应群主。

## 每个群单独配置

为了高效管理多个群聊，推荐按以下步骤进行配置：

1. **配置全局基础**：在目标选择器中选择「全局」，配置适合大多数场景的通用用途、主流模型以及默认人设。
2. **选中目标修改差异项**：在目标选择器中切换到目标群聊，仅修改需要与全局不同的字段。
3. **按需切换工作引擎**：若该群需要执行完全不同的任务，可将「用途」切换为其他引擎，并在新出现的引擎专属标签页中微调细节。
4. **发送消息验证效果**：保存规则后，直接在该群发送消息测试。你可以在规则摘要和控制台的轨迹页面中查看实际命中的规则链条。

以下是几个最常见的配置场景与操作步骤：

### 给某个群换人设

若希望某个特定群聊使用专属的人格预设：

1. 在顶部目标选择器中选择「群聊」，并选定目标群。
2. 切换到「基本」标签页，找到「人设」选项。
3. 将「人设」修改为所需的预设角色，点击右上角「保存」即可。

保存后，该群会使用专属人设与群友互动，其他群聊和私聊依然保持全局设定不变。若新预设依赖状态、人物经历、作息等角色引擎能力，记得将「用途」修改为「伪装」，并在新出现的伪装标签页中确认各项配置。

例如：在「动漫同好交流群」中将人设覆盖为特定角色预设，并将用途改为「伪装」；而「技术讨论群」依然继承全局的严肃工程师人设。

### 让某个群完全沉默

若希望机器人在特定群聊中不作任何回复，但仍保留记录或方便后续随时恢复：

1. 在目标选择器中选定目标「群聊」。
2. 进入「基本」标签页，找到「用途」设置项。
3. 将「用途」改为「不回复」，点击「保存」即可。

相比直接将机器人移出群聊，这种方式更轻量，且能保留记录与随时恢复的能力（具体行为取决于「群聊记录」中的设置）。后续若需重新唤醒机器人，只需将用途重新切回对话引擎即可。

例如：群聊即将举办线上活动，期间不希望机器人答疑。可提前将该群用途覆盖为「不回复」；活动结束后切回原本引擎，即可恢复日常互动。

### 只让某个群用某个模型

若某个群聊对生成质量有较高要求，需要单独调用高规格模型，同时避免在其他群产生额外开销：

1. 在目标选择器中选中目标「群聊」。
2. 进入「基本」标签页，找到「模型」设置项。
3. 在下拉列表中选择专用模型，点击「保存」即可。

下拉列表中的模型来自「提供商」页面中已配置好的模型。若列表中未找到所需模型，请先前往「提供商」页面添加，再返回此处配置。

例如：日常闲聊群统一继承全局的高性价比模型；涉及复杂代码讨论的「技术攻坚群」则单独覆盖为推理能力更强的高规格模型。

### 群里只对某个人开放

若希望将高权限操作或进阶能力仅向群主、管理员或测试人员开放，对普通群员保持限制：

1. 在顶部目标选择器中将目标类型切换为「群成员」。
2. 依次指定对应的群聊和目标成员。
3. 按需修改「人设」「模型」或「权限」等选项，调整完成后保存即可。

在规则叠加机制中，更具体的群成员规则优先级高于普通群聊规则。群内普通成员仍按群聊规则运行，而该成员发送消息时会匹配专属的高优先级规则。

例如：在大型公共交流群中，群聊规则的权限设为只读；同时为管理员单独添加一条群成员规则，将权限覆盖为完全放行，允许其在群内直接调用系统维护能力。

### 私聊单独一套

若希望机器人在私聊中拥有与群聊完全不同的交互体验：

1. 在目标选择器中选择「私聊用户」，并选定目标用户。
2. 针对私聊场景覆盖「人设」「模型」或「权限」等字段。
3. 检查无误后点击「保存」即可。

私聊场景通常比群聊更私密，且不存在打扰多人的顾虑。你可以在私聊中放宽工具权限或配置更深入的人设；反过来，也可以针对陌生用户单独收紧权限。

例如：在群聊中让机器人扮演活泼的群气氛调节员，并限制外部工具调用；而在私聊中为自己单独设置人设、模型与权限，放开工具调用，将其作为贴身的日常工作助手。

## 标签页都管什么

各常见标签页包含的核心设置项如下：

### 基本

- **用途**：决定由哪个引擎处理消息。默认为「对话」；「伪装」用于角色扮演，「编码」用于代码工作流，「设置」用于首次配置引导。
- **模型**：回复时调用的模型。留空时沿用上层设定。
- **思考深度**：模型支持时控制推理强度。可选档位取决于模型本身。
- **人设**：绑定的角色预设。预设切换即时生效，从下一个回合起采用新人格。

### 回复

- **什么时候回复**：控制直接触发条件，包括 @、引用、称呼、私聊与随机搭话等。
- **连发消息**：对方连续发送多条消息时的处理策略，可配置为收到即回复，或等待对方输入完成后合并回复。
- **群聊记录**：配置不回复时是否记录消息、回填历史条数、回复期间新消息的处理方式以及图片的提供方式。
- **主动说话**：管理冷场搭话、稍后继续、话题相关插话以及早晚安问候等主动交互。

### 能力

- **工具**：工具的使用策略（直接提供全部、先检索后调用、写代码调用、委派给子代理），以及允许或禁用的工具列表。
- **技能**：管理允许或禁用的技能，以及是否允许技能使用已保存的密钥。
- **子代理**：配置默认模型、最高档位、委派深度、允许的配置文件与后台驱动。
- **长期记忆**：管理是否自动提取记忆、是否主动回忆、记忆存储位置，以及按预设还是按会话隔离。
- **指令**：配置模型允许执行的指令列表；执行未列出的指令需要管理员确认。

### 安全

- **权限**：分为只读、文件、自动、完全放行四档。留空时根据用户权限等级决定。
- **执行环境**：默认执行代码的机器，以及允许委派的机器列表。
- **消息审核**：配置屏蔽词、记录词与内容替换规则。

### 高级

- **聊天记录**：配置记录共享模式（全员共用、每人一份、按自定义规则划分）以及对话分区通道。
- **机器人发出的消息**：是否将机器人自身发送的消息记录到对话历史中。
- **显示**：配置回复格式（纯文本、富消息、Markdown）、可用元素、分条方式、隐藏元素、引用与分段长度。
- **对话压缩**：配置上下文达到设定比例时自动压缩，以及是否使用模型自带的压缩能力。

## 规则、快捷设置和插件配置的关系

ChatLuna 包含三层相关的配置入口，各自的分工如下：

- **插件配置**：控制插件本身的底层运行机制（例如连接数据库失败时的重试策略），在控制台的「插件配置」页面中调整。
- **快捷设置**：面向新手的简化入口，仅挑出最常用的几项配置。它本质上修改的是场景规则中的「全局」配置，适合在初次安装后快速跑通对话。
- **场景规则**：完整的层级配置中心。在快捷设置中修改的内容会同步反映在此处，且支持进一步按群聊、用户进行针对性覆盖。

这三层配置最终会在消息处理时合并生效：插件配置提供运行时的底层参数，场景规则提供按场景定制的业务参数，而快捷设置仅是场景规则全局视图的精简窗口。

::: tip
若修改某项配置后未生效，建议先确认是否被更具体的规则覆盖。规则摘要与控制台的轨迹页面会清晰显示当前会话最终生效的规则来源。
:::

## 常见问题

**修改了全局配置，为什么某个群没有变化？**

通常是因为该群存在更具体的规则覆盖了该配置项。在顶部目标选择器中切换到该群，检查该项是否已被单独修改。若希望其继承全局设定，点击该项菜单中的「恢复默认」并保存即可。

**为什么规则保存后没有立即生效？**

不同配置项的生效时机有所区别：
- 「用途」「模型」「聊天记录」「工具」「指令」属于会话级设置。处于活跃状态的旧会话会继续沿用先前的参数，直到开启新会话时才会采用新配置。
- 「人设」「什么时候回复」「群聊记录」「显示」「长期记忆」属于即时生效设置。保存后，发送下一条消息即可立即按新配置运行。

**为什么规则无法匹配？**

若规则未生效，建议先检查右侧「设好的规则」摘要卡片是否标红：
- 条件冲突、群号填写错误或平台选择有误，都会导致规则无法匹配消息。
- 若条件配置无误，可前往控制台的轨迹页面，查看实际消息处理过程中命中的规则链条。

**能否使用一条规则管理多个群聊？**

可以。在群号输入框中可填入多个群号，各群号之间为「满足任意一个即可」的并集关系。与其他条件组合使用时，请留意检查摘要卡片中的逻辑是否符合预期。
