# 场景规则

::: tip
场景规则决定了机器人「在什么场合、对谁、用什么方式说话」。同一个机器人，可以在 A 群扮演活泼的角色、在 B 群只严肃回答问题、在某个私聊里保持安静——这些都不需要部署多份实例，只需要几条简单的规则就能搞定。
:::

当你的机器人加入越来越多的群聊，或者既要在私聊里为你处理日常事务，又要在摸鱼群、技术群里活跃时，你很快就会发现：不同的群聊，大家对机器人的期待完全不同。

有的群希望它是一个活泼的角色扮演玩伴，有的群只希望它严肃地回答技术问题，而在某些私聊里，你可能只希望它安安静静当一个笔记助手。

如果为每一个群都单独跑一套程序或复制一份配置，维护起来不仅麻烦，而且非常容易改错。ChatLuna 为此设计了「场景规则」机制。它的核心思路其实很简单：**把默认行为和特殊情况分开处理**。

我们只需要先为机器人配好一套通用的全局设置，再在需要特殊对待的群聊或私聊里，单独覆盖个别项目。每当机器人收到消息时，系统就会自动找到适用的规则，按照从通用到特殊的顺序叠在一起，拼出当前会话需要的完整配置。

这样一来，每当你把机器人拉进一个新群，就再也不用从头折腾一遍配置了，只需要设置「这个群有什么不一样」即可。

## 先认识页面

进入控制台，在侧边栏点击「配置 → 场景规则」，就能看到规则管理的主界面。

整张页面主要分为三个区域：
- **顶部目标选择器**：决定你当前正在给谁配置规则，默认是「全局」；
- **右上角保存按钮**：用来提交你刚才修改的所有内容；
- **中间的配置标签页**：按功能分类归纳的各项设置，每一项都可以单独决定是否覆盖。

### 目标选择器

目标选择器是配置规则的第一步。点击顶部的下拉菜单，你可以选择不同的生效范围：

- **全局**：所有消息的默认底座。只要某个群或用户没有单独配置特殊规则，都会默认采用这里的设定。
- **机器人**：针对某个平台上的具体机器人账号生效。如果你的实例同时登录了多个账号（比如同时挂了 QQ 和 Telegram），可以在这里区分账号层面的差别。
- **群聊**：只对指定的某一个群聊生效。这是日常使用中最常用的范围。
- **私聊用户**：只对某个特定用户的私聊生效，不会影响该用户在群里的表现，也不影响其他人的私聊。
- **群成员**：只对某个群里的某位成员生效。这种范围最具体，适合用来给群主或管理员单独放开某些能力。

选好目标后，页面右侧会即时显示一张「设好的规则」摘要卡片。

这张卡片会用通俗的语言告诉你当前规则在什么条件下会生效。比如你选了某个群，卡片就会显示类似「在群 123456 中，同时满足：平台是 onebot」。如果你不小心添加了互相冲突的条件（比如一条规则既要求是群聊又要求是私聊），卡片会直接标红提醒并给出修改建议，方便你在保存前排查问题。

### 标签页

选定目标后，中间区域就会展示该目标下的各项设置。为了方便查找，它们被整理成了几个不同的标签页：

- **基本**：涵盖最基础的对话设定，比如用途（决定由哪个引擎来处理消息）、模型、思考深度以及预设人设。
- **回复**：管理机器人什么时候开口，包括搭话时机、对方连续发消息时如何合并、群聊记录留存以及主动搭话等。
- **能力**：管理机器人可以调用的扩展功能，比如工具、技能、子代理、长期记忆和控制台指令。
- **安全**：控制使用权限与合规策略，包含权限等级、执行环境和消息审核规则。
- **高级**：偏底层的参数微调，例如聊天记录的切分方式、机器人发出的消息是否计入历史、回复显示格式以及对话压缩机制。
- **引擎专属标签页**：当你在「基本」标签页中把「用途」切换为「伪装」等特定引擎时，界面会自动出现对应的专属标签页，供你调整作息、心情、动作或思考方式等专属细节。

需要说明的是，界面的标签页是动态变化的。如果你安装了新的扩展插件，或者把「用途」切到了其他引擎，相关设置项就会自动出现或退场，无需手动刷新。

## 继承与覆盖

在场景规则中配置各项参数时，我们最常打交道的就是「继承」与「覆盖」这两个概念。

先来看看你要做什么：
在顶部选好这个群，找到想改的项目，直接填上新值就完成了一次覆盖；不想改的项保持原样，它们会继续沿用外层的设定。

改错了也没关系。每个字段右上角的菜单里有「恢复默认」，点一下就把这一项放回跟随上级的状态；旁边的「放弃修改」则把整块表单退回打开时的样子。

那么，为什么要设计成这种模式，而不是直接给每个群复制一份完整的配置表单呢？

原因在于后期的维护成本。试想一下，如果你加入了十几个群，每个群都存着一份包含几十个字段的完整副本，那么当你换了一个更实惠的大模型，或者微调了全局人设台词时，就不得不逐个点进每一个群里手动改一遍。而在「继承与覆盖」机制下，每个字段只有两种状态：

- **继承**：当前字段不设置独立的值，直接沿用更外层（通常是全局）的设定。
- **覆盖**：为当前目标显式指定一个独立的新值。

只有被显式填写过的字段，才会真正保存在当前群的规则里。其余保持继承的字段，未来只要你修改了全局默认值，所有未覆盖的群都会自动同步更新。

::: tip
覆盖是「按字段」生效的，而不是「按页面」生效。比如在技术交流群里，你只需要改「模型」和「人设」两项，其余的工具、权限、记忆等依然可以安心继承全局。点击保存时，页面还会提示哪些改动属于「只影响新会话」，哪些改动能够「即时生效」。
:::

让我们来看一个具体场景：

你在全局设置中把模型设为了基础对话模型，人设是「智能助理」，并且开启了网页搜索工具。现在你想在「内部测试群」里试用最新的推理模型，但希望人设和搜索工具依然和全局保持一致。

这时候，你只需要在目标选择器中选中「内部测试群」，在「基本」标签页里把「模型」改成专属的推理模型并保存。人设和工具完全不需要动。今后你在全局更新了人设台词，测试群也会自动跟进，唯独模型依然锁定在测试群专属的推理模型上。

### 保存与冲突

当你改完配置并点击右上角的「保存」时，系统会在后台校验当前规则的版本，确认在你编辑的这段时间里，是否有其他管理员也修改了同一目标的规则。

如果你打开页面后离开了一阵子，而另一个人抢先保存了修改，当前页面就会弹出保存冲突提示。此时系统会阻止直接覆盖，要求你先刷新页面获取最新配置，再重新修改保存。这样可以防止在多人协作或者打开多个标签页时不小心冲掉别人的成果。

规则保存成功后会立刻生效。留在当前页面的用户不需要手动刷新；如果此时恰好有其他人在编辑同一条规则，对方在提交时同样会受到版本冲突机制的保护。

## 多条规则怎么叠

当一个会话同时符合多条规则时，系统是按什么样的顺序来决定最终生效配置的呢？

先来看看要做什么：
日常使用时，你只需要按照自然的直觉，把规则建立在合适的层级上即可——通用的写在全局，群聊专用的写在群聊，个人特权写在群成员。系统会自动将它们一层一层叠在一起，算出最终的生效值。

为什么系统要按层级叠加？
因为在真实的聊天中，一条消息往往同时具备多种身份。例如，一条消息可以同时属于「某个聊天平台」「技术交流群」以及「群内的管理员」。系统在收到消息时，会把全局规则、平台规则、群规则、成员规则全部找出来，按照「越具体越优先」的标准依次叠加，后叠上去的配置会覆盖掉先前的同名字段。

具体来说，规则的合并排序遵循以下顺序：

1. **全局规则永远在最底层**：作为所有会话的通用底座。
2. **条件越具体的规则越靠后**：在叠加链条中，越靠后的规则覆盖力越强。
3. **具体程度相同时，优先级数值大的靠后**：如果两条规则的具体程度完全一致，系统会看优先级设置，数值更高的规则后叠加。
4. **仍然相同时，创建得早的靠前，最后按规则内部标识排序**：创建时间更早的靠前，最后依照规则内部标识确定先后。

这里的「具体」并不是单纯数一数规则里勾选了几个条件，而是看条件的范围类型：
- 限定了具体群号的群聊规则，自然比只限定了平台的机器人规则更具体；
- 同时限定了群号和特定用户的群成员规则，又明显比单纯限定群号的群规则更具体。

::: warning
不要试图用「优先级」去解决本应该用条件范围表达的事情。优先级主要用于处理同一层级内多条规则的先后微调，并不适合用来替代「群聊 → 群成员」这种天然存在的范围层次。
:::

有时如果配置不当，规则里的条件可能会互相打架。例如在同一条规则里既勾选了「是私聊」又勾选了「是群聊」，或者把群号同时限定为两个完全不同的群。面对这种情况，系统会在右侧的规则摘要中把冲突项明确标红，指出哪几个条件互相排斥。存在冲突的规则将无法匹配任何消息，保存前请务必按照提示修正条件。

让我们来看一个具体场景：

- 全局规则中，所有人设统一是「默认助手」；
- 你为「日常交流群」创建了一条规则，覆盖人设为「群管家」；
- 接着，你又为该群里的群主单独建了一条群成员规则，覆盖人设为「私人秘书」。

当普通群员在群里呼叫机器人时，系统会匹配到全局和群聊两条规则，叠加之后，人设最终生效为「群管家」；
而当群主在群里呼叫机器人时，三条规则全部被命中，群成员规则排在最后生效，机器人便会以「私人秘书」的人设回应群主。

## 每个群单独配置

在实际使用机器人时，我们最常见的需求往往是「平时用默认的一套，个别群开小灶」。

为了更高效地管理多个群聊，推荐按照下面的步骤来进行：

1. **先打好全局底座**：先将目标选择器停留在「全局」，把适合大多数群聊和私聊的通用用途、主流模型以及默认人设配置妥当。
2. **选中目标只改差异**：在目标选择器中切换到想要调整的特定群聊，只修改需要与全局不同的字段。
3. **按需切换工作引擎**：如果这个群需要执行完全不同的任务，把「用途」改成另一个引擎，随后在自动弹出的引擎专属标签页里微调各项细节。
4. **发送消息验证效果**：保存规则后，直接在该群发送消息进行测试。你可以在规则摘要和控制台的轨迹页面中看到实际命中的规则链条。

下面我们来看看几个最常见的群配置场景以及具体的操作方法。

### 给某个群换人设

**要做什么**：
你想让某个特定的群拥有专属的对话性格，比如把普通的问答助手变成特定的人格预设。

**具体操作步骤**：
1. 打开场景规则页面，在顶部目标选择器中选择「群聊」，并选定目标群。
2. 切换到「基本」标签页，找到「人设」选项。
3. 把「人设」换成准备好的预设角色，点击右上角保存。

**为什么这样做**：
这个群随后就会使用专属预设与群友互动，而其他所有群和私聊依旧保持全局设定不变。如果新预设依赖了状态、人物经历、作息等角色引擎的能力，记得顺便把「用途」改成「伪装」，并在下方新出现的伪装标签页中确认各项能力。

**具体场景示例**：
在「动漫同好交流群」中，你把人设覆盖为特定角色预设，并把用途改成伪装；而在隔壁的「技术讨论群」中，人设依然继承全局的严肃工程师助手。

### 让某个群完全沉默

**要做什么**：
在某些特殊群里，你不希望机器人主动或被动插话回复，但又希望它能留在群里观察记录，或者方便后续随时重新启用。

**具体操作步骤**：
1. 在目标选择器中选定对应的「群聊」。
2. 进入「基本」标签页，找到「用途」设置项。
3. 把「用途」改成「不回复」，点击保存。

**为什么这样做**：
比起直接把机器人踢出群，这样做不仅动作轻量，而且保留了记录和随时恢复的能力（具体行为取决于「群聊记录」中的开关）。后续如果需要重新唤醒机器人，只需把用途改回对话引擎即可恢复。

**具体场景示例**：
群聊即将举办一场线上宣讲，期间不需要机器人答疑。你提前把该群的用途覆盖为「不回复」；宣讲结束之后，再顺手切回原本的引擎，机器人便恢复了日常互动。

### 只让某个群用某个模型

**要做什么**：
群内对生成质量有特殊需求，希望该群专门调用高级模型，同时避免其他群产生额外的开销。

**具体操作步骤**：
1. 在目标选择器中选中对应的「群聊」。
2. 在「基本」标签页里设置「模型」。
3. 在下拉列表中选定专用的模型名称，点击保存。

**为什么这样做**：
列表中的模型选项来自「提供商」页里已经配置好的模型。如果下拉菜单中没有找到期望的模型，说明尚未在提供商列表中添加该模型，先到提供商页添加后再回来配置即可。

**具体场景示例**：
日常闲聊群统一继承全局的高性价比模型；而对于涉及复杂编程探讨的「技术攻坚群」，单独覆盖为一个拥有更强推理能力的高规格模型。

### 群里只对某个人开放

**要做什么**：
在一个公共群聊中，你希望把某些高权限操作或进阶能力只对群主、管理员或测试人员开放，而普通群员调用时不予放行。

**具体操作步骤**：
1. 打开顶部目标选择器，将目标类型切换为「群成员」。
2. 依次指定对应的群和目标成员。
3. 按需修改「人设」「模型」或「权限」等选项，调整为专属配置后保存。

**为什么这样做**：
在规则叠加的逻辑中，更具体的群成员规则会覆盖群规则，具有极高的特异性。群内的普通群员会按照群规则运行，而这位特定的群成员则会触发更高层级的专属规则，适合给管理员、常驻成员或测试用户单独放权。

**具体场景示例**：
在大型公共交流群中，群规则的权限被设定为普通只读；但你为群管理员单独添加了一条群成员规则，将其权限覆盖为完全放行，允许在群内直接调用系统维护能力。

### 私聊单独一套

**要做什么**：
希望机器人在与用户一对一私聊时，拥有与群聊完全不同的交互体验。

**具体操作步骤**：
1. 在目标选择器中选择「私聊用户」，并选定目标用户。
2. 针对私聊环境分别覆盖「人设」「模型」以及「权限」等字段。
3. 检查并保存设置。

**为什么这样做**：
私聊通常比群聊更私密，没有公共群聊里多人刷屏打扰的顾虑。你可以在私聊中放宽工具权限，或者配置更深入的个性化设定；反过来，也可以针对不熟悉的用户收紧权限。

**具体场景示例**：
你在群聊中让机器人扮演活泼的群气氛调节员，收紧外部工具调用；而在私聊中，你为自己单独设置人设、模型和权限，放宽工具权限，把它当作贴身的日常工作助手。

## 标签页都管什么

为了方便你在各个标签页中快速找到想要的开关，这里把常见标签页里包含的核心设置做一份系统汇总。

### 基本

- **用途**：用哪个引擎处理消息。默认是「对话」；「伪装」用于角色扮演，「编码」用于代码工作流，「设置」用于首次配置引导。
- **模型**：回复使用的模型。留空时沿用更外层。
- **思考深度**：模型支持时，控制推理强度。可选档位取决于模型。
- **人设**：绑定预设。预设切换是即时生效的，从下一个回合开始使用新人格。

### 回复

- **什么时候回复**：@、引用、叫名字、私聊、随机搭话等直接触发条件。
- **连发消息**：对方连续发多条时，是收到就回，还是等对方说完再一起回。
- **群聊记录**：不回复时是否记录消息、回填多少历史、回复期间的新消息怎么处理、图片怎么给模型看。
- **主动说话**：冷场搭话、稍后继续、话题相关插话、早晚安问候。

### 能力

- **工具**：工具怎么用（直接给全部、先搜再用、写代码调用、交给子代理），以及允许或禁用哪些工具。
- **技能**：允许或禁用哪些技能，以及是否允许技能使用保存的密钥。
- **子代理**：默认模型、最高档位、委派深度、允许的配置文件与后台驱动。
- **长期记忆**：是否自动提取、是否主动回忆、记忆存在哪里、按预设还是按会话隔离。
- **指令**：模型可以执行哪些指令；执行未列出的指令需要主人同意。

### 安全

- **权限**：只读、文件、自动、完全放行四档。留空时按用户等级决定。
- **执行环境**：默认用哪台机器执行，允许委派到哪些机器。
- **消息审核**：屏蔽词、记录词、替换规则。

### 高级

- **聊天记录**：共用一份、每人一份、按自定义规则分；以及对话分区通道。
- **机器人发出的消息**：是否把机器人自己发的消息也记进历史。
- **显示**：回复格式（纯文字、富消息、Markdown）、能用的元素、分条方式、隐藏元素、引用、分段长度。
- **对话压缩**：上下文占满多少比例时自动压缩，是否使用模型自带的压缩。

## 规则、快捷设置和插件配置的关系

在刚接触 ChatLuna 时，不少小伙伴会发现控制台里有好几处都可以改设置，容易把它们搞混。其实系统里清晰地划分了三层配置：

- **插件配置**：某个插件本身的底层默认行为，比如「场景规则」插件连不上数据库时该怎么办。这类偏底层的运行机制需要在「插件」页面中调整。
- **快捷设置**：面向初学者的简化入口，只把最常用的几项目录挑出来。它本质上修改的就是场景规则里的「全局」配置，适合刚部署好时快速跑通第一次对话。
- **场景规则**：完整的分层配置中心。你在快捷设置里改动的内容，在这里都能同步看到，并且可以进一步按群、按用户进行细化覆盖。

这三者最终都会汇聚到同一次消息处理中：
插件配置提供底层默认运行参数，场景规则负责提供按场景差异的个性化覆盖，而快捷设置只是场景规则全局视图的一个精简窗口。

::: tip
如果发现某个设置改了之后没有起效，不妨先确认一下它是不是被更具体的规则覆盖了。规则摘要和控制台的轨迹页面都会清楚告诉你，当前会话生效的参数究竟来自哪一条规则。
:::

## 常见问题

**为什么改了全局，某个群没变？**

这通常是因为这个群有一条更具体的规则覆盖了该字段。在顶部目标选择器中切换到这个群，看看这个群有没有单独填过这一项。如果希望它跟随全局走，点这一项的「恢复默认」再保存即可。

**为什么规则保存后没立刻生效？**

在场景规则中，不同的配置项生效时机有所区别：
- 「用途」「模型」「聊天记录」「工具」「指令」等属于会话级设置。已经处于活跃状态的会话可能仍在使用旧的会话参数，直到新建会话或下一次重新打开时才会更新；
- 而「人设」「什么时候回复」「群聊记录」「显示」「长期记忆」等属于即时设置，规则保存之后，发送下一条消息就会立即按新配置运行。

**为什么规则匹配不上？**

遇到规则不生效的情况，建议先看右侧「设好的规则」摘要卡片有没有标红：
- 条件冲突、群号填错、平台选错，都会导致规则无法匹配到任何消息；
- 如果配置看起来没有问题，也可以打开控制台的轨迹页面，查看一条真实消息在处理时究竟命中了哪几条规则。

**能不能一条规则管多个群？**

可以。在群号输入框里可以填入多个群号，它们之间是「满足任意一个即可」的关系。当与其他条件组合使用时，注意检查摘要卡片中的逻辑是否符合你的预期。
