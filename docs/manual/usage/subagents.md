# 子代理

::: tip
这一页讲怎么把一件大活儿交给「另一个自己」去做。子代理是独立开的小会话：它有自己的上下文、自己的工具循环，干完只把结论带回来。
:::

和机器人聊久了会遇到一种情况：你让它读十几个文件、翻一遍日志、跑几轮验证，最后只要一句结论。

问题在于，中间那些过程——读到的每一行文件、每一次命令输出——都会进主会话的上下文。等它真正要回答你的时候，窗口已经被中间过程占满了。

子代理就是为这种场景准备的。

主代理把任务派出去，子代理在自己的独立会话里干活，主代理这边只收到一段结果文字。中间过程留在子代理的会话里，需要的时候再去「轨迹」页翻。

## 它是怎么被派出去的

在对话里，模型通过一个叫「委派」的工具发起子代理调用。你不需要手动点任何按钮，模型判断任务适合分出去时就会调用它。

这个工具接受几个参数，对应到你可以控制的东西：

- **用哪个子代理**：留空就用通用子代理。
- **任务内容**：交给子代理的说明。
- **模型档位**：小、中、大，受场景规则的上限约束。
- **在哪台机器上执行**：留空就沿用父会话的机器。
- **接续哪个任务**：填之前返回的编号，继续同一个可续的子代理。
- **是否转到后台**：转后台后，主代理可以先回复你，子代理完成时再通知。

::: tip
「委派」这个名字可以在插件设置里改。如果你在工具页看到一个不太眼熟、但描述是「把任务交给子代理」的工具，多半就是它换了名字。
:::

## 子代理看到的上下文

这是最容易被误解的一点：子代理**不是**父会话的复制品。

默认情况下，主代理和子代理的上下文是分开的。子代理能看到什么，取决于这个子代理的继承方式：

| 继承方式 | 子代理能看到 |
| --- | --- |
| **不继承** | 只有你派给它的那段任务说明 |
| **摘要** | 父会话内容压缩成的一段摘要，加上任务说明 |
| **分叉** | 父会话的对话记录，加上任务说明 |

系统自带的委派工具用的是「分叉」：子代理能看到当前对话里说过的话，所以你不必在任务里重复背景。

但它看不到父会话里的工具调用和工具结果。这点很重要——如果你希望子代理知道某个命令的输出，得把关键内容写进任务说明里。

::: warning
「摘要」继承需要父会话能压缩上下文。如果压缩能力没启用，系统会退回「不继承」，只在日志里留一条警告。发现子代理「好像什么都不知道」时，先想想这条。
:::

## 会话与生命周期

子代理分两种生命周期：

- **一次性**：干完这次就结束。外部命令行后端都是这种。
- **可续**：子代理会保留自己的会话，之后还能接着聊。

可续子代理的用法很自然：第一次派任务，它返回一个编号；下次把编号一起传回去，它就在原来的上下文里继续干。

系统提示里列出的子代理，可续的那种会带「可续」标记。没有标记的，传编号也没有用。

同一个父会话下，同名子代理同一时间只能有一个在跑。想接着干，用编号续；想并行干不同的活，用不同的子代理名。

## 模型档位

子代理可以做重活，也可以做杂活，所以它的模型是单独选的。

- **小**：便宜的快速模型，适合机械的整理、检索、转写。
- **中**：默认档位，适合大多数需要动脑但不至于太复杂的任务。
- **大**：最强，适合需要长时间推理的硬任务。

档位会受两层限制：子代理自己的设置，以及场景规则里配的上限。

「默认模型」也可以直接指定成某个具体模型，而不只是档位。这样所有没写档位的委派都会落到那个模型上。

::: warning
子代理是独立会话，所以它的花费也是独立计算的，会出现在用量页里。

如果你的小模型配置得很便宜，但子代理默认用「大」，账单会比你想象的高。想省钱，把默认档位调到「中」。
:::

## 委派深度

子代理还能再派子代理。为了防止无限套娃，系统有一个「最大委派层数」，默认是四层。

超过这个深度的委派会被直接拒绝，派出去的那次调用会收到一个失败结果，父会话继续正常往下走。

四层听起来很多，实际上一层层派下去很容易就用完了。如果你的任务结构很深，考虑在中间层把任务合并，或者直接调高这个上限。

::: tip
深度限制按「从最外层算起」计。主会话是零层，它派出去的是第一层，再往下是第二层。默认的上限意味着最深处只能到第三层。
:::

## 外部子代理

除了系统自己起的子代理，还可以把任务交给外部命令行工具。

这类后端需要单独安装插件，目前提供的有：

- **Claude CLI**
- **Codex CLI**
- **OpenCode**
- **Pi**

装好之后，委派工具就能把任务派给它们。它们在自己的进程里跑，跑完只把最终结果交回来。

几个需要注意的地方：

- **一次性**：外部后端不支持接着聊，传编号会被拒绝。
- **需要更高权限**：启动外部后端默认要求最高权限等级，普通用户用不了。
- **有超时**：默认三十分钟，超时任务会被中止。
- **在本机执行**：外部命令走的是子代理绑定的机器；如果你希望它跑在沙箱里，记得把机器一起指定过去。

外部后端适合「这套活已经有成熟的命令行工具」的场景，比如让 Codex 去改代码、让 OpenCode 去查资料。它们的能力边界由那个工具自己决定，ChatLuna 只负责派活和收结果。

## 后台子代理

长任务不必让对话一直等着。

委派时选择转到后台，任务会进入「后台任务」页，主代理立刻拿到一个「已转到后台」的结果，可以继续回复你。

子代理完成、失败或被取消时，你会收到一条通知，内容就是它的结果。

后台任务也可以在「后台任务」页里手动取消。取消之后，子代理会被正常收尾，不会留下半截进程。

## 能看到的细节

想搞清楚某次委派到底发生了什么，去「轨迹」页。

每个子代理调用都会留下一条独立记录，带自己的会话编号、模型、工具调用和耗时。父会话的轨迹里只显示这次委派的起点和结果，中间的细节在子代理自己的记录里。

这带来一个排查习惯：**父会话看不到答案时，先找到子代理的轨迹，再判断是任务描述不清，还是子代理执行失败**。

## 什么时候该用子代理

不是所有任务都值得分出去。判断标准可以很简单：

- **中间过程远多于结论**：翻日志、扫文件、批量检索。
- **需要干净的上下文**：你在主会话里正聊着别的事，不想被打断。
- **想并行**：多个互不相关的调查可以同时进行。
- **想隔离**：任务可能会跑出大量输出、装上依赖、改动文件。

反过来说，一两步就能完成的任务、需要和你来回确认的任务，交给子代理反而更慢，因为它看不见你后续的回答。

::: tip
一个常见的误用是：让子代理去「问用户一个问题」。子代理没有对话渠道，它的任务必须自带足够的信息，并且一次跑完。
:::

## 推荐配置

### 个人使用

保持默认：通用子代理、分叉继承、中档模型。

把委派深度留在四层，够用。外部后端只在确实需要时安装，装上也别给普通群开放。

### 多人群聊

在场景规则里限制可用的子代理和执行后端，只开放给管理员。

普通群成员如果能随手派一堆子代理，既费钱又容易把宿主环境搞乱。

### 重度编码

装上 Codex 或 OpenCode 后端，把它们的模型档位配好，机器指定到沙箱或项目目录。

主会话保持轻量，让子代理去读代码、改文件、跑测试；主会话只负责决策和汇总。

### 省钱模式

默认档位设为「小」，把需要推理的任务在委派时显式提升。

同时限制委派深度和外部后端，避免「子代理又派子代理」把费用叠起来。

## 排查

**模型不肯用子代理。**

先确认委派工具在工具页里是启用状态、当前场景没有把它禁用；再看模型是否支持工具调用；最后确认子代理列表不是空的——列表为空时，系统提示里根本不会提这件事。

**委派立刻失败，提示超过深度。**

说明当前层级已经到底。减少嵌套，或者调高「最大委派层数」。

**子代理说找不到之前那个任务。**

编号只在可续的子代理上有效，而且必须由同一个父会话来续。换了会话，或者换了子代理名，都接不上，会新开一个。

**子代理的结果和预期差很远。**

多数情况是任务说明写得太省。子代理看不到父会话的工具结果，也看不到你后来的补充。把目标、约束、需要的输入都写进任务里。

**外部后端一直超时。**

检查那个命令行工具本身能否在终端里跑通，检查它需要的登录状态和网络，再考虑调大超时。

**后台任务一直不结束。**

去「后台任务」页看它的日志；如果确实是卡住了，直接取消。子代理被取消时会正常收尾，不会影响父会话。
