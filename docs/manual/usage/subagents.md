# 子代理

::: tip
本节介绍子代理 (Subagent) 的运作机制与边界配置。你可以将执行步骤繁复、产生大量上下文的长任务委派给隔离的子会话执行，主会话仅负责任务调度与结果汇总。
:::

当任务需要执行较多步骤、读取大量文件或需要独立的上下文空间时，主代理 (Agent) 可以拉起子代理处理具体工作。子代理拥有独立的会话日志和工具循环 (Tool Loop)，在执行完毕后将结论回传给父级主会话。

## 子代理类型

ChatLuna 支持以下几种子代理启动与委派模式：

- **全新启动 (spawn)**：创建一个全新的子会话，不携带主会话的历史记录，从零开始执行任务。
- **历史分叉 (fork)**：从父会话当前的消息历史分叉出子会话，继承已有上下文并在此基础上继续运行。
- **外部 Harness (External Harness)**：将任务委托给外部 Agent 实现（如 OpenCode、Codex、Claude、pi 等），由外部环境完成执行后，主会话仅接收其返回的最终结果。

## 隔离与安全边界

子代理在隔离的环境中运行，其日志与父会话相互独立，工具调用过程互不干扰。为了控制资源消耗和行为范围，你可以对子代理施加以下边界限制：

- **工具范围限制**：收窄子代理可用的工具集合，仅授予其完成当前任务所必需的工具。
- **人格指定 (Persona)**：为子代理指定独立的人格设定，使其更专注于特定领域的执行要求。
- **深度限制 (Depth Limit)**：限制任务向下递归委派的最大层数。

::: warning
- **深度超限**：当委派层级超出设定的深度限制时，系统将直接拒绝后续的委派请求。
- **权限不继承**：子代理不会隐式继承父会话的权限提升状态。子代理发起的每一次工具调用都会经过权限判定流程，涉及敏感操作时仍须遵循既定规则获得批准。
:::

## 适用场景

在以下场景中，建议将任务拆分给子代理执行：

- **控制上下文膨胀**：任务执行过程中会产生大量中间输出（如大文件扫描、多轮排错输出），使用子代理可以避免主会话上下文空间被中间过程占满。
- **并行探索**：需要脱离主会话流程，在不破坏当前上下文的前提下进行独立的尝试或验证。
- **临时与沙盒化任务**：需要一个生命周期明确、任务结束即可完全释放上下文的干净执行环境。
