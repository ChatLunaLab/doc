# 子代理

::: tip
子代理是一个独立的下属会话，有自己的上下文和工具调用循环。它独立完成任务后，只把最终结论交回主会话。
:::

阅读大量文件、排查多段日志这类任务，主会话往往只需要最后的结果。如果让主代理自己做，每一行文件、每一次命令输出都会进入主会话的上下文，很快就把它占满。

把任务委派给子代理后，执行过程留在子代理自己的会话中，主代理只收到结论。需要查看细节时，可以到「轨迹」页面查看。

## 委派

模型判断任务适合拆分时，会自动调用「委派」工具，无需手动操作。委派工具的参数：

- **用哪个子代理**：留空时使用通用子代理。
- **任务内容**：交给子代理的需求和说明。
- **模型档位**：「小」「中」「大」，受场景规则中档位上限的限制。
- **在哪台机器上执行**：留空时沿用父会话的机器。
- **接续哪个任务**：填写之前返回的任务编号，继续与可续子代理交互。
- **是否转到后台**：开启后主代理先回复用户，子代理完成后再通知。

委派工具的显示名称可以在插件设置中修改。在「工具」页面看到一个描述为「把任务交给子代理」的工具，就是它。

## 子代理看到的上下文

子代理不是父会话的完整镜像，它能看到什么取决于「继承方式」：

| 继承方式 | 子代理能看到 |
| --- | --- |
| **不继承** | 只有派发给它的那段任务说明 |
| **摘要** | 父会话内容压缩成的一段摘要，加上任务说明 |
| **分叉** | 父会话的历史对话记录，加上任务说明 |

默认的委派工具使用「分叉」，子代理能直接看到历史对话，不必反复交代背景。但子代理看不到父会话中的工具调用和返回结果，需要参考某条命令的输出时，请把关键信息写进任务说明。

::: warning
「摘要」继承需要父会话启用上下文压缩，否则会降级为「不继承」并在日志中警告。
:::

## 生命周期

- **一次性**：完成任务后结束。外部命令行后端都是这一类。
- **可续**：完成后保留上下文，可以继续追加任务。首次委派时会返回一个编号，之后带上这个编号就能接着交互。

系统提示中列出的子代理会标注是否「可续」。同一个父会话下，同名的子代理同一时刻只能运行一个；需要同时处理多项任务时，请使用不同名称的子代理。

## 模型档位

- **小**：便宜快速，适合整理、检索和格式转换。
- **中**：默认档位，适合大多数任务。
- **大**：推理最强，适合复杂分析和长流程任务。

实际使用的模型同时受子代理配置和场景规则中档位上限的限制。「默认模型」也可以直接指定为具体模型，未声明档位的委派都会使用它。

::: warning
子代理的 token 消耗独立计算，记录在「用量」页面。主会话用便宜模型而子代理默认用「大」档位时，费用可能超出预期，建议把默认档位保持在「中」或「小」。
:::

## 委派深度

子代理还可以继续委派。为避免无限嵌套，「最大委派层数」默认为 4：主会话是第 0 层，最多派发到第 3 层。超出时调用直接失败，父会话会收到失败结果并继续执行。确实需要更深的分工时，可以合并中间步骤或调高上限。

## 外部子代理

安装对应插件后，还可以把任务交给外部命令行工具：Claude CLI、Codex CLI、OpenCode 和 Pi。它们在独立进程中运行，完成后把结果回传给主会话。

- 都是一次性的，不支持接续。
- 默认需要最高权限等级才能调用。
- 默认超时 30 分钟。
- 在子代理绑定的机器上直接执行，需要隔离时请在委派时指定沙箱机器。

外部后端适合借助成熟的命令行工具完成任务，例如用 Codex 改代码。任务能做到什么由工具本身决定，ChatLuna 只负责分发和回收结果。

## 后台子代理

委派时开启「是否转到后台」，任务会进入「后台任务」页面运行，主代理收到「已转到后台」后可以继续回复用户。子代理完成、出错或被取消时，系统会通知对应会话并附上结论。可以在「后台任务」页面查看进度或取消，取消后资源会被正常回收。

## 查看细节

每次子代理调用都有独立的轨迹记录，包括会话编号、模型、工具调用和耗时。父会话的轨迹中只保留委派和交付两个节点。回答不符合预期时，先找子代理的轨迹，判断是任务描述不足还是子代理执行出了问题。

## 什么时候该用

适合使用子代理的情况：

- 中间过程远多于结论，例如检索大量日志、扫描工程文件、批量抓取网页。
- 主会话需要保持干净的上下文。
- 有多个互不依赖的调研可以并行。
- 任务需要安装依赖、修改文件或产生大量输出，需要与主环境隔离。

单步就能完成的简单问题，或需要和用户反复确认细节的任务，不适合交给子代理——它在执行途中无法接收用户的追问。任务说明必须包含完整的输入，让子代理能独立完成。

## 推荐配置

| 场景 | 建议 |
| --- | --- |
| 个人使用 | 保持默认：通用子代理、「分叉」继承、「中」档位、4 层深度；外部后端按需安装 |
| 多人群聊 | 在场景规则中收紧可用子代理和后端，只允许管理员委派 |
| 重度编码 | 安装 Codex CLI 或 OpenCode，执行机器指向沙箱或项目目录；主会话负责决策，子代理负责读代码、改文件和跑测试 |
| 省钱模式 | 默认档位设为「小」，需要深度推理时再手动指定高档位；调低委派层数，禁用不需要的外部后端 |

## 常见问题

**模型不肯用子代理**：确认委派工具已启用且未被场景规则禁用、主模型支持工具调用，以及子代理列表不为空。

**委派立刻失败，提示超过深度**：已达到最大委派层数，减少嵌套或调高上限。

**子代理说找不到之前的任务**：编号只对「可续」子代理有效，且必须由同一个父会话接续。

**子代理的结果和预期差很远**：通常是任务说明不够。子代理看不到父会话的工具结果，请写清目标、限制和需要的数据。

**外部后端一直超时**：先在终端中单独运行该命令行工具，检查认证和网络，正常后再按任务量调大超时。

**后台任务一直不结束**：在「后台任务」页面查看日志，确认卡死后直接取消。
