# 子代理

::: tip
子代理是独立的下属会话：拥有自己的上下文与工具调用循环，在独立完成任务后，仅将最终结论返回给主会话。
:::

当对话涉及较多繁重步骤时（例如阅读大量文件、排查多段日志或执行多次验证），主会话往往只需要一个最终结果。

如果让主代理直接执行这些操作，所有中间过程——每一行文件读取、每次命令执行的输出——都会直接计入主会话的上下文。随着交互增多，上下文窗口很快会被琐碎的中间过程占满，从而影响后续对话质量。

子代理机制正是为了解决这种问题而设计的。

主代理将复杂任务委派给子代理，子代理会在独立的会话环境中执行任务；任务完成后，主代理只接收并展示最终文字结论。所有执行细节与中间过程均保存在子代理自己的会话中，你可以在「轨迹」页面随时回溯。

## 它是怎么被派出去的

在对话过程中，模型会自动通过「委派」工具调用子代理，无需手动操作。当模型判断当前任务适合拆分处理时，便会自动触发此工具。

委派工具包含以下几个关键参数：

- **用哪个子代理**：指定负责执行的子代理类型；留空时默认使用通用子代理。
- **任务内容**：交付给子代理的具体需求与工作说明。
- **模型档位**：可选「小」、「中」、「大」，实际调用受场景规则中设置的档位上限约束。
- **在哪台机器上执行**：指定执行环境；留空时默认沿用父会话所在的机器。
- **接续哪个任务**：填写先前返回的任务编号，用于继续与某个可续子代理交互。
- **是否转到后台**：开启后，主代理无需等待结果即可先回复用户，子代理在后台完成后再行通知。

::: tip
委派工具的显示名称可在插件设置中进行修改。如果你在「工具」页面中看到一个名称不同但描述为「把任务交给子代理」的工具，即为委派工具。
:::

## 子代理看到的上下文

主代理与子代理的上下文默认是完全隔离的，子代理并不是父会话的完整镜像。

子代理能够获取到的历史信息，取决于为该子代理配置的「继承方式」：

| 继承方式 | 子代理能看到 |
| --- | --- |
| **不继承** | 只有你派给它的那段任务说明 |
| **摘要** | 父会话内容压缩成的一段摘要，加上任务说明 |
| **分叉** | 父会话的对话记录，加上任务说明 |

系统默认的委派工具采用「分叉」方式：子代理可以直接看到当前会话中的历史对话内容，因此你在下达任务时无需反复交代背景。

需要注意的是，子代理无法看到父会话的历史工具调用及返回结果。如果你希望子代理参考某条命令的执行输出，请务必将关键信息明确包含在任务说明中。

::: warning
使用「摘要」继承时，需要父会话具备上下文压缩能力。如果未启用上下文压缩，系统会自动降级为「不继承」，并在日志中记录警告。若遇到子代理缺失背景信息的情况，建议优先检查此项设置。
:::

## 会话与生命周期

子代理具有两种不同的生命周期形态：

- **一次性**：执行单次任务后立即结束生命周期。外部命令行后端均属于此类。
- **可续**：任务完成后保留独立的会话上下文，后续可以继续向其追加任务。

可续子代理的使用非常直观：初次委派任务时，子代理会返回一个会话编号；在后续调用中带上该编号，即可在原有的上下文中继续交互。

在系统提示词列出的子代理列表中，支持延续的子代理会标注「可续」。未标注可续的子代理不支持此机制，传入编号也不会生效。

在同一个父会话下，同一名称的子代理在同一时刻只能运行一个实例。如果需要推进已有工作，应通过编号进行接续；如果需要并发处理多项不同任务，请选用不同名称的子代理。

## 模型档位

子代理所承担的任务复杂度各不相同，因此其运行模型支持独立配置。

系统将模型划分为三个档位：

- **小**：成本较低的高速模型，适合文件整理、信息检索和格式转写等轻量工作。
- **中**：系统默认档位，兼顾响应速度与理解能力，适合绝大多数常规任务。
- **大**：推理能力最强的模型，适合复杂分析、深度推理与长流程逻辑任务。

调用时的实际模型受双重限制：不仅取决于子代理自身的配置，还会受到所属场景规则中模型档位上限的制约。

此外，「默认模型」也可以直接指定为具体模型名称而非仅设置档位。指定后，所有未声明模型档位的委派调用都会统一调度至该模型执行。

::: warning
子代理作为独立会话运行，其 Token 消耗同样独立计算，并统一记录在「用量」页面中。

如果主会话使用的是低成本模型，而子代理默认使用了「大」档位，可能会产生超出预期的 Token 消耗。若需要控制成本，建议将默认档位保持在「中」或「小」。
:::

## 委派深度

子代理在执行过程中同样可以继续向下委派新的子代理。为了避免形成无限循环嵌套，系统引入了「最大委派层数」配置，默认上限为四层。

当委派层级超出此限制时，调用将被系统直接拦截并返回失败状态，而父会话则会捕获该结果并继续正常执行。

在实际的多级任务分解中，层层派发可能会迅速达到深度上限。如果业务流程确实需要较深的分工结构，建议合理合并中间步骤，或者在配置中适当调高该上限。

::: tip
委派深度的计算从最外层会话开始计数：主会话为第 0 层，主会话发起的子代理为第 1 层，依此类推。在默认的四层上限下，最多支持派发至第 3 层子代理。
:::

## 外部子代理

除了系统内置的子代理机制外，还可以将任务转交给外部命令行工具执行。

使用此类后端需要先安装对应的扩展插件，目前支持的后端包括：

- **Claude CLI**
- **Codex CLI**
- **OpenCode**
- **Pi**

安装相应插件后，委派工具即可直接向其分派任务。这些后端会在独立的系统进程中运行，并在执行完毕后向主会话回传结果。

使用外部子代理时需留意以下特性：

- **一次性**：外部后端均不具备上下文持久化能力，不支持接续会话，传入编号将被拒绝。
- **需要更高权限**：调用外部后端默认要求最高权限等级，普通用户无法直接发起。
- **超时机制**：默认执行超时为三十分钟，超出时限的任务将被强制中止。
- **运行环境**：外部命令会在子代理绑定的机器上直接执行；若需隔离运行，请在委派时明确指定对应的沙箱机器。

外部后端非常适合存在成熟命令行生态的场景（如借助 Codex 修改代码、通过 OpenCode 检索资料等）。工具本身决定了任务执行的能力边界，ChatLuna 仅负责任务的分发与结果回收。

## 后台子代理

对于耗时较长的重型任务，无需让主对话一直处于阻塞等待状态。

在发起委派时开启「是否转到后台」选项，任务会被提交至「后台任务」页面运行。主代理随即会收到「已转到后台」的状态反馈，并可立即响应用户的后续提问。

当后台子代理执行完成、发生错误或被主动取消时，系统会向对应会话推送通知，并附带执行结论。

此外，你可以在「后台任务」页面中随时查看进度或手动取消任务。取消后系统会执行清理工作并正常终止子代理，不会残留孤立进程。

## 能看到的细节

若需要审计某次委派的具体执行流程，可前往「轨迹」页面查看详细追踪记录。

每次子代理调用都会生成独立的轨迹记录，完整记录对应的会话编号、所用模型、工具调用链路及耗时数据。父会话的轨迹中仅保留委派发起与最终交付两个节点，完整的中间过程都归档在子代理自身的轨迹记录中。

因此，日常排查建议遵循以下原则：**当父会话中的回答不合预期时，优先定位对应子代理的轨迹记录，从而确认是前置任务描述不足，还是子代理在内部执行时遭遇了异常**。

## 什么时候该用子代理

并非所有交互场景都适合使用子代理。通常可以参考以下判断准则：

- **中间过程远多于结论**：例如检索海量日志、递归扫描工程文件或批量爬取网页等产生大量过程信息的场景。
- **需要干净的上下文**：主会话正在推进特定核心议题，不希望被临时穿插的繁杂操作干扰记忆。
- **并发处理需求**：存在多个互不依赖的探索性调研，希望并行开展以缩短整体等待时间。
- **环境隔离需求**：任务涉及安装依赖、修改本地文件或产生大量终端输出，需要与主环境隔离。

相对地，对于单步即可完成的简单提问，或是需要与用户反复对齐细节的双向交互，交由子代理处理反而会降低效率，因为子代理无法在执行途中接收用户的后续追问。

::: tip
常见的配置误区是尝试让子代理向用户发起追问。子代理缺乏与用户的直接交互渠道，其接收的任务说明必须包含所有完备的上下文输入，并具备独立执行到底的能力。
:::

## 推荐配置

### 个人使用

推荐保持系统默认配置：选用通用子代理、使用「分叉」继承方式，并将模型档位维持在「中」。

默认四层的委派深度已足以覆盖日常绝大部分个人场景。外部后端按需安装即可，避免向未信任的环境开放调用权限。

### 多人群聊

建议在场景规则中收紧可用子代理及执行后端的权限，仅允许群管理员发起委派。

普通成员若能随意触发子代理，不仅容易造成 Token 额度的无谓消耗，还可能因频繁执行外部命令对宿主环境造成干扰。

### 重度编码

推荐安装 Codex CLI 或 OpenCode 扩展插件，为它们配置合适的模型档位，并将执行机器定向到沙箱环境或受管项目目录。

让主会话保持轻量上下文以专注逻辑架构与决策汇总，由子代理在底层负责源码阅读、文件编辑与测试套件执行。

### 省钱模式

可将默认模型档位设为「小」，仅在遇到明确需要深度推理的任务时，在委派参数中手动指定较高档位。

同时可以在场景规则中下调「最大委派层数」并禁用非必要的外部后端，防止深层级嵌套调用引起计费激增。

## 排查

**模型不肯用子代理。**

请先在「工具」页面确认委派工具处于启用状态，且当前场景规则未将其禁用；其次确认所选主模型是否具备原生工具调用能力；最后检查子代理列表中是否有可用配置——若配置列表为空，系统在注入提示词时将不会向模型声明子代理能力。

**委派立刻失败，提示超过深度。**

这表明当前子代理链路已达到最大层数上限。建议精简调用链中的多级嵌套结构，或前往配置项调高「最大委派层数」。

**子代理说找不到之前那个任务。**

任务编号仅在标注为「可续」的子代理中生效，且必须由同一父会话发起接续。如果更换了父会话或切换了子代理名称，均无法沿用旧会话，系统将自动创建全新的子代理实例。

**子代理的结果和预期差很远。**

多数情况下是由于任务说明信息不足。子代理无法获取父会话的历史工具执行结果，也无法监听后续输入。请在任务说明中详细补齐操作目标、限制条件与所需的上下文数据。

**外部后端一直超时。**

请优先验证对应的命令行工具能否在本地终端中独立执行，检查其身份鉴权状态与网络连通性；在确认工具本身正常后，再根据任务体量适当增加超时时间。

**后台任务一直不结束。**

可进入「后台任务」页面查阅其实时运行日志；若确认进程停滞或卡死，可直接在页面中点击取消。取消操作会安全回收子代理资源，不会对父会话造成不利影响。
