# 轨迹与用量

::: tip
本节介绍「轨迹」和「用量」页面的使用方法，帮助你回放每一轮对话的完整执行链路，并统计各模型的调用开销。
:::

## 查看会话轨迹

每次大语言模型调用、每个智能体 (Agent) 执行步骤以及每次工具执行，都会被记录为一个跨度 (Span)，并按父子依赖关系组织为一棵轨迹 (Trace) 树。

你可以通过以下步骤查看执行链路：

1. 前往「轨迹」页面。
2. 在会话列表中选择一个目标会话。
3. 点击需要排查的对话轮次，即可查看该轮对话的完整执行树。

轨迹详情中包含以下技术细节：

- **模型请求**：提示词 (Prompt) 组装内容、模型接口地址以及具体的调用参数。
- **工具调用**：传入参数、执行耗时、返回结果以及用户批准状态。
- **嵌套动作**：子代理调度、技能 (Skill) 读取过程以及 MCP (Model Context Protocol) 调用的执行链路。

::: tip
回放轨迹属于只读记录操作，系统仅展示历史记录，不会重新向模型提供商发起请求，也不会重复执行任何外部工具。
:::

## 轨迹存储与导出

轨迹数据默认保存在本地 SQLite 数据库中：

- **数据保留周期**：默认保留 90 天。你可以通过修改配置项 `retentionDays` 自定义保留天数。
- **离线分析导出**：系统支持可选写入一份 JSONL 格式文件到 `data/chatluna/traces.jsonl`，以便用于离线日志分析与处理。
- **OpenTelemetry 集成**：如果你需要将追踪数据接入现有的可观测性系统，可以启用 `trace-otel`（默认处于禁用状态）。

## 查看用量与成本

「用量」页面用于按天以及按模型汇总令牌 (Token) 的消耗情况：

- **计费统计**：若在模型提供商配置条目中填写了 `pricing` 单价，系统会自动根据 Token 消耗折算并展示实际成本；若未配置 `pricing`，页面将只统计 Token 消耗量。
- **数据一致性**：用量统计口径与轨迹记录保持一致。计费数据统一持久化存储在数据库的 `chatluna_usage_daily` 表中。

## 管理匿名使用统计

实例默认会向官方服务器上报匿名使用统计。上报内容仅包含实例启动事件以及每日的模型和 Token 计数，所有数据均经过加盐哈希处理，不包含任何对话内容或提示词文本。

若你需要停用遥测数据收集：

1. 前往「隐私 · 使用统计」页面。
2. 关闭匿名使用统计开关即可。
