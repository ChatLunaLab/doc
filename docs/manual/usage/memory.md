# 长期记忆

::: tip
长期记忆让机器人跨越会话记住人和事：谁喜欢什么、约定了什么、某个群最近在忙什么。它并不是把整段聊天原封不动地保存下来，而是把真正值得记住的事实提炼成条目，后续有需要时再按需取回。
:::

在开始使用之前，我们先来理清一个常见疑问：短期上下文和长期记忆有什么不同？其实它们负责解决完全不同的问题：

- **群聊记录**负责记住「刚才聊了什么」。它只在当前会话里生效，随着对话轮数变多和上下文压缩，早期的消息会逐渐淡出视野。
- **长期记忆**负责记住「这个人是谁、发生过什么」。它独立于当前的单次会话，哪怕换了一个群、隔了好多天，只要符合规则，机器人依然认得你。

这两套机制完全可以同时开启，互不干扰。关掉群聊记录并不会清除已经沉淀下来的长期记忆；同样，清空了长期记忆，也不会打断当前窗口正在进行的上下文历史。

## 记忆页

打开控制台，在侧边栏找到「能力 → 长期记忆」，即可进入记忆管理面板。在这里你可以查看当前实例保存的所有记忆条目，并对它们进行维护：

- **多维度筛选**：按预设、主题、类型或当前状态快速缩小范围。
- **全文检索**：在搜索栏中输入关键词，直接定位具体的条目内容。
- **追溯来源**：每一条记忆都能查看它的来龙去脉。它是哪次对话、哪条消息带来的？是对话中模型主动写进去的、后台自动提取的、夜间整理生成的，还是管理员手动导入的？
- **条目维护**：支持直接编辑正文、修改属性，也可以对条目执行归档、彻底删除、多条合并或拆分。
- **版本回滚**：条目的每次变更都会留下记录，你可以查看历史版本，必要时一键回滚到过去的状态。
- **导入与导出**：支持把某个预设下的全部记忆打包导出备份，或者直接导入现有的记忆库。

很多初学者容易以为记忆就是一段长文本，但实际上每个条目都是结构化的。每条记忆至少包含主题、标题和正文三个核心部分；除此之外，还可以附带关键词、说话人、重要度评分、情绪倾向、自定义结构化字段以及详细的来源信息。

### 条目类型

为了方便归类与使用，系统预设了几种常见的条目类型：

| 类型 | 说明与典型例子 |
| --- | --- |
| **身份** | 这个人是谁、怎么称呼、在群里担任什么角色等基本属性。 |
| **偏好** | 对方喜欢什么、讨厌什么、习惯使用怎样的语气或用词风格。 |
| **事实** | 客观发生过的事情、大家达成的约定、讨论得出的明确结论。 |
| **计划** | 还没做完的待办事项、未来的约定安排、需要机器人后续提醒的任务。 |
| **上下文** | 某个特定群聊或某段特定时间的背景信息与大环境。 |
| **其他** | 不太适合归入以上常规分类的零散信息。 |

条目的类型主要用于后续的检索排序和定期整理。在平时对话时，你完全不需要纠结当前内容该算哪一类，因为自动提取和睡眠整理阶段会自动识别并打上对应标签。

### 状态

记忆条目具有「活跃」和「归档」两种基本状态：

- **活跃**：条目处于正常生效状态，能够被日常对话直接检索并使用。
- **归档**：条目进入封存状态。归档并不等于删除，它只是不再出现在默认的检索结果里，条目原有的来源和历史版本依然完好保存，你随时可以在列表里将它重新恢复为活跃状态。

如果你点击了「删除」，系统就会真正从底层移除该条目。因此在执行删除前，建议先确认是否有正在进行的会话依然依赖该条目中的事实。

## 记忆的生命周期

长期记忆到底是怎么运作的？简单来说，整个流程可以串成三个核心动作：**写进去**、**取出来**和**定期整理**。

首先是「写进去」：把零散的对话事实提炼成条目；接着是「取出来」：在机器人回答问题时，按需把相关知识送进提示词；最后是「整理」：随着条目越攒越多，系统在空闲时把重复碎片合为一体，去粗取精。

### 自动提取

这就是记忆「写进去」的主要自动化途径。当一个会话里的对话积累到一定数量后，系统就会截取最近的一段消息交给后台模型，从中提炼出值得长久保留的事实，自动创建为记忆条目。

在配置界面中，你可以调整以下选项：

- **自动提取**：提取功能的总开关。如果关掉它，系统就不会在后台自动沉淀记忆，所有条目都需要人工手动添加或批量导入。
- **提取前先判断**：开启后，系统在提取前会先让轻量决策模型看一眼，判断这几句话到底有没有值得记的新信息，确认有价值再执行正式提取。这样能有效节省模型调用消耗，不过每次会多一步前置判断。
- **提取窗口**：指定每累积多少条新消息触发一次提取流程，默认值为 30 条。
- **记忆目录预算**：在提取过程中注入给模型的记忆目录所能占用的最大 Token 数量，默认值为 1500。

需要明确的是，提取并不是简单地把群友的聊天记录原文复制粘贴下来，而是让模型像做笔记一样，提炼出「谁、做了什么事、为什么重要」的核心摘要。当相同的事实被反复提及时，后续的整理阶段会自动合并，完全不必担心日积月累堆出一堆重复的闲聊条目。

### 主动回忆

有了写进去的条目，接下来就是如何在聊天中把它们「取出来」。开启「主动回忆」后，系统会在对话过程中定期拿最近的聊天内容去记忆库里检索，把命中度最高的相关记忆注入到当前轮次的上下文里，让机器人主动想起过去的细节。

- **回忆间隔**：指定每接收多少条消息执行一次主动回忆检索，默认值为 10 条。
- **职责划分**：回忆与提取是方向相反的两个动作——提取管的是「写进去」，回忆管的是「取出来」。
- **按需调用**：即使没有开启主动回忆，机器人也不会彻底变盲。在回答问题时，模型仍然可以通过内置的记忆工具，根据当前探讨的主题主动翻查记忆库，区别仅仅在于系统不会在每轮对话开始前自动帮它带出背景资料。

### 睡眠整理

随着机器人每天和大家聊天，记忆库里难免会积累大量琐碎、相似甚至已经失效的过期条目。这时候就需要第三个动作：整理。

睡眠整理（在很多场合也被形象地称为「做梦」）会在后台将零散冗余的条目合并重写，并将过时的内容转为归档。它通常在两种时机被触发：

- **安静一段时间后**：当前群聊或会话在一段时间内没有任何新发言，系统判断大家已经结束话题，默认阈值为 30 分钟。
- **每晚定时**：选择夜深人静的闲时统一处理，系统默认设置为凌晨 4 点。

在控制台中，可供调整的整理配置包括：

- **允许睡眠整理**：是否开启这项后台自动维护机制。
- **安静时长**：群聊静默多久后开始启动整理。
- **定时整理**：是否开启夜间固定整理，以及每天具体在几点执行。
- **触发条数阈值**：当某个作用域下累积的活跃条目达到多少条时触发整理，默认值为 300 条。

睡眠整理同样不是暴力删除。两段相关事实被合并后，提炼后的精华会保存为新的条目，而原来的旧条目会被标记为归档并保留完整出处。如果你觉得整理后的效果不满意，也可以在记忆页直接查看整理记录并一键撤销。

::: tip
整理任务非常适合放在低谷期安静执行。如果在一个热火朝天的群里把整理频率设得过高，不仅会抢占正常对话的模型调用配额，还可能导致刚刚写进去的记忆条目频繁变动，影响机器人的回答稳定性。一般保持默认的「安静 30 分钟 + 每天凌晨 4 点」就足以满足绝大多数场景。
:::

### 记忆目录与按需读取

不少人会担心：如果存了几千条记忆，每次对话都放进去，岂不是瞬间就把上下文撑爆了？

系统在这方面的设计非常克制：它绝对不会把整库条目一股脑塞给提示词。每次提供给模型的，其实只是一份经过浓缩的「记忆目录」。这份目录按主题分门别类，只列出当前有哪些记忆主题、大概记录了什么事情，并告诉模型如果在回答过程中需要哪块知识，应该通过什么工具去查。

只有当模型确实遇到了相关问题，需要深挖某件事的具体细节时，它才会通过工具去精确读取那个主题下的完整条目。此外，角色引擎还额外提供了按用户调取档案的能力，例如直接查看「某个用户的偏好习惯与历史印象」。

通过这套机制，即使长期记忆库扩充到了成千上万条，对话时的上下文体积也始终保持精炼可控，模型只在真正需要的时候才把关键细节取出来。

## 隔离与作用域

搞清楚了记忆的存取动作，我们接着看它们生效的边界：一条记忆到底应该对谁可见？

每一条记忆都严格绑定在特定的作用域上。这个作用域通常由当前的预设与会话共同确定，在底层还可以进一步细分到具体的聊天平台、群组、频道以及单个用户。在控制台界面中，通常提供两种基础的隔离模式：

| 隔离模式 | 生效机制 | 适用场景 |
| --- | --- | --- |
| **按预设隔离** | 只要使用同一个预设，所有会话都能共享这一整套记忆。一个群里沉淀下来的事实，换到另一个群或者私聊里，机器人依然能够检索得到。 | 适合「同一个角色在所有群里展现连贯设定与完整人生」的场景。 |
| **按会话隔离** | 每个群聊或私聊会话都拥有独立的记忆库，各个群之间互不相通，机器人只能调取在当前会话里提炼出来的条目。 | 适合不同群聊业务彼此独立、互相之间绝对不应该串话或泄露信息的场景。 |

::: warning
请特别注意：隔离模式控制的是「不同会话之间能不能互相读取」，而不是「记忆文件存放在硬盘的哪个目录」。因此，在界面上切换隔离模式并不会自动帮你把旧作用域下的记忆迁移或合并过去。在切换之前，请务必确认旧作用域下的条目是否已经备份或不再需要。
:::

选型的原则非常简单：如果你部署的实例同时服务于多个毫无关联的商业群组或私人群聊，强烈建议选择「按会话隔离」，避免把 A 群的讨论细节不小心带到 B 群；而如果你是想打造一个有血有肉的公共动漫或虚拟角色，让它在每个群里都拥有连续的人格和共同回忆，那么「按预设隔离」会自然得多。

## 记忆的写入来源

进入记忆详情页后，你会看到每条记忆都有明确的「来源」标签。条目的常见写入来源包括：

- **模型**：在聊天进行中，模型根据上下文逻辑通过记忆工具主动写入。
- **提取**：后台提取任务根据近期的聊天记录自动提炼生成。
- **整理**：由睡眠整理对若干相关旧条目进行合并、精简或改写后产生。
- **用户**：管理员或运营者在控制台记忆页中手动新建或编辑。
- **导入**：通过面板导入功能，从备份文件或其他实例打包导入。
- **角色**：由角色引擎自动生成并注入的人物印象卡或群画像数据。

来源标签不仅仅是一项展示属性，它还会直接影响系统对该条目的信任评级与后续维护策略。例如，由用户手动创建或者明确标记为锁定的条目，在后续的睡眠整理中会被系统特别保护，不会被模型擅自合并、改写或归档。

## 存储后端

在默认情况下，所有长期记忆都会以 Markdown 文件的形式直接保存在实例的数据目录中。系统会自动按主题拆分成不同的文件，这种设计非常便于人工翻阅、日常备份或者直接使用文本编辑器微调。

除了默认方案，系统也支持接入不同类型的存储后端：

- **文件型后端**：直接读写 Markdown 文件。它的结构直观透明，可读性极好，非常适合中小规模的日常部署。
- **数据库型后端**：将条目沉淀到专业数据库中。当实例的记忆条目迅速膨胀、日常高并发检索非常频繁时，数据库后端能带来更好的性能和检索响应。

你可以在「长期记忆」的配置面板中自由切换后端类型。不过需要留意的是，切换后端本身不会自动搬运既有数据；如果想要无缝迁移，请先在当前后端下将全部记忆导出为备份文件，切换完成之后再重新导入进去。

::: tip
Markdown 后端最大的优势就在于「所见即所得」。你可以随时在服务器目录里直接打开文件，清楚看到机器人这段时间到底记住了你的哪些细节，也可以在网页端随时修改。唯一的取舍在于，当积累的条目达到极大体量时，纯文件的检索效率会逊色于专门优化的数据库。
:::

## 与角色引擎的关系

长期记忆并不是孤立运作的，它与系统中的角色引擎有着紧密的配合关系。角色引擎底层的几项核心体验都依托于记忆的支持：

- **人物设定与关系**：包括用户对机器人的好感度、机器人对具体用户的印象标签与专属称呼。角色引擎内部维护有状态数据，但更深度的长期羁绊与个性化交互，需要借由长期记忆来持续沉淀。
- **群画像沉淀**：包括一个群聊的基本定位、大家经常聊起的热门话题、活跃成员的各自特点。这些画像的提炼都需要记忆功能持续提供语料输入。
- **近期记忆协同**：在角色引擎中，「近期记忆」特指当前单次会话中的短期摘要，它与跨越漫长时间的长期记忆相互补充、分工协作。

在没有启用长期记忆的情况下，角色依然能够正常回复聊天，但群画像和跨会话长期印象等高阶能力就会缺失。在打开角色的伪装设置页时，界面也会明确提示哪些选项依赖于长期记忆插件的配合。

## 推荐配置

不同使用场景下，记忆相关参数的最佳实践也不尽相同。这里列出几套常见的推荐搭配供你参考：

### 小型私聊助手

如果你把机器人当作私人随身助手，推荐开启「自动提取」和「主动回忆」，同时把提取窗口调小一些（例如设置为 20 条），让它反应更灵敏。记忆目录预算保持适中即可。整理方面可以关掉静默整理，只保留每天夜间一次。隔离方式建议选择「按预设隔离」，这样无论你在哪个私聊窗口找它，它都能共享对你的喜好认知。

### 多群角色

如果你让机器人作为一个性格鲜明的虚拟角色穿梭在好几个群里，推荐选择「按预设隔离」，并把自动提取、主动回忆和睡眠整理全部开启。由于多群接触的话题很广，可以适当调大记忆目录预算，让它知晓更广泛的主题范围，但注意不要调得过高挤占对话空间。同时单独打开群画像功能，以便它能够准确区分各个群聊的不同交流氛围。

### 隐私敏感部署

如果是企业内部、客服或对数据隔离要求极高的多部门环境，请务必选择「按会话隔离」。为了彻底杜绝任何潜在的跨会话串话风险，可以完全关闭后台的「自动提取」，仅由管理员在控制台手动录入可公开的公共业务常识。这样各群聊之间绝不会产生信息交叉，代价则是机器人不会再主动自发地学习群内闲聊。

### 记忆很多的老实例

对于已经稳定运行了很长时间、活跃记忆条目非常多的老实例，建议提高睡眠整理的频次，适当调低触发整理的活跃条数上限，并定期把不再活跃的历史事实转入归档。平时可以多利用记忆页的搜索和筛选工具，手动挑出语义重复的早期条目进行合并；必要时，也可以把记忆完整导出备份后，重新清理并构建一次索引。

## 排查

在日常使用过程中如果遇到记忆相关的问题，可以按下面的思路依次排查：

**它不记得我说过的事。**  
首先检查设置中的「自动提取」开关是否处于开启状态、提取窗口设置是不是太大导致还没攒够触发条数。其次检查隔离模式：如果当前是「按会话隔离」，那么在其他群说过的话这里自然检索不到。最后，建议直接打开控制台的记忆页，在搜索栏里搜一下对应的关键词，确认那段事实到底有没有被成功提取并写入记忆库。

**记忆里全是重复条目。**  
通常是因为「睡眠整理」未开启，或者当前累积的条目数量还没达到触发整理的阈值。你可以在记忆页里手动选中多条重复内容点击「合并」，或者把配置里的触发整理条数阈值适当调低一些。

**记忆越用越贵。**  
如果在账单中发现模型 Token 消耗增长过快，大概率是因为记忆目录预算设得太大，或者主动回忆的触发间隔设置得过于频繁。建议适当减少分配给目录的预算 Token 数、拉长主动回忆的触发间隔，并确认是否开启了「提取前先判断」等有助于过滤无效调用的优化选项。

**切换预设后记忆不见了。**  
当你选择了「按预设隔离」模式时，切换预设在逻辑上就等于切换了一套完全独立的记忆空间。只要切回原来的预设，旧的记忆立刻就会重新出现。如果确实需要把原预设积累下来的记忆搬给新预设使用，可以在记忆页将数据导出为文件，再切换到新预设执行导入。

**整理后条目变少了。**  
请放心，睡眠整理的机制是将多条零散事实合并重写，并将被合并的原条目自动转入归档，绝不会物理删除你的数据。你只需在记忆页顶部将状态筛选切换为「归档」，就能看到所有被归档的原始条目；如果觉得当前整理结果不符合预期，也可以在操作历史中直接撤销最近执行的整理任务。
