# 长期记忆

::: tip
长期记忆让机器人跨会话记住人和事：谁喜欢什么、约定了什么、某个群最近在忙什么。它不保存整段聊天，而是把值得记住的事实提炼成条目，需要时再取回。
:::

长期记忆与群聊记录分工不同：

- **群聊记录**：记住「刚才聊了什么」，只在当前对话中生效，较早的消息会随上下文窗口淡出。
- **长期记忆**：记住「这个人是谁、发生过什么」，独立于会话，换个群或隔很久也能认出你。

两者互不干扰。关闭群聊记录不会清除长期记忆，清空长期记忆也不影响当前对话的上下文。

## 记忆页

前往「能力」→「长期记忆」页面，可以：

- 按预设、主题、类型或状态筛选，或用关键词全文检索。
- 查看条目来源：哪次对话、哪条消息，由模型写入、后台提取、夜间整理还是手动导入。
- 编辑正文和分类，归档、删除、合并或拆分条目。
- 查看修改历史并回滚到任意版本。
- 按预设导出备份，或导入记忆库文件跨实例迁移。

每个条目至少包含主题、标题和正文，还附带关键词、说话人、重要度、情绪倾向、自定义字段和来源信息。

### 条目类型

| 类型 | 说明与典型例子 |
| --- | --- |
| **身份** | 这个人是谁、怎么称呼、在群里担任什么角色。 |
| **偏好** | 喜欢什么、讨厌什么、习惯怎样的语气。 |
| **事实** | 发生过的事、达成的约定、讨论得出的结论。 |
| **计划** | 待办事项、未来的安排、需要提醒的任务。 |
| **上下文** | 某个群或某段时间的背景信息。 |
| **其他** | 不适合归入以上分类的信息。 |

类型由自动提取和睡眠整理自动标注，也可以在条目详情中手动调整。

### 状态

- **活跃**：正常参与检索。
- **归档**：不再参与检索，来源和历史版本完整保留，可以随时恢复。

「删除」会彻底移除条目。不确定以后是否用得到时，优先选择归档。

## 记忆的生命周期

长期记忆由三个动作组成：**写入**（把事实提炼成条目）、**读取**（回复时按话题取回相关记忆）和**整理**（空闲时合并重复、归档过时内容）。

### 自动提取

会话累积的新消息达到指定数量时，系统在后台把最近的消息交给轻量模型，提炼成记忆条目，例如从闲聊中提炼出「某某对某食物过敏」。同一件事多次提到也没关系，整理阶段会自动合并。

- **自动提取**：总开关，关闭后只能手动录入或导入。
- **提取前先判断**：先让决策模型判断是否有新事实，有价值才提取，可以节省 token。
- **提取窗口**：每累积多少条新消息提取一次，默认 30。
- **记忆目录预算**：提取时提供给模型的已有目录的最大 token 数，默认 1500，用来避免重复记录。

### 主动回忆

开启后，系统每隔一定消息数用最近的消息检索记忆库，把最相关的记忆注入上下文。**回忆间隔**默认 10 条，调小更灵敏，调大更省。

提取负责写入，回忆负责读取。即使不开主动回忆，模型仍可以通过记忆工具按需查阅，区别只是系统是否在每轮前自动注入。

### 睡眠整理

在后台合并冗余条目、改写提炼并归档过时内容。触发时机：

- 会话安静一段时间后，默认 30 分钟。
- 每晚定时，默认凌晨 4 点。
- 某个作用域的活跃条目达到阈值时，默认 300 条。

以上都可以在配置中调整，「允许睡眠整理」是总开关。整理不会删除内容：合并时生成新条目，原条目标记为归档并保留来源。对结果不满意可以在记忆页撤销。

::: tip
整理太频繁会消耗调用额度，也会让刚写入的条目频繁变动。通常保持默认的「安静 30 分钟 + 每天凌晨 4 点」即可。
:::

### 记忆目录与按需读取

系统不会把整个记忆库传给模型，而是提供一份按主题分类的「记忆目录」。话题涉及某个主题时，模型再通过工具读取该主题的完整条目。角色引擎还支持按用户读取档案。这样即使记忆库有成千上万条，上下文依然紧凑。

## 隔离与作用域

每条记忆绑定在一个作用域上，通常由预设和会话共同确定，底层可以细分到平台、群组、频道和用户。

| 隔离模式 | 生效机制 | 适用场景 |
| --- | --- | --- |
| **按预设隔离** | 同一预设下的所有会话共享记忆 | 角色在所有群保持统一的记忆 |
| **按会话隔离** | 每个群聊或私聊拥有独立的记忆 | 群之间业务独立，防止串话或泄露信息 |

::: warning
隔离模式控制的是不同会话能否互读，而不是磁盘上的存放位置。切换隔离模式不会迁移或合并已有记忆，切换前请确认旧数据已备份或不再需要。
:::

## 记忆的来源

条目详情中的「来源」标签记录了生成途径：

- **模型**：模型在对话中调用记忆工具写入。
- **提取**：后台提取任务生成。
- **整理**：睡眠整理合并或改写后生成。
- **用户**：在记忆页手动创建。
- **导入**：从备份或其他实例导入。
- **角色**：角色引擎生成的印象或群画像。

来源会影响信任评级和维护策略。例如用户手动创建或锁定的条目在整理时受到保护，不会被自动合并、改写或归档。

## 存储后端

默认情况下，长期记忆以 Markdown 文件保存在数据目录中，按主题拆分，可以直接查看、备份和编辑。也可以切换为数据库型后端，在条目很多、检索频繁时性能更好。

在「长期记忆」配置页切换后端。切换不会自动迁移数据，请先导出，切换后再导入。

## 与角色引擎的关系

角色引擎的好感度、专属称呼、印象标签和群画像都依赖长期记忆沉淀；角色引擎中的「近期记忆」则负责当前会话的短期摘要，与长期记忆互补。未启用长期记忆时角色仍能正常回复，但群画像和跨会话印象不可用，角色配置页会标注哪些选项依赖记忆插件。

## 推荐配置

| 场景 | 建议 |
| --- | --- |
| 小型私聊助手 | 按预设隔离；开启自动提取和主动回忆，提取窗口调到 20 左右；关闭静默整理，只保留夜间整理 |
| 多群角色 | 按预设隔离；开启提取、回忆和睡眠整理，适当调大目录预算；开启群画像 |
| 隐私敏感部署 | 按会话隔离；可以关闭自动提取，由管理员手动录入业务知识 |
| 记忆很多的大型实例 | 提高整理频率、调低触发阈值；定期手动合并重复条目，必要时导出备份后重建 |

## 常见问题

**记不住说过的事**：检查自动提取是否开启、提取窗口是否太大；按会话隔离时，其他群的内容在当前群检索不到。可以在记忆页搜索关键词，确认是否已经入库。

**存在重复条目**：确认睡眠整理已开启，或调低触发阈值；也可以在记忆页手动合并。

**token 消耗过高**：调小目录预算、调大回忆间隔，并开启「提取前先判断」。

**切换预设后记忆消失**：按预设隔离时每个预设有独立的记忆，切回原预设即可。需要在新预设中使用时，先导出再导入。

**整理后条目变少**：原条目被归档而非删除，把状态筛选切换为「归档」即可查看，也可以撤销该次整理。
