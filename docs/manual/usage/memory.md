# 长期记忆

::: tip
长期记忆让机器人能够跨越不同会话记住人和事：谁喜欢什么、约定了什么、某个群最近在忙什么。它并不是把整段聊天原封不动地保存下来，而是把真正值得记住的事实提炼成条目，后续有需要时再按需取回。
:::

在开始使用前，你可能会好奇：平时聊天的群聊记录与长期记忆究竟有什么区别？

简单来说，二者的分工截然不同：

- **群聊记录**：负责记住「刚才聊了什么」。它仅在当前单次对话中生效，随着对话推进，较早的消息会随着上下文窗口滑动而淡出。
- **长期记忆**：负责记住「这个人是谁、发生过什么」。它独立于单次会话，即使换到新群聊或相隔很久未发言，只要符合识别规则，机器人依然能认出你。

这两套机制互不干扰，可以同时开启。关闭群聊记录不会清除已沉淀的长期记忆；清空长期记忆库，也不会影响当前对话正在进行的上下文。

## 记忆页

前往「能力」→「长期记忆」页面，即可进入记忆管理面板。

你可以在这里集中查看当前实例保存的所有记忆条目，并进行日常维护：

- **多维度筛选**：按预设、主题、类型或状态快速筛选，在大量条目中准确定位目标。
- **全文检索**：在顶部搜索栏输入关键词，实时检索正文与标题。
- **追溯来源**：查看记忆的具体来源，包括产生自哪次对话、哪条消息，是由模型主动写入、后台自动提取、夜间整理生成，还是手动导入。
- **条目维护**：直接编辑条目正文与分类属性，执行归档、彻底删除，或合并与拆分条目。
- **版本回滚**：条目的修改与整理均会保留历史记录，可随时查看并一键回滚到指定版本。
- **导入与导出**：支持将指定预设下的记忆打包导出为文件进行备份，或导入现有的记忆库文件以便跨实例迁移。

记忆条目在系统内部是高度结构化的，至少包含「主题」「标题」和「正文」三个核心部分。此外，系统还会附带关键词、说话人、重要度评分、情绪倾向、自定义字段以及详细的来源信息，帮助机器人更好地理解事件背景。

### 条目类型

系统预设了以下几种条目类型，用于后续检索排序和定期整理：

| 类型 | 说明与典型例子 |
| --- | --- |
| **身份** | 这个人是谁、怎么称呼、在群里担任什么角色等基本属性。 |
| **偏好** | 对方喜欢什么、讨厌什么、习惯使用怎样的语气或用词风格。 |
| **事实** | 客观发生过的事情、大家达成的约定、讨论得出的明确结论。 |
| **计划** | 还没做完的待办事项、未来的约定安排、需要机器人后续提醒的任务。 |
| **上下文** | 某个特定群聊或某段特定时间的背景信息与大环境。 |
| **其他** | 不太适合归入以上常规分类的零散信息。 |

平时对话时无需手动指定类型，自动提取和睡眠整理会自动识别句意并打上对应标签。查看条目详情时，也可以在下拉菜单中手动调整所属类型。

### 状态

记忆条目具有「活跃」和「归档」两种状态：

- **活跃**：条目正常生效，可在日常对话中被直接检索和使用。
- **归档**：条目进入封存状态，不再参与日常检索。条目的来源记录与历史版本依然完整保留，随时可以在列表中恢复为活跃状态。

点击「删除」会从底层彻底移除该条目。删除前请确认是否有正在进行的会话依赖该条目；如果不确定未来是否还会用到，建议优先选择「归档」。

## 记忆的生命周期

长期记忆的运作过程主要由三个动作串联而成：**写入**、**读取**与**整理**。

- **写入**：将对话中提到的零散事实提炼为结构化条目存入记忆库。
- **读取**：在回复时根据当下话题，按需将相关背景记忆注入提示词。
- **整理**：在空闲时合并重复碎片，去粗取精，归档过时内容。

下面依次介绍各阶段的具体运作机制。

### 自动提取

自动提取是记忆自动写入的主要途径。当会话累积的新消息达到指定数量时，系统会在后台截取最近的消息片段，交由轻量模型提炼事实并生成记忆条目。

提取不是原样复制聊天记录，而是提炼出「谁在什么背景下说了或做了什么」的核心摘要（例如从闲聊中提炼出「某某对某食物过敏」）。即便同一件事被多次提及，后续整理阶段也会自动合并，不会堆积重复闲聊。

在长期记忆配置中，你可以调整以下参数：

- **自动提取**：自动提取的总开关。关闭后系统不再自动记录，所有条目需手动录入或导入。
- **提取前先判断**：开启后，系统在提取前会先让轻量决策模型预判内容是否包含新事实，确认有价值后再执行提取，可有效节省 Token 开销。
- **提取窗口**：指定每累积多少条新消息触发一次提取，默认为 30 条。调小该值能加快入库速度，但会增加触发频次。
- **记忆目录预算**：提取时注入给模型的记忆目录最大 Token 数，默认为 1500。模型借此参考已有目录，避免重复记录相同主题。

### 主动回忆

开启「主动回忆」后，系统会在对话过程中定期用最近的消息去记忆库检索，并将相关度最高的记忆注入当前上下文，让机器人主动回忆起过去的细节。

相关配置项与说明如下：

- **回忆间隔**：指定每接收多少条消息执行一次主动检索，默认为 10 条。调小此值能提升反应灵敏度，调大则更节省开销。
- **职责划分**：提取负责「写入」（将新对话沉淀为条目），回忆负责「读取」（将已有条目带入上下文）。
- **按需调用**：即使未开启主动回忆，模型在回答时仍可通过内置记忆工具按需查阅记忆库。两者的区别仅在于系统是否会在每轮对话前自动注入背景资料。

### 睡眠整理

睡眠整理用于在后台合并冗余条目、改写提炼并归档过时内容，保持记忆库的精简与准确。

它通常在以下时机触发：

- **安静一段时间后**：会话在一段时间内无新发言时触发，默认静默阈值为 30 分钟。
- **每晚定时**：在设定的闲时固定执行，默认为每天凌晨 4 点。

相关配置项包括：

- **允许睡眠整理**：后台自动维护机制的总开关。
- **安静时长**：会话静默多久后开始整理。
- **定时整理**：是否开启夜间定时整理，以及具体的执行时间。
- **触发条数阈值**：当某个作用域下累积的活跃条目达到该数值时触发整理，默认为 300 条。

睡眠整理不会直接删除内容。合并两段事实时，系统会生成新的提炼条目，并将原条目标记为归档，保留完整来源。如果整理效果不符合预期，可以在记忆页查看记录并一键撤销。

::: tip
建议将整理任务安排在无人聊天的低谷期。若整理频率过高，不仅会占用模型调用额度，还可能导致刚写入的条目频繁变动，影响回答稳定性。通常保持默认的「安静 30 分钟 + 每天凌晨 4 点」即可。
:::

### 记忆目录与按需读取

系统不会将整个记忆库直接传入提示词。每次提供给模型的，仅是一份高度浓缩的「记忆目录」。

目录按主题分类，仅展示包含哪些主题及概要，并指引模型通过工具按需查询。只有当话题涉及特定主题、需要深入细节时，模型才会调用工具读取该主题下的完整条目。此外，角色引擎还支持按用户调取档案（如查看特定用户的偏好与印象）。

通过「平时看目录、按需读正文」的机制，即使记忆库累积了成千上万条内容，对话上下文依然紧凑可控。

## 隔离与作用域

每条记忆都绑定在特定的作用域上。作用域通常由预设与会话共同确定，底层可细分到聊天平台、群组、频道以及单个用户。

系统提供了两种基础隔离模式：

| 隔离模式 | 生效机制 | 适用场景 |
| --- | --- | --- |
| **按预设隔离** | 同一预设下的所有会话共享记忆。在一个群沉淀的事实，在其他群或私聊中也能被检索到。 | 适合需要角色在所有群保持统一设定的场景。 |
| **按会话隔离** | 每个群聊或私聊拥有独立的记忆库，群与群之间互不相通。 | 适合群聊业务相互独立、防止串话或泄露信息的场景。 |

::: warning
隔离模式控制的是「不同会话能否互读」，而不是「文件在磁盘上的存放目录」。切换隔离模式不会自动迁移或合并已有记忆。切换前请确认旧作用域下的数据已备份或不再需要。
:::

根据实际需求选择即可：

- **业务咨询或独立群聊**：建议选择「按会话隔离」，避免将 A 群的讨论内容带到 B 群。
- **公共虚拟角色**：建议选择「按预设隔离」，让角色在所有群聊与私聊中保持连续的情感与记忆。

## 记忆的写入来源

在条目详情页中，「来源」标签记录了该条目的生成途径：

- **模型**：对话过程中，模型根据上下文主动调用记忆工具写入。
- **提取**：后台提取任务根据近期聊天记录自动提炼生成。
- **整理**：睡眠整理合并、精简或改写旧条目后生成的新条目。
- **用户**：在控制台记忆页手动新建或保存的内容。
- **导入**：从备份文件或其他实例导入的条目。
- **角色**：角色引擎自动生成的角色印象或群画像数据。

来源属性会直接影响系统的信任评级与维护策略。例如，用户手动创建或标记为锁定的条目，在睡眠整理时会受到保护，不会被自动合并、改写或归档。

## 存储后端

默认情况下，长期记忆以 Markdown 文件的形式保存在数据目录中，并按主题拆分为不同文件，便于直接查看、备份或使用文本编辑器修改。

系统支持以下存储后端：

- **文件型后端**：直接读写 Markdown 文件，结构直观透明，适合中小规模或个人使用。
- **数据库型后端**：将条目存储在数据库中，在高并发检索和海量条目场景下性能更好。

你可以在「长期记忆」配置页面切换后端类型。注意切换后端不会自动迁移数据；如需迁移，请先导出备份文件，切换后再导入。

::: tip
Markdown 后端的优势在于直观透明，可随时直接查看和编辑文件。但在条目体量极大时，纯文件的检索性能会弱于专门优化的数据库。
:::

## 与角色引擎的关系

长期记忆为角色引擎提供事实沉淀与检索能力，角色引擎的多项特性均依赖长期记忆：

- **人物设定与关系**：包括用户好感度、专属称呼与印象标签等。深度的长期羁绊与个性化交互需要长期记忆持续沉淀。
- **群画像沉淀**：包括群聊定位、常聊话题与活跃成员特点，依赖记忆功能提供语料输入。
- **近期记忆协同**：角色引擎中的「近期记忆」负责当前会话的短期摘要，与跨越长时间的长期记忆分工互补。

未启用长期记忆时，角色依然可以正常回复，但群画像与跨会话长期印象等功能将不可用。角色配置页面中会明确标注哪些选项依赖长期记忆插件。

## 推荐配置

面对不同使用场景，可参考以下配置搭配：

### 小型私聊助手

- **隔离方式**：选择「按预设隔离」，在不同聊天窗口共享喜好认知与历史习惯。
- **提取与回忆**：开启「自动提取」和「主动回忆」，将「提取窗口」调小至 20 条左右以提升响应时效，「记忆目录预算」保持适中。
- **整理**：关闭静默整理，仅保留每天夜间定时整理。

### 多群角色

- **隔离方式**：选择「按预设隔离」，保持统一的人格与记忆。
- **提取与回忆**：同时开启「自动提取」「主动回忆」与「睡眠整理」。适当调大「记忆目录预算」，以覆盖更广泛的话题（注意避免过大挤占上下文）。
- **扩展**：建议开启群画像功能，便于区分不同群聊的氛围与成员特点。

### 隐私敏感部署

- **隔离方式**：务必选择「按会话隔离」，彻底杜绝不同会话间的信息交叉。
- **提取策略**：可关闭后台「自动提取」，由管理员在控制台手动录入公共业务知识。

### 记忆较多的大型实例

- **整理策略**：提高睡眠整理频次，适当调低「触发条数阈值」，定期将不活跃的历史条目转为归档。
- **日常维护**：利用搜索与筛选工具手动合并语义重复的早期条目；必要时可导出备份，清理并重建索引。

## 排查

若使用过程中遇到问题，可按以下方式排查：

**记不住说过的事**  
- 检查「自动提取」是否已开启，「提取窗口」是否设置过大导致尚未达到触发条数。
- 检查隔离模式是否为「按会话隔离」。若是，其他群聊中的发言在当前群聊中无法检索。
- 在「长期记忆」页面搜索对应关键词，确认该事实是否已被成功提取并入库。

**记忆中存在重复条目**  
- 检查是否开启了「睡眠整理」，或当前累积条数是否达到触发阈值。
- 可在记忆页手动选中重复条目并点击「合并」，或调低「触发条数阈值」让系统更早介入整理。

**Token 消耗过高**  
- 检查「记忆目录预算」是否过大，或「回忆间隔」是否设置过短。
- 适当降低目录预算 Token 数、调大回忆间隔，并开启「提取前先判断」以过滤无效调用。

**切换预设后记忆消失**  
- 在「按预设隔离」模式下，不同预设对应独立的记忆空间。切回原预设即可恢复。
- 若需在新预设中使用旧记忆，可在记忆页导出数据文件，再切换至新预设导入。

**整理后条目数量变少**  
- 睡眠整理会将多条碎片事实合并重写，并将原条目转为归档，不会物理删除数据。
- 在记忆页顶部将状态筛选切换为「归档」即可查看原始条目；如对整理结果不满意，可在操作历史中撤销该次整理任务。
