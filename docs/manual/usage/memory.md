# 长期记忆

::: tip
长期记忆让机器人能够跨越不同会话记住人和事：谁喜欢什么、约定了什么、某个群最近在忙什么。它并不是把整段聊天原封不动地保存下来，而是把真正值得记住的事实提炼成条目，后续有需要时再按需取回。
:::

在开始使用之前，很多小伙伴常常会产生一个疑问：平时聊天的群聊记录，和这里说的长期记忆到底有什么区别？

简单来说，它们分管着完全不同的两件事：

- **群聊记录**负责记住「刚才聊了什么」。它只在当前的单次对话中生效。随着大家聊得越来越久，早期的消息会随着上下文窗口的推移逐渐淡出机器人的视野。
- **长期记忆**负责记住「这个人是谁、发生过什么」。它完全独立于当前的单次会话。哪怕换了一个全新的群聊，或者隔了整整一个月没有说话，只要符合识别规则，机器人依然能够准确认出你。

这两套机制完全可以同时开启，彼此分工协作、互不干扰。

关掉群聊记录并不会清除已经沉淀下来的长期记忆；同样地，清空了长期记忆库，也不会打断当前聊天窗口里正在进行的上下文历史。你可以放心地同时使用它们。

## 记忆页

打开控制台，在侧边栏找到「能力 → 长期记忆」，即可进入记忆管理面板。

在这里，你可以集中查看当前实例保存的所有记忆条目，并对它们进行直观的浏览与日常维护：

- **多维度筛选**：支持按预设、主题、类型或当前状态快速缩小显示范围，方便在大量条目中准确定位目标。
- **全文检索**：在顶部的搜索栏中直接输入关键词，系统会实时检索正文与标题，帮你快速找到相关的具体记录。
- **追溯来源**：每一条记忆都能查到它的来龙去脉。它是哪次对话、哪条消息带来的？是对话中模型主动写进去的、后台自动提取的、夜间整理生成的，还是管理员手动导入的？在详情中都一目了然。
- **条目维护**：你可以直接修改条目的正文内容、调整它的分类属性，也可以对条目执行归档、彻底删除，或者将多条琐碎的记录合并为一条，甚至把长条目拆分开来。
- **版本回滚**：条目的每一次修改和整理都会留下清晰的历史记录。你可以随时查看过去的历史版本，并在必要时一键回滚到修改前的状态。
- **导入与导出**：支持把某个预设下的全部记忆完整打包导出为文件进行备份，也可以直接导入现成的记忆库文件，方便在不同实例之间迁移数据。

很多初学者容易以为记忆就是一整段纯文本，但实际上在系统内部，每个条目都是高度结构化的。

一条完整的记忆至少包含主题、标题和正文三个核心部分。

除此之外，系统还可以为它附带关键词、说话人、重要度评分、情绪倾向、自定义结构化字段以及详细的来源信息。这些信息让机器人不仅能知道「说了什么」，还能清楚理解这件事情的背景与分量。

### 条目类型

为了方便归类、检索与后期维护，系统预设了几种常见的条目类型：

| 类型 | 说明与典型例子 |
| --- | --- |
| **身份** | 这个人是谁、怎么称呼、在群里担任什么角色等基本属性。 |
| **偏好** | 对方喜欢什么、讨厌什么、习惯使用怎样的语气或用词风格。 |
| **事实** | 客观发生过的事情、大家达成的约定、讨论得出的明确结论。 |
| **计划** | 还没做完的待办事项、未来的约定安排、需要机器人后续提醒的任务。 |
| **上下文** | 某个特定群聊或某段特定时间的背景信息与大环境。 |
| **其他** | 不太适合归入以上常规分类的零散信息。 |

条目的类型主要用于后续的检索排序和定期整理。在平时对话时，你完全不需要纠结当前内容该算哪一类。自动提取和睡眠整理阶段会自动识别句意，并为提炼出来的内容打上对应的类型标签。

条目类型的划分使得信息检索更加有序。当你查看条目详情时，也可以随时在下拉菜单中调整它的所属类型，方便后续管理。

### 状态

记忆条目具有「活跃」和「归档」两种基本状态：

- **活跃**：条目处于正常生效状态，能够被日常对话直接检索并使用。机器人每轮思考时，都能从活跃条目中调取相关的知识。
- **归档**：条目进入封存状态。归档并不等于彻底删除，它只是不再出现在日常的检索结果里。条目原本的来源记录和历史版本依然完好无损地保存在系统中，你随时可以在列表里将它重新恢复为活跃状态。

如果你在界面上点击了「删除」，系统就会真正从底层移除该条目。因此在执行删除操作前，建议先确认是否有正在进行的会话依然依赖该条目中的事实；如果不确定未来是否还会用到，选择「归档」通常是更稳妥的做法。

在日常使用中，将暂时不用但依然宝贵的信息放入归档，既能给日常检索减轻负担，又不会丢失过去的珍贵回忆。

## 记忆的生命周期

长期记忆到底是怎么运作的？

如果抛开复杂的底层细节，整个运转过程其实非常自然，完全可以用三个核心动作串联起来：**写进去**、**取出来**和**整理**。

- **写进去**：把群友零散聊过的琐碎事实提炼出来，变成规整的记忆条目存入库中；
- **取出来**：在机器人回答问题时，根据当下聊到的话题，把相关的背景记忆按需送进提示词里；
- **整理**：随着条目越攒越多，系统在空闲时把重复的碎片合为一体，去粗取精，淘汰过时的旧内容。

让我们按顺序看看这三个动作具体是如何落实的。

### 自动提取

这就是记忆「写进去」的主要自动化途径。

在日常对话过程中，大家聊的内容往往天南海北。当一个会话里的新对话积累到一定数量后，系统就会在后台截取最近的一段消息交给轻量模型，从中提炼出值得长久保留的事实，自动创建为新的记忆条目。

在控制台的长期记忆配置界面中，你可以对自动提取的行为进行微调：

- **自动提取**：提取功能的总开关。如果关闭这项功能，系统就不会在后台自动沉淀记忆，所有条目都需要人工手动录入或从外部文件批量导入。
- **提取前先判断**：开启后，系统在正式提取前会先让轻量决策模型快速浏览一遍，判断这几句话到底有没有值得记住的新事实。确认有价值后才会执行完整的提取流程。这样能有效避免为无意义的灌水消息调用模型，节省不少调用消耗，不过每次触发时会多一步前置判断。
- **提取窗口**：指定每累积多少条新消息触发一次提取流程，系统默认设置为 30 条。调小这个数值能让新记忆更快入库，但也会相应增加后台提炼的触发频次。
- **记忆目录预算**：在提取过程中注入给模型的记忆目录所能占用的最大 Token 数量，默认值为 1500。这能保证模型在提取新记忆时能参考现有目录，避免重复记录相同主题。

需要明确的是，提取并不是简单地把群友的原话复制粘贴下来，而是让模型像做会议纪要一样，提炼出「谁、在什么背景下、说了或做了什么事」的核心摘要。

例如某位群友在聊天中提到自己对某种食物过敏，模型就会精准提炼出「某某对该食物过敏」这条偏好或事实。即便同一件事被大家反复提及，在后续的整理阶段系统也会自动把它们合并起来，你完全不必担心长期运行后会堆出海量的重复闲聊废话。

### 主动回忆

有了写进去的条目，接下来就是如何在聊天中把它们「取出来」。

开启「主动回忆」后，系统会在对话过程中定期拿最近的聊天内容去记忆库里主动检索，把命中度最高的相关记忆注入到当前轮次的上下文里，让机器人主动想起过去的细节。

在界面上，相关的选项包括：

- **回忆间隔**：指定每接收多少条消息执行一次主动回忆检索，默认值为 10 条。调小这个数值会让机器人对最近的话题反应更灵敏，调大则更节省开销。
- **职责划分**：回忆与提取是方向完全相反的两个动作——提取管的是「写进去」，把新发生的对话沉淀为条目；而回忆管的是「取出来」，把过去记下的知识重新带回脑海。
- **按需调用**：即使没有开启主动回忆，机器人也不会彻底变盲。在回答问题时，模型仍然可以通过内置的记忆工具，根据当前探讨的主题主动翻查记忆库。两者的区别仅仅在于，系统不会在每轮对话开始前自动帮它带出背景资料而已。

在实际使用中，主动回忆就像是机器人的潜意识，在每隔几句话时扫一眼记忆库；而如果它在聊到一半时突然需要查证更久远的事情，依然可以自己调用工具深入调取。

### 睡眠整理

随着机器人每天和大家打成一片，记忆库里难免会积累大量零碎、相似甚至已经失效的过期条目。

这时候就需要第三个动作登场了：整理。

整理的目的，就是为了去粗取精，让记忆库始终保持精干与准确。

睡眠整理（在很多场合也被形象地称为「做梦」）会在后台默默运转，将零散冗余的条目合并重写，并将已经过时的内容转为归档。它通常在两种时机被触发：

- **安静一段时间后**：当前群聊或会话在一段时间内没有任何新发言，系统判断大家已经聊完并离开，便会趁着空闲启动整理。系统默认的静默阈值为 30 分钟。
- **每晚定时**：选择夜深人静的闲时统一处理，系统默认设置为每天凌晨 4 点执行。

在控制台中，你可以根据需要调整整理的各项参数：

- **允许睡眠整理**：是否开启这项后台自动维护机制。
- **安静时长**：群聊静默多久后开始启动整理。
- **定时整理**：是否开启夜间固定整理，以及每天具体在几点执行。
- **触发条数阈值**：当某个作用域下累积的活跃条目达到多少条时触发整理，默认值为 300 条。

睡眠整理同样不是粗暴地删掉内容。

当两段相关的事实被合并后，提炼后的精华会保存为新的条目，而原来的旧条目会被自动标记为归档，并保留完整的来源出处。

如果你觉得整理后的效果不符合预期，随时可以在记忆页查看整理记录，并一键撤销这次整理。

::: tip
整理任务非常适合放在无人聊天的低谷期安静执行。如果在一个热火朝天的群里把整理频率设得过高，不仅会频繁抢占正常对话的模型调用配额，还可能导致刚刚写进去的记忆条目频繁变动，影响机器人回答的稳定性。一般保持默认的「安静 30 分钟 + 每天凌晨 4 点」就足以满足绝大多数场景。
:::

### 记忆目录与按需读取

不少刚刚上手的小伙伴可能会担心：如果机器人存了几千条记忆，每次对话都要放进去，岂不是瞬间就把上下文撑爆了？

系统在这方面的设计非常克制：它绝对不会把整个记忆库一股脑塞给提示词。

每次提供给模型的，其实只是一份经过高度浓缩的「记忆目录」。这份目录按主题分门别类，只列出当前系统里记录了哪些主题、每个主题大概涵盖了什么事情，并告诉模型如果需要深入了解某块知识，应该调用哪个工具去查。

只有当用户确实提到了相关话题、模型需要深挖某件事的具体细节时，它才会通过工具去精确读取那个主题下的完整条目。

此外，角色引擎还额外提供了按用户调取档案的能力，例如直接查看「某个用户的偏好习惯与历史印象」。

通过这套「平时只看目录、需要时才翻正文」的机制，即使你的长期记忆库扩充到了成千上万条，对话时的上下文体积也始终保持精炼可控。

## 隔离与作用域

了解了记忆「写进去、取出来、整理」的完整流程后，我们接着来看它们生效的边界：一条记忆被写进去之后，到底应该对谁可见？机器人又该在什么范围内把它取出来？

每一条记忆都严格绑定在特定的作用域上。

这个作用域通常由当前的预设与会话共同确定，在底层还可以进一步细分到具体的聊天平台、群组、频道以及单个用户。在控制台的设置界面中，系统提供了两种基础的隔离模式：

| 隔离模式 | 生效机制 | 适用场景 |
| --- | --- | --- |
| **按预设隔离** | 只要使用同一个预设，所有会话都能共享这一整套记忆。一个群里沉淀下来的事实，换到另一个群或者私聊里，机器人依然能够检索得到。 | 适合「同一个角色在所有群里展现连贯设定与完整人生」的场景。 |
| **按会话隔离** | 每个群聊或私聊会话都拥有独立的记忆库，各个群之间互不相通，机器人只能调取在当前会话里提炼出来的条目。 | 适合不同群聊业务彼此独立、互相之间绝对不应该串话或泄露信息的场景。 |

::: warning
请特别注意：隔离模式控制的是「不同会话之间能不能互相读取」，而不是「记忆文件存放在硬盘的哪个目录」。因此，在界面上切换隔离模式并不会自动帮你把旧作用域下的记忆迁移或合并过去。在切换之前，请务必确认旧作用域下的条目是否已经备份或不再需要。
:::

那么在实际部署时，我们应该如何选择呢？

选型的原则非常直观：

如果你的机器人同时加入了好几个毫无关联的商业工作群、客户咨询群或不同的私人圈子，强烈建议选择「按会话隔离」。在这种模式下，每个群的记忆都只能在自己群里「写进去」和「取出来」，这样可以彻底杜绝把 A 群的讨论细节或私密数据不小心在 B 群说漏嘴的风险。

反过来，如果你希望打造一个有血有肉的公共虚拟伙伴，让它在所有群聊和私聊里都拥有连续的情感记忆和完整人格，那么选择「按预设隔离」会让对话显得自然连贯得多——无论群友在哪个群与它互动，只要是同一个角色预设，沉淀下来的记忆都能被它顺利取出来并派上用场。

## 记忆的写入来源

进入任意一条记忆的详情页，你都会看到一个清晰的「来源」标签。

它记录了这条记忆最初是通过何种方式诞生的。条目通常包含以下几种常见的写入途径：

- **模型**：在聊天进行中，模型根据上下文的语义逻辑，主动调用记忆工具写进去的新鲜事实。
- **提取**：后台提取任务根据近期的聊天记录自动提炼生成。
- **整理**：由睡眠整理对若干相关旧条目进行合并、精简或改写后产生的新条目。
- **用户**：管理员或运营者在控制台记忆页中手动新建或编辑保存的内容。
- **导入**：通过面板的导入功能，从备份文件或其他实例打包导入进来的记忆。
- **角色**：由角色引擎自动生成并注入的人物印象卡或群画像数据。

来源标签不仅仅是一项展示属性，它还会直接影响系统对该条目的信任评级与后续维护策略。

例如，由用户手动创建或者明确标记为锁定的条目，在后续的睡眠整理中会被系统特别保护，不会被模型擅自合并、改写或归档。这样你手工录入的关键设定就能永远保持原汁原味。

## 存储后端

在默认情况下，所有长期记忆都会以 Markdown 文件的形式直接保存在实例的数据目录中。

系统会自动按主题拆分成不同的文件，这种设计非常直观透明，平时非常便于人工翻阅、日常备份，或者直接使用你喜欢的文本编辑器进行微调。你可以直接看清每一条记下来的事实。

除了默认方案，系统也支持接入不同类型的存储后端：

- **文件型后端**：直接读写 Markdown 文件。它的结构直观透明，可读性极好，非常适合中小规模的日常部署与个人使用。
- **数据库型后端**：将条目沉淀到专业数据库中。当实例的记忆条目迅速膨胀、日常高并发检索非常频繁时，数据库后端能带来更好的性能和更快的检索响应。

你可以在「长期记忆」的配置面板中自由切换后端类型。

不过需要留意的是，切换后端本身不会自动搬运既有数据；如果想要无缝迁移，请先在当前后端下将全部记忆导出为备份文件，切换完成之后再重新导入进去。

::: tip
Markdown 后端最大的优势就在于「所见即所得」。你可以随时在服务器目录里直接打开文件，清楚看到机器人这段时间到底记住了你的哪些细节，也可以在网页端随时修改。唯一的取舍在于，当积累的条目达到极大体量时，纯文件的检索效率会逊色于专门优化的数据库。
:::

## 与角色引擎的关系

长期记忆并不是孤立运作的，它与系统中的角色引擎有着紧密的配合关系。

长期记忆提供了沉淀与检索事实的通用仓库，而角色引擎则负责让机器人呈现出生动的性格与人设。

事实上，角色引擎底层的几项核心体验，都深度依托于长期记忆所提供的能力支持：

- **人物设定与关系**：包括用户对机器人的好感度、机器人对具体用户的印象标签与专属称呼。虽然角色引擎内部维护有状态数据，但更深度的长期羁绊与个性化交互，需要借由长期记忆来持续沉淀。
- **群画像沉淀**：包括一个群聊的基本定位、大家经常聊起的热门话题、活跃成员的各自特点。这些画像的提炼都需要记忆功能持续提供语料输入。
- **近期记忆协同**：在角色引擎中，「近期记忆」特指当前单次会话中的短期摘要，它与跨越漫长时间的长期记忆相互补充、分工协作。

在没有启用长期记忆的情况下，角色依然能够正常回复聊天，但群画像和跨会话长期印象等高阶能力就会缺失。

在打开角色的伪装设置页时，界面也会明确提示哪些选项依赖于长期记忆插件的配合。这样你在配置时就能清楚知道每一项功能到底需要哪些模块协作。

## 推荐配置

在不同的使用场景下，记忆相关参数的最佳组合也不尽相同。

面对丰富的配置项，你可能会一时拿不准该如何搭配。这里整理了几套常见的推荐搭配供你参考：

### 小型私聊助手

如果你把机器人当作私人随身助手，推荐开启「自动提取」和「主动回忆」，同时把提取窗口调小一些（例如设置为 20 条），让它的反馈更加敏锐即时。记忆目录预算保持适中即可。

整理方面可以关掉静默整理，只保留每天夜间定时整理一次。

隔离方式建议选择「按预设隔离」，这样无论你在哪个聊天窗口找到它，它都能共享对你的喜好认知与历史习惯，交互体验最为贴心。

### 多群角色

如果你让机器人作为一个性格鲜明的虚拟角色穿梭在好几个群聊里，推荐选择「按预设隔离」，并把自动提取、主动回忆和睡眠整理全部开启。

由于多群环境下接触的话题往往很广，可以适当调大记忆目录预算，让它知晓更广泛的主题范围，但注意不要调得过高挤占对话空间。

同时建议单独打开群画像功能，以便它能够准确区分各个群聊不同的交流氛围与成员风格，展现出多面而统一的性格。

### 隐私敏感部署

如果是企业内部、客户服务或对数据隔离要求极高的多部门环境，请务必选择「按会话隔离」。

为了彻底杜绝任何潜在的跨会话串话风险，可以完全关闭后台的「自动提取」，仅由管理员在控制台手动录入可公开的公共业务常识。

这样一来，各群聊之间绝不会产生任何信息交叉，业务边界清晰分明；代价则是机器人不会再主动自发地学习群内的日常闲聊。

### 记忆很多的老实例

对于已经稳定运行了很长时间、活跃记忆条目非常多的老实例，建议提高睡眠整理的频次，适当调低触发整理的活跃条数上限，并定期把不再活跃的历史事实转入归档。

平时可以多利用记忆页的搜索和筛选工具，手动挑出语义重复的早期条目进行合并；必要时，也可以把记忆完整导出备份后，重新清理并构建一次索引，让老实例重新焕发敏捷活力。

## 排查

在日常使用过程中如果遇到记忆相关的问题，可以按下面的思路依次排查：

**它不记得我说过的事。**  
首先检查设置中的「自动提取」开关是否处于开启状态、提取窗口设置是不是太大导致还没攒够触发条数。

其次检查隔离模式：如果当前是「按会话隔离」，那么在其他群聊说过的话这里自然检索不到。

最后，建议直接打开控制台的长期记忆面板，在搜索栏里搜一下对应的关键词，确认那段事实到底有没有被成功提取并写入记忆库。

**记忆里全是重复条目。**  
通常是因为「睡眠整理」未开启，或者当前累积的条目数量还没达到触发整理的阈值。

你可以在记忆页里手动选中多条重复内容点击「合并」，或者把配置里的触发整理条数阈值适当调低一些，让系统更早介入整理。

**记忆越用越贵。**  
如果在账单中发现模型 Token 消耗增长过快，大概率是因为记忆目录预算设得太大，或者主动回忆的触发间隔设置得过于频繁。

建议适当减少分配给目录的预算 Token 数、拉长主动回忆的触发间隔，并确认是否开启了「提取前先判断」等有助于过滤无效调用的优化选项。

**切换预设后记忆不见了。**  
当你选择了「按预设隔离」模式时，切换预设在逻辑上就等于切换了一套完全独立的记忆空间。

只要切回原来的预设，旧的记忆立刻就会重新出现。如果确实需要把原预设积累下来的记忆搬给新预设使用，可以在记忆页将数据导出为文件，再切换到新预设执行导入。

**整理后条目变少了。**  
请放心，睡眠整理的机制是将多条零散事实合并重写，并将被合并的原条目自动转入归档，绝不会物理删除你的数据。

你只需在记忆页顶部将状态筛选切换为「归档」，就能看到所有被归档的原始条目；如果觉得当前整理结果不符合预期，也可以在操作历史中直接撤销最近执行的整理任务，条目就会恢复如初。
