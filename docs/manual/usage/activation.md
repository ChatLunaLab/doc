# 什么时候回复

::: tip
这一页讲机器人「要不要开口」。回复得太少像不在线，回复得太多像刷屏；ChatLuna 让这件事由一组可调的判定规则决定，而不是写死的关键词表。
:::

把机器人加入群聊后，最常见的问题是它究竟应该什么时候说话。

如果每来一条消息都抢着接话，群聊很容易被刷屏；但如果每次都必须输入固定指令才理人，又会缺少日常交流的互动感。

在 ChatLuna 中，群聊每收到一条新消息，系统都会在后台进行一次唤醒判定。判定的结果只有三种：

- **回复**：将消息连同前后的聊天记录一起提交给模型，生成回复并发送到群内。
- **只记录**：机器人不回复，但会将消息写入聊天记录，供下次被呼叫时作为上下文参考。
- **忽略**：既不回复，也不写入上下文记录，就像这条消息从未发生过一样。

你无需担心消息判定会产生高额的模型调用费用。绝大多数判定规则均在本地计算完成（例如检测 @、比对名字、统计发言频率等），不需要调用远端大语言模型。除非你主动开启了后文介绍的「小模型判定」，否则判定本身不会产生任何模型开销。

## 默认行为

在刚安装完插件且未修改任何规则时，机器人的默认交互模式十分克制。

直接将机器人加入新群聊后，默认行为如下：

| 情况 | 默认行为 |
| --- | --- |
| 群里有人 @ 它 | 回复 |
| 有人回复它发过的消息 | 不回复（默认关闭） |
| 消息以它的名字开头 | 回复 |
| 消息中间提到它的名字 | 不回复（默认只认开头） |
| 私聊 | 回复 |
| / 开头的指令 | 交给指令系统，不进入对话 |
| 其他人在群里正常聊天 | 不回复，但记进聊天记录 |
| 没人叫它 | 不主动搭话（随机概率为 0） |

从上表可以看出，在默认状态下：

- **群聊**：只有被明确呼叫时才会开口（消息中 @ 了它，或消息以它的名字开头）。在句子中间顺口提到它，或者其他群友正常闲聊时，机器人均不会主动插话。
- **私聊**：默认对每一句话均作回复。
- **指令**：以斜杠等前缀开头的消息会被直接识别为指令，由指令系统执行，不进入模型对话。

其中需要特别说明的是「其他人在群里正常聊天会被记录」：平时机器人在群内作为旁听者记录上下文；当群友呼叫它时，模型就能结合刚才聊过的话题继续对话，而不需要群友重新陈述前因后果。同理，当机器人处于回复冷却期时，群友即使呼叫它，它也只会记录而不回复，以保证上下文的连续性。

如果你只需要机器人「有人找才回答、平时在旁边安静听着」，默认设置就已经能够满足需求，无需修改本页的任何配置。

## 三种判定方式

在场景规则设置的「什么时候回复」面板中，系统提供了三种判定方式：直接触发、气氛判断与小模型判定。

这三者在底层是并行的独立判定，裁决逻辑如下：

1. 只要任意一种已开启的判定方式得出了「回复」的结论，机器人便会生成回复并发送。
2. 只有当所有开启的判定方式均未要求回复时，系统才会继续判断该消息应该「只记录」还是「忽略」。

你可以根据群聊需求选择合适的判定方式：

- **仅在被叫到时回复**：保持默认的「直接触发」即可。
- **希望在群聊热闹时主动接话（零模型成本）**：在直接触发的基础上，开启「气氛判断」。
- **需要精准理解复杂语境与梗（有少量调用成本）**：开启「小模型判定」。

下面逐一介绍各判定方式的配置项。

### 直接触发

直接触发是系统默认启用的判定方式，负责处理最明确的呼叫行为。包含以下设置项：

- **@ 它就回复**：消息中包含聊天平台标准的 @ 元素时触发。纯文本打出的名字不会触发，可避免误判。
- **回复它的消息也算**：群友使用平台的引用回复功能回复机器人时触发。默认为关闭，开启后方便群友连续追问。
- **叫名字就回复**：消息以机器人的名字开头时触发。具体名称可在下方的「它的名字」列表中配置，支持添加多个称呼。
- **句中提到也算**：消息任意位置出现机器人名字时即触发回复。默认为关闭，可避免群友闲聊提及机器人名字时引起插话。
- **私聊直接回复**：开启后，私聊发送的每条消息均会触发对话。若关闭，私聊时也必须 @ 或叫名字才会回复。
- **回复私聊**：私聊的总开关。若不希望机器人在私聊中回复任何消息，关闭此项即可。
- **主动搭话概率**：无人呼叫时随机插话的概率。默认为 `0`，即不主动插话。
- **回复后安静时间**：机器人回复后的保护时间（单位为毫秒）。在此期间即便被呼叫也只会记录而不回复。默认为 `0`，表示不限制回复频率。
- **不回自己的话**：防止机器人回复自己发出的消息，避免消息回环转发时陷入自我对话的死循环。

::: tip
机器人的名字是全局同步生效的：无论在哪个场景规则中修改「它的名字」，匹配规则都会同步更新。如果不同群聊对机器人的称呼不同，直接将所有常用称呼添加到名字列表中即可。
:::

### 气氛判断

开启气氛判断后，机器人可以在群聊热闹时主动接话。

气氛判断无需调用大语言模型，而是在本地实时分析群聊动态，综合以下四个维度的信号：

- **热度**：统计最近 15 分钟、2 分钟和 30 秒内的群消息频率。
- **人数**：统计发言人数及发言分散程度。参与人数越多、分布越均匀，气氛分值越高。
- **线索**：检测是否有人引用回复机器人、叫它的名字或别名，或提及感兴趣的词汇。
- **惯性**：检测在机器人上次发言后，是否有群友顺着话题继续互动。

系统会将上述信号计算为「想说话的冲动」值，并与动态阈值进行比对（阈值受角色作息、距离上次发言的间隔及近期发言总量影响）。冲动值超过阈值后，系统会按照设定的频率抽样，决定是否开口说话。

相关配置项如下：

- **插话频率**：取值范围为 `0` 到 `1`。数值越高，主动插话概率越大；设为 `0` 则不主动插话（不影响正常的 @ 或叫名字回复）。建议初次使用时设为 `0.2` ~ `0.3` 观察效果。
- **感兴趣的关键词**：群友提及列表中的词汇时，机器人会获得更高的冲动加成，更容易参与对应话题。
- **它的别名**：角色的辅助称呼列表，出现时会被视作强烈的呼叫线索。
- **每小时发言上限**：限制每小时主动发言的最高次数。达到上限后开口冲动将大幅衰减，防止过于聒噪。

此外，气氛判断内置了节奏保护机制：两次主动发言之间至少间隔 30 秒。若计算出想发言但抽样未通过，系统会记录跳过标记，避免对同一段聊天内容在短时间内重复计算。

::: warning
出于交互安全性考虑，气氛判断默认仅在「伪装」引擎下启用。「对话」引擎默认仅使用直接触发，避免严肃的知识问答机器人在群聊中意外插话。
:::

### 小模型判定

开启小模型判定后，系统会将最近的聊天记录发送给轻量模型，由模型根据上下文判断「当前是否应该插话」。

这种方式对反讽、群梗等复杂语境的理解更为准确，适合拟人化要求较高的场景。需要注意的是，小模型的每次判定均是一次真实的远端模型调用。

相关配置项如下：

- **判定模型**：指定负责判定的小模型。默认使用内置决策角色，也可从下拉列表中选择其他轻量模型。
- **最低插话把握**：插话置信度阈值，达到该数值才会发言。默认值为 `0.55`。
- **两次判定最小间隔**：同出会话两次判定的最小时间间隔（单位为秒），默认值为 `60` 秒。
- **参考消息条数**：每次判定提供给小模型的最近聊天记录条数。条数越多判定越精准，但消耗的上下文也越多。
- **给模型看的简介**：向模型说明机器人的性格、喜好以及适合插话的场景。留空时系统会自动根据人设信息提取生成。
- **感兴趣的关键词**：命中关键词时将跳过前置冲动计算，直接发起小模型判定。
- **每天判定次数上限**：限制单日判定次数，防止活跃群聊产生过高费用。默认上限为 `200` 次。
- **同时判定数量**：全局小模型判定并发上限，默认值为 `2`。

为节省调用费用，系统会对单条消息的判定结果进行本地缓存，避免重复请求。此外，小模型除给出「回复」或「不回复」外，还可给出「稍后回复」的建议，系统会依据给出的延迟时间跟进回复。

::: tip
小模型判定是用于辅助识别语境的工具。如果群聊以明确 @ 和叫名字的日常问答为主，无需开启此项，以免增加延迟和调用费用。
:::

## 只记录与忽略的区别

在后台记录中，「只记录」与「忽略」的处理方式截然不同：

- **只记录**：消息正常写入聊天记录数据库，机器人下次被呼叫时，模型可在上下文中完整读取这段历史。冷却期内的呼叫、连续短消息合并、气氛判断跳过的消息以及群友的日常闲聊均属于此类。
- **忽略**：消息被系统直接丢弃，不进入上下文。机器人自身发出的消息、以指令前缀开头的命令、被安全过滤插件拦截的内容，以及关闭私聊总开关时的私聊消息均属于此类。

在配置场景规则时：

- **何时使用「只记录」**：正常的闲聊与讨论应保持记录，以便群友 @ 机器人追问前置话题时，模型能了解来龙去脉。
- **何时使用「忽略」**：仅将与对话完全无关或易引起模型混淆的内容设置为忽略，例如管理指令、系统通知或违规审核未通过的消息。

::: warning
请勿为了节省上下文而将正常群聊设为忽略。若上下文丢失，机器人被叫到时将无法结合前文作答。如需控制上下文长度，请通过「群聊记录」中的条数上限、历史回填策略和媒体限制进行配置。
:::

## 主动说话

除了对收到的消息做出判定，ChatLuna 还支持根据时间或场景主动开启新话题：

- **冷场时主动搭话**：长时间无人发言时，机器人会主动发起话题打破沉默。若发言后仍无人回应，系统将启用退避机制，逐步延长下一次尝试搭话的间隔。
- **稍后继续聊**：在回答复杂问题后，隔一段时间主动跟进后续（如询问进展或提醒）。
- **话题相关就插话**：群友聊到与角色设定高度相关的话题时主动开口插话。注意：此功能需先启用小模型判定才能生效。
- **早晚安问候**：根据角色的作息设定，在早晨醒来和睡前主动向群内打招呼。

主动说话严格受角色作息制约。若角色处于「睡眠」状态，机器人不会主动发言，只能通过直接呼叫唤醒。此外，主动说话同样遵循每小时发言上限与冷场退避限制，避免在夜间或成员忙碌时造成打扰。

## 推荐配置

针对常见的使用场景，推荐以下配置方案：

### 普通问答群

适用于客服答疑、知识库查询与工具助手等场景，核心需求为稳定、不干扰正常交流。

- **推荐方案**：开启直接触发中的「@ 它就回复」「叫名字就回复」与「私聊直接回复」。
- **关闭选项**：关闭「主动搭话概率」「气氛判断」和小模型判定。
- **效果**：机器人平时不发言，仅在被明确呼叫时精准作答，不浪费调用额度，不打扰群内日常交流。

### 角色扮演群

适用于作为群内的虚拟同伴或活跃气氛的陪伴机器人。

- **推荐方案**：开启直接触发与气氛判断。将「插话频率」先设为 `0.2` ~ `0.3` 观察效果，并在「感兴趣的关键词」中填入角色人设深度关心的几个爱好话题。
- **关闭选项**：若不打算承担额外的判定模型成本，保持小模型判定关闭即可。
- **效果**：群友聊到感兴趣的内容时自然插话。群聊较活跃时，可适当调低「每小时发言上限」，避免频繁刷屏。

### 大群 / 高风险群

适用于成员众多、发言频繁的大型群聊。

- **推荐方案**：在直接触发的基础上，谨慎启用小模型判定。
- **调整建议**：调高「最低插话把握」，增大「两次判定最小间隔」，并设置较小的「每天判定次数上限」。观察一段时间的实际回复质量与调用账单后再按需放宽。
- **效果**：在保留拟人化插话的同时，严格控制风险与调用成本。

### 私聊为主

适用于将机器人主要作为个人助理使用、群聊仅作辅助展示的场景。

- **推荐方案**：在全局配置中关闭群聊随机搭话与气氛判断，保持私聊为「直接回复」。
- **调整建议**：若少数群聊需要机器人发言，使用「场景规则」为指定群聊单独配置，避免在全局设置中放开。
- **效果**：私聊随时随问随答，群聊环境保持安静可控。

## 排查

如果机器人的回复表现不符合预期，请参考以下条目进行排查：

**机器人不回复**

- 确认发送的消息是否以指令前缀开头，导致被指令系统拦截。
- 确认是否在设置中关闭了「回复私聊」总开关，或发送者是否为机器人自身账号。
- 检查对应场景规则中的直接触发开关是否开启。
- 确认机器人是否正处于上次发言后的「回复后安静时间」冷却保护中。

**机器人在群里频繁插话**

- 检查是否误开启了气氛判断或小模型判定。可尝试调低「插话频率」，或调高小模型的「最低插话把握」。
- 在直接触发中关闭「句中提到也算」，避免群友闲聊无意提及名字时触发回复。
- 检查是否存在特定群聊的独立场景规则覆盖了全局设置。

**只记录不回复**

- 群友呼叫了机器人但未收到回复，而在后台日志中可以看到记录。这通常属于冷却保护期或连续消息合并时的防刷屏机制。可稍等片刻待冷却时间过去，或使用标准的 @ 元素重新呼叫。消息能够被正常记录，说明系统运作正常。

**判定很慢**

- 从群友发话到机器人开始回复之间存在明显延迟。多见于开启了小模型判定的场景，因为每次判定均需等待远端模型响应。可调大「两次判定最小间隔」，或直接关闭小模型判定，改用直接触发搭配气氛判断。
