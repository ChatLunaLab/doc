# 什么时候回复

::: tip
这一页讲机器人「要不要开口」。回复得太少像不在线，回复得太多像刷屏；ChatLuna 让这件事由一组可调的判定规则决定，而不是写死的关键词表。
:::

把机器人拉进群聊后，最让人头疼的问题往往是它究竟什么时候该说话。

如果群里每来一条消息它都抢着接话，整个群聊很快就会变成机器人的单口相声，甚至引来群友的反感。

但如果必须输入格式僵硬的固定指令它才理人，群内聊天又会显得索然无味，完全没有和 AI 伙伴日常互动的真实感。

在 ChatLuna 中，群聊里每来一条新消息，系统都会在后台快速做一次唤醒判定。判定的最终结果只有三种：

- **回复**：把这条消息连同前后的聊天记录一起交给模型，生成回复并发送到群里。
- **只记录**：机器人保持安静不说话，但会把消息悄悄记进聊天记录中，等下次被叫到时模型看得见。
- **忽略**：既不产生回复，也不将内容写入上下文记录，就像这条消息从未发生过一样。

看到这里，很多刚接触的小伙伴可能会犯嘀咕：群里每一条消息都要在后台做判定，会不会产生大量的模型调用费用？

答案是完全不用担心。

绝大多数判定规则都是在本地直接计算完成的（比如检测艾特、比对名字、统计发言频率等），完全不需要调用远端大语言模型。

除非你主动开启了后面会介绍的「小模型判定」，否则无论群里聊得多热闹，都不会因为判定本身产生任何模型开销。

## 默认行为

在刚安装完插件、没有修改过任何规则时，机器人的默认交互模式是非常克制且礼貌的。

如果你直接把它拉入一个新群聊，在默认设置下，它的行为表现大致如下：

| 情况 | 默认行为 |
| --- | --- |
| 群里有人 @ 它 | 回复 |
| 有人回复它发过的消息 | 不回复（默认关闭） |
| 消息以它的名字开头 | 回复 |
| 消息中间提到它的名字 | 不回复（默认只认开头） |
| 私聊 | 回复 |
| / 开头的指令 | 交给指令系统，不进入对话 |
| 其他人在群里正常聊天 | 不回复，但记进聊天记录 |
| 没人叫它 | 不主动搭话（随机概率为 0） |

从表格中可以看出，在开箱默认的状态下，机器人遵循的是非常明确的呼叫原则：

在群聊环境中，只有被大家明确呼叫时它才会开口——要么是群友在消息中直接 @ 了它，要么是消息开头带上了它的名字。

如果大家只是在句子中间顺口聊到它，或者在群里正常闲聊，它一概不会主动插话。

而在私聊环境中，因为是一对一的专属交流，它默认会对你的每一句话有问必答。

如果消息以斜杠等前缀开头，系统会直接将其识别为管理命令并转交给底层的指令系统去执行，根本不会惊动大语言模型。

在这套设计理念中，最值得关注的一项其实是「其他人在群里正常聊天会被记录」。

既然机器人现在不打算说话，为什么还要大费周章地把别人的闲聊存进聊天记录里呢？

不妨设想一个日常的聊天场景：你正坐在朋友们身边听他们热烈讨论，虽然你全程安静没有插嘴，但大家聊过的内容你其实都听在耳中。

当有人突然转头问你「你怎么看」时，你立刻就能根据刚才听到的话题发表看法，而不需要大家把前因后果重新给你讲一遍。

ChatLuna 的设计正是模拟了这种自然的社交逻辑。

平时它在群里做一个安静的旁听者，默默整理上下文；一旦某位群友正式呼叫它，它就能立即接住刚才的话题往下聊。

同理，当机器人处于回复冷却期时，群友即便叫它，它也只会记录而不会开口——如果直接把这些消息丢弃掉，它的记忆链条就会出现断层和空洞。

**操作建议：** 如果你对机器人的期望就是「有人找它才回答、平时在旁边安静听着」，那么开箱后的默认设置就已经完全够用，你甚至不需要修改本页中的任何选项。

## 三种判定方式

打开场景规则设置，进入「什么时候回复」面板，你会发现系统提供了三种各司其职的判定方式：直接触发、气氛判断与小模型判定。

它们在底层是彼此独立的并行关系。系统在处理新消息时，遵循着一条非常直截了当的裁决逻辑：

只要开启的任意一种判定方式得出了「回复」的结论，机器人就会立即生成回复并开口说话；

只有当所有开启的判定方式都没有要求回复时，系统才会进一步根据其它条件，判断这条消息是应该「只记录」还是彻底「忽略」。

面对这三种判定方式，你可以根据自己的群聊类型快速判断该开哪一项：

- **只想在被叫到时才回答**：保持默认的「直接触发」即可，其他两项完全不需要开启。
- **想在群里热闹时主动接话、且零成本**：在直接触发的基础上，开启「气氛判断」。
- **想精准理解复杂语境与梗、愿意承担少量调用成本**：开启「小模型判定」。

下面让我们逐一看看它们的具体设置项与使用技巧。

### 直接触发

直接触发是系统默认启用的基础判定方式，负责处理群聊中最直观、最确定的呼叫行为。

你在面板中可以调整以下设置项：

- **@ 它就回复**：消息中包含真实的聊天平台 @ 元素时触发。系统只认平台标准的艾特提醒，单纯文字打出来的名字前缀并不会触发，这样可以有效防止群友文字调侃时的误触发。
- **回复它的消息也算**：当别人使用平台的引用回复功能回复机器人发过的消息时，是否视为在叫它。这项功能默认关闭；如果你希望群友在追问时更加顺手，可以主动将它开启。
- **叫名字就回复**：消息以机器人的名字开头时直接触发。具体哪些词算它的名字，可以在下方的「它的名字」列表中添加，支持设置多个称呼。
- **句中提到也算**：开启后，只要句子的任意位置出现了它的名字就会触发回复。这项功能默认保持关闭，避免群友在聊天中无意间顺嘴提到机器人时频繁引起插话。
- **私聊直接回复**：针对私聊场景的便捷选项。开启时，私聊里的每一条消息都会直接进入模型对话；如果关闭它，即便在私聊窗口里，你也必须手动 @ 或者叫它的名字它才会理你。
- **回复私聊**：私聊环境的总开关。如果你彻底不希望机器人在私聊中回复任何人，直接将这个总开关关掉即可。
- **主动搭话概率**：当群里完全没人呼叫它时，按照设定的概率随机回上一句。默认数值为 0，也就是完全不主动进行随机插话。
- **回复后安静时间**：机器人回复后的一段保护时间（单位为毫秒）。在此期间内即便群友再次叫它，它也只会默默记录而不再开口。默认值为 0，表示不限制回复频率。
- **不回自己的话**：严格防止机器人对自己发出的消息做出回复，避免在消息回环转发等特殊情况下陷入自我对话的无限循环。

::: tip
机器人的名字是全局同步生效的：无论你在哪一条规则里修改了「它的名字」，聊天平台侧的昵称匹配也会一并更新。如果不同群聊里的群友习惯使用不同的称呼，只需要把所有常用称呼统一填进名字列表即可。
:::

### 气氛判断

如果你希望机器人更像一个真实的群友，在群里聊得热火朝天时能够主动接话，那么可以尝试开启气氛判断。

与死板的关键词匹配不同，气氛判断完全不需要调用大模型，而是通过在本地实时综合分析最近一段时间内的群聊动态，从中提炼出四个核心维度的信号：

- **热度**：综合统计最近 15 分钟、2 分钟以及 30 秒内的群消息发送频率，判断当前群里是冷清还是爆热。
- **人数**：统计参与发言的群成员数量及其发言分散程度。说话的人越多、越分散，整体气氛的分数就越高。
- **线索**：监测群聊中是否有人在引用回复它、叫它的名字、提到它的设定别名，或者聊到了它感兴趣的特定词汇。
- **惯性**：观察在机器人上次公开发言之后，群里是否有人顺着它的话题接茬互动。

系统会将这四个维度的信号综合折算为一个「想说话的冲动」数值，并将其与当前的动态阈值进行比对。

这个阈值并不是一成不变的，它会受到角色的作息状态、距离上次发言的时间间隔以及最近发言总量的动态制约。

当冲动值累积到突破当前阈值时，系统还会按照你设定的频率进行抽样，最终决定此时此刻是否真正开口说话。

在气氛判断中，你可以根据需要调整以下具体项目：

- **插话频率**：数值范围在 0 到 1 之间。设定值越高，机器人在热闹时插话的概率就越大；设为 0 时则完全不主动插话，但并不影响正常的被 @ 或叫名字回复。建议初次尝试时设置为 0.2 到 0.3 观察效果。
- **感兴趣的关键词**：当群友聊到列表中的特定词汇时，机器人会获得更高的冲动加成，更容易参与进对应的话题。
- **它的别名**：为角色配置的辅助称呼列表。群聊中一旦出现这些别名，系统就会将其视为强烈的呼叫线索。
- **每小时发言上限**：限制机器人一小时内主动发言的最高次数。一旦发言数量超出这个限制，它开口的冲动就会大幅衰减，防止过于聒噪。

为了避免出现接连抢话的情况，气氛判断内置了硬性节奏保护：两次主动开口之间至少要间隔 30 秒。

当系统计算出「想说话但这次抽样决定不说」时，内部也会记下一次跳过标记，避免同一批聊天内容在短时间内被反复计算。

::: warning
出于交互安全性考虑，气氛判断默认只在「伪装」引擎下启用。「对话」引擎在默认状态下只使用直接触发，避免严肃的知识问答机器人在群聊中毫无预兆地突然插话。
:::

### 小模型判定

如果你觉得基于统计的气氛算法仍然不够聪明，拿捏不准复杂的群聊语境，可以开启小模型判定。

开启后，系统会把最近的一小段聊天记录交给一个响应极快、费用极低的小模型，由它来阅读上下文并直接回答「现在要不要插话」。

这种方式对反讽、群梗以及微妙的谈话语境有着更准的理解，非常适合需要高度拟人化互动的群聊。但需要明白的是，小模型的每一次判定都是一次真实的远端模型调用。

在小模型判定中，包含以下可调参数：

- **判定模型**：指定负责判定的小模型，默认使用内置的决策角色，也可以在下拉列表中指定其他轻量模型。
- **最低插话把握**：小模型给出的插话置信度必须达到这个分值时才会真正开口，默认值为 0.55。
- **两次判定最小间隔**：同一个群聊会话中，进行一次判定后必须等待的时间（单位为秒），默认值为 60 秒。
- **参考消息条数**：每次判定时打包给小模型参考的最近聊天记录条数。给的条数越多判定越精准，但消耗的上下文也越多。
- **给模型看的简介**：向小模型说明机器人的性格、喜好以及适合插话的场景。留空时系统会自动根据人设信息提取生成。
- **感兴趣的关键词**：群消息中一旦命中了这些词汇，系统会跳过前置冲动计算，直接发起小模型判定。
- **每天判定次数上限**：防止群聊异常活跃导致费用超标的安全护栏，默认上限为 200 次。
- **同时判定数量**：全局所有会话加起来的小模型判定并发上限，默认值为 2。

为了尽可能替你节省费用，判定结果会针对单条消息进行本地缓存，绝不会对同一条群消息反复向模型发起询问。

更有意思的是，小模型除了回答「该说」或「不说」之外，还可以给出「等一会再说」的建议，系统收到后会按照它给出的时间延迟进行跟进回复。

::: tip
小模型判定并不是单纯用来替代直接触发的升级版，而是拿不准语境时多问一句的辅助工具。如果你的群里主要都是明确 @ 和叫名字的日常问答，完全没有必要开启这项功能；开了只会凭空增加等待延迟和调用费用。
:::

## 只记录与忽略的区别

很多新手用户在查阅后台记录时，经常会把「只记录」与「忽略」混为一谈。

从表面上看，这两种状态下机器人都没有在群里公开发言，但它们对后续对话的影响却有着天壤之别：

- **只记录**：消息会正常写进聊天记录数据库中，下次机器人被叫到时，模型能在上下文里完整读到这段历史。包括冷却期内的呼叫、多条短消息连发合并、气氛判断判定跳过的消息，以及其他群友平时的正常闲聊，都属于这一类。
- **忽略**：消息彻底被系统丢弃，完全不进入上下文窗口。机器人自己发出的消息、以指令前缀开头的管理命令、被安全过滤插件直接否决的内容，以及私聊总开关关闭时的私聊消息，都属于这一类。

理解了这两者的差异，你在配置场景规则时就能做出清晰的取舍：

- **什么情况下该「只记录」？** 凡是群友之间正常的闲聊、讨论或可能成为后续对话背景的信息，都应该保持记录。这样当群友突然艾特机器人询问「刚才聊的那个话题你怎么看」时，机器人才能完整掌握前因后果。
- **什么情况下该「忽略」？** 只有那些与大模型对话完全无关、或者会让模型理解产生混淆的内容，才应该彻底忽略。例如管理指令、平台的系统通知，或者安全审核不通过的内容。

::: warning
千万不要为了节省上下文把正常群聊随意关成忽略。如果机器人下次被叫到时完全看不见刚才群友聊了什么，回答就会显得像失忆一样前言不搭后语。真正需要控制上下文消耗时，应该使用「群聊记录」里的条数上限、历史回填策略和媒体限制，而不是切断消息来源。
:::

## 主动说话

除了对群友发送的消息做出判定之外，ChatLuna 还提供了一组独立的「主动说话」功能。

与「什么时候回复」侧重于被动响应不同，主动说话是机器人根据时间或场景自主开启新话题的机制：

- **冷场时主动搭话**：群里很长时间完全没人说话时，机器人会主动抛出话题打破沉默。如果发言后仍然没人理会，系统会自动启动退避机制，将下一次尝试搭话的时间间隔逐渐成倍拉长。
- **稍后继续聊**：允许机器人在回答完某个复杂问题后，自行决定过一段时间再来跟进后续，比如主动追问进展或发出提醒。
- **话题相关就插话**：判定群友聊起的话题与自己的设定高度相关时主动开口插话。注意：这项功能必须先启用小模型判定才能生效。
- **早晚安问候**：按照角色设定的日常作息，在早晨醒来和夜间入睡前向群友主动打招呼。

需要格外注意的是，主动说话会严格受到角色当前作息的制约。

当设定的作息处于「睡眠」状态时，机器人绝不会无端主动发起任何发言，此时只有直接呼叫才能叫醒它。

此外，主动说话也必须服从每小时发言上限以及冷场退避的频率限制，避免在半夜或者大家忙碌时造成打扰。

## 推荐配置

面对面板里众多的开关和参数，很多读者可能会觉得无从下手。

针对几种最典型的群聊场景，我们推荐以下配置组合，帮助你快速上手：

### 普通问答群

如果你搭建机器人的主要目的是用于办事、知识查询、客服支持或文档答疑，核心要求是安静、稳定、不干扰群友交流。

- **推荐方案**：只保留直接触发里的「@ 它就回复」、「叫名字就回复」以及「私聊直接回复」。
- **关闭选项**：彻底关闭主动搭话概率、气氛判断以及小模型判定。
- **效果**：机器人平时完全不吭声，只有被明确叫到时才会精准回答，既不浪费 API 额度，也不会打扰群内日常交流。

### 角色扮演群

如果你希望机器人作为群里的虚拟同伴或活跃气氛的吉祥物，展现鲜明的个性。

- **推荐方案**：启用直接触发并开启气氛判断。将「插话频率」先从 0.2 到 0.3 开始尝试，并在「感兴趣的关键词」中填入角色人设深度关心的几个爱好话题。
- **关闭选项**：如果不打算承担额外的判定模型成本，保持小模型判定关闭即可。
- **效果**：群友聊到感兴趣的内容时它会自然插话。如果群聊本身日常非常活跃，记得把「每小时发言上限」适当调低一些，避免角色过度抢戏刷屏。

### 大群 / 高风险群

如果群内成员多达数百上千人，消息发送极其频繁，单纯依靠关键词或频率统计容易引起误判。

- **推荐方案**：在直接触发的基础上，谨慎启用小模型判定。
- **调整建议**：将「最低插话把握」调高到更保守的数值，并将「两次判定最小间隔」适当拉大。同时，把「每天判定次数上限」先设小一些，在群内灰度观察一周的实际回复质量和调用账单，再根据反馈决定是否放宽。
- **效果**：既保留了拟人化的插话灵性，又通过额度和置信度双重保险牢牢锁住了风控与开销。

### 私聊为主

如果你主要在私聊中将机器人作为个人助理使用，群聊只作为顺带展示。

- **推荐方案**：在全局配置中关闭群聊里的随机搭话和气氛判断，保持私聊为「直接回复」。
- **调整建议**：如果偶尔有个别特殊的交流群需要它参与发言，请使用「场景规则」功能为那个群单独配置一套规则，而不是在全局设置中盲目放开。
- **效果**：私聊体验随时随地、随问随答；而群聊环境保持绝对安全可控，互不干扰。

## 排查

在实际使用中，如果机器人的开口表现与你的预期不符，可以按照以下条目逐步排查：

**它不理我。**  
首先确认你发送的消息是否以指令前缀开头，导致消息被当成了管理命令；再确认是否在设置里关闭了「回复私聊」的总开关，以及消息发送者是否为机器人自己的账号。接着查看对应场景规则中的直接触发开关是否开启，最后确认机器人是否正处于上次发言后的「回复后安静时间」冷却保护中。

**它在群里乱插话。**  
请检查是否误开启了气氛判断或小模型判定。你可以尝试调低插话频率、提高小模型的最低插话把握，或者在直接触发设置中关掉「句中提到也算」以避免名字被群友无意提及。另外，也可能是某个群单独配置的场景规则覆盖了你的全局设置。

**它只记录不回复。**  
群友呼叫了机器人但它没有回复，后台日志中却能看到记录。这通常属于冷却保护期或多条短消息连发合并时的正常防刷屏机制。你可以稍等几秒等待冷却时间过去，或者直接使用明确的 @ 元素再次呼叫。记录消息本身说明系统运作完全正常，并非系统故障。

**判定很慢。**  
从群友发话到机器人开始回复之间存在明显的等待卡顿。这种情况多半发生在开启了小模型判定的场景中，因为每次判定都要额外等待一次大语言模型的远端网络往返。你可以把「两次判定最小间隔」调大，或者直接关闭小模型判定，改用毫无延迟开销的直接触发配合气氛判断。
