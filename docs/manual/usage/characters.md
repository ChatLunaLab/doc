# 角色与预设

::: tip
预设决定「它以什么人格说话」，伪装决定「它在群里看起来是谁、过着什么样的生活」。两者可以分开用，也可以组合成一套完整角色。
:::

在许多聊天场景中，我们常常希望机器人不仅能回答问题，还能拥有生动的性格与鲜活的生活感。在 ChatLuna 里，这两件事在底层被清晰地解耦为两个层次：

- **预设 (Preset)**：一段可自由编辑的提示词与人格设定，核心作用是决定模型在对话开始时会收到什么样的系统提示。
- **伪装 (Character)**：由角色引擎带来的完整能力层，涵盖了状态、好感度、作息节律、近期记忆、互动动作以及思考方式。它必须依赖一份「角色预设」来作为自身的人格基石。

换句话说，如果只给机器人配置普通预设，它本质上仍是一个口吻固定的 AI 助手；但只要把角色预设交给伪装引擎托管，机器人就会真正鲜活起来——它会记住群里每个人的好感度与专属称呼，会在深夜按时睡觉，会在高兴时发送表情与贴图，甚至能察觉群聊气氛并主动接话。

## 预设页

如果你想要创建新角色或调整现有设定，预设页就是你的主工作台。

打开控制台，在侧边栏点击「配置 → 预设」，这里完整列出了当前实例中所有可用的预设模板。整个页面支持按名称实时搜索，也支持按预设类型进行快速筛选。

在列表中，你会看到几类不同来源的预设：

- **本地预设文件**：保存在数据目录中的自定义预设，支持自由编辑、重命名、复制或导出分享。
- **插件内置预设**：随插件或扩展包预装的只读预设，不能直接改动，但你可以随时查看内容或一键复制成副本进行二次创作。
- **导入获得的预设**：从早期版本迁移过来的旧预设，或是从其他实例导入的角色预设文件。

当你点击列表中的任意预设后，就会进入两栏布局的编辑工作区：左侧是源码编辑器，右侧则是所见即所得的实时渲染预览。

### 编辑与保存

在编辑预设时，你只需要专注于撰写角色设定，界面会实时反馈提示词的装配效果：

- **语法高亮与智能提示**：编辑器不仅对文本结构提供高亮，还能识别模板变量。输入左大括号时，编辑器会自动弹出补全浮窗，列出当前可用的全部变量名与内置辅助函数。
- **多维度实时预览**：当你停止输入片刻后，右侧预览区会严格按照模型实际接收到的装配顺序，依次呈现系统提示、前置引导对话、上下文环境以及包裹后的用户输入，并实时估算消耗的 token 数量。
- **调试环境切换**：你可以随时在右侧上方切换模拟的预览环境，例如从私聊切到群聊、更换模拟的用户名或群名称。这些切换只用于观察渲染结果，绝不会修改预设本身的文本。
- **保存与冲突提示**：修改完成后可以通过快捷键保存。未保存的草稿会自动暂存在当前浏览器缓存中，即使用户不小心刷新页面也不会丢失。如果预设文件在外部被其他程序修改过，点击保存时系统会弹出提示，由你决定是覆盖磁盘文件还是重新载入外部内容。

编写过程中产生的语法隐患也会直接在左侧源码中划线标出。比如拼写错误的不存在变量、误放入系统提示区的动态变量，或是从旧版本残留的过时语法。对于支持自动修复的错误，鼠标悬停即可一键完成修正。

::: warning
当预设保存之后，当前正在使用该预设的活跃会话并不会立刻清空并重建整个上下文。新的角色设定会在下一个对话回合正式生效；同时，系统提示的前缀缓存会失效一次，模型内部会收到一条折叠显示的「预设已切换」系统通知。
:::

### 预设的类型

预设在 ChatLuna 中主要分为两类，分别适用于不同的会话引擎与业务需求：

- **对话预设**：普通的提示词模板，结构轻量直接，主要适用于「对话」和「编码」引擎。它负责为模型设定固定的工作角色或回复风格，不包含复杂的行为机制。
- **角色预设**：带有角色预设类型标记的高级预设，除了基础的人格描述，还完整定义了说话风格、范例对话、状态声明、作息规律与动作权限，专为伪装引擎量身打造。

这两种预设并非完全互斥。如果你在普通的对话引擎里选中了一份角色预设，引擎同样可以正常运行，但它只会读取其中的人格正文与说话风格送入系统提示；至于状态跟踪、作息节律以及动作交互等高级能力，对话引擎会直接忽略，不会生效。

### 导入与兼容

如果你手头已有之前积累的人设资料，或者想直接使用社区分享的角色包，可以利用预设页提供的导入功能：

- **旧版预设文件**：系统能够识别早期版本的预设格式，在导入过程中会自动转换变量命名格式并迁移分区结构。
- **角色预设文件**：支持直接导入规范的角色预设文本文件，导入后即可在伪装引擎中启用。
- **外部导出预设**：可以无缝载入从其他 ChatLuna 实例导出的备份预设包。

导入完成后，强烈建议你在右侧预览区认真查看一次渲染结果与语法诊断。特别需要注意的是，在旧版语法中，有些用户习惯将当前时间等动态内容写在系统提示区。系统在导入后会将此类用法标为错误，你需要按提示将其移入上下文区；否则每次会话触发时，前缀缓存都会被强制打断重算，不仅让回复变慢，还会增加额外的开销。

## 角色预设的结构

角色预设在底层采用清晰易读的 Markdown 文本进行组织。文件的头部是一组用于角色定义的元数据，正文部分则借助指令划分为几个明确的功能区块。在实际编写时，你完全不需要死记硬背每个字段，预设编辑器提供的初始模板骨架与自动补全会协助你快速完成填空。

### 元数据

角色元数据位于预设的最上方，主要用于向引擎声明角色的基本档案、生理作息以及允许调用的能力组件。常见字段如下表所示：

| 字段 | 作用 |
| --- | --- |
| 名称 | 预设的显示名，也是默认的角色名。 |
| 描述 | 一句话说明这个角色是谁。 |
| 关键词 | 帮助搜索和识别角色。 |
| 昵称 | 角色在群里可能被叫到的其他称呼。 |
| 兴趣 | 角色关心的话题，供气氛判断和主动接话使用。 |
| 禁言词 | 群友说哪些话时，角色应该安静一段时间。 |
| 作息 | 睡觉时间段、忙碌时间段、早晚安问候时间。 |
| 状态 | 角色要维护的状态字段，例如心情、在做什么、对某人的好感度。 |
| 元素 | 角色可以发送的富消息元素，例如贴图、表情回应、戳一戳。 |
| 思考 | 思考方式：标签思考、模型原生思考、关闭。 |

在配置这些元数据时，建议读者优先确立好名称、描述与昵称。如果角色打算放入日常群聊中使用，合理设定兴趣与禁言词可以让机器人的互动更为自然得体，避免在不恰当的时机生硬插话。

### 正文与指令

在元数据下方是预设的正文区域。正文的默认部分是角色的人格核心描述，这部分内容会直接装配进模型的系统提示中。为了让人格更加饱满，你还可以使用指令将正文划分为若干独立区块：

- **风格**：用于规范角色的说话方式、口头禅、语言习惯或偏好的句子长度。这部分内容会稳定送入系统提示。
- **示例**：提供几段精心设计的问答范例对话。示例同样会被放置在系统提示中，帮助模型更准确地模仿角色的说话口吻。
- **上下文**：存放角色的背景设定、世界观细节或当前所处的虚拟场景。这一区块会被装配进上下文区，允许容纳随剧情推进而变化的内容。

在编写正文、风格与示例时，必须遵守一个重要原则：其中只能包含**不可变**变量，比如角色本身的姓名、所处平台名称或日期中相对固定的属性。任何在每回合都会变动的值（例如当下精确时间、实时心情状态、说话者的个人信息等）都不能写在系统提示区块。一旦写错，大模型的提示词缓存前缀在每一回合都将全部作废；这类动态值必须放入上下文区块，或者交给每回合的状态通知来传递。

::: tip
判断一个变量能不能放进系统提示区，只需看它会不会随消息频繁变动。角色的名字、预设的名称在会话中不会改变，可以放心放入；但当前的时间、角色的状态、正在说话的人都会不断变化，必须移出系统提示。页面会把放错位置的变量用红线标出，并给出移动建议。
:::

### 变量

预设里通过成对的花括号来引用各类环境信息，例如自动调取角色名、平台名称、当前群名以及发送者的用户名。在底层机制中，变量被严格区分为两类：

- **不可变变量**：在整个会话中保持稳定恒定，可以安全地写入系统提示，享受底层提示词缓存带来的加速与成本节省。
- **可变变量**：每回合都可能发生变化，只能出现在上下文区或用户输入的包裹模板中。

除基础环境信息外，角色引擎还会在后台动态维护角色的状态变量，比如当前的心情、精力数值、对特定群友的好感度以及对对方的专属称呼。这些变量默认会在每回合对话生成时，通过状态通知格式化提供给模型，因此不建议直接把它们写死在人格正文之中。

## 伪装页

如果说预设页是创作角色的画室，那么伪装页就是观察角色活跃状态的监控台。

在控制台侧边栏点击「对话 → 伪装」，页面会把正在使用角色预设的群聊和私聊会话排成卡片。你可以按角色名称进行折叠分组，也可以随时一键切换成紧凑的列表视图。

随意点开一张卡片，就能直接进入该角色在当前会话里的实时运行状态：

- **状态**：展示角色当前维护的所有动态变量，例如心情、精力与当前在做什么。你不仅可以在这里手动修改数值纠正偏差，还可以查看待办事项列表以及上一回合的状态分解推理细节。
- **群画像**：展示这个群的简介、群友常聊的话题偏好以及成员印象。该卡片需要配套的记忆插件提供数据来源支持。
- **活跃度**：反映角色在当前群内的发言积极性，包括当前接话意愿、触发阈值曲线以及最近的判定记录。安装观察插件后该卡片会自动点亮。

在卡片顶部的标题栏中，你还可以找到实用的快捷调试按钮：既可以直接手动唤醒处于休眠或安静状态的角色，也可以让它在当前会话中安静一段时间。

## 角色引擎的能力

要想让静态的角色预设真正运转起来，读者首先需要前往「场景规则」页面。在规则配置中，将当前场景的用途选定为「伪装」，并在关联选项中选中你刚才准备好的角色预设。

完成绑定后，下方会展开角色引擎的各项功能开关。在绝大多数情况下，你完全不需要逐一调整每一个选项，只需针对当前群聊的特殊需求去设置需要覆盖的项目，其余项目直接沿用系统默认值即可。

### 安静开关

在群聊中，有时群友会讨论严肃话题或单纯希望机器人不要插话。安静开关正是为了满足这一控制需求而设立：

- **工作机制**：当群聊消息中有人对角色说出禁言词时，角色会自动进入静默状态，在设定的时间内不会对群内发言做出普通响应。
- **字段配置**：你可以灵活设置安静时长与禁言词列表。词表留空时，引擎会自动沿用角色预设里的禁言词；如果明确清空整个列表，则表示彻底不设置禁言词。
- **使用建议**：安静期间角色并不是完全消失。如果群友直接发送带有艾特符号的强提醒，或者在消息中清晰呼叫角色的名字，角色仍然有可能被正常叫醒，具体取决于作息配置中的直接触发设置。

### 作息

为了让角色表现出类似真人的生活节奏，作息功能赋予了它拟真的日程安排：

- **工作机制**：角色可以按照预设里的时间段自动切换为睡觉或忙碌状态。在睡觉期间，只有直接呼叫才能将它叫醒；在忙碌时间段内，它的回复速度会更慢，内容也会显得更简短。早安和晚安问候同样由作息机制驱动。
- **字段配置**：你可以根据角色的背景故事设定睡觉与忙碌的起止时间点，并配置早晚安的问候触发规则。
- **使用建议**：对于日常陪伴型角色，建议配置合理的就寝作息。配合早晚安问候，能让群友真切感受到角色的生活节奏与时间感知。

### 心情状态

心情状态是角色产生情绪波动的核心驱动力：

- **工作机制**：角色在后台维护一组状态字段，例如心情指数、精力数值以及手头正在做的事情。这些值会随着群友的聊天话题与交互态度实时增减，并通过每回合的状态通知提供给模型。
- **字段配置**：你可以开启或关闭心情状态追踪，并设定初始数值与变化规则。
- **使用建议**：心情状态是高级扮演玩法的基础。需要特别注意的是，如果你将心情状态关闭，后文中依赖状态的一系列联动能力（包括细致状态更新、近期记忆以及记住每个人）都会被强制同步停用。

### 细致状态更新

常规情况下，主模型在生成回复的同时需要顺带维护自身状态，这有时会导致状态更新不够精准稳定。

- **工作机制**：开启细致状态更新后，每回合结束时系统会额外调用一个独立的小模型。该小模型专注于根据这一轮对话内容，精确更新角色的情绪与状态变化。
- **字段配置**：提供独立模型选择项，允许读者指定由哪个模型来负责状态更新。
- **使用建议**：这种分离模式比让主模型自己写状态更加稳定，但每次回复都会多产生一次模型调用。建议专门指定一个响应迅速且价格便宜的小模型来承担这项工作。

### 近期记忆

近期记忆用于保障角色在连续对话中的短期语境承接能力：

- **工作机制**：系统会实时记录当前群聊或私聊中最近聊过什么内容。当记录积累的内容超出设定的预算后，引擎会在后台自动精简并重写提炼。
- **字段配置**：可以针对当前场景调整近期记忆的预算大小，平衡上下文长度与细节保留度。
- **使用建议**：请注意，近期记忆是针对当前会话的短期记忆，它和跨会话、长周期的长期记忆不是一回事。另外，由于近期记忆依赖状态能力，一旦关闭心情状态，近期记忆也会一起停用。

### 记住每个人

真人社交的核心在于记住与每一个人的交往细节，这一能力让角色对不同的群友区别对待：

- **工作机制**：引擎为每位交流过的用户建立独立档案，持续记录好感度数值、对该用户的性格印象以及偏好的称呼。
- **字段配置**：好感度可以设定明确的上下限，单次回复允许波动的变动幅度也可以进行限制，避免好感度因为偶发对话出现剧烈震荡。此外，还可以开启「未更新时补充判定」选项：如果这一轮主模型没有更新任何人，就让小模型介入补做一次判定。
- **使用建议**：同一个角色在当前实例的所有群聊和私聊里，会全局共用这套人物记录。在生成回复时，用户的群名片、昵称以及群身份（群主或管理员）会一起提供给模型，角色自己的群身份也会一同提供，从而展现出自然的交往亲疏与分寸感。

### 群信息

每个群聊都有独特的文化风气与聊天定位，群信息模块能让角色迅速融入群聊环境：

- **工作机制**：把群聊的简介和常聊话题注入上下文，让角色清楚知道这个群是做什么的、平时都在讨论哪些领域。
- **字段配置**：支持设置字符预算上限，防止群信息占用过多的上下文空间。
- **使用建议**：该功能需要配套安装具有群分析能力的记忆插件，由插件负责分析群聊特征并提供数据来源。

### 思考

在复杂或深度扮演场景中，直接作答往往容易出现口吻出戏或前后矛盾，思考模式给模型留出了组织语言的缓冲区：

- **工作机制**：提供三种可选的工作方式：
  - **标签思考**：模型在正式回复前先在专用的思维标签内推导一段思考。思考内容只供内部处理，绝不会发送给群友。
  - **模型原生思考**：使用模型底层自带的推理能力。这种方式更聪明，推导更细腻，但不是所有模型都支持该特性。
  - **关闭**：不进行前置推导，模型收到消息后直接生成回复。
- **字段配置**：除了选择思考方式，还可以设置思考记录的保留策略：只保留最近一次、全部保留进历史，或者完全不保留。
- **使用建议**：保留的思考记录越多，模型越能连贯延续之前的构思思路，但伴随的历史 token 费用也会更高。日常普通对话建议选择关闭或只保留最近一次。

### 互动动作

文字交流往往不如生动的动作来得传神，互动动作赋予了角色调动即时通讯富消息的能力：

- **工作机制**：允许角色在恰当的语境下，主动向群内发送生动的互动交互。
- **字段配置**：引擎提供了贴图、戳一戳和表情回应这三项独立的动作开关，读者可以根据群聊风气逐一开启或关闭。
- **使用建议**：动作是否真的能够成功发送出去，还取决于当前所使用的聊天平台适配器是否支持对应的动作功能。开启前建议先确认适配器的支持情况。

### 回复方式

回复方式决定了模型如何将最终的文字内容回传给角色引擎：

- **直接输出**：模型直接输出文字和富消息元素。这是系统的默认选项，兼容性好且响应最快。
- **回复工具**：模型通过一个专门的回复工具来提交发言。
- **使用建议**：有的模型在直接输出时容易出现格式错误，甚至把系统标记输出出来；如果遇到这类情况，将回复方式切换为回复工具通常会更加稳定。

### 聊天记录长度

长线角色扮演最大的敌人往往是上下文超长带来的遗忘与费用暴涨：

- **工作机制**：角色引擎内嵌了一套专属的压缩机制。当聊天记录超过设定的 token 阈值时，引擎会自动把较早的部分整理成摘要，整理后依然保留最近一定数量的 token 原文。
- **字段配置**：可以按需设定触发整理的 token 数量上限，以及整理后保留的原文 token 预算。
- **使用建议**：请注意，角色引擎内部的这套设置与系统全局的「对话压缩」属于两层不同的机制。角色引擎的设置针对人际脉络与情感转折做了特别优化，更贴合长线角色扮演的持续运营。

## 推荐配置

面对如此丰富的配置开关，新手往往不知道从何下手。针对常见的典型应用场景，我们整理了三套经过实测的开箱推荐方案：

### 轻量角色

如果你只是在小型好友群、临时测试环境中使用，或者 API 调用预算相对有限，推荐采用轻量组合：

- **核心搭配**：仅开启心情状态、近期记忆和思考功能。
- **优化建议**：关闭细致状态更新与人物补充判定，减少额外的辅助模型调用。这种配置既能保持角色基本的性格波动与就近语境记忆，又能将调用开销控制在极低水平，非常适合小群测试。

### 完整角色扮演

如果你打算长期运营一个专属的角色交流群，希望角色展现出极致的拟真度与深度：

- **核心搭配**：心情状态、细致状态更新、近期记忆、记住每个人、群信息、作息以及互动动作全开。
- **优化建议**：思考方式选用标签思考模式，并将聊天记录压缩阈值适当调高，尽可能保留更多近期的对话原文。同时指定一个便宜的小模型专门打理状态更新，让角色呈现出细腻的性格成长与持久记忆。

### 多群共用一套角色

许多管理员希望同一个招牌角色能够同时进驻多个群聊，既保持统一的人设又互不串戏：

- **核心搭配**：借助引擎天生的隔离机制，人物记录天然在所有群聊和私聊中全局共用，而角色的心情状态与近期记忆则按不同会话严格隔离。
- **优化建议**：在「场景规则」中为不同群配置不同的人设规则或回复模型，但统一绑定同一份角色预设。这样一来，角色既能在全域认出某位老朋友，又不会把 A 群刚才聊的话题张冠李戴到 B 群。

## 排查

在实际运行过程中，如果你发现角色的行为表现不如预期，可以对照以下常见问题进行排查：

**角色不记得刚才聊过什么。**
首先检查近期记忆是否已经开启、分配的预算是否太小；其次检查当前群聊的历史记录策略是否被设为了「不记录」；此外，若长对话已经持续了很久，较早的内容可能已经触发了压缩机制变成了精简摘要，无法像原文那样保留所有字句细节。

**好感度不动。**
确认当前配置中是否同时开启了心情状态与记住每个人这两项能力；其次确认模型在这一轮对话中是否正常输出了状态更新。如果主模型经常漏判，可以开启「未更新时补充判定」选项，也可以直接进入伪装页手动调整该用户的好感度数值。

**角色在系统提示里报变量错误。**
这是最典型的变量位置错误。出现此提示说明可变变量被误写进了人格正文、说话风格或示例对话等系统提示区块中。请打开预设编辑器，把这些每轮都会变化的可变变量移到上下文区，或者改为通过每回合的状态通知提供给模型。

**切换预设后回复风格没变。**
修改预设后请不必着急，预设设定只会在下一个全新的对话回合正式生效，当前正在进行的这一轮对话依然在使用旧的提示词。只需等这一轮对话结束，或者在群里发送一条新消息即可看到新风格。
