# 指令一览

::: tip
除了日常聊天，机器人还认得一组以 `chatluna` 开头的指令。你可以用它们来管理对话、快速切换模型、查看运行状态，甚至直接在群聊里处理定时任务与审批决策。
:::

在日常交互中，指令和聊天走的是两条完全不同的路。

比如你在群里发送「今天天气真好」，这句话会进入对话流程并交给模型思考；但如果你输入 `chatluna.status`，系统会在第一时间拦截这条消息，由指令系统直接处理并返回结果，根本不会惊动模型。

正因如此，指令的处理响应极快、结果确定，非常适合在手机聊天窗口里随手管理机器人。

::: warning
几乎所有管理与配置类指令都要求发送者具备主人权限。

如果你还没有绑定主人身份，可以先前往控制台获取绑定码，并在私聊中向机器人发送绑定指令完成认证。
:::

## 怎么发

在支持指令的聊天平台里直接发送即可，调用格式通常是「指令名 + 空格 + 参数」。

指令的参数遵循标准的约定：尖括号 `<>` 表示必选参数，方括号 `[]` 表示可选参数；选项通常以 `--` 开头，部分选项也可以附带具体的参数值。

不少常用指令都配有简短的别名。例如开启新对话，无论发送完整名称还是发送简写别名，效果都是完全一样的。

如果你一时记不清有哪些指令可用，随时发送帮助指令就能调出命令清单或查看具体用法。

::: tip
不同聊天平台的指令前缀可能有所不同。

如果发送指令后机器人毫无反应，不妨先确认当前平台是否需要添加前缀（如 `/` 或 `.`），或者检查消息是否被平台误判成了普通闲聊。
:::

## 查看状态

### 主指令

`chatluna` 是所有子指令的父级指令。

- **什么时候发**：记不清有哪些可用的管理命令，或者想快速调出指令目录时。
- **发完看到什么**：通常会直接返回 ChatLuna 的帮助信息，列出可用的全部子指令及简要功能。

### 查看当前会话

`chatluna.status` 用来调出当前聊天窗口对应的会话详情。

- **什么时候发**：觉得机器人回复变慢、疑似卡住，或者想弄清楚当前群聊接到了哪个模型、积累了多少上下文时。
- **发完看到什么**：机器人会返回当前入口的概况卡片，清晰展示会话编号、运行状态（空闲、生成中、待处理消息数）、日志条目数与模型可见消息数，以及当前生效的提供商与模型。

### 查看活跃会话

`chatluna.routes` 用来列出当前实例中正在活跃的所有会话与调用引擎。

- **什么时候发**：排查场景规则生效情况，确认某个群聊或私聊到底有没有被对应规则正确接管时。
- **发完看到什么**：机器人会返回活跃路由与引擎列表。这是一条隐藏指令，平常不会出现在全局帮助里，但需要排查问题时随时可以直接调用。

## 管理对话

日常聊天免不了需要开启新话题、打断回复或整理记忆，你可以随时使用下面这些指令：

| 指令 | 别名 | 作用 |
| --- | --- | --- |
| `chatluna.new` | `new`、`clear` | 开启新对话，旧记录保留 |
| `chatluna.session.fork` | 无 | 从当前对话分出一个分支 |
| `chatluna.stop` | `stop` | 停止正在生成的回复 |
| `chatluna.compact` | `compact` | 压缩当前会话的上下文 |

那么，它们分别该在什么时候使用，发完又会发生什么呢？

- **`chatluna.new`**：当你准备开启全新话题、不想让之前的长篇大论干扰接下来的回答时发送。发完后机器人会提示新会话已创建；需要说明的是，新对话并不是删除，旧会话依然完整保存在控制台的轨迹页里供日后查阅。
- **`chatluna.session.fork`**：当你想在当前话题的基础上探索另一个分支、又不想破坏主线讨论时发送。发完后机器人会确认生成会话分支，随后的聊天将写入该分支，原对话完全不受影响。
- **`chatluna.stop`**：在模型正在滔滔不绝生成长篇回复，或者输出偏题需要紧急刹车时发送。发完后机器人会立刻中断当前这一轮的内容生成，不过队列中已排队的消息仍会保留。
- **`chatluna.compact`**：聊了很多轮后上下文过长，感觉反应迟缓或比较消耗 token 时发送。发完后机器人会确认压缩完成，将较早的历史消息整理为摘要，模型可见的上下文变短了，但底层完整日志一条都不会丢。

## 切换模型

想要临时换个模型体验效果，使用 `chatluna.model` 指令非常方便：

- **什么时候发**：不带参数时，适合在想确认当前会话正在使用哪个模型时发送；带上参数（格式为「提供商/模型」，如 `chatluna.model openai/gpt-4o-mini`），则适合在遇到模型限流、额度耗尽或想临时测试其他模型能力时发送。
- **发完看到什么**：不带参数时，机器人会直接展示当前生效的模型名称；带参数切换成功后，机器人会回复切换成功的提示，并在下一次请求时生效。如果模型名写错了，机器人会返回具体的失败原因，当前模型保持不变。

::: tip
通过该指令切换的模型只作用于当前会话，属于临时调整。

想让改动长期生效，应该去场景规则里为该入口绑定模型，或者直接修改对应的模型角色。
:::

## 定时任务

`chatluna.schedule` 让你无需打开控制台，在聊天窗口就能直接管理定时任务。通过在指令后追加子动作来指定具体操作：

| 动作 | 作用 |
| --- | --- |
| `list` | 列出当前频道的任务 |
| `add` | 新建任务 |
| `remove`（或 `cancel`） | 删除任务 |
| `pause` | 暂停任务 |
| `resume` | 恢复任务 |
| `fire` | 立刻触发一次 |

如果不填写子动作，默认效果等同于 `list`。每种动作的使用场景非常明确：

- **`list`**：想查看本频道已经添加了哪些定时安排时发送，发完后能看到任务编号、执行周期与当前状态。
- **`add`**：需要机器人按时提醒或定期干活时发送。新建时必须从四种触发方式中选择一种：指定时刻 `--at`（如标准时间格式、`时:分` 或相对时间 `+30m`）、固定间隔 `--every`（如 `30m`、`2h`、`1d`）、五段式 Cron 表达式 `--cron`，或后台监视条件 `--watch`。同时必须用 `--reason` 写清楚这次任务的目的。发完后机器人会确认任务已创建并分配唯一编号。
- **`remove` / `cancel`**：某个提醒或周期任务不需要了时发送，发完后机器人会提示指定任务已被成功删除。
- **`pause`**：特殊时段或节假日想要临时停用某个任务时发送，发完后机器人会回复该任务已进入暂停状态。
- **`resume`**：需要唤醒此前暂停的任务时发送，发完后能看到任务已恢复执行的提示。
- **`fire`**：刚配好任务想立刻测试效果、或者临时需要手动触发一次时发送，发完后机器人会立即执行该任务并返回触发结果。

所有定时任务均严格归属于创建它的频道，其他群聊既看不到内容，也无法跨群管理。

::: warning
为了保障系统稳定，任务的数量和频率都设有安全上限。过于频繁的调度会被系统直接拒绝，避免一个写错的任务拖垮整个实例。

具体频次限制与高级说明，请参阅[定时与后台任务](./automation)。
:::

## 撤销文件修改

当模型调用工具对文件产生变更后，你可以通过 `chatluna.undo` 快速回退。

- **什么时候发**：模型在执行代码或整理文件时出现了误删、改错内容，需要紧急挽救恢复时发送。
- **发完看到什么**：默认情况下，机器人会撤销最近一次的文件改动并告知回退结果。

该指令还提供了两个实用的调整选项：

- **本轮全部**：如果模型在这一轮对话里连续修改了多个文件，指定该选项可以一次性把它们全部撤销。
- **强制覆盖**：目标文件在改动之后如果又被其他人为编辑过，系统出于安全保护默认会拒绝撤销；加上强制选项后，机器人会忽略该保护并强行回退。

这项能力依赖后台的文件历史服务。如果对应插件未启用，该指令将不会出现。

::: tip
撤销功能主要用来挽救偶发误操作，并不是版本控制工具。改动较多时，优先使用你项目自身的版本管理系统。
:::

## 初始化与创作者模式

在刚接入机器人或进行深度调试时，这组指令能派上大用场：

| 指令 | 别名 | 作用 |
| --- | --- | --- |
| `chatluna.setup` | `setup` | 重新开始人设配置 |
| `chatluna.bind` | `bind` | 用绑定码把发送者设为主人 |
| `chatluna.creator` | 无 | 进入创作者模式 |
| `chatluna.creator.off` | 无 | 退出创作者模式 |

具体使用时机与返回表现如下：

- **`chatluna.setup`**：模型连接就绪后，想重新调整机器人的人设风格与参数时在私聊中发给它。发完后机器人会确认准备就绪，随后发送的下一条消息就会直接进入人设配置流程。
- **`chatluna.bind`**：初次配置时在控制台拿到绑定码后，私聊发给机器人并附带该码。发完后机器人会校验凭证并提示主人身份绑定成功。
- **`chatluna.creator`**：需要现场调试或者让机器人在当前会话里直接修改自身配置时发送。发完后机器人会确认进入创作者模式，赋予更高的配置调整权限。
- **`chatluna.creator.off`**：调试完毕需要关闭特权时发送。发完后机器人会提示已退出创作者模式，恢复正常的日常权限限制。

::: warning
创作者模式会显著扩大模型能做的事情。切记不要在对外的群聊里长期开着，也不要在公开演示完毕后忘记关闭。
:::

## 审批

当某个工具调用涉及到敏感操作时，系统不会擅自放行，而会在聊天里主动发出提问，并附上清晰的编号选项。

- **什么时候发**：审批由系统主动发起，当你在聊天窗口看到机器人推送审批问题时，直接回复对应编号即可。
- **发完看到什么**：发送编号后，机器人会确认授权决定并继续执行后续流程。你可以选择：仅允许这一次、本次对话内一直允许，或者直接拒绝本次调用。

这些问题是发给人工审核的，模型本身不会也不被允许代答，只有权限等级符合要求的用户回复才有效。

如果长时间没有人处理，超时后请求会依次转交给下一位可能的审批者；若所有候选人都没有回应，系统便会按照未批准直接终止操作。

::: tip
系统默认开启了「附带编号选项」，只需回复数字即可，体验非常直观；如果关闭了该特性，则需要手动回复完整的判定内容。
:::

## 帮助

想要了解指令家族的全局全貌，最基础的 `help` 是最好的起点。

- **什么时候发**：忘记了某个指令的具体拼写，或者想查阅特定指令支持哪些参数与选项时发送。
- **发完看到什么**：单独发送 `help` 时，机器人会列出当前权限下你能使用的全部指令列表；附带指令名时（如 `help chatluna.status`），机器人会返回该指令的语法格式、必选与可选参数、选项开关以及具体使用示例。

因为指令帮助是各插件注册时一同声明的，所以只要安装并启用了新插件，帮助列表里就会自动多出对应的功能条目。

## 常见组合

结合一些日常使用场景，这里整理了几条最常用的高频操作路径：

- **想看看刚才那一轮为什么卡住了**：先发送 `chatluna.status` 确认状态与排队进度，再去控制台轨迹页找同一个会话详细核查。
- **聊得太久上下文太长了**：随手输入 `chatluna.compact` 一键压缩，收到完成提示后继续正常畅聊。
- **模型突然被限流了，想临时换一个**：发送 `chatluna.model 提供商/模型` 切换线路，下一条消息立即生效。
- **想让它半小时后提醒开会**：发送 `chatluna.schedule add --at +30m --reason 提醒大家准备开会`，省心完成定时备忘。
- **工具误删改了关键文件**：直接发送 `chatluna.undo` 撤销改动；如果是这一轮修改了多个文件，加上本轮全部选项即可批量回滚。

## 排查

在使用指令的过程中如果遇到不符合预期的情况，可以先对照以下要点进行自查：

- **指令发送后没有任何反应**：先确认是否需要输入触发前缀，检查消息是否被平台当成了普通闲聊交给了模型，并确认发送者是否已完成主人绑定。
- **提示「当前入口未绑定路由」**：说明当前的群聊或私聊尚未被任何场景规则接住。请前往控制台的场景规则页面，为该会话入口配置一条生效规则。
- **提示「当前路由暂无活跃会话」**：说明规则已经接住了该入口，但此前尚未产生任何对话交互。你可以先发一条普通消息与机器人搭话，随后再使用管理指令。
- **切换模型提示失败**：检查输入的「提供商/模型」是否存在于模型列表里，并确认对应的提供商实例处于启用状态。
- **定时任务创建失败**：检查是否在四种触发条件中多选了；时间格式是否符合规范；并确认当前频道的任务总数没有达到上限。
- **审批提问发出后一直无人处理**：确认回复者的权限等级是否足够；若关闭了数字编号选项，检查输入的文本是否符合识别要求。
