# 指令一览

::: tip
除了聊天，机器人还认得一组以 `chatluna` 开头的指令。它们用来管理对话、切换模型、查看状态，以及在聊天里直接处理定时任务和审批。
:::

指令和聊天走的是两条路。

你在群里说「今天天气不错」，这句话会进入对话流程，交给模型；你发送 `chatluna.status`，这句话会被指令系统截住，直接执行对应动作，根本不会惊动模型。

所以指令响应快、结果确定，也更适合在手机聊天窗口里操作。

::: warning
几乎所有管理类指令都要求发送者是主人。

如果你还没有绑定主人身份，先完成绑定：控制台会给出一个绑定码，在私聊里发送绑定指令并输入它即可。
:::

## 怎么发

在支持指令的聊天平台里直接发送，格式是「指令名 + 空格 + 参数」。

参数用尖括号表示必填、方括号表示可选；选项以 `--` 开头，可以带值。

指令名支持别名。比如开启新对话，发完整名称和发简写效果一样。

输入帮助指令可以随时查看当前可用的指令列表，或者某个指令的具体用法。

::: tip
指令前缀（比如是否需要用斜杠开头）由平台与指令插件决定，不同平台可能不一样。

如果指令没反应，先试试加前缀，或者确认这个平台的消息是否被当成了普通聊天。
:::

## 查看状态

### 主指令

`chatluna` 是所有子指令的父级。单独发送它通常只会返回帮助信息，真正的功能在子指令里。

### 查看当前会话

`chatluna.status` 会返回当前入口的会话概况：

- 会话编号。
- 运行状态（空闲、生成中、待处理消息数）。
- 日志条目数与模型可见的消息数。
- 当前实际使用的提供商与模型。

排查「为什么回复很慢」「为什么上下文这么长」时，这是第一条该看的指令。

### 查看活跃会话

`chatluna.routes` 会列出当前实例里活跃的会话与引擎。

它是隐藏指令，不会出现在帮助列表里，但可以直接调用。适合确认「这个群到底有没有被规则接住」。

## 管理对话

| 指令 | 别名 | 作用 |
| --- | --- | --- |
| `chatluna.new` | `new`、`clear` | 开启新对话，旧记录保留 |
| `chatluna.session.fork` | 无 | 从当前对话分出一个分支 |
| `chatluna.stop` | `stop` | 停止正在生成的回复 |
| `chatluna.compact` | `compact` | 压缩当前会话的上下文 |

几个细节值得说明：

- **新对话不是删除**。旧会话会被完整保留，可以在控制台的轨迹页里找到，只是后续消息进入一个新的会话。
- **分支不影响原会话**。分叉之后，原对话依然可以查看和回放，新消息进入分支。
- **停止只停当前这一轮**，不会清空已排队的内容。
- **压缩只影响模型能看到的部分**。日志里的完整记录不会被删掉，只是较早的消息被整理成摘要。

## 切换模型

`chatluna.model` 有两个用法：

- 不带参数：显示当前路由正在使用的模型。
- 带参数：切换模型，格式是「提供商/模型」，例如 `chatluna.model openai/gpt-4o-mini`。

切换不会立刻打断正在生成的回复，而是在下一次请求时生效。

如果模型名写错，指令会返回失败原因，当前模型保持不变。

::: tip
这里切换的是当前会话的模型，属于临时调整。

想让它长期生效，应该去场景规则里改，或者改模型角色。
:::

## 定时任务

`chatluna.schedule` 是一个带子动作的指令，第一段参数决定做什么：

| 动作 | 作用 |
| --- | --- |
| `list` | 列出当前频道的任务 |
| `add` | 新建任务 |
| `remove`（或 `cancel`） | 删除任务 |
| `pause` | 暂停任务 |
| `resume` | 恢复任务 |
| `fire` | 立刻触发一次 |

不带动作时默认是列出。

新建任务时必须给出一个触发方式，而且只能选一个：

- **指定时刻**：`--at`，支持标准时间格式、`年/月/日-时:分:秒`、`时:分`，以及 `+30m` 这种相对时间。
- **固定间隔**：`--every`，例如 `30m`、`2h`、`1d`。
- **表达式**：`--cron`，五段式，精确到分钟。
- **监视条件**：`--watch`，交给系统在后台判断条件是否满足。

还要用 `--reason` 写清楚这次唤醒要做什么。这段说明会进入模型上下文，写得越具体，效果越好。

任务归属于创建它的频道。别的群看不到，也不能管理。

::: warning
任务的数量和频率都有上限。系统会拒绝过于频繁的调度，避免一个写错的任务把整个实例拖垮。

具体限制见[定时与后台任务](./automation)。
:::

## 撤销文件修改

`chatluna.undo` 用来回退工具对文件做的改动。

默认行为是撤销最近一次修改。两个选项可以改变范围：

- **本轮全部**：把当前这一轮对话里的文件改动一起撤销。
- **强制覆盖**：目标文件在改动之后又被修改过时，默认会拒绝；强制选项会忽略这个保护。

撤销依赖文件历史服务，如果这个插件没启用，指令不会出现。

::: tip
撤销是为了挽回误操作，不是版本控制。改动很多时，优先用你项目自己的版本管理工具。
:::

## 初始化与创作者模式

| 指令 | 别名 | 作用 |
| --- | --- | --- |
| `chatluna.setup` | `setup` | 重新开始人设配置 |
| `chatluna.bind` | `bind` | 用绑定码把发送者设为主人 |
| `chatluna.creator` | 无 | 进入创作者模式 |
| `chatluna.creator.off` | 无 | 退出创作者模式 |

- **人设配置**只能在主人的私聊里发起，而且要求模型已经连接好。发起后，发送下一条消息就会进入配置流程。
- **绑定**用于第一次接触：控制台显示绑定码，你在私聊里发送绑定指令并输入它。
- **创作者模式**让机器人在当前会话里获得修改自身配置的能力，适合现场调试。用完记得退出。

::: warning
创作者模式会显著扩大模型能做的事情。不要在对外的群聊里长期开着，也不要在公开群演示时忘记关闭。
:::

## 审批

当某个工具调用需要审批时，系统会在聊天里发出一个问题，并附上编号选项。

回复对应的编号即可：

- 允许这一次。
- 本次对话内一直允许。
- 拒绝。

问题是发给人的，不是发给模型的。谁有资格回答，取决于这个动作要求的权限等级。

如果没人回答，超时后会转给下一位可能的审批者；所有候选人都没有回应，就按未批准处理。

::: tip
关闭「附带编号选项」后，问题里不再列出编号，需要你直接回答；打开时对新手更友好。
:::

## 帮助

`help` 会列出当前可用的全部指令；`help` 加上指令名，会显示这个指令的参数、选项和示例。

帮助内容是各插件注册指令时一起声明的，所以装了新插件，帮助里会自动多出对应的条目。

## 常见组合

几个日常用得上的路径：

**想看看刚才那一轮为什么卡住了。**
先 `chatluna.status`，再去轨迹页找同一个会话。

**上下文太长了。**
`chatluna.compact`，然后正常继续聊。

**模型被限流了，临时换一个。**
`chatluna.model 提供商/模型`，下一条消息生效。

**想让它半小时后提醒一句。**
用定时指令新建一个任务，触发时间写相对时间，说明写清楚要提醒什么。

**误删了文件。**
`chatluna.undo`；如果是这一轮删了好几个，用本轮全部那个选项。

## 排查

**指令没反应。**

确认前缀、确认平台把消息交给了指令系统而不是对话系统、确认发送者是主人。

**提示「当前入口未绑定路由」。**

这个聊天入口还没被场景规则接住。去场景规则里给这个群或这个私聊配一条规则。

**提示「当前路由暂无活跃会话」。**

规则接住了，但还没有消息触发过会话。先发一条正常消息，或者直接问它一句话。

**切换模型失败。**

检查提供商与模型名是否存在于模型列表里；确认提供商实例是启用状态。

**定时任务创建失败。**

确认只选了一种触发方式；时间格式要能被解析；确认没有达到任务数量上限。

**审批一直没人处理。**

让权限等级足够的人回复；或者检查是不是关闭了提问里的编号选项。
