# 指令一览

::: tip
除了日常聊天，机器人还支持一组以 `chatluna` 开头的指令。你可以用它们管理对话、快速切换模型、查看运行状态，甚至直接在群聊里处理定时任务与审批决策。
:::

在日常交互中，指令与普通聊天走的是两条不同的处理流程。

例如在群聊中发送「今天天气真好」，消息会进入常规对话流程并交由模型处理；如果发送 `chatluna.status`，系统则会优先拦截该消息，由指令系统直接处理并返回结果，不会调用模型。

因此，指令的响应更快、结果更确定，适合在聊天窗口中直接管理机器人。

::: warning
大多数管理与配置类指令都要求发送者具备主人权限。

如果你尚未绑定主人身份，可以先前往控制台获取绑定码，然后在私聊中向机器人发送绑定指令完成认证。
:::

## 怎么发

在支持指令的聊天平台中直接发送消息即可，调用格式通常为「指令名 + 空格 + 参数」。

指令参数遵循以下约定：

- 尖括号 `<>`：必选参数。
- 方括号 `[]`：可选参数。
- 选项通常以 `--` 开头，部分选项可以附带参数值。

不少常用指令配有简短的别名。例如开启新对话时，无论发送完整指令名还是简写别名，效果完全相同。

如果记不清有哪些指令可用，随时发送帮助指令即可查看指令列表与具体用法。

::: tip
不同聊天平台的指令前缀可能有所不同。

如果发送指令后机器人没有反应，请先确认当前平台是否需要添加前缀（如 `/` 或 `.`），或者检查消息是否被平台识别为普通闲聊。
:::

## 查看状态

### 主指令

`chatluna` 是所有子指令的根指令。

- **什么时候发**：记不清可用的管理命令，或想快速查看指令目录时。
- **发完看到什么**：返回 ChatLuna 的帮助信息，列出所有可用的子指令与简要说明。

### 查看当前会话

`chatluna.status` 用于查看当前聊天窗口对应的会话详情。

- **什么时候发**：感觉机器人回复变慢、疑似卡住，或想确认当前群聊绑定的模型及上下文长度时。
- **发完看到什么**：返回当前会话的概况卡片，包含会话编号、运行状态（空闲、生成中、待处理消息数）、日志条目数与模型可见消息数，以及当前生效的提供商与模型。

### 查看活跃会话

`chatluna.routes` 用于列出当前实例中所有活跃的会话与调用引擎。

- **什么时候发**：排查场景规则生效情况，确认某个群聊或私聊是否被对应规则正确接管时。
- **发完看到什么**：返回活跃路由与引擎列表。这是一条隐藏指令，默认不会出现在全局帮助中，需要排查问题时可直接调用。

## 管理对话

日常聊天中如需开启新话题、打断回复或整理上下文，可以使用以下指令：

| 指令 | 别名 | 作用 |
| --- | --- | --- |
| `chatluna.new` | `new`、`clear` | 开启新对话，旧记录保留 |
| `chatluna.session.fork` | 无 | 从当前对话分出一个分支 |
| `chatluna.stop` | `stop` | 停止正在生成的回复 |
| `chatluna.compact` | `compact` | 压缩当前会话的上下文 |

各指令的具体使用场景与行为如下：

- **`chatluna.new`**：准备开启新话题、不想让历史内容干扰后续回答时发送。机器人会提示新会话已创建。注意：开启新对话不会删除旧记录，旧会话仍会完整保存在控制台的「轨迹」页面中供查阅。
- **`chatluna.session.fork`**：想在当前话题基础上探索其他分支、同时保留主线讨论时发送。机器人会确认生成会话分支，后续聊天将写入该分支，原对话不受影响。
- **`chatluna.stop`**：模型生成回复过长或输出偏离预期需要停止时发送。机器人会立即中断当前这轮生成，队列中已排队的消息仍会保留。
- **`chatluna.compact`**：对话轮数较多、上下文过长导致响应变慢或消耗过多 Token 时发送。机器人完成压缩后会发送提示，将较早的历史消息压缩为摘要。此时模型可见的上下文变短，但底层完整日志依然保留。

## 切换模型

如果想临时更换模型，可以使用 `chatluna.model` 指令：

- **什么时候发**：不带参数时，用于确认当前会话正在使用的模型；附带参数时（格式为「提供商/模型」，例如 `chatluna.model openai/gpt-4o-mini`），适用于遇到模型限流、额度耗尽或需要临时测试其他模型时。
- **发完看到什么**：不带参数时，机器人会直接返回当前生效的模型名称；附带参数切换成功后，机器人会提示切换成功，并在下一次请求时生效。如果模型名称填写错误，机器人会返回失败原因，当前模型保持不变。

::: tip
通过该指令切换的模型仅对当前会话生效，属于临时调整。

如果需要长期生效，请在控制台的「场景规则」页面中为该入口绑定模型，或直接修改对应的模型角色。
:::

## 定时任务

使用 `chatluna.schedule` 指令，无需打开控制台即可在聊天窗口中管理定时任务。在指令后追加子动作来指定具体操作：

| 动作 | 作用 |
| --- | --- |
| `list` | 列出当前频道的任务 |
| `add` | 新建任务 |
| `remove`（或 `cancel`） | 删除任务 |
| `pause` | 暂停任务 |
| `resume` | 恢复任务 |
| `fire` | 立即触发一次 |

如果不填写子动作，默认等同于 `list`。各动作的使用场景如下：

- **`list`**：查看当前频道已添加的定时任务。执行后会显示任务编号、执行周期与当前状态。
- **`add`**：需要机器人定时提醒或执行任务时发送。新建时必须从以下四种触发方式中选择一种：指定时刻 `--at`（如标准时间格式、`时:分` 或相对时间 `+30m`）、固定间隔 `--every`（如 `30m`、`2h`、`1d`）、五段式 Cron 表达式 `--cron`，或后台监视条件 `--watch`。同时必须通过 `--reason` 说明任务目的。创建成功后机器人会返回确认信息及唯一任务编号。
- **`remove` / `cancel`**：不再需要某项任务时发送。执行后机器人会提示该任务已被删除。
- **`pause`**：需要临时停用某个任务时发送。执行后机器人会提示该任务已暂停。
- **`resume`**：需要恢复此前暂停的任务时发送。执行后机器人会提示该任务已恢复执行。
- **`fire`**：测试任务效果或临时需要手动触发时发送。执行后机器人会立即运行该任务并返回结果。

所有定时任务均严格归属于创建它的频道，其他群聊无法查看或跨群管理。

::: warning
为了保障系统稳定，任务的数量与执行频率均设有安全上限。过于频繁的调度会被系统直接拒绝，防止异常任务影响整个实例。

具体限制与高级说明请参阅 [定时与后台任务](./automation)。
:::

## 撤销文件修改

当模型调用工具修改了文件时，可以通过 `chatluna.undo` 快速回退更改。

- **什么时候发**：模型在执行代码或整理文件时误删、改错内容，需要恢复文件时发送。
- **发完看到什么**：默认情况下，机器人会撤销最近一次文件修改并返回回退结果。

该指令支持以下选项：

- **本轮全部**：如果模型在本轮对话中连续修改了多个文件，指定该选项可一次性撤销全部改动。
- **强制覆盖**：若目标文件在模型修改后又被手动编辑过，系统默认会拒绝撤销以保护内容；指定强制选项后，机器人将忽略该保护并强制回退。

该功能依赖后台的文件历史服务。如果对应插件未启用，此指令将不可用。

::: tip
撤销功能主要用于挽回偶发的误操作，不能替代版本控制。如果改动较多，建议优先使用项目自身的版本管理系统。
:::

## 初始化与创作者模式

在初次配置机器人或进行深度调试时，可以使用以下指令：

| 指令 | 别名 | 作用 |
| --- | --- | --- |
| `chatluna.setup` | `setup` | 重新开始人设配置 |
| `chatluna.bind` | `bind` | 用绑定码把发送者设为主人 |
| `chatluna.creator` | 无 | 进入创作者模式 |
| `chatluna.creator.off` | 无 | 退出创作者模式 |

各指令的使用时机与行为如下：

- **`chatluna.setup`**：模型配置就绪后，想重新调整机器人的人设风格与参数时在私聊中发送。发送后机器人会提示准备就绪，下一条消息将直接进入人设配置流程。
- **`chatluna.bind`**：初次配置时，在控制台获取绑定码后，在私聊中向机器人发送并附带该码。发送后机器人会校验凭证并提示主人身份绑定成功。
- **`chatluna.creator`**：需要现场调试或允许机器人在当前会话中直接修改自身配置时发送。发送后机器人会确认进入创作者模式，并开放更高的配置调整权限。
- **`chatluna.creator.off`**：调试完毕需要恢复常规权限时发送。发送后机器人会提示已退出创作者模式。

::: warning
创作者模式会显著放宽模型的执行权限。切勿在公开群聊中长期开启，演示或调试结束后请及时关闭。
:::

## 审批

当工具调用涉及敏感操作时，系统不会直接放行，而会在聊天窗口中主动发起提问，并附带编号选项。

- **什么时候发**：审批请求由系统主动发起。在聊天窗口中收到审批提问时，直接回复对应编号即可。
- **发完看到什么**：回复编号后，机器人会确认授权决定并继续执行后续流程。通常包含三种选项：仅允许本次调用、本次对话内始终允许，或拒绝本次调用。

审批问题专供人工审核，模型无法代答，只有权限等级符合要求的用户回复才生效。

如果长时间无人处理，请求会在超时后依次转交给下一位审批者；若所有候选审批者均未回应，系统将按未批准处理并终止操作。

::: tip
系统默认开启「附带编号选项」，直接回复数字即可。如果关闭了该选项，则需要输入完整的判定指令内容。
:::

## 帮助

如果想了解可用的指令及其用法，可以使用基础的 `help` 指令。

- **什么时候发**：忘记指令拼写，或需要查阅特定指令支持的参数与选项时发送。
- **发完看到什么**：单独发送 `help` 时，机器人会列出当前权限下可用的全部指令；附带指令名时（如 `help chatluna.status`），机器人会返回该指令的语法格式、必选与可选参数、选项开关及使用示例。

由于指令帮助由各插件注册时提供，安装并启用新插件后，帮助列表中会自动出现对应的新指令。

## 常见组合

这里整理了日常使用中最常见的几组操作流程：

- **排查回复卡顿**：先发送 `chatluna.status` 确认运行状态与排队进度，再前往控制台的「轨迹」页面查看该会话的详细日志。
- **上下文过长**：发送 `chatluna.compact` 进行压缩，收到完成提示后即可继续对话。
- **临时更换模型**：发送 `chatluna.model 提供商/模型` 切换模型，下一条消息立即生效。
- **设置定时提醒**：发送 `chatluna.schedule add --at +30m --reason 提醒大家准备开会` 添加定时任务。
- **撤销文件改动**：发送 `chatluna.undo` 撤销最近一次修改；如果本轮连续修改了多个文件，可以附带选项批量撤销。

## 排查

使用指令时如遇到问题，可以先对照以下要点进行排查：

- **发送指令后没有反应**：确认是否需要输入触发前缀（如 `/` 或 `.`），检查消息是否被平台作为普通聊天交由模型处理，并确认发送者是否已完成主人绑定。
- **提示「当前入口未绑定路由」**：说明当前群聊或私聊尚未匹配任何场景规则。请前往控制台的「场景规则」页面为该入口添加生效规则。
- **提示「当前路由暂无活跃会话」**：说明规则已匹配该入口，但此前尚未产生对话。先发送一条普通消息与机器人交互，随后再使用管理指令。
- **切换模型提示失败**：检查输入的「提供商/模型」是否存在于可用模型列表中，并确认对应的提供商处于启用状态。
- **定时任务创建失败**：检查是否同时指定了多种触发条件；确认时间格式是否正确；检查当前频道的任务总数是否已达上限。
- **审批提问发出后无人处理**：确认回复者的权限等级是否满足要求；若关闭了数字编号选项，检查输入的文本是否符合要求。
