# 权限与安全

::: tip
权限系统回答一个问题：这次操作，该不该让它做？它管的是工具调用、文件读写、命令执行、技能密钥这些有后果的动作，不是聊天内容的审核。
:::

ChatLuna 的权限不是简单的「管理员 / 普通用户」两档。它把「谁」「做什么」「在哪个范围」「风险多高」拆开判断，再交给模式、规则和人工审批三层共同决定。这样既能给主人放权，也能在群里把危险动作收紧。

## 等级

每个用户有一个 0–5 级的权限等级：

| 等级 | 典型身份 | 默认模式 |
| --- | --- | --- |
| 0 | 未登记或受限用户 | 只读 |
| 1 | 普通群成员 | 只读 |
| 2 | 活跃成员 / 受信任用户 | 只读 |
| 3 | 群管理员 | 自动 |
| 4 | 群主 / 主人 | 自动 |
| 5 | 实例主人 | 完全放行 |

等级可以从几个地方来：

- **主人列表**：在权限设置里填写平台用户 ID，直接给到高等级。
- **平台身份**：群主、管理员、普通成员可以分别映射到不同等级。默认群主 4 级、管理员 3 级、普通成员 1 级。
- **角色**：自定义角色，每个角色有等级和继承关系。用户可以绑定多个角色，取最高等级。
- **手动指定**：在权限页给某个用户单独设等级。

等级不是「越权开关」，而是一个默认值。真正的判定还要看模式、规则和风险。

## 四种模式

| 模式 | 允许什么 | 适合谁 |
| --- | --- | --- |
| 只读 | 读取、查询类操作；写入和执行一律拒绝或询问 | 普通群成员、未信任用户 |
| 文件 | 允许文件读写；命令执行等高风险操作仍需审批 | 需要改文件但不该执行命令的用户 |
| 自动 | 由审查器模型判断，能放行的放行，拿不准的再问 | 管理员、受信任用户 |
| 完全放行 | 大部分操作直接执行；危险和高危操作仍受限制 | 实例主人、5 级用户 |

「完全放行」只对 5 级生效。低于 5 级的用户，即使规则写了放行，也会按自动模式处理。

模式可以出现在几个层级：

- 插件配置里的默认模式。
- 各等级的默认模式。
- 场景规则里的权限模式（按群、按用户覆盖）。
- 单次调用的模式上限。

多层同时存在时，取更严格的那个。场景规则可以替换基础模式，但不能把更严格的等级限制放宽。

::: warning
不要把「完全放行」当成省事的默认值。它只适合你完全信任的主人账号；群里的普通成员应该保持在只读或文件模式。
:::

## 风险等级

同样是「允许」，不同操作的风险不一样。系统把风险分为三档：

- **普通**：读文件、查记忆、访问网络等。按模式和规则判断即可。
- **危险**：写文件、执行命令、修改配置、使用技能密钥等。即使模式允许，也可能被要求审批。
- **高危**：删除、批量修改、影响实例运行的操作。需要 3 级以上；始终需要人工确认，规则里的「始终允许」对它无效。

风险不是按工具名硬编码的，工具可以声明自己的风险，权限系统再结合动作和目标判断。

## 规则

规则是权限系统的细粒度控制。一条规则通常包含：

- **动作**：例如读文件、写文件、执行命令、读取记忆、使用技能密钥。
- **目标**：动作作用的对象，例如某个路径、某个命令前缀、某个记忆主题。
- **谁**：用户、角色、等级、群、会话、路由、Agent 或平台。
- **效果**：允许、询问、拒绝。
- **有效期**：本轮、本会话、一段时间，或永久。
- **是否最终**：命中后是否还继续看后面的规则。

规则的判定顺序大致是：

1. 先看有没有明确的拒绝规则。任何一个拒绝都会让整个请求失败。
2. 再看有没有明确的允许或询问规则。
3. 没有规则命中时，才回退到模式和等级。

复合请求会拆成多个部分逐个判断：例如一条命令包含多个子命令，每个子命令都要通过，整体才通过。

::: tip
规则适合处理「这个人可以写这个目录」「这个群只能用只读命令」这类精确控制。不要用规则去替代等级；等级是默认值，规则是例外。
:::

## 审批

当模式或规则决定「询问」时，系统会发起一次审批：

- 在聊天里发一条消息，列出要执行的动作、目标、风险和原因。
- 在 WebUI 的审批槽位里显示同样的内容。
- 等待有足够等级的人确认。审批人的等级要达到这次操作要求的授权等级。

可选的回答：

- **允许本次**。
- **允许本轮**。
- **允许本会话**。
- **始终允许**（高危操作不提供）。
- **拒绝**。
- **始终拒绝**。

审批超时默认 120 秒，超时按拒绝处理。发给不可达的审批人会顺延给下一个可用的审批人；取消审批不等于允许。

审批结果会记入审计日志，包含谁请求、谁批准、批准了什么、有效期多长。

::: warning
「始终允许」会记住一个可复用的范围。对命令类操作，它可能记住命令前缀，而不是完整命令。批准前看清提示里写的「将记住」范围；不确定时选「允许本次」。
:::

## 审查器

自动模式下，系统会把请求交给审查器模型判断。审查器会看动作、目标、风险和上下文，决定放行还是转人工。

可调的项目：

- **审查器模型**：默认使用决策角色，也可以指定具体模型。
- **审批超时**：默认 120 秒。
- **各等级默认模式**。

审查器不是万能的。它适合减少管理员的重复确认，不适合替代明确规则。对确定不能做的操作，直接用拒绝规则或禁用工具，而不是指望审查器每次都拒绝。

## 权限预设

权限预设把一组常用的模式、规则和等级映射打包成一个可切换的方案。例如：

- **严格**：普通成员只读，写入和执行都要审批。
- **标准**：管理员自动，普通成员只读。
- **宽松**：受信任用户自动，只有高危操作需要审批。

切换预设会替换当前的权限配置。自定义规则不会被预设覆盖时，仍按规则优先。

## 常见场景

### 群里只允许查询

普通成员保持只读；管理员自动。场景规则里把命令执行和文件写入设为询问。这样群友可以问问题、查资料，但不能让机器人改东西。

### 私聊放开

私聊用户单独设等级或权限模式。主人私聊可以完全放行；普通用户私聊保持文件或自动模式，危险操作仍要审批。

### 给某个群管理员放权

用群成员规则，把指定用户设为 3 级或 4 级，并允许自动模式。不要给整个群放权，除非你信任群里的每个人。

### 技能密钥

技能密钥默认是危险操作，需要较高等级。可以按群禁止技能使用密钥，这样即使技能被加载，也拿不到敏感变量。

### 子代理

子代理继承发起者的权限上下文，并带上委派链。审批提示会显示「子代理：A → B」，方便判断是谁发起的。子代理不能绕过发起者的权限上限。

## 排查

**工具调用一直被拒绝。**
看权限模式是不是只读，用户等级够不够，有没有拒绝规则命中。审批超时也会按拒绝处理。

**主人也无法执行。**
高危操作始终需要人工确认，规则里的放行对它无效。确认审批人等级是否达到要求。

**审批消息没收到。**
检查 IM 审批插件是否启用、审批人是否在可达的会话里、审批动作是否被过滤。超时后会顺延给下一个审批人。

**批准了但下次还要问。**
选择的是「允许本次」而不是「允许本会话 / 始终允许」。高危操作只提供本次允许，这是有意的。

**规则改了不生效。**
检查是否有更严格的模式或等级限制；多层模式取更严格的那个。场景规则可以替换基础模式，但不能放宽等级限制。
