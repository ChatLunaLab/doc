# 权限与安全

::: tip
权限系统负责管辖工具调用、文件读写、命令执行等具有实际影响的行为，不限制日常聊天的文本内容。它的核心职责是判断：当前操作是否允许执行？
:::

除了日常闲聊，机器人还可以调用工具读写文件、执行系统命令甚至管理服务。为了防止误操作损坏数据或泄露敏感信息，安全防护至关重要。

ChatLuna 的权限系统并非简单的「管理员」与「普通用户」二选一。每次操作发生时，系统会综合评估发起者身份、操作内容、影响范围与危险程度，再由权限模式、精准规则与人工审批共同裁决。

这样你既可以在私聊中放开高级工具，也可以在公开群聊中严格收紧危险操作。

![权限页 · 用户、角色与待审批列表](/webui/permissions.png)

前往控制台，在左侧导航栏中点击「权限与安全」，即可查看实例当前的权限管理界面。

你可以在这里查看用户列表、自定义角色以及实时的待审批事件，并按需调整不同账号在各环境下的权限。下面我们从最基础的用户等级开始介绍。

## 等级

在 ChatLuna 中，每个用户都会被赋予一个 0 到 5 级的权限等级：

| 等级 | 典型身份 | 默认模式 |
| --- | --- | --- |
| 0 | 未登记或受限用户 | 只读 |
| 1 | 普通群成员 | 只读 |
| 2 | 活跃成员 / 受信任用户 | 只读 |
| 3 | 群管理员 | 自动 |
| 4 | 群主 / 主人 | 自动 |
| 5 | 实例主人 | 全部允许 |

用户的权限等级主要来源于以下几个途径：

- **主人列表**：在控制台权限设置中填入的各平台用户账号。主人直接拥有 5 级权限。
- **平台身份**：在群聊场景中，系统会自动映射平台原生身份。群主对应 4 级，群管理员对应 3 级，普通成员对应 1 级，无需手动录入。
- **角色**：你可以创建自定义角色并指定等级。当用户拥有多个角色时，系统会自动取其中的最高等级。
- **手动指定**：在用户列表中点击某个用户，即可在详情面板中手动为其指定权限等级。

需要注意的是，拥有权限等级并不意味着可以任意执行操作。具体操作能否执行，还要取决于当前生效的模式与规则。

## 四种模式

在等级之上，系统通过「权限模式」划定用户在当前环境下的基础行为边界：

| 模式 | 允许什么 | 适合谁 |
| --- | --- | --- |
| 只读 | 读取、查询类操作；写入和执行一律拒绝或询问 | 普通群成员、未信任用户 |
| 只改文件 | 允许文件读写；命令执行等高风险操作仍需审批 | 需要改文件但不该执行命令的用户 |
| 自动 | 由审查器模型判断，能放行的放行，拿不准的再问 | 管理员、受信任用户 |
| 全部允许 | 大部分操作直接执行；危险和高危操作仍受限制 | 实例主人、5 级用户 |

`全部允许` 仅对 5 级的实例主人真正生效。如果为低于 5 级的用户配置了该模式，系统会自动降级为 `自动` 模式运行，防止出现意外越权。

权限模式可以配置在不同的层级上：

- 插件配置中的全局默认模式
- 各权限等级绑定的默认模式
- 在「场景规则」中针对单个群聊或用户设置的覆盖模式
- 单次特定调用所允许的模式上限

当多个层级的模式同时存在时，系统始终遵循「取更严格者」的原则。

例如，即便你在某个群聊的场景规则中放宽为自动模式，但只要用户自身的等级限制在只读模式，最终依然按只读模式执行；同样，场景规则也无法突破底层等级设定的安全上限。

::: warning
请勿将 `全部允许` 设为全局默认模式。在多人公开群聊中，请务必让成员保持在 `只读` 或 `只改文件` 模式。
:::

## 风险等级

即便属于允许调用的动作，不同操作的潜在破坏力也各不相同。

为了防止误操作引发危险，系统将所有动作划分为三个风险等级：

- **普通**：例如读取本地文件、查询记忆库、搜索网页等只读操作。只要符合当前模式即可直接放行，无需额外确认。
- **危险**：例如写入并保存文件、执行终端命令、修改配置、读取技能密钥等具有实际影响的操作。即使处于允许写入的模式，系统仍可能要求审批。
- **高危**：例如删除文件目录、批量修改关键数据、重启或终止实例等核心操作。此类操作仅限 3 级及以上用户申请，且必须经过人工确认；即便配置了「一直允许」规则也不会自动放行。

动作的风险等级并不是固定不变的。

工具在注册时会声明基准风险，运行时权限系统还会结合操作目标做出动态评估。例如同样是读写文件，修改普通文本属于普通或危险动作，而试图覆盖系统关键配置文件则会被立即升级为高危动作。

## 规则

如果预设的等级与模式无法满足特定群聊或特殊成员的需求，可以通过添加自定义规则来精细控制。

前往「权限与安全」页面的「规则」标签页，点击右上角的「添加规则」按钮即可创建一条新规则。规则包含以下核心字段：

- **动作**：具体执行的操作类型，例如读取文件、写入文件、执行命令、读取记忆或使用技能密钥。
- **目标**：动作施加的对象范围，例如特定的文件路径、允许执行的命令前缀或记忆主题，支持通配符匹配。
- **谁**：规则适用的主体，可以精确指定到具体用户、角色、等级、群组、会话、路由、Agent 乃至平台。
- **效果**：命中后的裁定结果，分为允许、询问或拒绝。
- **有效期**：规则的生效周期，支持本次调用、本轮对话、当前会话、特定时间段或永久生效。
- **是否最终**：指定该规则在命中后是否立即终止判定，不再继续比对后续规则。

当模型发起操作时，系统会自顶向下依次比对规则：

1. 检查是否存在匹配的明确「拒绝」规则。一旦命中任何一条拒绝规则，请求立即终止。
2. 依次检索是否存在匹配的明确「允许」或「询问」规则。
3. 若未命中任何规则，系统将回退到当前主体的权限模式与等级进行兜底判定。

若一个请求包含多个子操作，系统会将其拆解为独立部分分别判定。只有所有子操作全部通过时，整个请求才会执行；任意一处被拒都会整体验退。

::: tip
规则非常适合用于「允许某人修改指定目录」等特殊需求。在日常管理中，建议使用权限等级覆盖大多数场景，仅将规则留给个别例外。
:::

## 审批

![权限页 · 审批弹窗与授权选项](/webui/permissions.png)

当权限模式无法确定操作意图，或者命中了效果为「询问」的规则时，系统会主动暂停当前操作并触发人工审批。

此时，系统会通过两个渠道推送审批提示：

- **聊天窗口**：直接发送审批消息，包含发起人、操作内容、目标对象、风险等级及调用原因。
- **控制台**：在 WebUI 右上角显示待办徽标，并展示相同的审批卡片。

审批人自身的权限等级必须达到该操作要求的最低门槛，只有合规的管理者才能裁决。审批卡片上提供了以下几种处理方式：

- **允许这一次**：仅放行当前这次操作，后续再次调用时仍会重新发起询问。这是最推荐、最稳妥的日常选项。
- **这一轮都允许**：在当前对话回合的全部后续交互中放行该动作，进入下一轮新对话后恢复审批保护。
- **这个会话都允许**：在当前整个会话期间不再重复询问，适合集中调试代码或处理任务。
- **一直允许…**：为该操作自动生成一条持久放行规则（高危操作出于安全考虑不提供该选项）。
- **拒绝**：直接驳回本次操作请求，模型会收到拒绝反馈并尝试调整后续策略。
- **一直拒绝…**：驳回请求并沉淀一条永久拒绝规则，杜绝后续重复提示。

系统内置的审批等待超时时间默认为 120 秒。若超时未获批复或被用户主动取消，系统将自动按「拒绝」处理。每次审批结束后，系统都会把申请人、批准人、操作对象与生效时限完整记录到审计日志中备查。

::: warning
点击「一直允许…」时请格外留意。对于终端命令类调用，系统匹配的通常是命令前缀而非单一完整指令。在批准前请看清提示中的范围；一旦拿不准，建议优先选择「允许这一次」。
:::

## 审查器

在 `自动` 模式下，系统并不会盲目放行操作，而是将请求交给「审查器模型」进行前置评估。

审查器模型会审阅模型打算调用的动作、目标路径、风险评级，并结合前后的对话上下文，推断这次操作是否合理、是否存在越权隐患，进而决定是直接放行还是转交人工审批。

前往控制台的「权限与安全 → 审查器」配置区域，你可以调整以下几项核心参数：

- **审查器模型**：默认选用当前系统配置的决策角色，你也可以指定一个推理能力更强的专用模型。
- **审批超时**：控制审批卡片等待人工处理的最长时限，默认为 120 秒。
- **各等级默认模式**：灵活调节 0 到 5 级用户所绑定的预设权限模式。

需要注意的是，审查器无法保证百分之百准确。

它的主要作用是替管理员过滤常规的无害读取操作，减轻频繁弹窗的负担。对于绝对不能发生的危险操作，请务必在规则中添加明确的「拒绝」规则，或直接禁用对应工具，切莫单纯依赖审查器拦截。

## 权限页

前往控制台的「权限与安全」页面，顶部共有四个标签页，分别负责不同的管理任务：

- **待审批**：集中处理等待人工答复的操作请求。页面列出了实时的待办卡片列表，每张卡片清楚展示了申请人、具体动作、目标对象、风险等级以及审批所需的最低权限门槛，右侧配有快捷审批按钮。
- **谁能做什么**：查看与管理所有用户与角色的权限边界。左侧列出当前已记录的用户与自定义角色列表，点击任意用户可以直接调整其权限等级与指定模式；点击任意角色则能配置其基准等级、生效模式以及继承关系。
- **规则**：管理自定义的精准权限匹配规则。表格详细展示了动作、目标、主体、效果与有效期等字段，右上角提供「添加规则」按钮用于快速新建策略。
- **记录**：查看系统最近 24 小时的权限判定足迹。页面提供操作判定日志与统计图表，按允许、询问、拒绝与审查放行等状态分类归纳，点击单条记录可展开查看详细判定依据与当时匹配的上下文信息。

页面上方的「缺省模式」决定没有命中任何规则时的兜底行为，旁边会列出单独设置过的对象，方便你确认哪些用户或角色未跟随缺省值。

### 审批选项

在审批卡片或弹窗中，系统提供了以下几种处理选项：

- **允许这一次**、**这一轮都允许**、**这个会话都允许**、**一直允许…**
- **拒绝**、**一直拒绝…**

其中，「一直允许…」与「一直拒绝…」会自动保存为持久规则，后续命中相同条件的请求将直接生效而不再询问；「这个会话都允许」则仅在当前会话窗口内有效。同时，审批人自身的权限等级必须达到卡片上标明的门槛，否则无法执行放行操作。

## 常见场景

本节介绍日常维护中最常见的几种典型场景与配置建议：

### 群里只允许查询

在日常群聊中，如果希望群友能够自由提问、查资料或让机器人搜索网页，但不希望机器人随意修改主机文件：

1. 让普通群成员保持默认的 `只读` 模式，将群管理员设为 `自动` 模式。
2. 在「场景规则」中，针对该群聊将命令执行与文件写入的权限效果统一设为「询问」。

这样群友在群里正常聊天与查资料完全不受影响；一旦有人尝试诱导模型生成脚本写入磁盘或执行 Shell 命令，系统会立即发起审批，群管理员点击拒绝即可拦截。

### 私聊放开

与群聊相比，私聊通常更具隐私性与专属感。

你可以在权限页为经常私聊的用户单独指定更高的等级或权限模式。对于你本人的私聊会话，可以直接配置为 `全部允许`；而对于其他私聊协作者，建议维持在 `只改文件` 或 `自动` 模式，确保涉及系统底层的危险操作依然需要经过你的把关。

如果需要让协作者在私聊中协助维护某个插件的配置文件，分配 `只改文件` 模式即可：对方可以自由读写指定数据，但依然无法越权执行宿主机系统命令。

### 给某个群管理员放权

如果你希望某位群管理员能够独立管理本群的机器人特性，但又不想给全群放权，请勿直接提升整个群的基准等级。

正确的做法是前往该群的配置面板，在群成员规则列表中定位到该成员，单独将其权限等级提升为 3 级或 4 级，并为其开启 `自动` 模式。

这样既能满足协同管理的需要，又不会将多余权限误放给其他群成员。当普通群友试图调用管理指令时，系统依旧会拦截。

### 技能密钥

很多外部技能在调用第三方 API 时都需要依赖专属的访问凭据。

在权限体系中，读取与注入「技能密钥」属于明确的「危险」动作，需要较高的权限等级才能调取。你可以在场景规则中按群直接禁止技能调取密钥，这样即使在群聊中有人触发了对应技能，系统也会拒绝下发凭据，避免敏感变量泄露。

对于某些需要消耗付费 API 额度的高级技能，你可以仅在专属管理群中放开密钥使用，而在普通公开群里将其设为禁用。

### 子代理

当主代理将复杂任务拆解并指派给子代理并发执行时，子代理会自动继承发起者的全部权限上下文，并在执行链条中完整附带委派链路信息。

当子代理需要发起审批时，审批卡片中会清晰标注委派链条（例如显示「子代理：A → B」），帮助审批人一眼看清任务源头。需要注意的是，子代理的权限永远不会超出初始发起者的权限上限，无法通过多层委派完成越权突破。

## 排查

在日常使用权限系统的过程中如果遇到未达预期的情况，可以对照以下条目快速排查：

**工具调用一直被拒绝**
- 确认当前会话生效的权限模式是否处于只读状态。
- 检查当前用户的权限等级是否达到工具要求的门槛。
- 排查规则列表中是否存在命中的明确拒绝规则。
- 检查是否存在审批超时未处理的情况（超时默认按拒绝记录）。

**主人也无法执行**
- 删除重要文件、影响实例运行等高危操作始终需要人工确认，即便配置了始终放行规则也一律无效。
- 检查界面是否已弹出审批卡片，并确认当前操作账号的实际等级是否满足高危授权门槛。

**审批消息没收到**
- 检查即时通讯平台的审批插件是否处于启用状态。
- 检查审批人账号是否处于机器人可达的私聊或管理会话中。
- 检查审批通知是否被平台侧的消息过滤器拦截。注意审批超时后系统按拒绝处理，不会自动顺延给其他人。

**批准了但下次还要问**
- 检查上次弹出审批提示时点击的是否为「允许这一次」。若选择单次允许，下次调用仍会重新发起审批。
- 高危操作出于安全考虑仅提供单次允许选项，无法配置为始终放行。

**规则改了不生效**
- 检查是否存在层级更高、限制更严的模式或等级约束。当多个层级的模式叠加时，系统始终以更严格的限制为准。
- 场景规则虽然能够替换基础运行模式，但不能打破底层等级设定的硬性上限。
