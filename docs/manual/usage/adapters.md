# 接入聊天平台

::: tip
这一页讲怎么把机器人接进 QQ、Discord、Telegram 这些聊天平台。接进去之后，平台上的消息会进入 ChatLuna 的对话流程，回复再原路发回去。
:::

ChatLuna 本身不直接和具体的聊天平台打交道。

中间隔着一层适配器 (Adapter)：适配器负责登录平台账号、接收消息、把消息转换成统一格式；ChatLuna 处理完再交给适配器发回去。

这样做的好处是，不管是 QQ 还是 Discord，对后面的对话逻辑来说都一样。场景规则、权限、角色、记忆这些配置，换平台不用重写。

同一个实例可以同时接入多个适配器、多个账号。一个 QQ 号加一个 Discord 机器人，完全可以共存。

## 聊天平台页

在控制台左侧导航的「配置」分组里，点击「聊天平台」。

页面上每一张卡片，对应一个平台或一个账号实例。卡片上能看到：

- **平台与名称**：是哪个平台、这个实例叫什么。
- **启用状态**：是否正在运行。
- **包状态**：对应的适配器插件是否已经安装。
- **凭据状态**：必填的密钥是否都配好了。
- **机器人状态**：在线、离线、连接中、断开、重连中，以及账号的头像和昵称。

机器人状态会定时刷新，即使平台那边悄悄断线，几秒内也能在页面上看到变化。

### 添加一个平台

点击「添加」，先选平台类型，再填写配置。

平台列表里包含常见的即时通信平台：

| 平台 | 说明 |
| --- | --- |
| **OneBot (V11)** | QQ 生态最常见的协议，需要配合 OneBot 实现端使用 |
| **QQ** | 官方 QQ 机器人接口 |
| **Discord** | 服务器与频道 |
| **Telegram** | 群组与私聊 |
| **KOOK** | 语音社区平台 |
| **飞书 / 钉钉 / 企业微信** | 企业办公场景 |
| **Slack / Matrix / Zulip** | 团队协作场景 |
| **WhatsApp / LINE / Mail / 微信公众号** | 其他平台的接入 |
| **Satori** | 连接另一个 Satori 服务，适合多实例组网 |

选中之后，右侧会显示这个平台的配置表单。

不同平台的字段不一样，但常见的就几类：账号标识、服务地址、访问令牌，以及一些平台特有的参数。

表单来自适配器插件本身。也就是说，插件更新后新增的配置项，会自动出现在这里。

::: tip
有一个平台不用配置：控制台内置的网页渠道。

它让「聊天」页可以直接和机器人对话，不需要任何外部账号，非常适合在接平台之前先验证配置是否走通。
:::

### 安装与卸载

有些平台适配器是单独发布的包，第一次使用时并没有安装。

这种情况下，页面会提示「未安装」，并提供安装按钮。点一下就会从软件源拉取对应的适配器包。

启用之前必须先安装。如果安装失败，通常是网络问题或者包名不对，页面会给出命令行的输出。

卸载是反过来的：必须先停用，再卸载。这样能避免把正在使用的账号配置留在一个不存在的插件上。

::: warning
卸载适配器**不会**删除你在平台上创建的内容。它只是让 ChatLuna 不再连接这个账号。如果你确实要断开，记得在平台侧也处理一下。
:::

## 配置项

每个适配器的表单结构不同，但配置的存储方式是一样的。

### 凭据

访问令牌、密钥、密钥文件这类字段，会被单独加密保存。

它们在界面上不会回显，只显示「已配置」或「缺失」。修改时留空表示保留原来的值。

如果某个必填的密钥缺失，适配器可以被保存，但不能被启用。页面会明确告诉你缺了哪一项。

::: warning
不要把令牌贴在聊天记录、截图或者公开的配置文件里。

一旦泄漏，别人可以冒充你的机器人发消息。发现泄漏时，先在平台侧重置令牌，再回到这一页更新。
:::

### 账号标识

每个适配器实例都必须有一个能区分它的账号标识，通常是机器人在平台上的账号 ID。

同一个平台接入两个账号时，两个实例的标识不能相同，否则系统无法判断某条消息该由哪个账号处理。

### 配置快照

适配器插件的设置里，可以指定一个目录来保存配置快照。

开启之后，每次修改适配器配置前都会留一份备份。配置改坏了想回退，比重新填一遍表单省事得多。

这个目录默认是关闭的，需要自己指定。

## 启用与停用

保存好配置，点击启用，适配器才会真正开始连接。

启用之后，系统会做几件事：

1. 加载对应的适配器插件。
2. 用你填的凭据登录平台账号。
3. 把账号状态、头像、昵称同步到页面。
4. 开始接收这个账号的消息。

停用则相反：断开连接、卸载消息处理，但保留配置。适合临时下线，或者排查某个平台的问题。

::: tip
改完配置后，适配器会自动重连，不需要手动重启实例。

如果改了配置但状态一直不对，先停用再启用一次，比反复改配置更有效。
:::

## 多个账号

一个实例可以同时跑多个账号，常见的组合是：

- 一个 QQ 号负责群聊，另一个只负责私聊。
- 不同群用不同的机器人，避免「一个号被踢，所有群失联」。
- 测试账号与正式账号分开。

每个账号在场景规则里都可以单独指定。比如你可以让 A 号只在技术群回答，B 号只在娱乐群出现。

规则里能区分「平台」和「机器人账号」，两者一起用，就能精确到「哪个平台的哪个机器人」。

## 消息怎么流转

理解这条链路，排查问题会轻松很多：

1. 平台把新消息推给适配器。
2. 适配器把消息转换成统一的内部格式，交给 ChatLuna。
3. ChatLuna 根据消息内容、群、用户等信息匹配场景规则。
4. 命中规则后，交给对应的引擎和模型处理。
5. 生成的回复再交回适配器。
6. 适配器按平台要求格式化并发送。

这条链路上任何一环出问题，表现都是「机器人不说话」。所以排查时不要一上来就怀疑模型。

## 平台差异

不同平台对消息的限制不一样，这会影响最终的回复效果：

- **长度限制**：有的平台单条消息有字数上限，超长回复会被拆成多条。
- **消息元素**：图片、语音、表情、按钮这些元素，不是每个平台都支持。
- **撤回与编辑**：部分平台支持编辑已发送的消息，流式输出体验会更好。
- **频率限制**：发得太快可能被平台限流，表现为部分消息丢失。
- **@ 与引用**：@ 的实现方式不同，直接影响「什么时候回复」的判断。

遇到「在 A 平台正常、在 B 平台异常」时，先确认是不是平台能力差异，而不是配置写错了。

## 推荐配置

### 只接一个 QQ 号

最省事的组合：一个 OneBot 适配器，配合一个 OneBot 实现端。

先在自己的实现端里登录 QQ，再回到 ChatLuna 的聊天平台页，填入它的地址和令牌。两边都连通后，机器人状态会变成在线。

建议单独建一个测试群，先把基础对话跑通，再拉进正式群。

### 多平台同号

QQ、Discord、Telegram 各接一个，共用同一套模型和角色。

此时要注意账号与场景规则的配合：不同平台的群 ID 不一样，规则需要分别配置。

共享的东西（模型、预设、记忆策略）放全局，平台相关的东西（规则、权限、名字）分开配。

### 企业办公

飞书、钉钉或企业微信，通常需要企业管理员开通机器人应用，再拿凭据填进来。

这类平台对消息格式和权限审核更严格，建议先在小范围内部群里试运行。

### 自建网关

如果你已经有多个 ChatLuna 实例，可以用 Satori 适配器把它们串起来。

一个实例作为消息汇聚点，其他实例作为处理节点，按平台或群分流。

## 排查

**适配器一直显示未安装。**

点击安装按钮，看返回的输出。常见原因是网络无法访问软件源，或者包名已经变更。

**状态是「已启用」但机器人离线。**

先看页面上的错误信息。常见原因：令牌失效、服务地址写错、平台侧账号被限制、网络无法出站。

如果是 OneBot，先确认实现端本身是否在线、是否允许当前 IP 连接。

**机器人在线，但群里不回话。**

这已经不是适配器的问题了。去「场景规则」确认这个群有没有命中规则，再去「轨迹」页看消息有没有进来。

**消息发出去了，但格式很乱。**

平台不支持某些消息元素，或者长度超限被拆分。可以调整回复格式，或者在该场景限制输出长度。

**两个账号互相回话。**

两个机器人同时在一个群里，会互相触发。关掉其中一个的自动回复，或者在规则里排除对方账号。

**改完配置没生效。**

确认点过保存并重新启用；确认改的是正确的那张卡片；确认没有更高优先级的规则覆盖。
