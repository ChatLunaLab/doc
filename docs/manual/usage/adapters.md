# 接入聊天平台

::: tip
在这一节中，我们来聊聊如何把机器人接入 QQ、Discord、Telegram 这些大家常用的聊天平台。接入完成后，平台上的消息就会平滑流转进 ChatLuna 的对话系统，而生成的回复也会原路推送到对应的聊天中。
:::

ChatLuna 本身并不会直接和具体的聊天平台打交道。

在它们之间，其实是由一层适配器 (Adapter) 在负责沟通。适配器的工作就像是一个翻译官：它负责登录具体的平台账号、接收聊天消息，并把各平台结构各异的数据转换成统一的标准格式交给 ChatLuna；而在 ChatLuna 处理完毕后，再交回给适配器发送出去。

这样做最大的好处，是把平台差异与具体的对话逻辑彻底隔离开来。无论是 QQ 还是 Discord，对底层的对话系统来说都完全一样。你配置好的场景规则、用户权限、预设角色以及长期记忆，换到新平台时依然可以直接复用，完全不需要重写一遍。

另外，同一个 ChatLuna 实例支持同时接入多个适配器与多个账号。一个 QQ 号加上一个 Discord 机器人，完全可以在同一个控制台里并存运行，互不干扰。

## 聊天平台页

打开控制台，在左侧导航的「配置」分组中，点击进入「聊天平台」页面。

在这里，页面以卡片的形式呈现所有已添加的适配器。每一张卡片都对应着一个平台或具体的账号实例。在卡片上，你可以直观地确认以下信息：

- **平台与名称**：当前卡片所属的平台类型，以及你为这个实例设置的别名。
- **启用状态**：显示当前适配器是否正在运行。
- **包状态**：对应的适配器插件是否已经安装就绪。
- **凭据状态**：连接所需的 Token、密钥等必填项是否已经填妥。
- **机器人状态**：显示账号的实时连接状态，例如 `在线`、`离线`、`连接中`、`断开`、`重连中`，同时展示机器人的平台头像与昵称。

卡片上的机器人状态会定时保持自动刷新。即便外部平台偶尔悄悄断开连接，几秒钟内你也能在页面上看到状态变动。

### 添加一个平台

如果想要接入一个新平台，只要在页面右上角点击「添加」按钮。系统会引导你先选择平台类型，然后再进入具体的配置表单。

平台列表中已经涵盖了日常使用的大多数主流聊天应用：

| 平台 | 说明 |
| --- | --- |
| **OneBot (V11)** | QQ 生态最常见的协议，需要配合 OneBot 实现端使用 |
| **QQ** | 官方 QQ 机器人接口 |
| **Discord** | 服务器与频道 |
| **Telegram** | 群组与私聊 |
| **KOOK** | 语音社区平台 |
| **飞书 / 钉钉 / 企业微信** | 企业办公场景 |
| **Slack / Matrix / Zulip** | 团队协作场景 |
| **WhatsApp / LINE / Mail / 微信公众号** | 其他平台的接入 |
| **Satori** | 连接另一个 Satori 服务，适合多实例组网 |

在列表中选中目标平台后，右侧就会展开这个平台的配置表单。

虽然每个平台的底层机制不尽相同，但需要填写的核心项通常只有几类：账号唯一标识、服务连接地址、访问令牌，以及少数平台专属的扩展参数。

这里的表单内容由适配器插件自身提供。换句话说，当插件发布更新并增加了新功能时，对应的新配置项就会直接呈现在表单中，不需要手动调整页面。

::: tip
其实控制台内置了一个完全不需要配置的网页渠道。

在左侧导航点击进入「聊天」页面，你就可以直接在浏览器中与机器人对话。在正式接入外部聊天平台之前，非常推荐先用它来验证模型和预设是否能够正常工作。
:::

### 安装与卸载

为了保持系统的轻量，有些平台适配器是以独立扩展包形式发布的，初次使用时可能尚未安装。

遇到这种情况时，卡片上的包状态会显示为 `未安装`，并在旁边提供一个「安装」按钮。只要点击一下，系统就会自动从软件源拉取并安装该适配器插件。

适配器必须在安装成功之后才能被启用。如果安装失败，通常是由于本地网络无法访问软件源或包名有误，此时卡片底部会直接展示命令行的输出信息供你排查。

当你不再需要某个平台时，操作流程正好相反：必须先停用，再卸载。这样能有效避免正在运行的账号失去插件支撑，防止残留无法清理的配置。

::: warning
卸载适配器**不会**删除或注销你在第三方平台上创建的机器人应用。它仅仅是让 ChatLuna 不再连接这个账号。如果你确实打算彻底停用，记得前往平台侧同步处理。
:::

## 配置项

虽然不同适配器的表单字段各不相同，但它们在数据存储与安全上的机制是一致的。

### 凭据

访问令牌、应用密钥或密钥文件这类敏感字段，在提交保存后都会被系统单独加密存储。

为了保护敏感信息不被泄露，这些凭据在前端界面上不会回显明文，而是统一显示为 `已配置` 或 `缺失`。后续再次编辑表单时，将输入框留空就代表保留原有的凭据不变，不需要每次都重新填一遍。

如果系统检测到某个必填密钥处于 `缺失` 状态，你可以正常保存该表单，但无法将其启用。界面上会清晰地提示你具体缺了哪一项。

::: warning
千万不要把机器人的访问令牌粘贴到群聊记录、截图或公开的文件中。

一旦令牌泄露，他人就能直接冒充你的机器人对外发消息。万一不慎泄露，请第一时间前往平台侧重置令牌，再回到这一页更新保存。
:::

### 账号标识

每个适配器实例都必须配置一个能区分身份的账号标识，通常就是机器人在该平台上的账号 ID。

当你在同一个平台中接入两个账号时，两个实例的账号标识必须保持不同。如果填了相同的标识，系统在分发消息时就无法判断某条消息究竟该交给哪个账号处理。

### 配置快照

在适配器插件的设置项中，你还可以指定一个本地目录来保存配置快照。

开启这项功能后，每次在修改并保存适配器配置前，系统都会在后台自动留存一份备份。万一不小心改坏了配置想回退，直接从快照恢复要比重新填写一遍表单省事得多。

这个快照目录默认是关闭的，需要你手动填入指定的备份路径后才会生效。

## 启用与停用

把配置表单填写完整并点击「保存」后，再点击卡片上的「启用」开关，适配器才会真正开始连接平台。

在点击启用后，系统会在后台依次完成以下几件事：

1. 加载对应的适配器插件核心。
2. 使用你填写的凭据登录第三方平台账号。
3. 把账号状态、头像与昵称同步更新到页面卡片上。
4. 正式挂载消息监听，开始接收该账号在平台收到的消息。

停用的逻辑则正好相反：断开平台连接、卸载消息处理流程，但保留已填写的配置内容。如果你需要临时下线机器人，或者排查某个平台的异常，先停用它是最合适的操作。

::: tip
修改完配置并保存后，适配器会自动尝试重连，通常不需要手动重启实例。

如果修改配置后状态长时间没有恢复，先点击停用再重新启用一次，往往比反复修改配置更有效。
:::

## 多个账号

单个 ChatLuna 实例原生支持多账号同时运行。在实际场景中，常见的组合方式有：

- 一个 QQ 账号负责在群聊里活跃，另一个 QQ 账号只用于私聊答疑。
- 不同的群聊分配不同的机器人，避免出现「一个号被封禁或风控，所有群全部失联」的尴尬情况。
- 把日常测试用的账号与对外运营的正式账号彻底分开，互不干扰。

每个接入的账号，在场景规则中都可以被单独指定。例如，你可以让 A 号只在技术交流群里回答，而 B 号只在休闲娱乐群里出现。

在场景规则的配置中，系统能够同时识别「平台」和「机器人账号」。两者结合使用，就能精准定向到「哪个平台的哪个机器人」。

## 消息怎么流转

理解一条消息在系统内部的完整流转链路，能让你在排查问题时清晰很多：

1. 平台用户发送消息，平台将新消息推送给适配器。
2. 适配器把平台消息转换成统一的内部格式，交给 ChatLuna。
3. ChatLuna 根据消息内容、群组、发送者等信息去匹配场景规则。
4. 命中规则后，交由绑定的引擎与模型进行思考和处理。
5. 模型生成的回复内容重新交还给适配器。
6. 适配器按照平台规范完成格式化，并最终推送回聊天中。

正因如此，这条链路上任何一个环节出现阻塞，在外部看来都表现为「机器人不说话」。因此排查问题时，千万不要一上来就怀疑是模型坏了。

## 平台差异

不同的即时通信平台在功能实现与机制限制上各有不同，这会直接影响最终的回复效果：

- **长度限制**：不同平台对单条消息的字数上限不同，遇到超长回复时适配器会自动拆分成多条逐一发送。
- **消息元素**：图片、语音、表情、富文本卡片或交互按钮，并不是每一个平台都提供原生支持。
- **撤回与编辑**：部分协作平台支持对已发送的消息进行编辑，在流式输出打字效果时体验会显著更好。
- **频率限制**：短时间内下发消息过于频繁可能会触发平台的限流风控，表现为部分回复被平台静默丢弃。
- **@ 与引用**：各平台对 @ 与引用的实现协议不同，这会直接影响系统对「什么时候回复」的触发判断。

遇到「在 A 平台表现正常、在 B 平台却格式混乱」的情况时，先确认是不是平台本身的能力差异，而不是配置写错了。

## 推荐配置

### 只接一个 QQ 号

这是最省事、也最普遍的入门接入组合：准备一个 OneBot 适配器，配合一个 OneBot 实现端即可。

操作流程很简单：先在你的 OneBot 实现端中顺利登录 QQ 账号；接着打开 ChatLuna 的「聊天平台」页，添加 OneBot 适配器并填入它的连接地址与访问令牌。两端建立连通后，卡片上的机器人状态就会变为 `在线`。

建议先单独建一个私密测试群，把基础对话和指令跑通无误后，再将机器人拉入正式群。

### 多平台同号

如果你希望在 QQ、Discord 与 Telegram 中同时提供服务，可以让它们共用同一套模型与角色预设。

此时需要特别注意账号与场景规则的配合：不同平台的频道 ID 与群 ID 格式各不相同，规则需要分别配置对应的路由条件。

合理的规划是：将通用的模型选择、提示词预设与记忆策略放在全局配置中，而将各平台特有的群规则、权限划分与触发名称独立分开管理。

### 企业办公

如果用于飞书、钉钉或企业微信等企业协同办公场景，通常需要企业管理员在平台开放平台中开通机器人应用，再将获取到的凭据填入配置表单。

这类平台对消息格式与权限审核的要求更为严格，完成配置后建议先在小范围内部群中试运行。

### 自建网关

如果你已经部署了多个 ChatLuna 实例，可以通过 Satori 适配器将它们串联组网。

你可以将其中一个实例作为中心消息网关，统一汇聚各平台的外部消息；其余实例作为具体的数据处理节点，按平台或业务群组分流执行计算。

## 排查

**适配器一直显示未安装。**

点击卡片上的「安装」按钮，查看展开的命令行输出日志。常见原因是网络无法顺畅访问软件源，或者适配器包在源仓库中的名称已经变更。

**状态是「已启用」但机器人离线。**

先查看卡片上给出的具体错误提示。常见原因包括访问令牌失效、服务地址或端口填写错误、平台侧账号被风控限制，或者本地网络无法访问外网。

如果是 OneBot 适配器，先确认实现端本身是否在线，并检查其连接白名单是否允许当前 IP 连接。

**机器人在线，但群里不回话。**

这说明适配器本身的连接没有问题。请前往「场景规则」页面确认该群聊是否正确命中了触发规则，再去「轨迹」页面查看用户的消息是否成功进入了系统。

**消息发出去了，但格式很乱。**

这通常是平台不支持某些富文本消息元素，或者回复内容超长被强制拆分所致。你可以调整预设中的回复格式，或者在该场景规则中限制单次输出的最大字数。

**两个账号互相回话。**

当两个具备回复能力的机器人同时位于同一个群聊时，可能会互相触发陷入死循环。建议在规则中关掉其中一个机器人的无前缀触发，或者在过滤条件中明确排除对方的账号 ID。

**改完配置没生效。**

确认在表单修改后点击过保存并重新启用了适配器；确认编辑的是当前正在生效的那张卡片；同时确认没有优先级更高的场景规则覆盖了当前配置。
