# 接入聊天平台

::: tip
本节将介绍如何将机器人接入 QQ、Discord、Telegram 等主流聊天平台。接入完成后，平台消息会自动流转至 ChatLuna 对话系统，模型生成的回复也会原路推送到对应平台。
:::

ChatLuna 本身不直接与聊天平台通信，而是通过一层适配器 (Adapter) 进行交互。适配器负责登录具体的平台账号、接收聊天消息，并将各平台结构各异的数据转换为统一格式交给 ChatLuna；在 ChatLuna 处理完成后，再交回适配器发送给用户。

适配器将平台差异与具体的对话逻辑隔离开来。无论是 QQ 还是 Discord，对底层的对话系统来说并无区别。你配置好的场景规则、用户权限、预设角色以及长期记忆，在接入新平台时均可直接复用。

同一个 ChatLuna 实例支持同时接入多个适配器与多个账号。例如一个 QQ 账号和一个 Discord 机器人可以在同一个控制台中并行运行，互不干扰。

## 聊天平台页

打开控制台，在左侧导航栏的「配置」分组中点击进入「聊天平台」页面。

在此页面中，已添加的适配器以卡片形式展示。每张卡片对应一个平台或具体的账号实例。卡片包含以下信息：

- **平台与名称**：当前卡片所属的平台类型，以及为该实例设置的别名。
- **启用状态**：显示当前适配器是否正在运行。
- **包状态**：对应的适配器插件是否已安装。
- **凭据状态**：连接所需的 Token、密钥等必填项是否已填写。
- **机器人状态**：显示账号的实时连接状态，例如 `在线`、`离线`、`连接中`、`断开`、`重连中`，同时展示机器人的平台头像与昵称。

卡片上的机器人状态会自动定时刷新。即使外部平台断开连接，几秒内也能在页面上看到状态变动。

### 添加一个平台

如果需要接入新平台，点击页面右上角的「添加」按钮。系统会引导你先选择平台类型，再进入具体的配置表单。

平台列表中包含了常见的主流聊天应用：

| 平台 | 说明 |
| --- | --- |
| **OneBot (V11)** | QQ 生态最常见的协议，需要配合 OneBot 实现端使用 |
| **QQ** | 官方 QQ 机器人接口 |
| **Discord** | 服务器与频道 |
| **Telegram** | 群组与私聊 |
| **KOOK** | 语音社区平台 |
| **飞书 / 钉钉 / 企业微信** | 企业办公场景 |
| **Slack / Matrix / Zulip** | 团队协作场景 |
| **WhatsApp / LINE / Mail / 微信公众号** | 其他平台的接入 |
| **Satori** | 连接另一个 Satori 服务，适合多实例组网 |

在列表中选中目标平台后，右侧会展开该平台的配置表单。

虽然各平台的底层机制不同，但需要填写的核心配置通常只有几项：账号唯一标识、服务连接地址、访问令牌，以及少数平台专属的扩展参数。

表单内容由适配器插件提供。当插件发布更新并增加新功能时，对应的新配置项会直接显示在表单中，无需手动调整页面。

::: tip
控制台内置了一个无需配置的网页渠道。

在左侧导航栏点击进入「聊天」页面，即可直接在浏览器中与机器人对话。在接入外部聊天平台之前，建议先在此验证模型和预设是否正常工作。
:::

### 安装与卸载

为了保持系统轻量，部分平台适配器以独立扩展包形式提供，初次使用时可能尚未安装。

此时卡片上的包状态会显示为 `未安装`，并在旁边提供「安装」按钮。点击该按钮，系统会自动从软件源拉取并安装该适配器插件。

适配器必须在安装成功后才能启用。若安装失败（通常是由于本地网络无法访问软件源或包名有误），卡片底部会显示命令行输出日志，方便排查问题。

如果不再需要某个平台，操作流程正好相反：必须先停用，再卸载。这样可以避免正在运行的账号失去插件支持，防止残留无法清理的配置。

::: warning
卸载适配器**不会**删除或注销你在第三方平台创建的机器人应用，仅解除 ChatLuna 与该账号的连接。如果需要彻底停用，请前往平台侧同步处理。
:::

## 配置项

虽然不同适配器的表单字段各不相同，但数据存储与安全机制保持一致。

### 凭据

访问令牌、应用密钥或密钥文件等敏感字段，在保存后均会加密存储。

为了防止敏感信息泄露，这些凭据在前端界面上不显示明文，而是统一显示为 `已配置` 或 `缺失`。后续再次编辑表单时，将输入框留空即可保留原有凭据，无需重复填写。

若系统检测到必填密钥处于 `缺失` 状态，你可以正常保存表单，但无法启用该适配器。界面会标明具体缺失的项目。

::: warning
切勿将机器人的访问令牌发送到群聊、截图或公开文件中。

一旦令牌泄露，他人即可冒充机器人发送消息。如果不慎泄露，请立即前往平台侧重置令牌，并在此页面重新保存。
:::

### 账号标识

每个适配器实例都必须配置一个能够区分身份的账号标识，通常为机器人在该平台上的账号 ID。

在同一平台接入两个账号时，两个实例的账号标识必须不同。若填写相同的标识，系统在分发消息时将无法判定该消息交由哪个账号处理。

### 配置快照

在适配器插件的设置项中，可以指定一个本地目录用于保存配置快照。

开启此功能后，每次在修改并保存适配器配置前，系统都会在后台自动备份。若修改配置后出现问题需要回退，直接从快照恢复即可。

快照目录默认处于关闭状态，填入指定的备份路径后生效。

## 启用与停用

填写完整配置表单并点击「保存」后，点击卡片上的「启用」开关，适配器才会开始连接平台。

启用适配器时，系统会在后台依次执行以下操作：

1. 加载对应的适配器插件核心。
2. 使用填写的凭据登录第三方平台账号。
3. 将账号状态、头像与昵称同步更新到卡片上。
4. 挂载消息监听，开始接收该账号在平台收到的消息。

停用适配器的逻辑正好相反：断开平台连接并卸载消息处理流程，但保留已填写的配置内容。如果需要临时下线机器人或排查平台异常，先将其停用即可。

::: tip
修改并保存配置后，适配器会自动尝试重连，通常无需手动重启实例。

若修改配置后状态长时间未恢复，可以尝试先停用再重新启用。
:::

## 多个账号

单个 ChatLuna 实例原生支持多账号同时运行。常见的使用场景包括：

- 一个 QQ 账号负责群聊互动，另一个 QQ 账号用于私聊答疑。
- 不同的群聊分配不同的机器人，避免单账号封禁或风控导致所有群同时失联。
- 将日常测试账号与对外运营的正式账号分离，互不干扰。

每个接入的账号均可在场景规则中单独指定。例如，可以让 A 账号仅在技术交流群回答，而 B 账号仅在休闲娱乐群出现。

场景规则支持同时识别「平台」和「机器人账号」，两者结合即可精准定向到特定平台的特定机器人。

## 消息怎么流转

理解消息在系统内部的流转链路有助于排查问题：

1. 平台用户发送消息，平台将新消息推送给适配器。
2. 适配器将平台消息转换为统一的内部格式，交给 ChatLuna。
3. ChatLuna 根据消息内容、群组、发送者等信息匹配场景规则。
4. 命中规则后，交由绑定的引擎与模型处理。
5. 模型生成的回复内容返回给适配器。
6. 适配器按照平台规范格式化消息，并推送回聊天中。

因此，链路上任何环节出现阻塞，外部均表现为「机器人不回复」。排查问题时，建议先检查链路各环节，无需直接归咎于模型故障。

## 平台差异

不同的即时通信平台在功能实现与机制限制上存在差异，这会直接影响最终的回复效果：

- **长度限制**：不同平台对单条消息的字数上限不同。遇到超长回复时，适配器会自动拆分为多条消息逐一发送。
- **消息元素**：图片、语音、表情、富文本卡片或交互按钮并非所有平台均原生支持。
- **撤回与编辑**：部分协作平台支持编辑已发送的消息，在流式输出打字效果时体验更佳。
- **频率限制**：短时间内频繁发送消息可能触发平台的限流风控，导致部分回复被平台静默丢弃。
- **@ 与引用**：各平台对 @ 与引用的实现协议不同，会影响系统对触发时机的判定。

如果遇到「在 A 平台表现正常，在 B 平台格式混乱」的情况，请先确认是否为平台本身的能力差异。

## 推荐配置

### 只接一个 QQ 号

这是最基础的入门配置：准备一个 OneBot 适配器，配合一个 OneBot 实现端即可。

操作步骤如下：

1. 在 OneBot 实现端中登录 QQ 账号。
2. 打开 ChatLuna 的「聊天平台」页面，添加 OneBot 适配器并填入连接地址与访问令牌。
3. 两端连接成功后，卡片上的机器人状态将显示为 `在线`。

建议先建立私密测试群，测试基础对话和指令确认无误后，再将机器人拉入正式群。

### 多平台同号

如果需要在 QQ、Discord 与 Telegram 中同时提供服务，可以让它们共用同一套模型与角色预设。

此时需要注意账号与场景规则的配置：不同平台的频道 ID 与群 ID 格式不同，需要为规则分别配置对应的路由条件。

建议将通用的模型选择、提示词预设与记忆策略保存在全局配置中，将各平台特有的群规则、权限划分与触发名称独立管理。

### 企业办公

用于飞书、钉钉或企业微信等企业协同办公场景时，通常需要管理员在平台开放平台中创建机器人应用，再将获取到的凭据填入配置表单。

企业平台对消息格式与权限审核的要求更为严格，配置完成后建议先在小范围内部群中测试。

### 自建网关

如果部署了多个 ChatLuna 实例，可以通过 Satori 适配器将它们串联组网。

你可以将其中一个实例作为中心消息网关，统一汇聚各平台的外部消息；其余实例作为数据处理节点，按平台或业务群组分流处理。

## 排查

**适配器一直显示未安装**

点击卡片上的「安装」按钮，查看展开的命令行输出日志。常见原因包括网络无法访问软件源，或适配器包名变更。

**状态显示为「已启用」，但机器人离线**

查看卡片上的错误提示。常见原因包括访问令牌失效、服务地址或端口填写错误、平台账号受风控限制，或本地网络无法访问外网。

若使用 OneBot 适配器，请先确认实现端本身是否在线，并检查其连接白名单是否允许当前 IP 连接。

**机器人在线，但群里不回复**

这表明适配器连接正常。请前往「场景规则」页面确认该群聊是否命中了触发规则，并在「轨迹」页面检查用户消息是否成功进入系统。

**消息已发送，但格式混乱**

通常是由于平台不支持某些富文本消息元素，或回复内容超长被强制拆分。可以调整预设中的回复格式，或在场景规则中限制单次输出的最大字数。

**两个账号互相回复**

当两个具备回复能力的机器人位于同一个群聊时，可能会互相触发陷入死循环。建议在规则中关闭其中一个机器人的无前缀触发，或在过滤条件中排除对方的账号 ID。

**修改配置后未生效**

确认修改表单后已点击保存并重新启用适配器；确认编辑的是当前正在生效的卡片；同时确认没有优先级更高的场景规则覆盖当前配置。
