# MCP

::: tip
MCP（Model Context Protocol）用于将外部服务提供的工具接入 ChatLuna。连接成功后，这些工具在模型眼中与原生工具无异，实际运算则由独立的本地进程或远程服务完成。
:::

在很多场景下，接入外部系统并不需要专门编写插件。如果已有现成的服务（如本地数据库、自建搜索引擎、GitHub 等项目管理平台，或是企业内部业务系统），直接对接现有的标准接口往往更加轻量。

MCP 是一套开放的标准协议。只要外部服务支持 MCP，即可通过统一的方式接入 ChatLuna。接入后，外部服务提供的工具将直接出现在 ChatLuna 的工具箱中。大语言模型可以按需调用这些工具，而实际的任务执行与数据读写均在外部进程或远端服务器中完成。

## MCP 页

在控制台中，点击左侧导航栏的「能力 → MCP」，即可进入 MCP 服务的统一管理页面。

页面中集中展示了当前实例接入的所有 MCP 服务。你可以在右上角切换「卡片」或「列表」视图；当接入的服务较多时，也可以按「连接状态」或「传输方式」对服务进行分组筛选。

每个服务卡片包含以下关键信息：

- **服务 ID 和名称**：服务的唯一标识与自定义显示名称。
- **传输方式**：通过本地命令启动或连接远程地址。
- **连接状态**：包括已连接、连接中、已停用、出错、缺少传输支持、空闲等。
- **工具数量**：成功导入并可供使用的工具总数。
- **最近一次连接错误**：若连接遇到问题，卡片会直接显示具体报错。

点击任意服务卡片，右侧会展开详情抽屉。你可以在此查看服务的配置详情、数据来源、底层连接参数，以及完整的「工具清单」。

清单中列出了每个工具的名称、功能说明与调用参数。若外部服务的某些工具参数结构不兼容，系统在解析时会自动跳过该工具并在列表中注明原因，便于排查调整。

### 添加服务

在 MCP 页点击「添加服务」，系统提供了三种添加方式：

- **本地命令**：填写可执行文件、启动参数、环境变量和工作目录。适合在运行 ChatLuna 的宿主机上直接启动的服务。
- **远程地址**：填写服务端点和请求头。适合已独立部署在服务器或容器中的 HTTP 服务。
- **粘贴导入**：直接粘贴现成的服务配置文本，系统会自动解析并批量导入。

填写配置后，建议先点击「测试连接」进行验证。系统会在后台尝试连接目标服务、拉取一次工具清单，并在校验完毕后主动断开。测试连接仅为轻量级探测，不会实际加载工具到实例中，也不会影响正在运行的会话。

确认连接正常且能读取工具清单后，点击「保存并启用」即可使服务生效。

::: warning
本地命令会以实例进程的同等权限在后台运行。请勿随意连接来源不明的命令或脚本，以免带来安全隐患。如需运行不可信的服务，建议将其部署在隔离容器或远程主机中，通过远程地址接入。
:::

## 两种传输方式

MCP 协议支持多种底层通信媒介。在 ChatLuna 中，可以根据服务的部署位置选择适合的传输方式。

### stdio

本地命令方式会在宿主机上派生独立的子进程，并通过标准输入输出（stdio）与系统收发消息。该方式适合本地轻量工具、CLI 命令行封装，或需要直接读写本地磁盘文件的服务。

在配置界面中，可以设置以下选项：

- **启动命令**：可执行文件名称或系统中的绝对路径。
- **命令行参数**：启动程序时附加的一系列参数。
- **环境变量**：程序运行所需的环境变量。对于敏感信息，可以勾选将其作为密钥保存，避免在界面上明文展示。
- **工作目录**：子进程执行任务时的基准路径。
- **单次调用超时**：单个工具执行的最长等待时间，默认值为 `120` 秒。

子进程的生命周期与服务状态同步：启用服务时会自动拉起子进程；停用服务、卸载插件或关闭实例时，子进程会被终止。若运行中子进程意外断开，卡片状态会变为出错，你可以随时手动点击重连。

### http

远程地址方式通过 HTTP/HTTPS 协议与远端的网络端点通信，适合已部署在独立服务器上的服务。当多个 ChatLuna 实例需要共享同一个服务，或网络环境有特定网关与安全策略时，可以使用该方式。

在配置界面中，可以设置以下选项：

- **端点 URL**：远程 MCP 服务的访问入口地址。
- **请求头**：请求外部端点时附加的 Header。如果包含认证令牌，可以作为密钥脱敏保存。
- **单次调用超时**：等待远程服务响应的最长时间。

HTTP 方式无需在本机创建和管理子进程，资源占用更低。需要注意的是，所连接的远程服务端必须完整支持 MCP 协议要求的流式传输规范，否则可能无法正常交互。

## 工具是怎么投影进来的

为防止外部工具与本地原生工具冲突，ChatLuna 对所有 MCP 工具采用统一的投影命名规范。

投影后的工具名称格式为 `mcp__服务ID__工具名`：以 `mcp__` 开头，中间拼接服务 ID，最后附上原工具名称。例如，服务 ID 为 `github` 且提供 `search_repos` 工具时，投影后的工具名称为 `mcp__github__search_repos`。

在转换过程中，系统还会进行规范化处理：

- 若原工具名包含非法字符，系统会自动替换为合规符号。
- 过长的工具名会被截断至 `64` 个字符以内。
- 若替换或截断后与系统已有工具重名，系统会跳过该工具并记录一条警告日志。

与此同时，工具的参数结构也会被自动映射转换为 ChatLuna 内部的工具参数模型。若遇到暂不支持的特殊规范参数，系统会忽略该参数并写入日志；若工具的整体结构完全无法兼容解析，该工具会被直接跳过。

::: tip
在「工具」管理页面中，在搜索框输入 `mcp__` 前缀即可筛选出所有接入的 MCP 工具。你可以借助通配符对它们进行批量管理，例如批量设为按需加载，或统一要求执行前人工审批。
:::

## 连接与重连

卡片上常见的连接状态包括：

- **已停用**：配置已保存在系统中，但未开启启用开关。
- **连接中**：正在建立进程通道或网络连接，并拉取工具定义。
- **已连接**：连接成功，兼容的工具已投影就绪，可随时响应调用。
- **出错**：连接失败或中途异常断开，卡片会显示具体出错原因。
- **缺少传输支持**：系统当前缺少对应传输方式的插件支持。
- **空闲**：服务开关处于开启状态，但尚未触发实际连接。

ChatLuna 具备故障隔离机制，单个服务的连接失败不会影响系统整体运行。故障服务会保持在出错状态，其他服务和功能照常工作。修复外部环境或修改配置后，点击卡片上的重连按钮即可恢复，无需重启实例。

修改服务配置、安装或卸载相关插件，以及重启 ChatLuna 实例时，系统均会自动重新连接并刷新工具列表。刷新过程中，正在执行的工具调用不会被强制中断，以保证任务连续性。

## 与工具页、权限的关系

MCP 工具投影成功后，在系统内与原生工具地位相同，完全遵循 ChatLuna 的工具治理体系：

- **工具策略独立配置**：在「工具」页面中，可以为每个 MCP 工具单独配置策略，设置为自动执行、需要审批或直接禁用。
- **场景规则精细划分**：通过「场景规则」，可以控制特定群聊对 MCP 工具的可用性与可见性。
- **全局权限机制兜底**：系统权限模式会对高风险工具调用进行统一把控，敏感操作是否需要审批由全局权限决定。
- **支持按需动态加载**：开启工具搜索后，支持将 MCP 工具设为按需加载模式（这也是推荐的默认做法）。

MCP 服务本身不负责访问控制，其职责仅是提供工具能力。工具能否执行、是否需要审批，始终由 ChatLuna 的工具策略与权限规则共同决定。

## 常见服务类型

社区中已有大量成熟的 MCP 服务可供使用，常见类型包括：

- **文件与代码**：读取与修改本地文件、检索代码仓库、在隔离沙盒中执行系统命令。
- **数据库**：获取数据库表结构信息、安全执行只读查询操作。
- **搜索与网页**：调用外部搜索引擎获取最新资讯、抓取网页正文内容或生成页面摘要。
- **项目管理**：管理 GitHub 或 GitLab 等平台的 Issue、查看 Pull Request 变更、跟进任务看板。
- **内部系统**：对接企业私有业务系统，如查询订单状态、同步库存数据或创建客服工单。

接入新服务前，建议先了解其工具特性（例如是否为只读、是否依赖外部认证凭据、调用后是否有不可逆的副作用）。带有写入、修改或执行外部指令性质的工具，通常建议在「工具」页面中设置为需要审批。

## 推荐配置

针对不同的运行环境，推荐按如下方案配置 MCP 服务：

### 个人实例

在个人电脑上单人使用时，建议选择本地命令（stdio）方式，仅接入一两个最常用的工具服务即可，配置简单且响应直接。对于涉及本地文件修改或终端命令执行的高风险工具，建议在「工具」页面中手动设置为需要审批。

### 多实例共享

多用户团队或部署了多个 ChatLuna 实例时，建议将服务部署为独立的远程 HTTP 服务，供多个实例共同连接复用。各实例在请求头中配置各自独立的鉴权凭据，并根据实际场景分别设置工具策略。

### 工具很多

当接入的服务较多、工具总数累计达到几十甚至上百个时，全部暴露给模型容易导致上下文超限或注意力分散。建议在「工具」页面中开启工具搜索功能，让所有 MCP 工具默认保持按需加载。仅将少量高频核心工具设为常驻，其余工具由模型按需动态检索匹配。通常将搜索阈值保持在 `20` 左右即可获得较好体验。

### 高风险环境

在面向公开群聊或复杂多租户的高风险环境中，应避免使用本地命令方式运行不可控的程序，建议将服务部署在安全的容器或独立主机中，通过远程地址接入。若必须使用本地命令，仅保留经过审计的可信命令。权限方面，建议将所有具有写入行为的工具设为需要审批，命令执行类工具默认保持禁用。

## 排查

在接入和使用 MCP 服务时，若遇到非预期情况，可参考以下条目进行排查：

**服务一直显示出错。**

查看卡片上展示的错误提示文本。常见的故障原因包括：指定的本地命令不存在或路径有误、参数格式错误、远程端点无法连通、请求头鉴权失败，或是服务协议版本不兼容。对于本地命令，可先在系统命令行中确认能否独立运行；对于远程地址，请检查网络连通性与请求头配置是否正确。

**连上了但没有工具。**

若状态显示连接成功但工具列表为空，可能是外部服务本身未暴露任何可用工具，也可能是工具参数格式特殊导致无法被系统识别而被全部跳过。可以点击卡片打开服务详情，在工具清单中查看具体的跳过原因说明。

**模型看不到某个 MCP 工具。**

当模型在对话中无法调用某个工具时，可以按以下顺序逐项核对：

1. 确认对应的 MCP 服务当前处于「已连接」状态。
2. 检查该工具是否因参数兼容性问题在工具清单中被标记跳过。
3. 前往「工具」页和「场景规则」页，检查该工具是否被全局禁用，或在当前群聊中被规则过滤。
4. 检查是否开启了按需加载。若处于按需模式且当前提示词未匹配中该工具，模型暂时无法看到该工具。可在「工具」页面查看工具的最终可见状态。

**工具名冲突。**

当两个不同的 MCP 服务导出了同名工具，或不同工具在替换非法字符并截断后生成了相同的投影名称，就会触发名称冲突。遇到这种情况时系统会跳过冲突工具。你可以在服务设置中修改该服务的 ID 来调整投影前缀，也可以在「工具」管理页面中手动禁用其中一个冲突工具。

**调用总是超时。**

如果工具调用频繁出现超时报错，可以尝试在对应服务的配置中适当调大「单次调用超时」的设定值。同时建议检查外部服务是否存在死锁、网络阻塞或长时间无响应的问题。若开启了工具搜索，初次检索时较高的网络延迟也可能导致耗时增加，可留意底层网络状况。
