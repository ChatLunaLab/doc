# 技能

::: tip
技能是将特定任务的操作流程编写为可按需加载的说明文档。模型平时仅加载技能目录，必要时才读取完整步骤。这样既能让机器人掌握丰富的专业能力，又不会在日常对话中占用过多的上下文空间。
:::

在前面的章节中，我们已经了解了工具的基本用法。工具解决的是机器人「能做什么」的动作问题，而技能解决的则是「如何做好」的流程问题。

通常情况下，如果你希望机器人掌握一套复杂的业务操作，最直接的做法是将执行指南全部写入系统提示词。但在场景较多时，静态文档会迅速占满上下文空间，不仅增加额外的 Token 消耗，还可能影响模型对日常指令的理解。

技能正是为了解决这个问题而设计的。一份技能的核心通常是一份 Markdown 说明文档；在复杂场景下，技能目录中还可以包含脚本文件、文本模板以及参考资源。

当用户发起对话时，模型默认只会加载一份精炼的「技能目录」，其中仅包含各技能的名称与简短描述。只有当对话涉及特定专业领域时，模型才会按需读取该技能的完整说明，并依照步骤调用工具或执行脚本。

这种机制被称为「渐进披露」。得益于此，你可以为机器人配置大量技能，而无需担心日常问答受到影响。技能说明所产生的上下文开销，仅会出现在实际调阅它的那轮对话中。

## 技能页

打开控制台，在左侧导航栏中点击「能力 → 技能」，即可进入技能管理页面。这里列出了当前实例中所有已发现且可供调用的技能。

技能页顶部提供了视图切换与筛选工具：

- **切换视图**：支持在卡片视图与列表视图之间切换。
- **分组查看**：可按来源层级对技能进行分组折叠，便于理清技能出处。
- **检索与排序**：在搜索栏中输入关键字即可过滤，也可按名称或更新时间排序。

点击列表中的任意技能，右侧将滑出详情面板，展示该技能的完整属性与状态：

- **名称、简介与正文预览**：显示技能标题、简要功能概述，并可直接阅读说明正文。
- **来源**：标明技能的加载路径（内置、宿主机目录、用户自定义、工作区、导入或市场）。
- **文件清单**：列出该技能目录下包含的脚本文件、模板及参考文档。
- **环境变量声明**：列出技能所需的配置项，标明必填项、敏感密钥及默认值。
- **覆盖关系**：当存在多个同名技能时，显示当前生效的版本以及被遮蔽的副本。

### 导入与管理技能

如果你获取了新的技能文件，可以直接在技能页中导入。目前支持以下导入形式：

- 单个 `SKILL.md` 文件
- 包含完整资源的技能文件夹
- 打包好的 `.zip` 压缩包

导入完成后，系统会自动扫描并将其加入技能列表。若导入的技能与已有技能同名，新技能将直接覆盖原有的同名技能。对于已导入的技能，可在详情面板中点击「删除」按钮将其移除。

随插件分发的「内置技能」默认处于只读保护状态，无法直接在界面上修改或覆盖。如需调整其内容，可在详情面板中点击「复制」，将其复制到用户自定义目录后再行修改。

::: warning
同名技能不会合并内容，而是按照来源优先级仅保留一份生效，其余同名项将被遮蔽。

若修改技能后机器人的表现未发生变化，请前往技能页查看右侧面板中的覆盖关系，确认当前生效的具体来源。
:::

## 技能来源与优先级

系统支持从多种途径加载技能。当出现同名技能时，系统将按照自上而下的固定优先级决定生效版本：

1. **工作区**：位于当前 Agent 工作目录中的技能，优先级最高。用于存放特定项目的专属技能，不会影响其他项目。
2. **内置**：随插件一同分发的技能，提供开箱即用的通用能力，默认只读受保护。
3. **宿主机目录**：存放于数据目录或指定宿主机路径下的技能，适合运维人员跨实例集中维护与分发。
4. **用户自定义**：存放于数据目录自定义技能文件夹中的技能。在控制台中手动创建或从内置技能复制的副本均保存在此处。

若两个同名技能处于相同的来源层级，系统将依据扫描顺序或内部规则决定，通常以最新注册或排序靠前的版本为准。同名技能最终仅有一个版本生效，其余版本会被标记为遮蔽。

若当前实例启用了技能市场功能，从市场下载的技能文件将存放在宿主机目录中，并同样遵循上述优先级规则。

## 一份技能长什么样

在最简情况下，一个标准技能仅需包含一个 `SKILL.md` 文件。该文件分为两部分：文件头部的元数据，以及供模型阅读的说明正文。

头部元数据包含以下字段：

| 字段 | 作用 |
| --- | --- |
| 名称 | 技能的唯一标识，通常采用小写短横线命名。 |
| 描述 | 技能的功能简述，会显示在技能目录中。 |
| 版本 / 作者 / 许可 | 可选的来源与元信息。 |
| 平台 | 适用操作系统，如 macOS、Linux、Windows。 |
| 环境 | 适用的运行环境。 |
| 环境变量 | 运行所需的配置项，可标记为密钥、必填或提供默认值。 |

元数据下方的正文详细描述了技能的使用场景、执行步骤、注意事项以及异常处理逻辑。步骤与说明越明确，模型执行时的表现就越稳定。

除 `SKILL.md` 之外，技能目录下还可以存放脚本、模板及参考文档等附加资源。当模型按需加载该技能后，即可通过相应工具查阅参考文件或执行脚本。

### 环境变量与密钥

部分技能在运行时需要依赖外部配置。你可以在元数据中声明所需的环境变量：

- **必需**：缺少该变量时技能将无法运行，系统会在加载时提示缺失。
- **密钥**：敏感变量，不会出现在日志或模型的对话上下文中。
- **默认值**：未显式配置该变量时所采用的缺省值。

敏感密钥的使用受场景规则管控。管理员可在特定群聊或私聊中禁止技能调用已保存的密钥。若被规则限制，依赖该密钥的技能在对应会话中将直接不可用，以防止未授权调用。

::: tip
请勿将密码、API Token 等敏感信息直接明文写入 `SKILL.md` 的正文中。正确的做法是在元数据中声明环境变量，真实凭据保存在实例的凭据或环境配置中，正文中仅引用变量名称。
:::

## 模型怎么用技能

在初始状态下，模型仅接收一份轻量级的技能目录，包含各技能的名称、简要描述以及查阅指南。

当用户的输入命中某项技能的适用场景时，模型会根据目录指引向系统发起请求：

- 搜索或列出可用技能
- 读取指定技能的完整说明文档
- 读取技能目录下的参考文件
- 运行技能附带的执行脚本

模型调阅技能说明后，该说明仅存在于当前对话轮次的上下文中，不会永久常驻系统提示词。后续对话若需再次使用，模型会按需重新调阅。

此外，技能不仅可以作为操作指南，还能直接注册专用的工具入口。例如，某技能可直接注册「查询订单」工具，模型无需完整阅读操作说明，即可直接调用该工具获取数据。

## 技能脚本

对于数据计算、格式转换或系统命令等确定性任务，交由脚本处理往往比由模型推理更加高效可靠。因此，推荐将分析与决策交由模型，将确定性的操作封装进脚本。

当模型请求执行技能脚本时，系统将遵循以下流程：

1. 在受控的独立工作目录中执行脚本。
2. 注入技能元数据中声明的环境变量。
3. 根据当前的权限模式检查是否需要人工审批。
4. 捕获脚本的标准输出与错误流，并返回给模型作为后续推理的依据。

::: warning
技能脚本具备在宿主机环境中执行命令的能力，具有一定的安全风险。

请勿将来源不明的第三方技能直接导入生产环境。导入前请务必审查脚本内容；在无法确认安全性的情况下，建议将脚本的执行权限配置为需要人工审批。
:::

## 技能市场与自动进化

若当前实例启用了技能市场功能，你可以在技能页中直接浏览、搜索并安装社区技能。从市场安装的技能与本地技能遵循相同的发现逻辑、覆盖规则与权限限制。

除手动安装外，系统还提供了可选的「技能自进化」插件（默认未安装）：

- 允许模型根据对话中的成功经验生成技能草稿。
- 草稿需经过测试验证、人工审查并手动确认安装后方可正式生效，支持版本回滚。
- 模型仅能提交草稿提议，无法直接绕过人工审查将其上线。

在未启用该插件的默认环境中，技能注册表保持只读。所有技能的添加与修改均需管理员通过界面手动导入、编辑本地文件或通过市场安装完成，系统不会在后台擅自生成或修改技能。

## 与工具、MCP 的关系

在实际使用中，这三者经常协同工作，但职责划分有所不同：

- **工具**：模型可直接调用的原子动作，负责执行具体操作（如读取文件或发送消息）。
- **技能**：指导模型完成复杂任务的方法与流程，由说明文档和脚本组成，规定了调用工具的时机与顺序。
- **MCP**：将外部独立服务接入本系统的协议标准，用于将外部服务的能力转换为系统可用的工具。

三者的协作关系如下：

- 一份技能可以组合调用多个工具。
- 一个 MCP 服务器可以提供多个工具。
- 技能也可以调用由 MCP 接入的外部工具。

无论工具来源为何，系统都会执行统一的权限校验与审批策略。

## 推荐配置

根据不同的使用场景，推荐采取以下配置策略：

### 个人实例

- 保持技能精简，仅启用高频技能，使技能目录短小清晰。
- 完善必要配置，将涉及敏感凭据的环境变量标记为密钥。
- 技能脚本执行建议保留默认的人工审批机制，以降低误操作风险。

### 多人群聊

- 在「场景规则 → 能力 → 技能」中为各群单独配置技能白名单或黑名单，并明确是否允许访问密钥。
- 公共群聊中建议仅开放查询类技能；涉及写入或系统执行的技能，建议限制在管理员私聊等受信环境中可用。

### 团队与项目

- 将项目特有的技能存放于工作区目录。工作区技能优先级最高，既能满足项目定制需求，又不会影响全局其他配置。
- 建议将技能文件纳入版本控制（如 Git），并在上线前先在测试实例中验证。

### 技能数量较多时

- 依赖系统的渐进披露机制，避免将过多技能转换为常驻工具。
- 定期清理无用技能，防止技能目录过长及同名覆盖混乱。
- 关注技能页中的覆盖状态，确保目标技能正常生效。

## 排查

**模型未识别到技能**
- 检查技能是否已被系统成功扫描、所在目录是否在扫描路径中。
- 确认是否被更高优先级的同名技能遮蔽。
- 检查当前会话是否被场景规则禁用。技能页右侧面板会展示其实际生效状态。

**技能已加载但模型未调用**
- 通常是因为技能描述过于模糊，或正文缺乏明确的触发条件。建议在描述及正文开头明确注明「何时使用该技能」，降低模型的匹配成本。

**技能脚本提示缺少环境变量**
- 在技能页中打开详情面板，检查其环境变量声明并补齐必填项。若涉及密钥变量，还需确认当前会话的场景规则是否允许使用密钥。

**导入后同名技能未生效**
- 导入的技能可能所处来源层级较低，被更高优先级的同名技能遮蔽。请在技能页查看覆盖关系，通过重命名或移除冲突项使目标版本生效。

**技能正文过长导致上下文不足**
- 建议将大型技能拆分为多个小型技能，或将具体细节移至技能目录下的参考文件中，正文仅保留核心流程与入口，引导模型按需读取参考文件。
