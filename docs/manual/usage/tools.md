# 工具

::: tip
本节将介绍「能力 → 工具」页面的使用方法，如何为工具配置执行策略，以及在工具数量较多时如何节省上下文消耗。
:::

在与大语言模型对话时，如果仅依赖模型自身预训练的知识，往往只能得到宽泛的回答，甚至可能出现事实性幻觉。但若让模型在需要时主动搜索网页、读取本地数据文件，或在沙箱中运行计算脚本，回答的准确度与实用性就会显著提升。

在 ChatLuna 中，这些能够被模型在对话中主动调用的外部能力称为**工具**。

工具并非写死在底层的固定逻辑，而是由各个插件动态注册到运行环境中的。只要启用了某个插件，其附带的工具就会注入系统供模型使用；停用插件后，对应的工具也会一并卸载。

随着安装的插件增多，你可能会面临以下问题：

- 模型如何在合适的时机调用正确的工具？
- 涉及修改本地文件、执行终端命令等高风险操作时，如何防止误操作？
- 工具数量较多时，如何避免将所有工具的定义塞入上下文导致 Token 消耗过大？

ChatLuna 提供了可视化的工具管理界面。你可以在控制台中查看当前已注册的工具、所属插件及参数规范，并针对不同场景配置执行策略，决定哪些工具可以直接运行、哪些需要人工审批，或彻底对模型隐藏。

## 工具页

前往「能力 → 工具」页面，你可以在这里看到当前实例中已注册的所有工具。无论是系统内置的文件读写，还是第三方插件提供的功能，都会集中列出。

页面右上角提供了「卡片」与「列表」两种视图切换按钮：卡片视图适合快速浏览，列表视图信息密度更高，适合条目较多时排查。

视图切换按钮旁支持调整列表的分组方式：

- **按插件分组**：工具按照所属插件折叠归类，便于按模块查看新插件提供的能力。
- **按规则分组**：根据当前策略（如自动、询问或禁用）进行分组，便于集中复核待审批的高危工具。
- **不分组**：平铺展示所有工具，适合配合搜索快速定位。

如果安装的插件较多，可以使用顶部的搜索框输入关键字搜索，或点击排序菜单调整排列顺序。

点击列表中任意工具，右侧会弹出详情面板，展示该工具的关键属性：

- **工具名称与功能说明**：说明工具的具体功能。这不仅供用户查阅，模型也会依据该说明判断是否调用。
- **注册插件与作用域**：标明注册该工具的插件，并显示其属于全局工具还是特定 Agent 的专属工具。
- **参数规格**：展示调用该工具所需的参数结构，包括参数名称、数据类型、取值范围以及是否必填。
- **当前策略**：显示当前的控制策略（如「自动」「询问」或「禁用」），点击即可切换。
- **来源标记**：若工具来自外部 MCP 服务，此处会标注对应的 MCP 服务器名称。

在详情面板中修改策略后，系统会自动保存配置并即时生效。如果修改策略时正有对话在进行，当前运行中的对话回合不会被中断，新的策略会在下一轮对话中生效。

详情面板中各字段的说明如下：

| 属性名称 | 界面位置 / 呈现形式 | 作用说明 | 常见操作与建议 |
| :--- | :--- | :--- | :--- |
| **工具名称与说明** | 详情顶部标题与描述 | 解释工具职责，供用户查阅及模型意图匹配 | 若模型频繁在不恰当的场景调用，可核验说明是否准确清晰 |
| **注册插件与作用域** | 详情信息标签 | 标明提供该工具的插件，以及全局生效或专属 Agent | 用于排查来源；停用对应插件即可卸载该工具 |
| **参数规格** | 详情参数列表抽屉 | 展示调用参数，包含类型、取值范围及必填状态 | 遇到调用失败时，可在此核对模型传入的参数是否符合规范 |
| **当前策略** | 策略切换下拉菜单 | 控制当前工具的执行策略（自动、询问、禁用） | 对读写、命令等高风险工具，建议调整为「询问」 |
| **来源标记** | 详情附加标签 | 标明外部 MCP 服务器名称 | 用于追溯第三方工具来源及关联服务器状态 |

### 三种策略

针对不同的工具风险与使用场景，ChatLuna 提供了三种控制策略：

- **自动**：模型发起调用时直接在后台执行并返回结果，无需人工干预（除非全局权限模式另有要求）。适合查询、计算或只读操作。
- **询问**：模型调用该工具前会暂停执行，并在界面弹出确认提示，等待用户或管理员手动核准。适合有副作用、产生额外费用或涉及隐私安全的操作。
- **禁用**：对模型完全隐藏该工具，模型看不到其描述，也无法在对话中调用。

除了在详情面板中逐个调整策略外，你还可以在工具策略插件的配置项中使用通配符进行批量规则匹配。支持使用 `*` 代表任意多个字符，`?` 代表单个字符。例如，你可以配置规则将所有外部 MCP 工具统一设为「询问」，或将特定只读查询工具批量设为「自动」。

::: warning
「禁用」仅在界面与上下文层面将工具对模型隐藏，并不会卸载插件。插件本身仍在运行，随时可以重新开启。如果需要彻底移除工具，应前往插件市场卸载对应的插件；但对于命令执行、磁盘写入等高风险操作，直接设为「禁用」即可。
:::

## 工具从哪里来

系统中的工具主要来自以下几种途径：

- **内置工具插件**：系统自带的基础能力，涵盖文件读写、命令执行、代码运行、网页请求与搜索、定时任务、配置管理及运行时自省等。
- **技能**：将用户编写的技能目录与专属脚本封装暴露的工具。
- **MCP 服务器**：通过模型上下文协议（Model Context Protocol）接入的外部服务工具。
- **子代理**：将任务委派与调度动作包装为工具，主模型可将子任务派发给指定的子代理执行。
- **机器**：将远端主机、本地环境或容器沙箱的操作接口映射出的底层工具。
- **业务插件**：各类扩展插件注册的功能，如群组管理、AI 绘图、语音合成、记忆库检索等。

不同来源的工具可以在同一个对话回合中混合调用。例如，模型可以先调用搜索工具检索文档，再调用文件工具记录要点，最后调用通知工具发送提醒。底层的权限校验、审批机制与可见性规则对所有来源的工具均一致生效。

### 工具可见性

系统不会将所有已安装的工具都提供给模型。一个工具最终能否在特定会话中被模型调用，由以下几层规则自上而下依次决定：

1. 插件注册时声明的前置过滤条件。
2. 当前 Agent 配置的局部工具过滤。
3. 「场景规则」中为特定群聊或私聊配置的允许与禁用工具清单。
4. 「工具」页面及工具策略插件中设置的全局禁用状态。
5. 对应技能或 MCP 服务器自身的启用状态。

过滤机制遵循「逐步收窄」原则：靠后的规则只能进一步缩小可用范围，无法重新启用已被前序规则隐藏的工具。例如，若某个工具在全局策略中已被禁用，即使在场景规则的允许清单中添加它，模型也无法调用。

如果在对话中发现模型无法找到预期工具，可以依照上述顺序自顶向下排查。

## 工具模式

前往「场景规则 → 能力 → 工具」页面，你可以看到「工具模式」配置项。它决定了工具以何种形式呈现在模型的提示词上下文中：

- **直接给全部**：将当前可见工具的参数定义与功能描述完整传入提示词。工具总数较少时，这种方式最直接稳定。
- **先搜再用**：提示词中仅保留少量高频常驻工具和一个专用的工具搜索器。模型需要调用其他功能时，先通过搜索获取参数规范，再发起调用。工具数量较多时，可大幅减少上下文占用。
- **写代码调用**：提供代码解释环境，引导模型编写脚本组合并批量调用多个工具。适用于数据多步流转、结果批处理或需要精确逻辑控制的场景。
- **交给子代理**：模型不直接在当前会话中调用工具，而是将子任务完整派发给子代理，由子代理在独立的隔离上下文中调用工具并汇总结果。适用于步骤较长的复杂任务。

默认采用的模式通常取决于所配置的模型引擎类型。普通对话引擎默认采用「直接给全部」；部分特定引擎或重型工作流可能会默认推荐「交给子代理」。具体以场景规则界面中展示的默认选项为准。

::: tip
工具模式并非越复杂越好。工具数量较少时，「直接给全部」响应最快且最稳定；接入大量 MCP 服务使工具数量达到数十上百个时，建议开启「先搜再用」以节省 Token 开销；而在需要批量处理与流转数据的场景下，使用「写代码调用」更为合适。
:::

## 工具搜索

当工具数量较多时，将所有工具的参数定义全部传入提示词会导致上下文开销过大。ChatLuna 提供了工具搜索机制，将工具划分为两类：

- **常驻工具**：完整说明与参数定义始终保留在提示词中，模型可直接调用。
- **按需工具**：基础提示词中仅包含工具名称与简要说明；当模型通过搜索工具主动检索并命中后，系统才会动态注入其完整的参数说明。

前往「场景规则 → 能力 → 工具」页面，可以在搜索配置区域调整以下参数：

- **搜索模式**：提供「自动」「始终搜索」和「关闭」三种选项。其中「自动」模式仅对支持工具延迟加载特性的模型提供商生效。
- **自动启用阈值**：触发延迟检索的工具数量阈值（默认为 20）。当前会话可用工具总数超过该数值时自动启用按需检索，低于该数值时则全部展开。
- **按需加载列表**：配置需要按需加载的工具列表，支持通配符。系统默认将所有 MCP 接入的工具包含在内。
- **单次搜索返回数量**：模型执行工具搜索时最多返回的候选工具数，默认为 5。

如果希望某些常用的 MCP 工具跳过搜索直接可用，可以在「能力 → 工具」详情面板中将该工具单独设为「常驻」；同样，也可以将某些参数复杂的内置工具单独指定为「按需」。

::: warning
按需检索会增加一次额外的交互轮次：模型需要先检索工具列表确认格式，然后再发起调用。因此在工具总数较少时盲目开启搜索，反而会导致响应变慢并消耗额外的交互次数。请根据实际工具数量合理权衡阈值。
:::

## 执行与审批

模型在对话中发起工具调用时，系统会在底层依次执行以下阶段：

1. **意图输出**：模型根据对话上下文判断需要调用的工具，生成工具名称与调用参数。
2. **结构校验**：内置校验层核对参数类型、必填字段与取值范围是否符合工具声明。
3. **权限判定**：安全与权限系统评估该调用是否需要人工审批或被策略拦截。
4. **运行处理**：在指定环境中执行工具，并将执行细节整理为结构化数据与文本反馈。
5. **写回上下文**：将执行结果追加到会话上下文和轨迹日志中，推进模型进入下一阶段的解答。

此外，扩展插件还可以在调用生命周期的前后阶段介入：

- **调用执行前**：动态补全或修改传入参数；若发现异常，可直接中止调用。
- **调用执行后**：为返回结果追加补充信息、对敏感字段进行脱敏，或注入辅助模型判断的额外上下文。

停用或卸载相应插件后，这些钩子逻辑也会自动撤回，不会在系统中残留。

### 审批与权限模式

在「能力 → 工具」详情面板中将策略设为「询问」后，系统会在调用前进行拦截；此外，全局配置的权限模式也会参与判定。

在全局安全与权限配置页面中，提供了四种权限模式：

- **只读**：仅允许无害的查询操作，任何写文件、修改数据或执行命令的请求都会被直接拒绝或拦截。
- **文件**：允许日常文件读取与写入，但终端命令等高风险操作仍需弹窗审批。
- **自动**：由审查模型评估操作安全性，安全调用自动放行，高风险或边界模糊的操作交由人工审批。
- **完全放行**：最高信任模式，通常仅对高权限用户开放；普通或低权限用户在此模式下会自动降级并按「自动」模式严格审查。

触发审批时，界面中会弹出审批卡片，显示调用的工具名称、参数详情及潜在风险提示：

- 点击「仅本次允许」放行当前调用；
- 点击「拒绝执行」中止调用；
- 若权限允许，可勾选「记住此选择」免去后续重复确认。

审批卡片若超时未响应，系统将默认按拒绝流程处理，防止会话长时间挂起。

四种权限模式的表现与适用场景对比如下：

| 模式名称 | 核心表现 | 高危操作（如 Shell / 写文件） | 推荐适用场景 |
| :--- | :--- | :--- | :--- |
| **只读** | 仅允许查询与数据检索 | 直接拒绝或强制拦截 | 公开群聊、只供信息查询的问答机器人 |
| **文件** | 允许普通文件读写与保存 | 终端命令等系统操作强制审批 | 日常文档编写、报表整理等轻度协作场景 |
| **自动** | 审查模型评估安全等级 | 判定安全则放行，高危操作交由人工审批 | 个人日常使用、轻量级自动化助理 |
| **完全放行** | 最高信任级别，全自动放行 | 受信任管理员免审批；低权限用户自动降级 | 本地调试、管理员专属环境 |

::: tip
请根据使用场景合理区分策略：「询问」适合有实用价值但存在操作风险、需要人工把关的功能；「禁用」则适合完全不希望该场景碰触的功能。若某项工具在每次询问时都会被直接拒绝，建议直接将其设为「禁用」，以免中断对话流程。
:::

## 常见工具家族

根据已安装的插件，工具列表中通常包含以下几类工具（具体以控制台实际显示的为准）：

- **文件家族**：提供工作区文件的查看、编辑写入、增量修改、目录浏览与关键字检索。
- **命令家族**：在受限终端中执行 Shell 命令。属于高风险类别，建议开启审批。
- **代码家族**：在隔离解释器中执行指定代码并获取输出，常用于数学运算、正则处理或批量文本转换。
- **网络家族**：提供搜索引擎检索、网页抓取与解析、发送 HTTP 请求以及调用 OpenAPI 接口的能力。
- **运行时家族**：查看 ChatLuna 系统状态、实时日志、已启用的插件与配置项，修改核心配置通常需要管理员权限。
- **记忆家族**：负责向量记忆或长期记忆的检索、更新与持久化存储。
- **技能家族**：用于枚举已加载的技能包、读取技能指引正文及执行技能脚本。
- **MCP 家族**：通过外部 MCP 服务接入的工具，通常带有服务器名称前缀。
- **子代理家族**：提供任务派发能力，主模型可将特定子任务交由子代理处理并汇总返回结果。
- **机器家族**：将本地执行器、远端 SSH 主机、Docker 容器或云端沙箱的操作接口映射为可调用的工具。
- **业务家族**：各类业务扩展插件注册的功能，例如 AI 绘图、语音合成、定时器及社群管理等。

## 推荐配置

以下是几种常见场景下的配置建议：

### 个人小实例

如果搭建 ChatLuna 主要用于个人日常私聊，建议在「场景规则 → 能力 → 工具」中将「工具模式」保持为默认的「直接给全部」。

个人环境中的工具数量通常较少，直接提供工具定义的响应速度最快，无需增加搜索环节。在「能力 → 工具」页面中，将命令执行与文件修改类工具的「当前策略」设为「询问」，常规查询工具保持「自动」即可。

### 接了多个 MCP 的实例

当接入了 GitHub、数据库等多个 MCP 服务，工具数量较多时，推荐在「场景规则 → 能力 → 工具」中开启「工具搜索」。

保持「自动启用阈值」为默认的 20，并确保「按需加载列表」包含了 MCP 来源的工具。对于日常最高频使用的两三个基础工具，可以在「能力 → 工具」详情面板中单独设为「常驻」；涉及外部数据增删改的高危 MCP 工具则单独设为「询问」。

### 多人群聊

在群聊等公开环境中，安全性应当放在首位。建议在「场景规则 → 能力 → 工具」中为各个群聊单独配置工具白名单。

群聊中通常仅保留信息查询、网络搜索与趣味互动等只读类业务工具；涉及配置修改、文件读写及 Shell 终端的高风险工具，应统一限制在管理员私聊或受控的管理群中使用，防止群内普通成员诱导模型执行破坏性指令。

### 自动化 / 编码

当需要让模型协助编写代码或执行批处理自动化任务时，推荐在「场景规则 → 能力 → 工具」中将模式切换为「写代码调用」，或选用专用的编码引擎。

为模型配齐文件读写、目录检索与代码解释器工具，同时将高危指令设为「询问」，或限制在沙箱工作区内运行。在此模式下，模型可以编写脚本直接组合批处理多个工具的输出，减少繁琐的往返对话轮次。

## 排查

在日常使用工具的过程中，如果遇到预期之外的问题，可参考以下步骤排查：

**模型在回答中声称自己「没有某个工具」**  
顺着可见性链路逐项排查：首先在「能力 → 工具」页面确认该工具已成功注册且未处于「禁用」状态；其次检查插件是否设置了运行环境过滤；再前往「场景规则」确认当前场景未将其列入禁用黑名单；最后查看该工具是否处于「按需加载」状态且模型在当前轮次尚未发起针对性的搜索。

**模型界面显示发起了工具调用，但后续一直没有进展**  
通常是触发了审批机制正在等待人工放行，或是生成的入参未能通过结构校验。前往控制台「轨迹」页面查看对应会话回合的运行状态与报错信息；若处于等待审批状态，请检查聊天窗口下方的审批槽位中是否有待处理的确认卡片。

**工具返回的文本内容过长，导致上下文直接爆满**  
读取大文件或检索全文容易产生大量文本。可以开启大文本结果自动转存机制：当返回值超出设定阈值时，系统会自动将内容存入临时存储，转而只向模型提供内容摘要与读取路径；也可以针对此类工具切换为按需检索模式。

**工具调用总是提示被系统自动拒绝**  
优先检查当前会话的权限模式是否被误设为了「只读」，导致写入与调用请求被一律驳回；同时核对调用用户的权限等级。对于高风险操作，「完全放行」策略仅对管理员生效，低权限用户即便匹配到放行规则，系统底层依然会降级退回「自动」模式并拦截高危请求。
