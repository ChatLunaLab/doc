# 机器与工作区

::: tip
本节介绍「环境」页面中机器 (Machine) 与工作区 (Workspace) 的配置。机器决定工具在何处执行，工作区则是该机器上的文件根目录。
:::

工具调用并不局限于 ChatLuna 进程所在的本地环境。机器是工具的底层执行环境：它提供一个独立的工作区（文件根目录）以及对应的执行能力（读写文件、运行系统命令）。同一个 Agent 可以根据任务需求，将不同的操作委派到不同的机器上执行。

## 认识机器类型

ChatLuna 支持以下四种机器类型：

- **`local`（默认启用）**：ChatLuna 进程所在的宿主环境。
- **`docker`**：为每个会话启动一个独立的容器环境（依赖沙箱服务，默认禁用）。
- **`ssh`**：连接到指定的远程主机执行。
- **`e2b`**：使用托管的云端沙箱环境。

除 `local` 外，其余机器类型默认处于禁用状态。你可以在项目清单文件中配置，或前往控制台的「环境」页面启用对应的插件以激活它们。

## 配置委派路由

通过配置路由规则，你可以控制 Agent 能够调度哪些机器：

- **`default`**：未指定目标机器时，工具默认执行的机器。
- **`allowed`**：允许委派 (Delegate) 调用的机器列表集合。

当任务需要环境隔离或必须在特定远程环境中运行时，模型会通过委派工具在 `allowed` 列表中选择目标机器执行命令。

::: danger Docker 机器的安全风险
`docker` 机器类型依赖宿主机的 `/var/run/docker.sock` 套接字挂载，这在安全层面等价于向容器赋予宿主机 root 权限。启用前请务必确认 `DOCKER_GID` 设置正确，并仔细阅读[权限与安全](./permissions)。
:::
