# 机器与工作区

::: tip
这一页讲「模型在哪里动手」。机器 (Machine) 决定命令在哪台电脑、哪个容器里执行；工作区 (Workspace) 是这台机器上允许模型自由读写的根目录。
:::

机器人能聊天，靠的是模型；机器人能干活，靠的是工具。工具里的文件读写、命令执行、代码运行，最终都要落在某个真实的环境里执行。

默认情况下，这个环境就是运行 ChatLuna 的那台机器。

但如果你的实例部署在一台轻量的云服务器上，而你希望模型去整理另一台 NAS 上的文件；或者你担心模型在宿主环境里乱执行命令，想把它关进一个用完即弃的容器里，这时就需要「机器」出场了。

一句话概括：**机器是工具的执行环境，工作区是这个环境里的家**。

## 环境页

打开控制台，在左侧导航栏中依次点击「能力 → 环境」，就能看到当前实例配置的所有机器。

页面右上角可以在「卡片」与「列表」两种视图之间切换，也可以按「按类型」分组、按「按名称」或「按会话数」排序。

每张卡片上显示的信息不多，但都很有用：

- **名称与类型**：这台机器叫什么、属于哪一种环境。
- **连接状态**：当前是已连接还是未打开，以及正在使用它的活动会话数量。
- **默认标记**：未指定机器时，任务会落到哪一台。

点开卡片，右侧抽屉里可以查看和修改配置，还能进行「测试连接」「设为默认」「关闭连接」「删除」这些操作。

::: tip
一台机器可以同时被多个会话使用。卡片上的「会话数」就是这个参考值；数字突然变大，通常意味着同时有很多对话在跑工具。
:::

## 四种环境

添加机器时，系统会让你先选择环境类型。目前提供四种：

| 类型 | 说明 | 适合的场景 |
| --- | --- | --- |
| **本机** | 就在运行 ChatLuna 的这台电脑上执行 | 个人使用、单机部署 |
| **SSH** | 通过 SSH 连接到一台远程服务器 | 有独立的开发机、NAS 或算力机 |
| **E2B** | 每个会话一个云端沙箱 | 需要隔离、又不想自己维护容器 |
| **Docker** | 每个会话一个本地容器 | 自托管，需要沙箱隔离 |

本机是开箱即用的，其他三种需要在「环境」页添加。

### 本机

本机是最简单的一种：不远程、不隔离，直接用宿主环境。

工作区默认在一个由 ChatLuna 管理的数据目录下，你也可以改成任何你希望的路径。

模型在这里看到的文件和你在终端里看到的是同一份，所以它写的脚本、生成的文件，你可以直接用系统里的工具打开。

也正因为如此，本机是最方便、但也最没有隔离的一类。个人使用完全够用；如果实例面向陌生人开放，就要慎重。

::: warning
本机环境下的命令执行拥有与 ChatLuna 进程相同的权限。

不要在公开群聊里对本机环境放开命令执行，也不要让模型访问你存放密钥、备份和私人文件的目录。
:::

### SSH

SSH 机器通过远程主机的账号登录，把命令和文件操作发到那台服务器上执行。

需要填写的内容包括主机地址、端口、用户名，以及登录凭据：

- **私钥**：推荐方式，填写私钥文件路径。
- **密码**：作为备选，需要远程主机允许密码登录。
- **远端工作区**：模型在这台服务器上的文件根目录。

SSH 机器是共享的：所有使用它的会话看到的是同一个远程目录。如果你希望每个对话互不干扰，需要自己准备不同的目录或不同的机器。

这类机器很适合「把机器人当远程运维助手」的用法：机器人跑在一台小机器上，真正干活的工具在另一台性能更好的服务器上。

### E2B

E2B 是托管的云端沙箱。填好 API 密钥和模板名称后，ChatLuna 会为每个会话单独开一个沙箱。

这类机器按会话隔离：会话 A 里装的依赖、写的文件，会话 B 看不到。

沙箱闲置一段时间后会被自动挂起，下次用到时再恢复。这个空闲时间可以在配置里调整，默认是十分钟。

云沙箱的好处是不用自己维护容器运行时；代价是要额外付费，而且需要把工作内容发到第三方服务上。

### Docker

Docker 机器在你自己的机器上为每个会话启动一个容器。

你需要填写镜像名称，也可以补充挂载目录和容器内的工作区路径。

和 E2B 一样，它按会话隔离，同样有闲置挂起的行为。

::: danger
Docker 环境需要访问宿主机的 Docker 服务，这在本机上等价于很高的系统权限。

只在你信任镜像来源、并且清楚后果的前提下启用；不要在面向公众的实例上随意开放。
:::

## 添加与修改

在「环境」页点击「添加」，选择类型，填写配置，然后先点「测试连接」。

测试连接会真实地打开一次环境，读取它的系统类型与工作区路径，确认没问题后再断开。

看到「连接成功」的提示后，再点「保存」。此时机器才会真正出现在列表里，可以被场景规则和模型使用。

修改现有机器时，抽屉里的表单会直接把已保存的配置填好。

::: tip
密钥、密码、API 密钥这类字段不会回显。留空表示保留原来的值，只有填入新内容时才会覆盖。
:::

几个常用按钮的作用：

- **测试连接**：临时打开一次，验证配置是否可用。
- **设为默认**：让未指定机器的任务默认落到这一台。
- **关闭连接**：断开当前已经打开的连接，已启动的会话机器会被收起。
- **删除**：先关闭所有连接，再删除配置和保存的密钥。

删除是不可逆的。如果这台机器正在被某个会话使用，建议先确认没有任务在跑。

## 空闲挂起与会话恢复

按会话隔离的机器（E2B、Docker）不会一直开着。

一类机器闲置一段时间后会被挂起，节省资源；下次这个会话再使用工具时，会自动恢复，不需要你手动操作。

这个空闲时间在机器配置里，默认十分钟。

还有一件事值得单独说明：**重启 ChatLuna 之后，会话还能找回自己的沙箱**。

系统会把沙箱的标识记录在会话里。进程重启后，同一个会话再次使用机器时，会尝试用这条记录重新接上原来的沙箱，而不是开一个新的。

所以，如果你的机器人中途重启过，发现会话里的文件还在，这是正常行为。

反过来说，如果你想彻底丢弃某个沙箱，应该在「环境」页关闭连接，而不是重启进程。

## 机器与场景规则

机器不是随便用的。在「场景规则 → 安全 → 执行环境」里，有两个设置决定模型能用哪些机器：

- **默认机器**：没指定时用哪一台。
- **允许委派**：模型可以把任务派到哪些机器上执行。

「允许委派」是一份白名单。不在名单里的机器，即便存在，模型也不能用。

用途很直接：你可以只把一台受限的沙箱机器放进白名单，让模型永远碰不到宿主环境。

::: warning
如果你发现模型「找不到某台机器」，先检查场景规则里的「允许委派」，再看这台机器的权限等级是否允许当前用户使用。
:::

## 权限

每台机器都会注册成一项权限动作，默认等级不同：

- **本机**：较低等级，普通使用者即可调用。
- **其他机器**：较高等级，通常只对管理员开放。

也就是说，即使场景规则允许，普通群成员也未必能用更敏感的机器。

具体等级是怎么算的、怎么调整，参见[权限与安全](./permissions)。

## 工作区边界

工作区是模型默认的活动范围。相对路径都会按工作区根目录解析。

读取文件不限制在工作区内，但**写文件、删除文件越出工作区**时，系统会先索要一次授权，用户同意后才继续。

这带来两个实用建议：

1. 把希望模型自由整理的目录放进工作区，省得每次都确认。
2. 把不该动的目录留在工作区之外，用授权作为最后一道闸门。

::: tip
写操作的范围检查是按「这台机器」做的，不是按「这个用户」。把工作区设在合适的位置，比事后靠确认弹窗兜底更可靠。
:::

## 推荐配置

### 个人自用

只保留本机机器，工作区指向一个专门的目录，例如你的笔记或项目文件夹。

命令执行设成需要审批，文件写入保持自动。这样日常整理文件很顺，执行命令前还能踩一脚刹车。

### 家里有台服务器

添加一台 SSH 机器，把它设为默认，本机也保留但不放进「允许委派」。

模型平时在远程服务器上操作，宿主环境只负责聊天和调度，两边互不干扰。

### 对外公开的群聊

只允许一台 Docker 或 E2B 沙箱机器，本机从「允许委派」里移除。

镜像使用干净的官方基础镜像，挂载目录尽量少。这样即使模型被诱导执行了危险命令，影响范围也限于一次性容器。

### 多会话并行

需要多个对话同时干活、又不想互相踩文件，优先用 Docker 或 E2B 这类按会话隔离的机器。

如果只能用共享机器，至少为不同群配置不同的工作区目录，避免「甲群删了乙群的文件」。

## 排查

**机器列表是空的。**

说明还没有任何机器被配置。正常情况下系统会自带一台本机机器；如果没有，去「插件」页确认对应插件是否已启用。

**测试连接失败。**

- 本机：检查工作区路径是否存在、是否有写权限。
- SSH：检查主机、端口、用户名和凭据；确认这台机器能从这个网络连过去。
- E2B：检查 API 密钥是否有效、模板是否存在。
- Docker：检查本机的 Docker 服务是否在运行、镜像是否能拉取。

**模型说没有可用机器。**

先看场景规则的「允许委派」；再看权限等级；最后确认这台机器的插件已经启用、环境页里能看到它。

**会话里的文件突然没了。**

按会话隔离的机器在关闭连接或沙箱过期后会被回收。如果你需要长期保留某个工作目录，改用共享机器，或者把目录挂载到持久位置。

**写入工作区外的文件总被拦。**

这是设计如此：越出工作区的写操作需要授权。把目标目录挪进工作区，或者临时批准一次。
