# 机器与工作区

::: tip
本节介绍「机器」与「工作区」的核心概念。机器 (Machine) 决定了命令在哪个物理系统或容器中执行；工作区 (Workspace) 则是该机器上允许模型直接读写文件的根目录。
:::

机器人能够聊天，依赖于大语言模型；机器人能够完成具体任务，则依赖于工具。无论读取文件、执行系统命令还是运行代码脚本，工具最终都需要运行在一个真实的环境中。

在默认情况下，该执行环境就是运行 ChatLuna 的宿主机器。

在许多实际场景中，执行环境需要与宿主机分离。例如，ChatLuna 部署在轻量云服务器上，而你需要模型整理局域网内 NAS 上的文件；或者为了系统安全，需要将不受信任的命令限制在一次性沙箱容器中运行。这时就需要配置独立的「机器」。

简而言之：**机器是工具的执行环境，工作区是该环境中模型的操作根目录**。

## 环境页

打开控制台，在左侧导航栏中依次点击「能力 → 环境」，即可查看当前实例配置的所有机器。

页面右上角支持在「卡片」与「列表」两种视图之间切换，并提供「按类型」分组，以及「按名称」或「按会话数」排序功能。

卡片展示了机器的核心运行状态：

- **名称与类型**：机器的自定义名称以及所属的环境类型。
- **连接状态**：当前连接处于已连接还是未打开状态，以及正在调用该机器的活动会话数量。
- **默认标记**：未显式指定机器时，任务默认派发的目标机器。

点击卡片可在右侧抽屉中查看并修改详细配置，同时支持「测试连接」、「设为默认」、「关闭连接」和「删除」等操作。

::: tip
同一台机器可以同时被多个会话并发使用。卡片上的「会话数」即为当前的活动负载参考；如果数值明显上升，通常意味着当前有多个对话正在调用工具。
:::

## 四种环境

在添加机器时，需要首先选择环境类型。目前提供四种环境支持：

| 类型 | 说明 | 适合的场景 |
| --- | --- | --- |
| **本机** | 就在运行 ChatLuna 的这台电脑上执行 | 个人使用、单机部署 |
| **SSH** | 通过 SSH 连接到一台远程服务器 | 有独立的开发机、NAS 或算力机 |
| **E2B** | 每个会话一个云端沙箱 | 需要隔离、又不想自己维护容器 |
| **Docker** | 每个会话一个本地容器 | 自托管，需要沙箱隔离 |

其中「本机」环境默认开箱即用，其余三种环境则需要在「环境」页手动添加。

### 本机

本机是最直接的运行方式：无需网络远程连接，也不做沙箱隔离，直接调用宿主机环境。

其工作区默认位于 ChatLuna 管理的数据目录下，你也可以根据需要将其修改为系统中的任意指定路径。

在宿主环境中，模型读写的文件与你在终端中访问的完全一致。模型生成的代码、文档或脚本，可以直接使用系统中的本地软件打开或编辑。

由于完全没有隔离机制，本机虽然最为便捷，但安全性也最为脆弱。对于个人本地使用而言非常顺手；但如果你的机器人实例面向公开群聊开放，请务必保持谨慎。

::: warning
本机环境中的命令执行拥有与 ChatLuna 宿主进程完全一致的系统权限。

请勿在公开群聊中开放本机环境的命令执行权限，也切忌将工作区指向存放敏感凭据、备份或私人文件的目录。
:::

### SSH

SSH 机器通过远程主机的账号登录，将工具的文件读写与命令派发到该服务器上执行。

配置时需要指定目标主机地址、端口、用户名以及登录凭据：

- **私钥**：推荐的认证方式，需要填写私钥文件的存放路径。
- **密码**：备用认证方式，要求远程主机允许密码登录。
- **远端工作区**：模型在远程服务器上允许读写的文件根目录。

SSH 机器属于多会话共享环境：所有接入该机器的会话看到的都是同一个远端工作区。如果希望不同会话互不干扰，需要自行规划不同的工作区路径或配置多台独立的 SSH 机器。

这种环境非常适合运维与远程算力场景：ChatLuna 自身运行在轻量服务器上，而真正干活的工具与命令派发到另一台性能更好的远程服务器上执行。

### E2B

E2B 是一项托管式的云端沙箱服务。填入 API 密钥与模板名称后，ChatLuna 会为每个独立的对话会话按需创建专属的沙箱实例。

E2B 环境具备严格的会话级隔离：不同会话之间的环境与文件互不可见，某个会话中安装的依赖也不会污染其他会话。

沙箱实例在闲置一段时间后会被自动挂起以节省额度，当该会话再次调用工具时会自动唤醒恢复。该空闲超时时间可在配置中调整，默认值为十分钟。

使用云端沙箱无需自行维护本地容器运行时，开箱即用；但依赖第三方云端服务，并且需要消耗对应的 API 额度。

### Docker

Docker 机器利用本地 Docker 守护进程，为每个会话分别创建并启动独立的容器沙箱。

配置时需要指定容器镜像名称，并可按需设置挂载目录以及容器内部的工作区路径。

与 E2B 类似，Docker 同样提供会话级沙箱隔离与闲置自动挂起机制。

::: danger
Docker 环境需要访问宿主机的 Docker 服务，这在本地系统中通常等同于很高的系统权限。

请务必只使用可信的基础镜像，并了解挂载目录带来的潜在风险；切勿在面向不受信任用户的公开实例上随意开放。
:::

## 添加与修改

在「环境」页点击「添加」按钮，选择所需的环境类型，填入各项连接参数后，建议先点击「测试连接」。

「测试连接」会真实建立一次会话连接，读取环境的系统类型与工作区路径，验证无误后再断开连接。

在界面看到「连接成功」提示后，点击「保存」完成配置。只有保存成功的机器才会出现在列表当中，并可供场景规则与模型调用。

如需修改已有机器，点击对应卡片即可在右侧抽屉中调整已有配置。

::: tip
密码、私钥与 API 密钥等敏感字段在编辑时不会回显。留空表示保留原有的值，仅在输入新内容时才会覆盖旧凭据。
:::

抽屉中常用操作按钮的功能如下：

- **测试连接**：临时打开连接以验证网络与参数有效性。
- **设为默认**：将当前机器设为默认环境，未指定机器的任务会自动派发至此。
- **关闭连接**：主动断开当前的连接，并收起关联的会话容器或沙箱。
- **删除**：先关闭所有活跃连接，随后彻底清除该机器的配置与保存的密钥。

需要注意的是，删除操作不可恢复。如果该机器当前有会话正在使用，建议在删除前确认相关任务已执行完毕。

## 空闲挂起与会话恢复

支持会话隔离的机器（如 E2B 和 Docker）不会持续占用系统资源。

当某个沙箱在设定的时间内没有接收到新的工具调用，系统会自动将其挂起以节省资源；当下一次会话发起工具调用时，沙箱会自动唤醒并恢复上下文，无需手动干预。

闲置挂起的超时时间可以在机器配置中设定，默认通常为十分钟。

此外，**ChatLuna 支持跨进程重启的沙箱会话恢复**。

系统会将容器或沙箱的唯一标识记录在会话中。当 ChatLuna 进程重启后，同一个会话如果再次发起工具调用，系统会优先根据记录重新接驳已有的沙箱实例，而不是开辟新容器。

因此，即便机器人经历过重启，只要沙箱未被系统回收，原有工作目录中的文件依然会保留。

如果确实需要彻底清理并销毁某个沙箱实例，应当在「环境」页面手动点击「关闭连接」，单纯重启 ChatLuna 进程并不会自动清除存量沙箱。

## 机器与场景规则

机器的调度受到场景规则的严格约束。在「场景规则 → 安全 → 执行环境」中，可以通过两项配置控制模型对机器的访问权限：

- **默认机器**：当模型或任务未显式指定目标机器时，系统默认使用的执行环境。
- **允许委派**：模型被允许自主将任务派发至哪些机器上运行。

其中「允许委派」采用白名单机制。未包含在此列表中的机器，即便已在环境中正确配置，模型也无权调度。

通过这种设计，你可以将白名单严格限制在受限的沙箱容器内，确保模型在任何情况下都无法触及宿主环境。

::: warning
当模型提示「找不到某台机器」时，请优先检查当前场景规则中的「允许委派」白名单，并核实调用者的权限等级是否满足该机器的要求。
:::

## 权限

在系统中，每台已配置的机器都会注册为一个对应的权限动作，并具有不同的默认权限等级：

- **本机**：默认拥有较低的权限门槛，普通用户即可在会话中触发。
- **其他机器**：默认设置了更高的权限要求，通常仅限管理员权限调用。

因此，即便场景规则放行了某台机器，普通群成员若未达到该机器所需的权限等级，依然无法调用。

关于权限等级的判定与具体配置方式，请参阅[权限与安全](./permissions)。

## 工作区边界

工作区界定了模型在机器上的核心活动范围。所有相对路径操作均以工作区根目录为基准进行解析。

为了兼顾便利与安全，系统允许自由读取工作区外的文件；但一旦涉及**在工作区外写入或删除文件**，系统将强制触发审批流，必须经由用户确认授权后方可执行。

合理利用工作区边界，可以平衡自动化与安全性：

1. 将允许模型自由管理和生成的文件夹设置为工作区，减少频繁的确认打扰。
2. 将敏感的系统目录或核心业务文件留在工作区之外，利用审批机制形成安全屏障。

::: tip
工作区越界检查针对的是「目标机器」的文件范围，而非「当前用户」。合理规划工作区的物理路径，能从根本上降低越权误操作的风险。
:::

## 推荐配置

### 个人自用

仅保留本机机器，将工作区路径指向专门的文件夹（例如笔记库或个人项目目录）。

安全策略上可将命令执行设置为需要审批，而文件写入保持自动执行。这样既能保证日常自动化文件整理的顺畅，又能在执行高危命令前保留确认环节。

### 家里有台服务器

新增一台 SSH 机器并设为默认机器，同时保留本机机器但将其从「允许委派」列表中移除。

模型的所有工具调用均直接派发至远程服务器执行，宿主机仅负责消息接收与逻辑调度，两边互不干扰。

### 对外公开的群聊

在群聊场景中仅开放 Docker 或 E2B 沙箱机器，并将本机从「允许委派」中彻底移除。

容器镜像推荐使用干净的官方基础镜像，同时严格限制挂载目录。即便模型遭遇提示词注入等恶意引导，命令执行的影响也会被限制在一次性容器内。

### 多会话并行

当多个群聊或会话需要频繁并发执行工具且互不干扰时，优先选用 Docker 或 E2B 等具备会话隔离特性的机器。

如果受限于环境只能使用共享机器，建议为不同的会话或群聊配置互相独立的工作区目录，避免不同对话之间产生文件读写冲突。

## 排查

**机器列表是空的。**

说明当前尚未注册任何机器配置。系统在初始化时通常会预置一台本机机器；如果列表中为空，请前往「插件」页面确认对应的环境扩展插件是否已正常启用。

**测试连接失败。**

- 本机：检查指定的工作区路径是否存在，以及当前运行用户是否具备读写权限。
- SSH：检查主机地址、端口、用户名和认证凭据是否正确，并确认宿主机网络能够正常连通远程端口。
- E2B：检查填入的 API 密钥是否有效，以及指定的模板名称是否存在。
- Docker：检查宿主机上的 Docker 守护进程是否正常运行，以及所需镜像能否正常拉取。

**模型说没有可用机器。**

请依次排查以下几点：首先检查场景规则中的「允许委派」是否已将目标机器加入白名单；其次检查当前用户的权限等级是否达到该机器的要求；最后在「环境」页面确认目标机器处于正常连接状态。

**会话里的文件突然没了。**

具备会话隔离特性的机器（如 E2B 和 Docker）在手动关闭连接或沙箱闲置超时回收后，其内部临时状态会被销毁。如果需要长期保留生成的文件，建议改用共享式机器，或通过 Docker 卷挂载将目录持久化到宿主机。

**写入工作区外的文件总被拦。**

这是系统的安全机制：在工作区之外的文件写入与删除操作必须经过人工授权。如果该目录属于常规操作范围，可直接将工作区路径调整至该目录，或在弹出的授权请求中点击确认。
