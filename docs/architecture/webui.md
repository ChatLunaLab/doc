# 控制台

::: tip
WebUI 并不是简单地「给后端套一层展示页面」，而是一个独立的前端应用，配合一组实时通信通道。页面由插件自主注册，数据状态由服务端按需推送，用户的写操作则统一通过带校验的动作接口处理。
:::

在控制台里，你会看到聊天、轨迹、工具、权限、记忆、MCP、插件市场等三十多个页面。

这些页面并不是写死在一个单体应用里的，而是来自各个独立的插件。每个插件分别声明自己的页面、接口与本地化文案，最后由控制台外壳（Shell）统一发现并组装呈现。

## 双面包

在控制台中，一个页面插件通常采用「双面包」结构，同时涵盖前后两端：

- **服务端**：负责声明路由、管理状态、处理动作并执行权限检查。
- **客户端**：基于 React 编写界面组件，提供可视化表单并订阅实时数据。

两端通过类型化的契约配合，共享一套清晰的数据结构：状态类型、动作名称以及各自的输入输出格式。

这样一来，前端清楚该调用哪个动作与参数，后端明确该返回什么数据。修改代码时，任何契约不一致都会触发 TypeScript 类型报错，省去了很多排错成本。

## 通信

控制台客户端与服务端之间维护着两条分工明确的通信通道。

### HTTP

常规的单向请求均通过 HTTP 通道进行：

- 读取前端外壳与插件的静态资源
- 提交写操作（即执行动作）

动作接口内置了输入校验、幂等键支持以及细粒度的权限检查。

### WebSocket

实时长连接通道主要负责服务端的主动推送与状态同步：

- 握手连接与初始化
- 客户端认证与会话凭据校验
- 拉取初始状态快照，广播后续增量更新
- 连接健康保活心跳

::: tip
为什么不把所有交互都收拢到 WebSocket 中？

写操作需要重试与幂等语义，HTTP 请求在这类场景下更合适；而状态流转追求「数据变了就推」，WebSocket 能提供极低的延迟与开销。两条通道各司其职，比强行合并在单个协议中更可靠。
:::

## 认证

长连接建立后不会立即生效，必须先完成身份认证：

1. 服务端向客户端发送一条初始化帧。
2. 客户端回应认证帧，附带登录令牌（Token）或会话凭据。
3. 服务端认证通过后，正式开始向该连接推送业务状态。

未完成认证的连接只能接收初始化帧与心跳保活帧，无法获取任何业务数据。

此外，服务端会定期复核认证状态。一旦令牌失效或被撤销，连接会被服务端主动切断，防止客户端持有旧权限继续接收推送。

### 路径保护

控制台的访问路径与底层接口路径默认都处于受保护的前缀之下。

如果宿主环境未配置保护规则，或者保护路径配置错误，控制台的自检诊断会直接报错拦截。这是刻意设计的防护机制：控制台拥有极高的系统权限，不能在未受保护的状态下运行。

## 状态

控制台的状态以服务端为单一事实源。插件向服务端注册状态（State）时，需要声明：

- **快照读取方法**：如何计算或获取该状态的最新快照。
- **触发刷新事件**：哪些系统事件发生时需要重新计算状态。
- **广播范围**：向所有已连接的客户端广播，还是仅对特定连接可见。

插件声明状态后，控制台客户端只需订阅该状态，服务端便会在数据变化时主动推送更新。

### 刷新策略

状态刷新支持多种触发方式：

- **事件驱动**：订阅配置变更、插件状态切换或连接断开等系统事件，实时推流。
- **定时刷新**：用于缺乏底层事件机制、但数值随时间变动的数据，例如机器人当前的在线状态。
- **手动刷新**：在某个动作执行完成后，由处理函数显式触发关联状态的重新计算与推送。

### 背压

服务端的推送不会无限积压：

- 当客户端连接出现网络拥塞时，服务端会丢弃中间过程状态，只保留并下发最新的快照。
- 若客户端长时间失去响应，该长连接会被直接断开。

这样可以避免个别网络较慢的浏览器窗口拖慢整个控制台的推送通道。

## 动作

动作（Action）是控制台处理所有写操作的统一入口。

一个标准的动作声明通常包含：

- **名字**：动作的唯一标识，例如保存适配器、启用或停用插件。
- **输入 Schema**：定义入参结构并在运行时执行校验。
- **处理函数**：实际执行业务逻辑的代码。
- **权限检查**：由动作内部或统一中间件校验调用权限。

### 幂等

所有动作均原生支持传递幂等键。

当网络抖动引发客户端自动重试时，服务端识别到重复的幂等键后，会直接返回第一次的执行结果，而不会重复执行内部逻辑。

这对于「安装插件」或「切换开关」等带有副作用的关键操作尤为重要。

## 资源

控制台在前端资源加载上兼顾了性能与平滑更新。

### 版本化外壳

控制台外壳（Shell）的静态资源均带有版本号标识。

浏览器命中强缓存时会直接使用本地缓存快速渲染，只有检测到远端外壳版本更新时才会重新下载最新资源。

### 插件资源

每个插件的客户端代码均采用独立打包机制，按插件 ID 与修订号（Revision）命名文件。

插件更新后，旧版本的资源文件不会被直接覆盖。已打开旧版页面的客户端仍可继续加载所需的代码分块（Chunk），不会因为插件更新而产生运行时动态加载错误。

### Service Worker

控制台内置的 Service Worker 提供了灵活的离线与网络缓存策略：

- **版本化的外壳与插件分块**：采用缓存优先（Cache First）策略。
- **页面路由导航**：采用网络优先（Network First）策略，在离线或弱网请求失败时，自动回退到上次可用的外壳。
- **数据接口与实时长连接**：直接走网络请求，不进行本地缓存。

这套机制让控制台在弱网环境下也能正常使用。

::: warning
修改了前端代码却看不到界面变化时，应当首先检查浏览器缓存。

建议先尝试强制刷新页面（`Ctrl+F5` 或 `Shift+Reload`），或等待新版本生效，不必急于怀疑代码没有保存成功。
:::

## 页面与插槽

页面由插件通过路由注册接口动态挂载到控制台中：

```ts
ctx.slots.route({
  path: '/tools',
  page: async () => (await import('./tools')).ToolsPage,
  title: '工具',
  icon: 'wrench',
  order: 10,
  group: 'capabilities',
})
```

只需在插件中完成上述声明即可生效，无需改动控制台外壳的代码。

### 分组与排序

每个页面在注册时都可以声明所在的导航分组（Group）与排序权重（Order）。

导航分组的分类标签（如概览、对话、配置、插件、能力、观测等）由控制台外壳统一预置，页面只需声明引用即可归类展示。

### 隐藏页面

某些页面需要拥有独立的 URL 路径以支持跳转和传参，但不适合在左侧主导航中展示（例如轨迹详情页）。

遇到这类需求时，只需在注册路由时将其标记为隐藏即可。

### 插槽

除了挂载独立整页之外，插件还可以向现有页面的指定插槽（Slot）中注入自定义内容：

- 仪表盘上的自定义概览卡片
- 规则配置页中的专属标签页
- 复杂表单内部定制的字段控件

插槽本身是强类型的：提供插槽的页面会严格定义所容纳内容的类型结构，插件注入的组件与数据必须与其契约完全匹配。

## 表单

控制台的大部分配置界面均由 Schema 驱动渲染：

1. 插件在服务端声明配置的数据结构（Schema）。
2. 服务端在建立连接时将该结构序列化并同步至前端。
3. 前端根据结构自动渲染出对应的交互表单。
4. 表单提交修改时，服务端再次校验数据的合法性。

得益于这种模式，当你为插件添加新的配置项时，通常不需要额外编写前端代码。

### 表单扩展

如果某些特定字段需要更复杂的交互组件（例如工具列表、角色预设选择、技能列表或多媒体选择器等），可以通过「表单扩展」机制进行注册。

扩展控件会根据字段的类型或角色（Role）自动匹配并加载。

## 文案

控制台页面支持国际化，自带中文与英文等多语言文案，通过本地化接口统一注册。

如果在渲染时遇到缺失的文案键，系统会自动回退到默认语言，而不会在界面上展示空白或报错。

## 生命周期

控制台中注册的所有扩展资源，都深度绑定在 Cordis 插件的生命周期上：

- 路由、插槽、推送状态、动作接口与本地化文案，均随插件上下文统一注册。
- 当插件被停用或卸载时，对应的所有注册项会被自动注销并清理。

得益于完备的生命周期管理，控制台在热重载过程中不会留下无法清除的「幽灵页面」。

## 安全

控制台具备极高的系统管理权限：

- 可以安装并运行任意扩展插件
- 可以查看并直接修改全局系统配置
- 可以完整读取历史会话内容与 Agent 执行轨迹

因此在部署和运维时必须格外注意安全边界：

- 控制台默认只允许本机（`localhost`）访问。
- 所有的页面路由与底层接口均受登录令牌保护。
- 在公网部署时，必须配置反向代理并强制开启 HTTPS 加密通信。

## 排查

**页面白屏**

打开浏览器开发者工具，检查控制台报错与网络请求。常见原因是插件客户端构建产物的版本与外壳不匹配，或者某个异步分块（Chunk）加载失败。

**页面存在但数据为空**

检查对应的状态（State）是否已在服务端正常注册、关联的触发事件是否成功派发，以及后端数据接口是否返回了错误。

**动作提示参数非法**

说明前端提交的参数结构与服务端的 Schema 校验规则不一致，对照接口报错中指出的字段即可快速定位。

**一直提示未认证**

通常是因为登录令牌已失效，或者保护路径与受保护前缀配置不匹配。请检查当前会话凭据及安全路径配置。

**修改配置后不生效**

首先确认动作接口是否已成功返回；其次确认该配置项是否绑定了对应的状态刷新事件；最后也可以手动刷新页面查看最新快照。
