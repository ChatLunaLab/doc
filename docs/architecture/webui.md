# 控制台

::: tip
WebUI 并不是简单地「给后端套一层展示页面」，而是一个独立的前端应用配合一组实时通信通道。页面由插件自主注册，数据状态由服务端按需推送，用户的写操作则统一走带校验的动作接口。
:::

在控制台里，你会看到诸如聊天、轨迹、工具、权限、记忆、MCP、市场等三十来个页面。

细心的小伙伴可能会好奇，这些页面是如何组织的？其实它们并不是写死在一个庞大单体应用中的，而是来自各个独立的插件：每个插件负责声明自己的页面、接口与本地化文案，最后由控制台外壳（Shell）统一发现并组装呈现在你面前。

## 双面包

在控制台中，一个页面插件通常采用「双面包」式的结构，同时涵盖前后两端：

- **服务端**：负责声明路由、管理状态、处理动作并执行权限检查。
- **客户端**：基于 React 编写界面组件，提供可视化表单并订阅实时数据。

两端通过类型化的契约紧密配合，共享一套清晰的数据结构：状态类型、动作名称以及各自的输入输出格式。

这样一来，前端清楚该调用哪个动作与传参，后端明确该返回什么数据；在修改代码时，任何契约不一致都会触发 TypeScript 类型报错，极大地降低了沟通与排错成本。

## 通信

控制台客户端与服务端之间维护着两条分工明确的通信通道。

### HTTP

常规的单向请求均通过 HTTP 通道进行：

- 读取前端外壳与插件的静态资源。
- 提交写操作（即执行动作）。

动作接口天然内置了输入校验、幂等键支持以及细粒度的权限检查。

### WebSocket

实时长连接通道则主要负责服务端的主动推送与状态同步：

- 握手连接与初始化。
- 客户端认证与会话凭据校验。
- 初始状态快照拉取与后续增量更新广播。
- 连接健康保活心跳。

::: tip
为什么不把所有交互都收拢到 WebSocket 中呢？

因为写操作需要重试与幂等语义，HTTP 请求在这类场景下更加合适；而状态流转则追求「数据变了就推」，WebSocket 能够提供极低的延迟与开销。两条通道各司其职，相比强行合并在单个协议中要可靠得多。
:::

## 认证

长连接建立后并不会立即处于可用状态，必须先完成身份认证流程：

1. 服务端先向客户端发送一条初始化帧。
2. 客户端回应认证帧，附带登录令牌（Token）或会话凭据。
3. 只有在服务端认证通过后，才正式开始向该连接推送业务状态。

未完成认证的连接只能接收初始化帧与心跳保活帧，无法获取任何业务数据。

此外，服务端会对认证状态进行定期复核：一旦令牌失效或被撤销，连接会被服务端主动切断，而不是任由客户端继续持有旧权限接收推送。

### 路径保护

控制台的访问路径与底层接口路径默认都处于受保护的前缀之下。

如果宿主环境未配置保护规则，或者保护路径配置错误，控制台的自检诊断会直接报错拦截——这是刻意设计的防护机制，因为控制台拥有极高的系统执行权限，绝对不能在裸露状态下运行。

## 状态

控制台的状态以服务端为单一事实源。插件在向服务端注册一项状态（State）时，需要声明：

- **快照读取方法**：如何计算或获取该状态的当前最新快照。
- **触发刷新事件**：哪些系统事件发生时需要触发状态重新计算。
- **广播范围**：该状态是向所有已连接客户端广播，还是特定连接可见。

插件完成状态声明后，控制台客户端只需订阅该状态，服务端便会在数据变化时主动推送更新。

### 刷新策略

状态的刷新支持多种触发方式：

- **事件驱动**：订阅系统内部的配置变更、插件状态切换或连接断开等事件，实时推流。
- **定时刷新**：用于缺乏底层事件机制但数值会随时间变动的数据，例如机器人当前的在线状态。
- **手动刷新**：在某个动作执行完成后，由处理函数显式触发关联状态的重新计算与推送。

### 背压

服务端的推送并非不计代价地无限积压：

- 当某条客户端连接出现网络拥塞时，服务端会主动丢弃中间过程状态，只保留并下发最新的快照。
- 若客户端长时间失去响应，该长连接将被直接断开。

这保证了个别网络迟缓的浏览器窗口不会拖慢整个控制台系统的推送通道。

## 动作

动作（Action）是控制台处理所有写操作的统一入口。

一个标准的动作声明通常包含：

- **名字**：动作的唯一标识，例如保存适配器、启用或停用插件。
- **输入 Schema**：严格定义入参结构并在运行时执行校验。
- **处理函数**：实际执行业务逻辑的代码。
- **权限检查**：由动作内部或统一中间件负责校验调用权限。

### 幂等

所有动作均原生支持传递幂等键。

当遇到网络抖动引发客户端自动重试时，服务端识别到重复的幂等键后会直接返回第一次的执行结果，而不会重复执行内部逻辑。

这对于「安装插件」或「切换开关」这类带副作用的关键操作尤为重要。

## 资源

控制台在前端资源加载上兼顾了性能与平滑更新。

### 版本化外壳

控制台外壳（Shell）的静态资源均带有版本号标识。

浏览器命中强缓存时会直接使用本地缓存快速渲染，只有检测到远端外壳版本更新时才会重新下载最新资源。

### 插件资源

每个插件的客户端代码均采用独立打包机制，按插件 ID 与修订号（Revision）进行文件命名。

插件更新后，旧版本的资源文件并不会被直接覆盖——已打开旧版页面的客户端仍然可以继续加载自己所需的代码分块（Chunk），不会因为发版而产生运行时动态加载错误。

### Service Worker

控制台内置的 Service Worker 提供了灵活的离线与网络缓存策略：

- **版本化的外壳与插件分块**：采用缓存优先（Cache First）策略。
- **页面路由导航**：采用网络优先（Network First）策略，在离线或弱网失败时自动回退到上次可用的外壳。
- **数据接口与实时长连接**：直接走网络放行，绝不进行本地缓存。

这套机制让弱网环境下的控制台依然具备良好的可用性。

::: warning
修改了前端代码却看不到界面变化时，第一反应应当是检查浏览器「缓存」。

建议先尝试强制刷新页面（Ctrl+F5 或 Shift+Reload）或等待新版本生效，不要先怀疑代码没有保存成功。
:::

## 页面与插槽

页面由插件通过路由注册接口动态挂载到控制台中：

```ts
ctx.slots.route({
  path: '/tools',
  page: async () => (await import('./tools')).ToolsPage,
  title: '工具',
  icon: 'wrench',
  order: 10,
  group: 'capabilities',
})
```

只需在插件中完成上述声明即可直接生效，无需改动控制台外壳的任何代码。

### 分组与排序

每个页面在注册时都可以声明所在的导航分组（Group）与排序权重（Order）。

导航分组的分类标签（如概览、对话、配置、插件、能力、观测等）由控制台外壳统一预置，页面只需声明引用即可归类展示。

### 隐藏页面

某些页面需要拥有自己的 URL 路径以支持跳转传参，但并不适合在左侧主导航中展示，例如轨迹详情页。

对于这类需求，在注册路由时将其标记为隐藏即可。

### 插槽

除了挂载独立整页之外，插件还可以向现有页面的指定插槽（Slot）中注入定制内容：

- 仪表盘上的自定义概览卡片。
- 规则配置页中的专属标签页。
- 复杂表单内部定制的字段控件。

插槽本身是强类型的：提供插槽的页面会严格定义所容纳内容的形状，贡献方插件注入的组件与数据必须与其契约完全匹配。

## 表单

控制台大部分配置界面均由 Schema 驱动渲染：

1. 插件在服务端声明配置的数据结构（Schema）。
2. 服务端在建立连接时将该结构序列化同步至前端。
3. 前端根据结构自动将其渲染成对应的交互表单。
4. 表单提交修改时，服务端会再次校验数据的合法性。

这种驱动模式让开发者为插件添加新配置项时，通常完全不需要额外编写前端代码。

### 表单扩展

如果某些特定字段需要更复杂的交互组件，例如工具列表、角色预设选择、技能列表或多媒体元素选择器等，可以通过「表单扩展」机制进行注册。

扩展控件会根据字段的类型或角色（Role）自动匹配并加载，实现无缝替换。

## 文案

控制台页面支持国际化，自带中文与英文等多语言文案，通过本地化接口统一注册。

如果在渲染时遇到缺失的文案键，系统会自动回退到默认语言的文案，而不会在界面上展示空白或报错。

## 生命周期

在控制台中注册的所有扩展资源都深度绑定在 Cordis 插件的生命周期上：

- 路由、插槽、推送状态、动作接口与本地化文案，均随插件上下文统一注册。
- 当插件被停用或卸载时，对应的所有注册项会被自动注销与清理。

正是因为拥有完备的生命周期管理，控制台在热重载过程中绝不会留下无法清除的「幽灵页面」。

## 安全

控制台具备极高的系统管理权限：

- 可以安装与运行任意扩展插件。
- 可以查看并直接修改全局系统配置。
- 可以完整读取历史会话内容与 Agent 执行轨迹。

因此在部署与运维时必须格外注意安全边界：

- 控制台默认只允许本机（localhost）访问。
- 所有的页面路由与底层接口均受登录令牌严格保护。
- 在公网部署时，必须前置反向代理并强制开启 HTTPS 加密通信。

## 排查

**页面白屏。**

打开浏览器开发者工具检查控制台报错与网络请求。常见原因是插件客户端构建产物的版本与外壳不匹配，或者某个异步分块（chunk）加载失败。

**页面存在但数据为空。**

检查对应的状态（State）是否已在服务端正常注册、关联的触发事件是否成功派发，以及后端数据接口是否返回了错误。

**动作报参数非法。**

说明前端提交的参数结构与服务端的 Schema 校验规则不一致，仔细对照接口报错中指出的字段即可快速定位。

**一直提示未认证。**

通常是登录令牌已失效，或者保护路径与受保护前缀配置不匹配。请检查当前会话凭据及安全路径配置。

**改了配置不生效。**

首先确认动作接口是否已成功返回；其次确认该配置项是否有绑定对应的状态刷新事件；最后可以手动刷新页面查看最新快照。
