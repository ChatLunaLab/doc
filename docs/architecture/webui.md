# 控制台

::: tip
WebUI 不是「给后端套一个页面」，而是一个独立的前端应用 + 一组实时通道。页面由插件注册，状态由服务端推送，操作走带校验的动作接口。
:::

控制台里有三十来个页面：聊天、轨迹、工具、权限、记忆、MCP、市场……

这些页面不是写死在一个大应用里的。

它们来自各个插件：每个插件声明自己的页面、自己的接口、自己的文案，然后由控制台外壳组装起来。

## 双面包

一个页面插件通常包含两部分：

- **服务端**：路由、状态、动作、权限检查。
- **客户端**：React 页面、表单、实时数据订阅。

两者通过类型化的契约共享数据结构：状态类型、动作名、输入输出。

这样前端知道该调什么，后端知道该返回什么，改动时类型会报错。

## 通信

控制台有两条通道。

### HTTP

普通请求走 HTTP：

- 读取静态资源。
- 执行动作（写操作）。

动作接口带输入校验、幂等键、权限检查。

### WebSocket

实时通道负责推送：

- 连接初始化。
- 认证。
- 状态快照与增量更新。
- 心跳。

::: tip
为什么不全用 WebSocket？

因为动作需要重试与幂等，HTTP 的语义更合适；而状态需要「变了就推」，WebSocket 更合适。

两条通道各司其职，比强行合二为一可靠得多。
:::

## 认证

连接建立后并不立刻可用：

1. 服务端发一条初始化帧。
2. 客户端发认证帧（令牌或会话凭据）。
3. 认证通过后，才开始推送状态。

未认证的连接只能收到初始化与心跳。

认证会定期复核：令牌失效后，连接会被主动断开，而不是继续拿着旧权限推送。

### 路径保护

控制台路径与接口路径默认在受保护前缀里。

未配置保护、或者保护路径配错时，诊断会报错——这是刻意的，因为控制台等于执行权限。

## 状态

服务端为每个「状态」声明：

- 如何读取当前快照。
- 哪些事件会触发刷新。
- 是否推送给所有客户端。

插件注册状态后，控制台订阅它，服务端在变化时推送。

### 刷新策略

- **事件驱动**：订阅配置变更、插件状态、连接状态等事件。
- **定时刷新**：用于「没有事件但会变化」的东西，例如机器人状态。
- **手动刷新**：动作执行后主动触发。

### 背压

推送不是无条件的：

- 连接拥塞时，服务端会丢弃中间状态，只保留最新快照。
- 长时间无响应会被断开。

这保证了一个慢浏览器不会拖垮整个推送通道。

## 动作

动作是写操作的统一入口。

一个动作包含：

- **名字**：例如保存适配器、启停插件。
- **输入 Schema**：校验参数。
- **处理函数**：真正干活。
- **权限检查**：由动作内部或中间件完成。

### 幂等

动作支持幂等键。

网络抖动导致的重试，不会重复执行——服务端会返回第一次的结果。

这对「安装插件」「切换开关」这类操作尤其重要。

## 资源

### 版本化外壳

前端壳资源带版本号。

浏览器缓存命中时直接使用，版本不符才重新下载。

### 插件资源

每个插件的客户端代码单独打包，按插件 id 与修订号命名。

插件更新后，旧资源不会被覆盖——已打开的页面仍然能加载自己的 chunk。

### Service Worker

服务 worker 负责缓存策略：

- 版本化的壳与插件文件：缓存优先。
- 页面导航：网络优先，失败回退到上次可用的壳。
- 接口与实时通道：直接放行，不缓存。

这让弱网环境下的控制台仍然可用。

::: warning
改动前端后看不到变化，第一反应应该是「缓存」。

强制刷新一次，或者等待版本更新。不要先怀疑代码没保存。
:::

## 页面与插槽

页面通过路由注册：

```ts
ctx.slots.route({
  path: '/tools',
  page: async () => (await import('./tools')).ToolsPage,
  title: '工具',
  icon: 'wrench',
  order: 10,
  group: 'capabilities',
})
```

注册即可用，不需要改外壳。

### 分组与排序

每个页面声明所在的导航分组与顺序。

分组标签（概览、对话、配置、插件、能力、观测）由外壳提供，页面只引用。

### 隐藏页面

有些页面需要一个地址但不该出现在导航里，比如轨迹详情。

声明为隐藏即可。

### 插槽

除了整页，插件还可以往已有页面里插入内容：

- 仪表盘卡片。
- 规则页的标签。
- 表单字段的控件。

插槽是带类型的：声明了插槽的页面会定义内容形状，贡献方必须匹配。

## 表单

大部分配置页由 Schema 驱动：

1. 插件注册配置结构。
2. 服务端把结构序列化给前端。
3. 前端渲染成表单。
4. 提交时服务端再校验一次。

这样新增配置项不需要写前端代码。

### 表单扩展

某些字段需要特殊控件：工具列表、预设选择、技能列表、元素选择。

这些通过「表单扩展」注册，按字段类型或角色匹配。

## 文案

页面自带中文与英文文案，通过本地化接口注册。

缺失的键会回退到默认语言，而不是显示空白。

## 生命周期

所有注册都绑定在插件生命周期上：

- 路由、插槽、状态、动作、文案。
- 卸载时自动清理。

所以热重载不会留下「幽灵页面」。

## 安全

控制台的能力边界很大：

- 安装任意插件。
- 修改任意配置。
- 读取会话与轨迹。

因此：

- 默认只允许本机访问。
- 接口与控制台路径受令牌保护。
- 公网部署必须走反向代理与 HTTPS。

## 排查

**页面白屏。**

看控制台报错与失败请求。常见原因是插件资源版本不匹配，或者某个 chunk 加载失败。

**页面存在但数据为空。**

检查对应的状态是否注册、事件是否触发、接口是否返回错误。

**动作报参数非法。**

前端提交的结构与服务端 Schema 不一致。看错误里指出的字段。

**一直提示未认证。**

令牌失效或路径保护配置有问题。检查登录状态与受保护前缀。

**改了配置不生效。**

确认动作成功返回；确认状态有对应的事件刷新；刷新页面看快照。
