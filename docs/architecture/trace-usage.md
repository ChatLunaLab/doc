# 轨迹与用量

::: tip
轨迹回答「这一轮发生了什么」，用量回答「这些事花了多少钱」。两者共享同一份数据来源：span。
:::

模型调用是一个黑盒。

它为什么这么回答、为什么用了这么久、为什么花了这么多 token，光看最终文本是看不出来的。

轨迹系统把每一次调用拆成可观察的片段：一轮、一步、一次工具调用、一次子代理执行。

## Span

一条轨迹由一棵 span 树组成：

| 类型 | 代表什么 |
| --- | --- |
| turn | 一轮完整对话 |
| step | 一次模型请求及其工具执行 |
| model | 一次模型调用 |
| tool | 一次工具调用 |
| subagent | 一次子代理执行 |
| chat | 一次对话请求 |

每个 span 记录：开始时间、结束时间、状态、属性、用量、子 span。

属性是键值对，记录上下文：模型、提供商、工具名、参数摘要、错误信息。

### 生命周期

span 有两个事件：

- 开始时广播一次。
- 结束时广播一次，带上最终快照。

事件载荷是深拷贝的快照，订阅者不能持有可变引用——这是为了避免界面与写入互相干扰。

### 用量

span 可以累计用量：输入、输出、缓存读写、推理 token。

累计发生在 span 上，而不是每个 sink 自己算。这样不同消费者看到的是同一个数字。

## 消费者

span 事件可以被多个消费者订阅：

- **会话存储**：把轨迹写进数据库，供界面查询。
- **文件输出**：追加写入 JSONL，适合外部分析。
- **计费**：把用量折算成成本。
- **自定义**：插件可以订阅事件做自己的统计。

它们彼此独立，一个消费者出错不应该影响其他消费者。

## 轨迹页

控制台里的轨迹页展示的是持久化之后的数据：

- 按会话列出最近的活动。
- 点进去看某一轮的完整树。
- 每个节点可以展开属性、输入输出摘要、错误。

几个实用功能：

- **回放**：按时间顺序重看这一轮发生了什么。
- **草稿重调**：拿到当时的请求快照，重新发起一次调用，用于对比。
- **进程视图**：把并发执行的步骤按时间线排开。

::: tip
排查「为什么答非所问」时，最有用的不是最终回复，而是这一次请求里实际带上了哪些上下文。

轨迹里能看到提示词摘要、可用工具、模型参数，这些才是原因所在。
:::

## 用量

用量是轨迹的聚合视图。

### 记什么

每次模型调用记录：

- 提供商与模型。
- 用途（对话、判定、提取、摘要等）。
- 输入、缓存读、缓存写、输出、推理 token。
- 是否流式。
- 耗时。
- 成本。

失败的调用也会记录，但只有能确定提供商与模型时才会产生计费行。

### 成本从哪来

两种来源：

- **配置的价格**：你在计费插件里填写的单价。
- **模型目录的价格**：提供商元数据里自带的价格。

配置优先。两边都没有时，成本记为 0，并标记来源为「无」。

价格按百万 token 计，分成输入、缓存读取、输出三项。

::: warning
成本估算不等于账单。

中转服务、阶梯价、促销、缓存策略都可能让实际费用与估算不同。想精确对账，以服务商账单为准。
:::

### 聚合

明细保留一段时间（默认 90 天），每日汇总永久保留。

汇总维度包括：日期、模型、用途、会话。

这样既能看「今天花了多少」，也能追溯「哪个模型、哪个功能最贵」。

### 导出

用量可以导出 CSV，用于外部报表或对账。

## 界面

用量页通常包含：

- **概览卡片**：今日花费、请求数、缓存命中。
- **趋势图**：按时间的花费曲线。
- **分组表**：按模型、会话、用途拆分。
- **明细**：单次调用的记录。

仪表盘上也会放一张今日用量的卡片。

## 与其他子系统的关系

**缓存**直接影响用量：命中缓存的前缀按缓存价计费，而不是输入价。

**压缩**会改变上下文长度，从而改变每一轮的成本。

**子代理**是独立会话，用量单独统计，但会汇总到同一个账户视角。

**判定模型**（唤醒、审查、意图）也会产生用量，通常走小模型。

## 采样与开销

轨迹本身有开销：序列化、写库、事件广播。

在极高频的场景里，可以考虑：

- 只持久化关键 span。
- 降低属性粒度。
- 缩短明细保留时间。

不要为了「留证据」无限期保留所有明细。

## 排查

**轨迹页是空的。**

确认轨迹插件已启用；确认数据库可用；确认这一轮确实产生过模型请求。

**用量对不上。**

先确认价格配置；再确认缓存 token 是否被正确记录；最后确认是否有调用走了别的提供商实例。

**成本一直是 0。**

没有配置价格，模型目录里也没有价格。补上单价即可。

**某次调用没有被记录。**

检查是否在记录之前就失败了；检查轨迹消费者是否报错。

**数据太多，查询很慢。**

缩短保留期，或者只保留汇总。轨迹适合排查，不适合长期归档。
