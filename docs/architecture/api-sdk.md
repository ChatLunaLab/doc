# 接口与 SDK

::: tip
ChatLuna 可以脱离聊天平台，被外部程序调用。接口是 HTTP + 实时流，SDK 是一层薄封装。
:::

控制台自己用的就是这套接口。

所以你可以在脚本、CI、自己的应用里做同样的事：创建会话、发消息、读回复、看用量、管理预设。

## 认证

所有受保护接口都需要访问令牌。

两种方式：

- **请求头**：直接带令牌。
- **会话**：先换成短期会话凭据，再用于后续请求。

路径前缀（默认是接口与管理界面）在服务端受保护，未认证的请求会被拒绝。

::: warning
令牌等于控制台权限。

把它放进前端代码、公开仓库、或者聊天记录，等于把实例交出去。外部调用应该放在服务端进行。
:::

## 会话接口

会话是外部调用的核心概念：一次对话、一个持久化的上下文。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/agents` | 列出可用的 Agent 分组 |
| GET | `/api/sessions` | 分页列出会话 |
| POST | `/api/sessions` | 创建会话 |
| DELETE | `/api/sessions/:id` | 删除会话 |
| GET | `/api/sessions/:id/messages` | 读取消息 |
| POST | `/api/sessions/:id/messages` | 发送消息 |
| POST | `/api/sessions/:id/steer` | 在回合中途补充输入 |
| POST | `/api/sessions/:id/cancel` | 取消当前回合 |
| POST | `/api/sessions/:id/fork` | 从当前会话分叉 |
| POST | `/api/sessions/:id/compact` | 压缩上下文 |
| GET | `/api/sessions/:id/events` | 事件流 |
| GET | `/api/sessions/:id/live` | 实时流 |

### 创建会话

可以指定标题、预设、模型。

不指定时使用默认配置。

### 发送消息

发送是异步的：接口接受消息后返回，回复通过实时流或事件流获取。

不要把「接口返回了」当成「模型答完了」。

### 分页

列表接口用游标分页，而不是页码。

这样做是为了在数据不断变化时仍然保持一致：翻页时不会因为新增记录而重复或遗漏。

## 实时流

实时流有两条：

- **事件流**：会话级事件（状态、回合、工具调用）。
- **实时流**：面向外部程序的简化流，缺点是能力相对有限。

流式响应的好处是：不用轮询，模型输出的一部分一到达就能拿到。

连接会定期心跳；长时间无响应会被服务端断开。

## 幂等

写接口支持幂等键。

同一个键重复提交时，服务端返回第一次的结果，而不是执行两次。

这对重试很重要：网络超时后不确定是否成功，可以安全地重发。

## 错误

错误响应有统一的形状：

```json
{
  "error": {
    "code": "INVALID_ARGUMENT",
    "message": "invalid input: model"
  }
}
```

常见错误码：

| 码 | 含义 |
| --- | --- |
| `INVALID_ARGUMENT` | 参数不合法 |
| `UNAUTHORIZED` | 未认证或令牌失效 |
| `FORBIDDEN` | 已认证但无权执行 |
| `NOT_FOUND` | 资源不存在 |
| `PRECONDITION_FAILED` | 状态不允许，例如插件未安装 |
| `CONFLICT` | 并发冲突，例如会话被别处修改 |

状态码与错误码分开：状态码表示 HTTP 层面的成败，错误码表示业务原因。

## SDK

SDK 是一层薄封装：

```ts
const sdk = new ChatLunaSDK({
  baseUrl: 'http://127.0.0.1:5028',
  token: process.env.CHATLUNA_TOKEN,
})

const session = await sdk.createConversation({ title: '脚本任务' })
await sdk.sendMessage(session.id, '帮我总结一下这个文件')
const history = await sdk.listMessages(session.id)
```

它只做了三件事：拼 URL、带令牌、解析错误。

没有隐藏状态，也没有本地缓存——所有状态都在服务端。

### 能力探测

SDK 可以先查服务端支持哪些能力（实时流、版本等），再决定用哪条路径。

这比假设「一定有某个接口」更稳。

## 典型用法

### 脚本与自动化

在 CI 里跑一次对话，检查输出。

或者定时触发一次总结，把结果发到别的地方。

### 自定义前端

不想用自带控制台，可以用接口自己搭一个聊天界面。

会话、消息、流式输出都是现成的。

### 桥接其他平台

把别的平台的消息转发进来，再把回复转发出去。

注意这时候会绕过适配器，平台能力（编辑、撤回）需要自己实现。

### 数据导出

读取会话、用量、轨迹，做自己的报表。

## 安全

- 只在内网或本机暴露接口。
- 公网访问放在反向代理与 HTTPS 之后。
- 令牌按最小权限管理。
- 外部输入的会话 id、文件名要校验，不要直接拼路径。

::: warning
接口能创建会话、能触发工具调用。

不要把它当成「只读 API」暴露给不可信调用方。
:::

## 排查

**401。**

令牌错误或过期。确认请求头格式，确认令牌来源（配置、环境变量或数据目录）。

**403。**

认证通过但无权操作。检查路径是否在受保护前缀、动作是否被权限系统拒绝。

**创建会话失败。**

检查预设与模型是否可用；检查是否有插件处于未加载状态。

**发送后没有回复。**

确认实时流已连接；确认这一轮没有被判定为忽略；看轨迹。

**重复消息。**

没带幂等键，重试被执行了两次。补上幂等键。

**列表翻页重复。**

用了页码而不是游标。用返回的游标继续翻。
