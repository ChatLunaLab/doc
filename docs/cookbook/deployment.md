# 反向代理与网络接入

::: tip
这一页只谈网络这一层：怎么把控制台放到代理后面、代理需要注意什么、不同接入方式的取舍。访问令牌、允许远程访问、受保护前缀这些安全设置，见[公网部署](/manual/recipe/server)。
:::

## 代理必须做到的四件事

无论用 Nginx、Caddy 还是 Traefik，把请求转发到实例端口时都要满足四个条件：

1. **保留真实来源**：把访问者的真实地址以转发头传给实例。实例靠它判断请求来自哪里，不传的话所有请求看起来都来自代理本机。
2. **支持协议升级**：控制台依赖长连接推送实时数据，代理必须转发协议升级请求头，并把连接按长连接处理。
3. **不缓冲响应**：长连接上的数据要立刻下发，代理一旦攒批，聊天、轨迹、日志都会变成「过一会儿才刷出来」。
4. **超时够长**：空闲的长连接会被代理按默认超时掐断，需要显式调大。

::: warning
最常见的失败不是打不开，而是「能登录、页面在，但不刷新」。

出现这种情况先查协议升级和缓冲：这两项配错时，普通请求全部正常，只有实时数据不流动。
:::

## HTTPS

证书交给代理管理，实例保持明文监听在本机回路地址上。

这样做把证书续期、加密套件、HTTP/2 都收敛在一处，实例本身不必关心 TLS。使用支持自动签发的代理（比如 Caddy 的自动 HTTPS、Traefik 的证书解析器）可以省掉手动续期。

## 子路径部署

把控制台挂在域名下的某个子路径时，需要同时处理两边：代理要把子路径剥掉或保留，实例要按同样的基础路径生成资源地址。

部署后打开浏览器开发者工具，看有没有 404 的静态资源。子路径问题几乎都会在这一步暴露：少拼一层就是白屏，多拼一层就是样式丢失。

## 三种接入方式

| 方式 | 适用场景 | 代价 |
| --- | --- | --- |
| 反向代理 + 域名 | 长期对外提供服务 | 需要证书、需要维护代理配置 |
| SSH 隧道 | 临时远程排错 | 只在那台机器上临时可用，用完即断 |
| 内网 / VPN | 家用 NAS、公司内网 | 外网访问需要先连 VPN |

### SSH 隧道

在本机把远程实例的端口映射到本地端口，然后像访问本机一样打开控制台。不需要证书，不需要修改实例配置，也不会暴露任何端口。

### 内网直连

客户端与服务器在同一内网时，直接访问实例地址即可。需要移动端在外访问，就在路由器或 VPN 上开一条通往内网的通道，而不是把控制台直接放到公网。

## 代理之后的配置项

| 项目 | 位置 | 说明 |
| --- | --- | --- |
| 监听地址与端口 | 服务插件配置 | 默认只监听本机 |
| 允许远程访问 | 服务插件配置或环境变量 | 不开时，即使代理正确请求也会被拒 |
| 访问令牌 | 配置 / 环境变量 / 数据目录 | 公网环境必须用固定强口令 |
| 受保护前缀 | 服务插件配置 | 接口与控制台路径必须在其中 |

逐项含义与检查方法见[公网部署](/manual/recipe/server)。

## 上线前自检

1. 从另一台机器（手机流量即可）能打开登录页。
2. 登录后聊天页的新消息是即时出现的，不是攒一批。
3. 轨迹页在对话过程中实时刷新。
4. 关掉代理后长连接断开，恢复后自动重连。
5. 用诊断命令确认配置没有报错。
