# 反向代理与网络接入

::: tip
本节介绍如何配置反向代理以访问控制台、代理层的关键配置项，以及不同接入方式的权衡取舍。

关于访问令牌、允许远程访问、受保护前缀等安全配置，请参考 [公网部署](/manual/recipe/server)。
:::

完成机器人的基础部署后，下一步通常是考虑如何从外部网络稳定且安全地访问控制台。

直接将实例端口映射到公网缺乏灵活的路由控制，也会将内部服务直接暴露在公网环境中。更稳妥的做法是通过反向代理统一接管外部流量。

## 代理必须做到的四件事

无论使用 Nginx、Caddy 还是 Traefik，只要将外部请求转发给实例端口，都需要满足以下四个基本条件：

1. **保留真实来源**：反向代理必须将访客的真实地址通过请求头传递给实例。
   实例依赖这些请求头判断请求来源。若未正确传递，实例记录的所有请求都会来自本机回环地址（如 `127.0.0.1`）。这不仅会导致访问日志无法记录真实 IP，后续基于来源地址的安全策略与限频规则也会失效。
2. **支持协议升级**：控制台依赖长连接实时向浏览器推送状态与数据。
   反向代理在转发 HTTP 请求时，必须能够识别并透传协议升级请求头，将初始的 HTTP 连接升级为 WebSocket 等长连接。若未配置协议升级，浏览器与实例之间的握手会失败，控制台无法建立双向通信。
3. **关闭响应缓冲**：长连接传输的数据需要即时下发，不能在代理层排队缓冲。
   反向代理默认通常会开启响应缓冲，将上游的数据包积攒成批后再发送给客户端。这会导致聊天流式输出、调用轨迹和运行日志无法即时显示，表现为界面卡顿数秒后内容一次性弹出。
4. **保持足够超时**：空闲长连接容易被代理服务器按默认超时断开，需要显式调大超时时间。
   普通网页请求通常在数秒内完成，反向代理默认的读写超时设置一般较短（如 30 秒或 60 秒）。控制台长连接在无操作时会持续处于空闲等待状态，一旦超时被代理断开，前端就会频繁报错并不断发起重连。

::: warning
最常见的配置问题并非页面无法打开，而是「可以登录且页面正常显示，但数据不刷新」。

出现这种情况时，请优先检查协议升级与响应缓冲设置。普通的静态资源与登录请求走的是标准 HTTP，不受长连接影响；只有依赖长连接推送的实时数据，才会在代理配置不当时停止更新。
:::

## HTTPS

推荐将 TLS 证书完全交由反向代理统一管理，实例自身仅在本地回环地址上保持明文 HTTP 监听。

这种架构可以将证书申请、自动续期、加密套件协商以及 HTTP/2 等特性收敛在代理层。实例无需关心复杂的 TLS 握手细节，只需专注于业务逻辑。

若使用支持自动签发证书的现代代理（例如 Caddy 的自动 HTTPS 功能，或 Traefik 配合 Let's Encrypt 证书解析器），无需手动下载和替换证书文件，即可全自动完成配置与续期。

## 子路径部署

若打算将控制台部署在域名的子路径下（例如将特定前缀路径转发到控制台），需要同时处理好代理与实例两端的路径约定。

相比独立域名（所有资源请求直接从根路径计算），子路径部署的前端资源定位更为敏感。

在反向代理侧，需要明确路径转发规则：是剥离子路径前缀后再转发给实例端口，还是原样传递完整路径。同时，实例侧也必须配置对应的基础路径参数，确保返回页面时内部引用的脚本、样式和接口请求都带有正确的子路径前缀。两端路径预期不一致会导致请求错位。

配置完成后，可以通过以下方式验证子路径是否正常工作：

打开浏览器开发者工具，切换到「网络」面板观察是否有请求返回 404 状态码：
- 路径缺失时，前端无法加载入口脚本，通常表现为页面白屏。
- 路径多余时，页面骨架虽然可以加载，但样式和图标会因加载失败而错乱。

## 三种接入方式

面对不同的使用环境，需要在安全性、便利性与维护成本之间做出权衡。下表对比了常见的接入方式：

| 方式 | 适用场景 | 代价 |
| --- | --- | --- |
| 反向代理 + 域名 | 长期对外提供服务 | 需要证书，需要维护代理配置 |
| SSH 隧道 | 临时远程排错 | 仅在连接期间可用，断开即失效 |
| 内网 / VPN | 家用 NAS、公司内网 | 外网访问需要先连接 VPN |

下面介绍 SSH 隧道与内网直连的具体用法。

### SSH 隧道

如果只是临时需要对远程服务器上的机器人进行排错或修改设置，SSH 隧道是成本最低且安全的选择。

它的原理是通过 SSH 在本地与远程服务器之间建立加密通道，将远程实例监听的端口映射为本地端口。之后直接在本地浏览器中访问该端口，效果与在远程服务器本机打开控制台一致。

这种方式无需额外配置：
- 无需申请域名与 SSL 证书
- 无需改动实例现有的监听配置
- 无需在安全组或防火墙中对外开放端口

排查结束后断开 SSH 会话，外部访问通道即刻关闭。

### 内网直连

若服务器与访问设备处于同一局域网（如家用 NAS、软路由或公司内网），直接通过局域网地址访问即可。设备间直接通信，无需绕行公网，兼顾速度与安全性。

若需要在外网访问内网中的控制台，不建议将端口直接映射到公网。更稳妥的做法是在内网设备上搭建虚拟专用网络（例如使用 WireGuard 或 Tailscale）。在外网时先连入 VPN，再通过内网地址访问控制台，既能满足移动访问需求，又避免将服务暴露给公网扫描。

## 代理之后的配置项

配置好反向代理后，还需要调整实例自身的访问控制策略，否则请求仍会被实例拒绝。

对接反向代理时，请在实例侧核对以下四个关键配置项：

| 项目 | 位置 | 说明 |
| --- | --- | --- |
| 监听地址与端口 | 服务插件配置 | 默认只监听本机 |
| 允许远程访问 | 服务插件配置或环境变量 | 未开启时，即便代理配置正确也会被拒绝访问 |
| 访问令牌 | 配置 / 环境变量 / 数据目录 | 公网环境下必须使用固定强口令 |
| 受保护前缀 | 服务插件配置 | 接口与控制台路径必须包含在内 |

其中最常见的问题是未开启「允许远程访问」。配置完代理后若浏览器提示连接被拒绝，通常是因为实例仍处于仅允许本地访问的限制中。

关于上述配置项的具体含义、环境变量优先级以及检查方法，请参考 [公网部署](/manual/recipe/server)。

## 上线前自检

在控制台正式投入使用前，建议按照以下清单逐条测试，确保整条数据链路正常稳定：

1. **公网连通性**：从处于外网环境的设备（例如断开 Wi-Fi 并使用移动蜂窝网络）访问控制台，确认能够正常加载并展示登录页面。
2. **实时消息推送**：登录控制台并发起对话，观察机器人的流式回复是否即时出现，确认消息未在代理层被成批积攒。
3. **轨迹实时刷新**：在对话进行时切换到轨迹页面，观察各项执行步骤是否实时滚动刷新，而非等待整轮对话结束后一次性显示。
4. **断网重连**：尝试在服务器上临时停止反向代理服务，控制台的长连接应当及时断开；代理恢复后，页面应能自动重连并恢复正常状态。
5. **健康诊断**：在实例中运行配套的诊断指令，确认系统配置无报错或潜在的监听警告。
