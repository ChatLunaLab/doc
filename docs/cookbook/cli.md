# 命令行诊断

::: tip
控制台打不开、实例起不来、会话数据可疑时，终端里的几条命令往往比界面更管用。
:::

WebUI 挂了、实例起不来、会话数据可疑——这时候能救你的不是界面，是终端。

## 两个入口

### 全局启动器

安装后可以直接在终端使用 `chatluna` 命令。

它管理 `~/.chatluna` 下的实例：创建、启动、停止、升级、修复。

### 实例内命令

实例自己的 `chatluna` 命令（通常在项目里用包管理器运行）专注于诊断与导出。

它不负责启动实例——启动是启动器的事。

::: tip
分不清的时候看帮助。

全局启动器的命令面向「实例」，实例内命令面向「数据」。
:::

## 实例管理

| 命令 | 作用 |
| --- | --- |
| `create <名字>` | 创建实例（可选模板、包管理器、目录） |
| `start [名字]` | 启动（可后台运行） |
| `list` | 列出实例与运行状态 |
| `stop [名字]` | 停止 |
| `restart [名字]` | 重启 |
| `dev [目录]` | 开发模式启动（热更新，不做恢复与安全模式） |

### 默认实例

不带名字时启动默认实例。

默认实例记录在启动器配置里。创建第一个实例时会自动写入。

### 后台运行

`start` 带后台参数时，日志写到日志目录，进程脱离终端。

适合部署在服务器上。

### 开发模式

`dev` 用源码方式启动，支持热更新。

它刻意关闭了快照恢复与安全模式——开发时你希望看到真实失败。

## 依赖管理

| 命令 | 作用 |
| --- | --- |
| `add <包...>` | 往实例里装插件 |
| `remove <包...>` | 卸载 |
| `link <目录>` | 链接本地插件目录 |
| `unlink <名字>` | 取消链接 |

安装走的是与控制台相同的包管理队列，不会与界面操作冲突。

链接适合开发：改本地代码，实例立刻看到。

## 维护

### update

更新启动器与实例插件。

流程是：快照 → 更新 → 健康检查 → 失败回滚。

这条命令把「升级」变成了可回退的操作。

### repair

实例起不来时使用。

它会收集诊断信息，尝试一次本地修复，并生成一份报告。

### report

查看最近一次修复的报告，包括失败启动的日志尾部。

::: warning
`repair` 不是魔法。

它解决的是「配置或依赖明显不对劲」这类问题，不能修复逻辑 bug。修复失败时，报告里的日志才是关键。
:::

### new

在实例、项目或仓库里生成一个插件骨架。

适合开始写自定义插件时用。

## 诊断

### 配置检查

检查清单是否合法、包契约是否满足、控制台入口是否完整。

常见发现：

- 插件名拼错。
- 依赖缺失。
- 受保护路径配置错误。
- 控制台入口找不到资源。

### 会话检查

针对某个会话检查日志不变量：

- 是否有断档。
- 索引与内容是否一致。
- 标记是否成对。

### 缓存检查

分析会话的缓存周期与切换原因。

如果你怀疑「为什么每轮都没命中缓存」，这条命令能直接告诉你哪一次切换破坏了前缀。

### 提供商检查

检查各提供商的连通性。

需要实例正在运行，命令会通过接口探测。

### 导出

把某个会话的完整日志导出成 JSONL。

适合：

- 提交问题报告。
- 本地分析。
- 备份重要会话。

::: tip
导出的是完整日志，包含工具调用与系统消息。

发给别人之前，先确认里面没有敏感信息。
:::

## 输出与退出码

诊断命令输出人类可读的报告。

脚本里使用时，注意退出码：有错误时非零。

修复报告有固定结构，方便粘贴到 issue。

## 部署中的用法

### 服务器

用后台模式启动，交给系统服务管理器托管。

升级时先 `update`，不行就按报告回滚。

### 容器

容器入口通常直接启动实例。

健康检查探 WebUI 端口；起不来时看容器日志。

### CI

可以用实例内命令做冒烟检查：

- 配置是否合法。
- 包依赖是否完整。
- 会话日志是否能读出。

## 与 supervisor 的关系

命令行启动时，进程由 supervisor 监管：

- 崩溃自动重启。
- 健康检查失败进入恢复。
- 恢复失败进入安全模式。

命令行本身只是发起者；持续运行的是 supervisor。

## 排查

**命令找不到实例。**

确认名字拼写、确认 `~/.chatluna/instances` 下确实存在。

**start 后立刻退出。**

看日志尾部。端口占用、配置错误、依赖缺失是最常见的三类。

**list 显示运行中，但打不开。**

可能是健康检查还没通过，或者端口被代理挡了。

**update 后起不来。**

用修复或回滚到快照。报告里会有失败原因。

**doctor 报路径保护错误。**

控制台路径没有列进受保护前缀。这是危险的配置，必须修。

**导出失败。**

会话 id 不对，或者会话数据损坏。先跑会话检查。
